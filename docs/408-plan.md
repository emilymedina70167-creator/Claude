# 计划：408 四门课的教学工具（数据结构、操作系统、组成原理、计算机网络）

线代的组件已经比较成熟。这一份是计算机四门课的总计划：怎么做、先做什么、做到哪了。
`docs/ds-components-design.md` 是数据结构里 `trace`、`tree`、`net` 三个组件的细节方案，这份计划采用它。

## 0. 目标和定下来的口径

学习发生在 claude.ai 的项目里：Claude 用这个仓库的组件库（`la-kit.js`）发布 artifact，在黑板上教，而不是在对话框里打字。所以要做的是「教学引擎」：Claude 写几行描述，页面负责画、算、动、判分、报错。

- **口径：王道**。下标、next 数组、CLOCK、周转时间这些有不同写法的地方，一律按王道。比如 KMP 的 next 从 1 开始数、`next[1] = 0`；堆和顺序存储的树下标从 1 开始。
- **术语**：线代照旧附英文；计算机四门课是中文考试，默认不附（`subject:` 不是线代时，课堂说明里的这一条换掉）。
- 原则和线代一样：
  1. **组件来算**：Claude 只写输入（序列、代码、引用串……），每一步的状态由程序算，不让 Claude 手算。
  2. **写错要报出来**：写法看不懂、参数不合理，页面自检列出来，课堂模式会让 Claude 自动重写。
  3. **要学生动脑**：先猜下一步再揭晓；作答（答错的也算）和草稿都进记录。
  4. **课堂里能指挥**：每个演示都接 `figure`（跳到第几步、播放、闪一下）和 `board mark`。

## 1. 思路：按「引擎」做，不按「课」做

408 的题大多是三种形态：模拟一个过程一步步走、算出一个数、把一串二进制位拆成字段。同一种形态在几门课里反复出现：

| 引擎 | 数据结构 | 操作系统 | 组成原理 | 计网 |
|---|---|---|---|---|
| 步进器外壳 | 全部 | 全部 | 流水线、cache | 滑动窗口、TCP |
| `trace` C 子集解释器 | 代码逐行跟踪 | PV 同步（多进程交替） | | |
| `net` 图算法 | 遍历、最小生成树、最短路、拓扑、关键路径 | | | 距离向量、链路状态 |
| `bits` 位和字段 | | 虚拟地址拆页号 / 偏移 | 补码、IEEE 754、标志位、指令格式、cache 地址 | IP、子网、CIDR |
| 替换策略（FIFO / LRU / CLOCK / OPT） | | 页面置换 | cache 替换 | |
| 时间轴 / 甘特图 | | CPU 调度 | 流水线时空图 | |
| `matrix`（已有） | 邻接矩阵、Floyd | 银行家算法 | | |

**步进器外壳**（`stepper.js`）是最关键的一块：每个算法只写一个纯函数「输入 → 每一步的状态和一句说明」，外壳统一给上一步 / 下一步 / 播放 / 进度、`ask` 先猜再揭晓、`quiz` 写出结果、课堂的 `figure step`、刷新后恢复、草稿。新算法只用写引擎和画面。

## 2. 分批

| 批 | 内容 | 状态 |
|---|---|---|
| 0 | 地基：组件手册按科目分包（课堂说明有 160 KiB 上限）；表达式加进制、`mod`、整除、位运算、`log2`；判分加序列答案和二进制答案；步进器外壳 | 完成（`sort` 是第一个演示组件：插入、冒泡、选择、快排、归并、基数） |
| 1 | 数据结构一：`tree`（遍历、BST、堆、堆排序）；查找（KMP、散列表、折半查找判定树） | 完成（`tree`、`kmp`、`hash`、`bsearch`） |
| 2 | 数据结构二：`net`；`trace` 一期（不含指针） | 完成（`net`、`trace`：C 子集解释器 `cinterp.js`） |
| 3 | 操作系统：CPU 调度、页面置换、地址转换（页表、TLB、多级页表）、银行家、磁盘调度 | 完成（`sched`、`paging`、`banker`、`disk`、`addr`；多级页表、PV 同步留到第 6 批） |
| 4 | 组成原理：`bits`（补码、溢出和标志位、IEEE 754、指令字段和寻址）、cache 访问模拟、五段流水线和冒险 | |
| 5 | 计网：子网划分 / 聚合 / 最长前缀匹配、停等 / GBN / SR 时序图、TCP 握手挥手和拥塞窗口 | |
| 6 | 加深：`trace` 二期（指针、链表）、PV 同步、AVL / B 树 / 哈夫曼 / 线索二叉树 | |

数据通路、存储器扩展、文件系统结构这类静态图先用 `sketch` 加计算题（`practice type: custom`），不单独做组件。

每批做完：`npm test` 全过；iPad 横竖屏各走一遍；写进 `CLAUDE-PROJECT.md` 的组件说明（课堂里的 Claude 自动会用）；`class-demo.html?dev` 里加一个暗号能看到新组件。

## 3. 组件手册按科目分包

课堂里每一轮的说明（`buildSystem`）要在 160 KiB 以内，资料包还要占到 104 KiB。四门课的组件说明全塞进去会超，所以：

- `CLAUDE-PROJECT.md` 第三节「组件参考」的小节标题下面写 `<!-- 科目：数据结构 操作系统 -->` 这样的标记（一个引擎几门课都用时写几门），没写的是通用的。
- 构建时整节打包，课堂按课件开头的 `subject:` 挑（`subject.js` 的 `docsForSubject`）：线代课拿「通用 + 线代」，操作系统课拿「通用 + 操作系统」。不认识的科目全部带上。
- 课堂说明「教法」里偏线代的几条（挑矩阵、附英文、`formula: n`）按科目换成计算机的一套（`prompt.js` 的 `defaultRules`），红线不变。
- `tests/subject.test.js` 守着：每门课的整份说明加上最大的资料包都在 160 KiB 以内。
