# 需求：课堂模式（课堂里的 Claude 实时出画面）

给 Claude Code 的实现说明。前一份 `live-board-spec.md`（实时黑板）已经实现。这份在它之上再做一步，现有的组件和 live 模式都保留。

## 0. 要解决什么

实时黑板试下来，暴露出一个问题：黑板上的每一段，都是项目对话里的 Claude 提前写好的。学生在第 2 步卡住，后面 3 步照样摆着，连锁失败。老师要等学生做完一整段、回对话说一声，才看得到情况。好的家教在学生卡住的那一秒就会反应：退一步、换个更小的问题，或者在图上指给他看。

课堂模式要做到这一点：

- 学生进入一个课堂页面。**页面底部是对话框**，学生和「课堂里的 Claude」实时对话。
- **整块黑板都由课堂里的 Claude 现场画**：讲一句话，同时在黑板上写公式、出能拖的图、放动画、出一步步揭开的题。用的是组件库现有的全部组件，不是新的画图方式。
- 学生在黑板上的任何作答（选择、填数、拖点、手写、「想不出来」），课堂里的 Claude 马上就能看到，并且接着往下教。
- 课堂里的 Claude 没有学生的全局记忆，只有**这节课的资料包**（课前由项目对话里的 Claude 写进数据库）和**这节课本身的完整对话**。
- 项目对话里的 Claude 只在课前（备资料包）和课后（读整段课堂记录、判断掌握、更新记忆）出场，上课过程中不需要它。

## 1. 页面

```html
<title>秩一方阵</title>
<script src="la-kit.js"></script>
<script type="text/markdown">
---
mode: class
unit: 第2讲 §2 · 秩一方阵
---
</script>
```

发布参数和 live 模式一样：`capabilities: {"sample": {"images": true}, "db": {}, "assets": {}}`。

### 1.1 布局（iPad 横竖屏都要好用）

- **黑板区**占满上方：沿用 live 模式的段落样式，新内容追加在下面并自动滚过去。绑定了题目的图（`link:`）照常吸附在旁边。
- **对话条**固定在底部：
  - 输入框（打字），旁边是「✎ 手写」（弹出手写板，写完连图一起发）和「截图」（粘贴或选图）。
  - 快捷按钮：「没懂」「想不出来」「换个说法」「继续」。点了等同于发一句对应的话。
  - 课堂里的 Claude 说的话，显示在对话条上方一个可以展开的消息区。默认只显示最近一两句，展开能看全部。它的话要短，主要内容写在黑板上。
  - 生成时显示「Claude 正在写黑板…」，话和黑板内容都**边生成边出现**。
- 已有的「板书」（整页手写）、「问 Claude」入口：课堂模式下「问 Claude」就是底部对话框，不再单独出现。

## 2. 课堂里的 Claude 怎么出画面

### 2.1 输出协议（主路径：纯文本，可流式解析）

每一轮，课堂里的 Claude 输出一段文本，由页面边收边解析：

- 普通文字 = 对学生说的话，显示在消息区。
- 黑板指令用围栏代码块，语言名是 `board`。块结束（收到闭合的 ```）时立即执行：

````
```board add id=b7 title="Ax 也是一个向量"
（这里是一段课件 Markdown，和 guided / live 课件里一节的写法完全一样，可以含任何组件）
```

```board replace id=b5
（替换 b5 的内容）
```

```board hide id=b5
```

```board figure target=fig-b7 set x=[1,2]
```

```board figure target=fig-b7 play t
```
````

- `add`：在黑板末尾加一段。`id` 由 Claude 起，同一节课里不能重复。
- `replace` / `hide`：改掉或撤回一段。
- `figure`：操作黑板上的图。`target` 是图的 `id:`（课堂模式下组件都要写 `id:`）。`set 变量=值` 改变量，`play t` 从 0 播放到 1，`highlight 命令序号` 让某个元素闪一下。复用现有 `scene` / `space` / `graph` 的 `snapshot()` / 变量设置接口（tutor.js 里的 `set_variable` 已经有一部分）。

为什么用文本协议而不是工具调用：工具调用不是每个查看方式都支持（`sample.limits().tools` 可能没有），而且文本协议能边生成边显示。如果 `tools` 可用，可以额外提供工具（见 2.4），但主路径不依赖它。

### 2.2 写错了怎么办

- `board add/replace` 的内容先过组件库现有的写法自检（`session.problems` 那一套）。有错时**不显示坏掉的组件**，把错误信息作为一条系统消息发回给课堂里的 Claude，让它重写这一段。最多重试 2 次；还不行就把那一段显示成一个小提示「这段没画出来」，课堂继续。
- 围栏没闭合、指令看不懂：当作普通文字显示，不报错。

### 2.3 每一轮发给课堂里的 Claude 什么

用 `sample(turns, opts)`，`turns` 是多轮对话。最前面一条是完整的课堂说明，按这个顺序拼：

1. **角色与红线**（组件库内置一份默认的，资料包里的 `rules` 可以覆盖）：你是这节课的老师；一次只推进一件事，给完就停下等学生；学生没有作答就不往下推；卡住时先分清缺知识还是缺思路，缺知识直接讲清，缺思路给提示不给答案，同一个点三轮提示还不通就讲清楚、换同类题；学生说「没把握」按没过处理；不要宣布学生「已经掌握」；**资料包里没有的教材内容不讲**，说「这个课后问对话里的 Claude」；话要短，主要内容写在黑板上；能让学生拖、点、预测的，就不要让他写长段文字。
2. **组件写法**：组件库内置一份精简的组件说明（从 `CLAUDE-PROJECT.md` 第三节生成，构建时打包进去），加上 2.1 的黑板指令协议。
3. **资料包**（见第 3 节），原样放入。
4. **黑板现状**：现在黑板上有哪些段（id、标题、一句话摘要），每段里学生的作答结果（对 / 错 / 放弃 / 拖到哪 / 手写转写）。

后面是课堂对话本身：学生说的话、学生在黑板上的动作（作为一条用户消息，例如「[作答] b7 里的 steps 第 3 步：选了『跑到线外去』（错），用时 44 秒」），以及 Claude 之前的输出。

- **学生在黑板上作答时自动发起一轮**：提交后等 1.5 秒（学生可能连着操作），把这期间的所有动作合成一条消息发出去。学生点了「想不出来」「没懂」立即发。
- **手写和截图**：图片随这一轮的 `images` 一起发，同时存进 `assets`（和现在一样）。
- **长度控制**：`maxPromptBytes` 是 256 KiB。资料包预算约 120 KiB。对话超过约 80 KiB 时，让课堂里的 Claude 先写一段「到目前为止的课堂摘要」（学生卡在哪、错过什么、已经讲到哪），用摘要替换最早的那部分对话，最近 20 轮保留原文。
- **模型（学生已明确指定）**：课堂里的 Claude 用 **Opus 5.5**：每次调用传 `model: "claude-opus-5-5"`，同时传 `modelTier: "complex"` 作为退路（指定的模型用不了时，平台会不报错地退到这个档）。`effort` 默认不传（用平台的常规思考量）；资料包 `pack/main` 里可以写 `model` / `effort` 覆盖。
  - 每次返回后看 `modelApplied`：等于 `"claude-opus-5-5"` 才是 Opus 5.5 在讲。对话条上常驻一个小标记「Opus 5.5 授课」；某一轮退到了别的模型（`modelApplied` 缺失），标记改成「这一轮由备用模型回答（complex 档）」，并把这件事记进 `class/turns` 的那一轮。
  - 其他小活不必用 Opus：手写转写用 `"default"` 档；后台的长度摘要可以用 `"default"` 档。
- **出错**：`rate_limited` 时显示「请求太频繁，等一下再说」；`not_granted` 时说明需要允许页面使用 Claude。不要自动循环重试。

### 2.4 可选：工具

`sample.limits().tools` 可用时，额外给这些工具（只是方便，不是必需）：

- `get_answers(blockId)`：读某个组件的全部作答记录，包括每次尝试和手写转写。
- `view_handwriting(answerId)`：把某次手写原图再发给自己看。
- `lesson_note(text)`：记一条给课后看的观察，例如「W19 又出现：把 βᵀα 当成矩阵」。

## 3. 资料包（项目对话里的 Claude 课前写进数据库）

| 路径 | 内容 |
|---|---|
| `pack/main` | `{ unit, goal, scope, textbook, plan, student, rules?, model?, effort?, updatedAt }`，字段都是长文本 |
| `pack/problems` | `{ items: [...] }`：这节课可用的题（题面、答案、考点、来源），课堂里的 Claude 从里面取，也可以自己改数 |

- `goal`：这节课要学生最后能做到什么，例如「看到行成比例的方阵能认出秩一，并用 tr 写出 Aⁿ，能说清为什么」。
- `scope`：文稿规定的范围和详略、考试口径。超出范围的不讲。
- `textbook`：教材原文的定义、公式、例题（逐字或忠实转写，数字准确）。课堂里的 Claude 只能用这里的教材内容。
- `plan`：建议的推进顺序和每一步想让学生动脑的点。这是建议，课堂里的 Claude 根据学生实际情况调整。
- `student`：学生和这节课相关的弱点、过去的典型错误、上一次课停在哪。
- 资料包被改动时（课中也可能被项目对话改），下一轮自动用新版本。

## 4. 课堂记录（给项目对话里的 Claude 课后读）

- `class/turns/{seq}`：每一轮一条：`{ seq, role: 'student' | 'claude' | 'system', text, actions, images, boardOps, at }`。`boardOps` 记下这一轮执行了哪些黑板指令（add / replace / hide / figure 及 id）。课后要能完整复原「谁说了什么、黑板上出现了什么、学生怎么作答」。
- 现有的 `answers`、`events`、`steps`（黑板段落，`by: 'class'` 标明是课堂里的 Claude 写的）照常写。
- `class/notes/{id}`：`lesson_note` 记的观察，以及下课时（学生点「下课」或关掉页面前）让课堂里的 Claude 写的一份小结：讲了什么、学生哪里卡住、哪里看起来懂了但证据不够、建议下一节怎么接。
- 重新打开页面时，从数据库恢复黑板和对话，接着上。

## 5. 本地开发与验收

- `?dev` 模式下，可以选「模拟老师」：一份写死的脚本按顺序回放几轮输出（含 `board add`、`figure`、写错的组件），用来测解析、流式显示、自检重试、恢复，不用真的调用 Claude。
- 验收：
  1. 发一句话，课堂里的 Claude 一边说话，一边在黑板上加段，内容边生成边出现。
  2. 黑板上的 `steps` / `answer` / `predict` / 拖动 / 手写作答提交后，不用学生再说话，课堂里的 Claude 自动接着回应。
  3. `figure set/play` 能让已有的图动起来。
  4. 写错的组件不显示，并且会被自动重写（`?dev` 脚本里故意放一段写错的来测）。
  5. 刷新页面，黑板和对话完整恢复。
  6. `class/turns` 能完整复原整节课；手写原图能通过 asset id 取回。
  7. 在 iPad 上横屏、竖屏各走一遍：底部对话条不挡住正在作答的组件，键盘弹出时布局正常，Apple Pencil 在黑板和对话条的手写里都能用。
  8. `guided`、`live` 模式不受影响；`npm test` 通过；重新打包，更新组件库 artifact；加一个示范页 `kit/examples/class-demo.html`；在 `CLAUDE-PROJECT.md` 里加一节「课堂模式」，写清项目对话里的 Claude 课前写什么、课后读什么。

## 6. 第一次试用

项目对话里的 Claude 会准备「秩一方阵」的资料包，从学生在实时黑板第二段卡住的地方开始：$A\mathbf x$ 本身也是一个向量，所以 $A$ 再作用一次，它还在那条线上。
