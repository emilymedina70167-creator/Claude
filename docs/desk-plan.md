## 3. 第 1 批：记录能力（记得全、记得准、存得稳）

### 3.1 课后报告（页面代码算，不调用 Claude）

下课时（以及「以前的课」打开一节时）由代码把这节课整理成一份 `sessions/{编号}/report/main`，结果确定、可测：

- 每个作答组件一行：题面（截短）、所在段和板、尝试次数、每次对错的序列、总用时、放弃 / 揭开 / 看答案、最终结果、手写原图 id。
- 按块、按知识点（`tags`）汇总：做了几题、一次对几题、错几题、放弃几题、用时。
- 没做完的题、没提交的草稿（下课那一刻的 `drafts.js` 快照）。
- 我说的话（`say` 证据）原样列出，附的图列 id。
- 课堂 Claude 这节课的观察、提议、小结的 id。
- 这节课时长（开课到下课，去掉长时间没动静的段）。

用途：课后整理（第 2 批）、「以前的课」页面（第 3 批）、外部 Claude 课后只读这一份就够。纯函数放 `memory/report.js`，配测试。

## 4. 第 2 批：内部 Claude 改学习台的能力（分档、可确认、可撤销）

### 4.1 三档权限（默认值如下，动手前问我要不要调）

| 档 | 哪些 | 怎么写 |
|---|---|---|
| **直接写** | 讲法偏好、学习习惯（写进 `profile`，`topic` 用「讲法」「习惯」）；它自己的教学失误（`slips`）；观察（`observations`） | 课堂 Claude 用工具写，这一轮核验是 Opus 5.5 才生效 |
| **我确认才写** | 新错题（`errors`）、新弱点 / 弱点证据级变化（`weaknesses`）、新复现组 / 往复现组加题（`reviews`）、下一节从哪接（`position`） | 课堂 Claude 写成「待确认」，我在页面上点「确认」才写进去 |
| **只能提议** | 掌握状态（`mastery`，红线：课堂不能宣布掌握）、规则（`rules`） | 照旧写 `observations` 的 proposal，外部 Claude 或我决定 |

- 「我确认才写」的落地方式：新集合 `pending`（`{ coll, op: "add" \| "update", id?, data / patch, reason, basis: [证据 id], session, turn, at }`）。确认时页面按记忆库规矩写进目标集合：状态类自动记 log（`by: "class"`，`note` 写「我确认于 …」），历史类只增不改。不要的标成 `rejected`，留着给课后看。
- `schema.js`：给对应集合的 `writers` 加上确认路径（建议新角色 `confirmed` 或在 log 里区分），`assertWrite` 照旧拦住课堂 Claude 直接写这几类；`check.js` 认新的 `by` 值。
- **不用工具写，写在输出里：**每调用一次工具，课堂 Claude 就要多跑一整轮、把整份说明（几万 token）重读一遍。所以写记忆不走工具，而是像黑板指令一样写在它这一轮的输出里，页面解析后执行，**不多花一轮**：

  ~~~
  ````board memo
  error id=L2-08 weakness=W19 basis=ev-…,ev-… step="第 1 步换括号" cause="把 βᵀα 当矩阵"
  pref topic=讲法 text="先看图再推公式"
  slip text="一次出了两道题" lesson="一块板一件事"
  ````
  ~~~

  `protocol.js` 加一种 board 块 `memo`（和 `mark` 一样一行一条），解析成纯函数配测试；每条都要 `basis`（证据 id，从记忆摘要里来），没有依据的拒绝并在 `[系统]` 提醒里说原因。现有的 `lesson_note`、`slip_note` 工具也改成这种写法（工具留着兼容，说明里不再推荐）。`memory_read` 照旧是工具（它要等回答），说明里写清「很贵，只在摘要里确实没有时用」。
- 每一轮写了什么，在板顶那句话下面小字列出来（「记下了：偏好 1 条；待你确认：错题 1 条」），点开能看、能撤。

### 4.2 下课时的整理单

点「下课」时，**和小结在同一次调用里**（不多调用一次）：课后报告（3.1）放进这次的输入，课堂 Claude 先写小结，再用 `memo` 块列出整理单：新错题、弱点变化、复现组怎么调、下一节从哪接、它这节课的失误。全部进 `pending`，在小结那块板上逐条显示：理由 + 证据（点开看那次作答原文）+「确认 / 改 / 不要」。这样大部分课后不用回外部对话（外部对话读一遍说明书和记录要花得多）。外部 Claude 照旧能做同样的事（读报告、读 `pending`），两条路写同一份记忆。

### 4.3 撤销和我自己改

- 任何一条写入（不论谁写的）在一段时间内能撤：状态类按 log 回退一步（回退本身也记一条 log），历史类追加一条「作废」更正（不删原条）。
- 我在页面上能直接改：偏好、某条错题标「已解决」（加更正，不改原条）、复现组暂停。新角色 `me`（我自己），log 里写清楚。

### 4.4 安全线（不能松）

- 只有核验过是 Opus 5.5 的那一轮，工具写入才生效（现有 `staged` 机制）。
- 页面在代码层面拦住越权写入（`assertWrite`），不靠提示词。
- 资料包、证据里的文字可能影响它调用哪个工具：所有「我确认才写」的都必须经过我点确认。

## 7. 省额度（贯穿每一批）

在学习台里上课，**每一轮**都要把整份说明重新发给 Claude（页面调用 Claude 不记得上一轮）：角色和规则、组件手册、记忆摘要、资料包、黑板现状、对话。现在一轮大约 60～160 KB（约 2～6 万 token）。多跑一轮（工具、重写）就再花一次。要做的：

1. **量出来再说。**每一轮记下发了多少字节（现在开发面板已经有 `lastPrompt`），写进 `class_turns` 和 `sessions/{编号}`（这节课一共多少、平均每轮多少、多跑了几轮、为什么多跑）。「⋯」菜单和「以前的课」里显示，单位换成「约多少千 token」。有了数字，后面每一项改动都能比较前后。
2. **少跑轮：**
   - 写记忆用输出里的 `memo` 块，不用工具（第 4.1 节）。
   - 整理单和下课小结同一次调用（第 4.2 节）。
   - 重写（组件写错要它再写一轮）是最常见的额外轮：统计哪些组件最常写错，把它们的说明写清楚、例子写准，减少重写。
   - 「停久了提醒老师」（`stuck.js`）每触发一次就是一整轮，默认改成关（「⋯」里能开），问我同不同意。
3. **每轮少发：**
   - 记忆摘要的预算从 32 KiB 降到 16 KiB，先放和这一块直接有关的；测一下够不够用（真课里看它有没有频繁去 `memory_read`，那更贵）。
   - 组件手册（每门课约 40 KB，是最大的一块）：资料包里写了 `components`（这节课要用的组件）时，进一步只带「最常用的几个 + 点名的」，其余只列名字和一句话；要用再查。改完用 `evals/` 和真课看写错有没有变多。
   - 黑板现状里旧板只留标题和一句话（现在已经比较省，量一下再决定动不动）。
4. **不加：**会在课外反复调用 Claude 的功能（比如「问学习台」）。

**不能为了省额度改的（硬性规定）：**讲课只用 Opus 5.5、effort high；平台换了别的模型就整轮作废。
