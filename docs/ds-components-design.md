# 设计方案：数据结构组件（代码逐行跟踪、树、图）

> 2026-10 更新：`trace` 一期（解释器，不含指针）、`tree`（遍历、二叉排序树、堆）、`net`（遍历、最小生成树、最短路径、拓扑、关键路径）已经做了，写法以 `CLAUDE-PROJECT.md` 第三节为准（和下面的方案有出入的地方以那里为准）。还没做：`trace` 二期（指针、结构体、链表）、AVL、B 树、哈夫曼、线索二叉树。总计划见 `docs/408-plan.md`。

原方案：

## 0. 为什么要做

现在组件库是为线代做的。数据结构（408）只有排序那几个：`array`、`sortpass`、`shellsort`。其中 `shellsort mode: code` 能一行一行走王道的 `ShellSort`，但那是专门为这一段代码写死的，别的代码用不了。

于是课堂里的 Claude 讲数据结构时，只能用文字和数组硬讲：
- 讲代码时，它只能把代码贴出来，再用文字解释每一行。
  - 你的记录里写着「逐行步进的演示比文字逐行解释有效」。
  - C 语言基础（赋值方向、下标和值、for 三段的执行顺序）是高频弱点。
- 树和图完全没有图示。

三条原则和现在的组件一样：

1. **组件来算**：Claude 只写代码、结构和输入；每一步的变量值、遍历顺序、最短路径都由程序算，不让 Claude 手算轨迹。手算会算错，学生跟着错。
2. **写错要报出来**：写法看不懂时页面自检列出来（课堂模式会自动让 Claude 重写），不静默。
3. **要你动脑**：先猜下一步，再揭晓；你的作答（答错的也算）和草稿都进记录，课堂里的 Claude 能看到。

## 1. `trace`：代码逐行跟踪

### 写法

````
```trace
id: tr-ins
title: 直接插入排序（带哨兵）
call: InsertSort(A, 5)
let A = [0, 38, 49, 65, 13, 27]
watch: i, j, A[0]
show: A as array from 0
ask: line 7, i == 4 → j 现在是多少？
code:
void InsertSort(int A[], int n){
    int i, j;
    for(i=2; i<=n; i++)
        if(A[i]<A[i-1]){
            A[0]=A[i];
            for(j=i-1; A[0]<A[j]; --j)
                A[j+1]=A[j];
            A[j+1]=A[0];
        }
}
```
````

- `code:` 下面是一段 C 代码（王道写法照抄就行），`call:` 是从哪个函数、用什么参数开始跑，`let` 给出输入。
- `watch:` 右边变量表里列哪些。`show: A as array` 把数组画成格子，`i`、`j` 这类下标变量当指针标在格子下面。
- `ask:` 预测点：走到那一行、满足条件时，先把相关的值遮住，让我填或选，判分并记录，再接着走。

### 怎么跑

页面里带一个 C 子集的解释器：纯函数，不碰 DOM，用 `node --test` 测。它把代码真的跑一遍，记下每一步的行号和变量值。

- **第一期**：
  - 类型：`int`、`double`、`char`、`bool`，一维和二维数组；
  - 运算：算术、比较、逻辑运算，`++`、`--`、`+=` 等；
  - 语句：`if` / `else`，`for`、`while`、`do-while`，`break`、`continue`、`return`；
  - 函数和递归（递归时显示调用栈，快排、归并、DFS 都要用）；
  - `printf` 输出到页面上的「输出」框。
- **第二期**：`struct` 和指针（链表、二叉链表、邻接表），`malloc` / `free` 画成结点框和箭头。
- 不支持的写法（`goto`、宏、文件读写……）由自检报出来：「第 5 行：不支持 goto」。
- 步数上限 10000，防止死循环卡住页面；超过了就停下，并说明「可能是死循环」。

### 界面（iPad 横竖屏）

- **左边是代码**：
  - 当前行高亮，执行过的行淡淡标出来；
  - 点行号能设断点。
- **右边是状态**：
  - 变量表（这一步变了的值闪一下）；
  - 数组格子（下标变量当指针标在格子下面）；
  - 调用栈（递归时一层一层叠起来）；
  - 输出框。
- **按钮**：上一步、下一步、跳到下一次到这一行、运行到结束，以及一个进度条。
- **竖屏**：代码在上、状态在下，代码框高度固定、可以滚动，当前行自动滚到中间。

### 动脑

- `ask` 预测点（见上）。
- `mode: quiz`：只给代码和输入，我写出最后的数组或输出，自动判分。和 `sortpass` 一样，每次检查都记录。
- `mode: findbug`：代码里藏一个错（比如 `j>=0` 写成 `j>0`），我先猜错在哪一行，再运行看结果哪里不对。

### 课堂里怎么动

- `figure target=tr-ins step 12`：跳到第 12 步。
- `figure target=tr-ins goto line=7 hit=3`：第 3 次到第 7 行。
- `figure target=tr-ins highlight 7`：只高亮第 7 行。
- 黑板现状里写着现在停在第几步、哪一行、变量值是多少。

### 和现有的关系

`shellsort mode: code` 以后可以改成用 `trace` 实现。旧写法保留，已经发布的课件不受影响。

## 2. `tree`：树

### 写法

````
```tree
id: t1
title: 中序遍历
nodes: A(B(D, E), C(, F))
walk: inorder
ask: order
```
````

- **结点的两种写法**：
  - 括号写法 `A(B(D, E), C(, F))`：逗号前是左子树，空着表示没有；
  - 层序数组 `level: 1 2 3 null 4`。
- `walk:` 演示一种遍历（`preorder` / `inorder` / `postorder` / `levelorder`），结点按顺序亮起来，旁边写出序列。
- `ask: order`：我依次点结点，写出遍历序列，自动判分。

### 种类

- **第一期**：
  - 普通二叉树：遍历，以及由两种序列还原树的检查；
  - 二叉排序树 BST：插入和删除一步步走，比较路径高亮，删除的三种情况都演示；
  - 堆：`heap: 53 17 78 09 45 65 87 32`，树和数组两种视图联动，建堆、插入、删除时上滤 / 下滤的每一步。
- **第二期**：
  - 平衡二叉树 AVL：插入后找失衡点，LL / RR / LR / RL 旋转动画；
  - 哈夫曼树和编码；
  - 树、森林和二叉树的互相转换；
  - 线索二叉树。

### 动脑

- 点结点写出遍历序列；
- 在 BST 里点出新结点该插在哪；
- 在堆里点出下一次要交换的两个结点；
- 指出 AVL 的失衡点。

都是自动判分、记录、草稿看得到。

### 课堂里怎么动

- `figure target=t1 play inorder`：播放中序遍历。
- `figure target=t1 highlight B`：高亮结点 B。
- `figure target=t1 set nodes=...`：换一棵树。

## 3. `net`：图（数据结构里的图）

现有的 `graph` 是函数图（概率分布那种），所以这个叫 `net`，说明里写清楚两者的区别。

### 写法

````
```net
id: g1
title: Dijkstra
edges: A-B 4, A-C 2, B-C 1, B-D 5, C-D 8, C-E 10, D-E 2
run: dijkstra from A
view: graph, table
ask: next
```
````

- **边**：`edges:` 里 `A-B 4` 是无向边加权值，`A->B` 是有向边，权值可以不写。
- **布局**：自动排（圆形、分层，有向无环图从左到右）。也可以写 `pos: A(0,0) B(2,1)` 固定位置，跟教材上的图对得上。
- **算法**：`run:` 后面接算法和起点，可选 `bfs`、`dfs`、`prim`、`kruskal`、`dijkstra`、`floyd`、`topo`（拓扑排序）、`critical`（关键路径）。
- **视图**：`view:` 选显示哪些，可选 `graph`（图）、`table`（每一步的 dist / path 表，Floyd 是矩阵）、`adjmatrix`（邻接矩阵）、`adjlist`（邻接表）。
  - BFS / DFS 在邻接矩阵和邻接表下的访问顺序可能不同，两个视图并排能看出来。
- **每一步显示什么**：当前顶点、队列或栈里有什么、表里刚变的那一格高亮、选中的边加粗。

### 动脑

- `ask: next`：每一步先让我选下一个顶点（或下一条边），再揭晓。
- 让我填 dist 表的某一格、写拓扑序列、点出最小生成树的边、算 ve / vl。

都是自动判分并记录。

## 4. 建议的顺序

1. **`trace` 第一期**（不含指针）：对你最有用。C 语言基础是弱点，逐行演示又最有效；而且排序、查找、栈和队列各章的代码题都能马上用上。
2. **`tree`**：遍历、二叉排序树、堆。
3. **`net`**：遍历、最小生成树、最短路径、拓扑排序、关键路径。
4. **`trace` 第二期**：指针、链表、二叉链表。

每一步做完都在 iPad 横竖屏下验证、写进组件说明（课堂里的 Claude 自动就会用），再发一节测试课给你试。

## 5. 要你定的

1. 名字 `trace`、`tree`、`net` 行不行。
2. `trace` 有两种做法：
   - **解释器**：真的跑代码。准确，任何简单的 C 代码都能跑，但工作量大。
   - **只做几段固定的王道代码**：像现在的 `shellsort` 那样，快，但换一段代码就用不了。

   我推荐解释器：王道各章的代码都很短，C 子集足够覆盖。
3. 先做哪一个。我建议先做 `trace`。
