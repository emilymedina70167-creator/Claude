# 考情：让学习台里的 Claude 懂这场考试（第八轮）

2026-11-12 起。这一份是第八轮的总计划和进度。舞台主线（`docs/stage-mainline.md`）停在第七轮；第八轮不做舞台的新功能，只做这一件事。每一批开工前照仓库的习惯在 `docs/superpowers/specs/` 写这一批的设计、在 `docs/superpowers/plans/` 写实施计划，做的时候自己定的事记进同目录的 `…-rulings.md`。写计划时请了一个助手对着代码审过一遍，查出来的 21 处已经改进这一份（末尾「进度」里记着改了什么）。

## 我要的

（2026-11-12 我说的）学习台里的 Claude 要**足够懂这场考试**，才能对我当下学的东西做出评估。不是答疑，是像一个专业的考研教学团队：知道考什么、怎么考、考到多难、我离要求还差多远、下一步该学什么。而且要**越来越懂**：考试的信息（院校、科目、大纲、历年真题）放进去以后，多起来也能整合好、不丢；我每上一节课，它对我和这场考试的判断都更准。**不要靠我手动维护**。额度很富裕，可以做一个很强的技术系统来支撑。

## 先说清楚：Claude 自己不会学

学习台里每一次调用 Claude 都是从零开始，模型不会因为上过我的课就变聪明，也记不住上一轮。它「懂」多少，**全看页面每一轮交给它的那一份**。所以「越来越懂」只能这样实现：

1. **存**：关于这场考试、关于我的东西都进数据库，越积越多、越积越准（有守卫、有指纹、能重算）；
2. **炼**：零散的原料由代码统计、由教研室归纳，变成小而准的结论（谁归纳的、依据是哪几道题都写着）；
3. **取**：每一轮按这一课挑出最相关的那一小份交给它，其余留一行目录。

「懂我」那一半已经是这么做的（记忆库、复盘、守则、`digest.js` 的全文 + 目录）。这一轮照同样的三层，把「懂考试」那一半搭起来，再让两半接上。

## 线画在哪

和舞台主线同一条线：

- **考试的事实归代码**：考没考过、哪年、第几题、几分、考了几次、占这门课多少、答案对不对、我做没做过、做对没有。这些从带标签的真题里**算出来**，不让 Claude 凭记忆说，也不让它在一大堆文字里数。
- **考试的判断归 Claude**：这一块怎么考、坑在哪、教到什么程度才够、我这一次错在哪儿和真题的哪个坑是一回事。写的时候**必须引题号**，守卫核题号真有、没引留作模考的题。
- **每一层都能重算**：原料（真题原文）→ 标签 → 统计 → 画像，下游都记着上游的指纹，上游一变下游自己知道过时了，不靠人记得去改。

Claude 本来就懂不少考研的东西，但具体到哪年考了什么、几分，凭记忆会错。说明里写明：**考情的数字和年份只用页面给的**，页面没给的不说。

## 一、数据层

### 1.1 两张表，分开放

**考试的资料**（真题、考点、画像、动态）**不进记忆库**。记忆库的每一类都会被首页整类订阅（`desk.js` 对 `MEMORY_COLLECTIONS` 逐类 `onSnapshot`）、课堂开课时整类读进来、自检逐条查并把指纹写进单个文档 `meta/ledger`（单个文档上限 256 KiB）、`memory_read` 能读、备份整类导出——四门课十五年上千道题这样走会拖垮开课、撑爆 ledger。所以：

- **`EXAM_COLLECTIONS`**（新文件 `kit/src/exam/schema.js`）：`syllabus`、`papers`、`questions`、`passages`、`exam_profiles`、`exam_intel`。像教材（`books`）那样**按需读**：开课时只取这一块挂的考点、它们的画像、这些考点下能用的题（`kit/src/exam/load.js`，放进 `desk.js` 的 `openClassSafely` 的时限 `within` 里，读不到先开课、后台接着读，和教材一样）。**不订阅、不进 `meta/ledger`、不进 `memory_read`、不进首页的整类订阅**。写的时候照样过 `writer.js` 的 `validateWrite`（不在 `COLLECTIONS` 里的集合它现在直接放行，所以要让它也认 `EXAM_COLLECTIONS` 的规则）。备份（`backup.js`）单独加一段导出它们。
- **放进记忆库 `COLLECTIONS` 的只有两个小的**：`exam`（考试档案，一两条）和 `exam_bar`（每块的真题级，页面算的缓存，每块一条）。

编号避开已有的（记忆点 `K12`、守则 `T-…`、复现组 `R`、弱点 `W`、错题 `L2-07`、关于我 `p-…`、题库 `d-…`）。真题、考点的编号 `spaceOfId` 认不出来（它对不认得的前缀一律回退成线代），所以这几类每一条都**写明 `space` 和 `course` 字段**，代码里用 `kit/src/exam/` 自己的 `examSpaceOf`，不走 `spaceOfId`。

### 1.2 每一类

「谁写」照权限模型写：教研室、开发那边都不直接写库（教研室的回答由页面并进来，`labdesk.js` 用的是 `assertWrite('page', …)`），所以角色只有 `page`（页面并收件箱、算缓存）、`me`（我在页面上填）、`chat`（开发那边修数据）；是谁做的写在每一条的 `by` 字段里（`dev` / `lab` / `me` / `page`）。

| 集合 | 编号 | 是什么 | 角色 |
|---|---|---|---|
| `exam`（记忆库） | `target` | **考试档案**：目标院校、院系、专业和代码、学位类型、考哪几门（`101` 政治、`201` 英语一、`301` 数学一、`408`）、每门满分、总分目标和四科分配（现在 `score.js` 写死的 `GOAL` 410 和 `SUBJECTS` 的 `target` 改成读这里，没有档案时用原来的数）、考试日期（`journey.js` 的 `EXAM_DATE` 同样改成读这里）、历年复试线 / 招生人数 / 报录比（每一条带 `src`：链接或书、哪天查的、核过几次） | `me`、`chat`、`page`（并核过的考情动态） |
| `exam_bar`（记忆库） | 块的编号 | **这一块的真题级**（页面算的缓存，第五节）：做过哪几道真题、对没对、过没过、踩过哪些坑（`traps`，复盘对上的） | `page` |
| `syllabus` | `G-DS-6.4`、`G-LA-2.3`、`G-HM-3.2.1` | **考点树**（大纲）：门课、路径、标题、要求层级（了解 / 理解 / 掌握 / 会用，照大纲原文）、大纲原文、父节点、大纲年份、和上一年比变没变（`changed`）、挂到课程地图的哪几块（`blocks`，多对多，带 `mapAt` 和映射时课程地图的指纹）。线代的考点也带 `G-LA-` 前缀；课程地图里线代的块不带前缀，映射时单独认 | `page`（并收件箱、并教研室的映射）、`chat` |
| `papers` | `X-408-2019` | **一套真题卷**：卷子代码、年份、来源（私有仓库里的哪个文件、哪几页）、题数和总分（必须和结构表对上）、`reserve`（留作模考） | `page`、`chat` |
| `questions` | `Q-408-2019-23`、`Q-301-2021-17`、`Q-201-2020-46` | **一道真题**：卷、题号、题型、分值、题面（LaTeX）、选项、答案、解析（书上的原文）、原页图（asset id）、所属篇章（英语）、**标签**（下面）、**核对**（`verified`：答案怎么核过的——`engine` 引擎算过 / `exact` 精确计算核过 / `double` 两个助手独立做一致 / `book` 只照书 / `none`）。标签改了记在这一条自己的 `tagLog` 里（不走 ledger） | `page`、`chat` |
| `passages` | `PA-201-2020-T1` | 英语的一篇文章（阅读、完形、新题型、翻译的原文），几道题共用。前缀用 `PA-`，不用 `P-`（和关于我的 `p-` 只差大小写）也不用 `PS-`（概率的门课前缀） | `page`、`chat` |
| `exam_profiles` | 和考点同号 `G-DS-6.4` | **一个考点的画像**：统计（页面算、存一份缓存）、「怎么考」的文字（教研室写，引题号）、典型的坑（`traps`：每个坑一个编号 `G-DS-6.4#t2`、一句话、出现过的题号）、上游指纹（`src`：这几道题的编号和标签版本） | `page` |
| `exam_intel` | `ix-…` | **考情动态**：招生简章、专业目录、复试线、大纲变化、报录比。每条：种类、原文摘录、数字、链接、抓取日期、核过几次 | `page`（并教研室交回来的） |
| `exam_inbox` / `exam_inbox_log` | 随便 / 同号 | **只给开发那边入库用**的收件箱和回执：页面照 `kit/src/exam/schema.js` 查过再并进上面几类。写法照 `bookview.js` 的 `takeInbox`（并的时候写进度、屏幕常亮、出错重试、写回执），但并的逻辑另写一份（`takeInbox` 只认 `B\d+` 的书）。教研室不用这个，走现有的 `lab_brief` / `lab_inbox`（第六节） | 开发那边写、`page` 收 |

**真题的标签**（`questions/{编号}.tags`）用固定的词表，不写自由的话，才算得了统计：

- `syl`：考点编号 1～3 个，第一个是主考点（必须在 `syllabus` 里有）；
- `how`：考法，每门课一张固定的表（`kit/src/exam/taxonomy.js`；比如数据结构：手算过程 / 写结果序列 / 判性质 / 算复杂度 / 写代码 / 设计算法；线代：算 / 判秩和相关性 / 证明 / 含参讨论 / 抽象矩阵；英语：成分和结构 / 词义 / 推断 / 主旨 / 翻译要点……）。表在第 0 批照真题定下来，写进 rulings；
- `traps`：坑，一两句话（教研室归纳进画像时并成考点的坑编号）；
- `difficulty`：1～5（`est`）、谁估的（`by`）、依据（`basis`：「比 2019-41 多一层」这样的相对比较）；
- `time`：建议用时，页面按分值算（`分值 × 这门考试的分钟数 / 卷面总分 × 0.85`，留检查时间），不让 Claude 估；
- `engine`：能用黑板的引擎重算的题写上引擎名和**这个引擎的组件本来就收的那组字段**（比如排序是 `{ name: 'sort', algo: 'shell', array: '…', gaps: '…' }`），原样交给 `engine.parse`。入库时用它核答案，上课时舞台的 `follow` / 过程表、练一练的题都能直接接。

**留作模考**（`papers/{编号}.reserve`）：最近三年的整卷默认留到冲刺阶段做模考。留着的卷**只进统计**（考没考、几分），题面、答案、坑、代表题一律不出现在课堂、备课、教研室出题和练一练里。光过滤 `questions` 拦不住：王道的条目里本来就带年份真题（「【2014 统考真题】…」），会经 `textbookForClass` 的按书页取、整章补和 `textbook_search` 进课堂。所以 `kit/src/exam/reserve.js` 有两个函数：`usable(q)`（题）和 `scrubChunks(chunks)`（教材条目里出现留着那几年的统考标记就整条剔掉），后者接在 `textbookForClass`、`textbook_search`、`bookCatalog` 里。有测试守着（第六节）。

## 二、入库（Claude Code 做，一次性的重活）

照教材入库的路子（`docs/textbook-plan.md`、`tools/books.mjs`），多一个脚本 `tools/exam.mjs`。**真题和解析的 PDF 只放在我的私有仓库里**（不进这个公开的开发仓库，也不存成学习台的书：存成书会被当成教材带进课堂）。

1. **画页、转写**：`tools/books.mjs render` 那一套在云端画页、裁白边、传原页图（asset），照教材的转写规矩（`ingest.js` 的 `transcribePrompt`）看图转写，公式写 LaTeX。真题有自己的转写格式（`=== 第 N 页` / `--- 真题 | 2019-23`），写在 `tools/exam.mjs` 里，**不加进教材的条目类型 `KINDS`**（加了所有书的转写提示词都会变）。解析册同样转。
2. **切题** `node tools/exam.mjs split`：按题号切成一道一道，题面、选项、答案、解析对上同一个题号。**卷面结构表** `kit/src/exam/structure.js`（每门课每一年：几道题、每道几分、哪几题是哪种题型、合计多少分，比如 408 是 40 道单选每道 2 分加 7 道综合应用题；数学一的结构这几年改过，要分年份）照真题卷核过再写，**不凭记忆**；切出来的题数、分值和结构表对不上，整卷不收，报哪一题对不上。
3. **对答案**：答案从解析册取；能算的再算一遍——408 的过程题用黑板的引擎（`kit/src/engines/registry.js`：排序、散列、图、页面置换、调度……），线代的数值题用 `exact.js` / `paramcalc.js`，选择题核解析里的推理和选项字母一致；都不能算的，两个助手各自独立做一遍，一致才记 `double`。核对结果写进 `verified`，对不上的列出来给我看，不进库。
4. **打标签**：每道题交给**两个互不知道的助手**各打一遍（同一份说明、同一张词表、这门课的考点树和课程地图），比主考点、考法、难度：主考点一致的直接收；不一致的交第三个助手看两份理由定，记下分歧。每一批算一致率（主考点 ≥ 90% 才算这批合格，不合格先改说明、改词表再重打）。最后抽 20 道给我看（每道一行：题、主考点、考法、坑），我说不对的改了以后整批同类的再查一遍。
5. **做成能练的题** `node tools/exam.mjs drills`：页面判得了分的真题生成一段黑板组件（题库 `drills` 必填 `md`，`DRILL_MAX` 12 KiB）：选择题 → `quiz`；填空的数值 → `answer`（答案写成 `let` / `\calc`，不手写数）；408 的过程题 → 对应引擎的演示组件 `mode: fill`；别的题型（证明、写代码、翻译、作文）不做成练习。生成的每一段先用 `node tools/check-lesson.mjs` 在两种 iPad 尺寸下画一遍，有写法错误的不收。
6. **检查** `node tools/exam.mjs check`：编号都在、每道题至少一个考点、分值加起来等于卷面总分、留作模考的标对了、答案核对等级、英语的题都挂着篇章、每一条都有 `space` 和 `course`。
7. **写进去**：拼成收件箱记录，`ArtifactData batch` 写进 `exam_inbox`，学习台打开时并进去。

大纲同样转写，`tools/exam.mjs syllabus` 切成考点树。

**课程地图补门课**：现在 `space.js` 的 `COURSES` 只有 LA、DS、OS、CO、CN、EN，没有高数、概率（`HM-L1` 会被 `courseOf` 当成线代，`score.js` 又把带前缀的块从线代里排除，补出来也不算分）。第 2 批先在 `space.js` 的 `COURSES` 和 `subject.js` 里加 `HM`（高数）、`PS`（概率），再按考点树和教材目录给组成原理、操作系统、计网（第 2 批）、高数、概率（第 7 批）补出章的骨架（只到章，`weight` 按真题统计），410 分的进度从此不缺块。

先做 408（王道四本已经全部入库，真题和王道的章节几乎一一对应，引擎最全），跑通再铺数学一、英语一。

## 四、接进用的地方

### 4.1 作答带题号（字段叫 `exam`）

`q` 已经被占了：证据里的 `q` 是题面（`memory/session.js` 的 `toEvidence`、`live/sync.js`），黑板组件的 `q:` 是题面字段（`stepperspec.js` 的 `SHELL_FIELDS` / `TEXT_FIELDS`），题库、记忆点的 `q` 也是题面。所以题号的字段叫 **`exam`**，对标的题叫 **`like`**：

- **舞台**：`ask` 的七种和 `goal` 都收 `exam=Q-408-2019-23` / `like=Q-…`——`stage/script.js` 的 `OPTIONS` 加上（不在里面的选项会当场报「不认得」），`stage/scene.js` 里 goals 和等着的那一问存下这个字段，`stage/classroom.js` 写 goal、act 两条记录时带上，`stage/evidence.js` 的记录带上。舞台写法的说明里这一行**不加进 `stageDoc`**（数据结构那份离 24576 字节的上限只剩 476 字节），写进考情那一节（4.2，计入它自己的预算）。
- **黑板组件**（练一练用）：`stepperspec.js` 的 `SHELL_FIELDS` 加 `exam`、`like`，各个作答组件记 `session.record` 时带上；`toEvidence` 会把记录的其余字段原样带进证据，新字段名不用另改。
- **限时**：要算「在建议用时以内做对」，得知道这一问是什么时候亮出来的。舞台的作答记录现在只有作答那一刻的 `at`，没有 `ms`；黑板组件只有一部分记了 `ms`。所以舞台那一问亮出来时记 `shownAt`，作答记录带 `ms`；黑板组件里带了 `exam` 的统一记 `ms`。

### 4.2 舞台课的每一轮：「这一块在考试里」

`stage/doc.js` 的 `buildStageSystem` 加一节（说明的编号现在用了四个，`NUM` 有五个），放在资料包后面、记忆前面，**只在这节课有块、这一块有考情时才有**。内容按要紧程度装（`context.js`）：

1. 一行档案：目标院校和专业、考哪几门、这门课满分几分、离考试几天；
2. 这一块挂的考点和大纲原文（要求层级）；
3. 统计（页面算的）：近几年考了几次、哪几年、什么题型、平均每年几分、在这门课里排第几、最近是多了还是少了；
4. 「怎么考」和典型的坑（教研室写的，带题号）；
5. 代表题两三道全文（题、答案、解析要点）；
6. 我在这一块真题上的情况（读 `exam_bar` 缓存）：做过哪几道、对没对、真题级过没过、踩过哪些坑；
7. 其余能用的真题，一行一道的目录（年份、题型、考法）；
8. 这一节的用法，几句话，**写在这一节里、计入这一节的预算**（`STAGE_TEACH` 和 `stageDoc` 都没地方再加）：讲课的难度照真题定；这一块讲完前让我做一道真题级的题（代表题，或用 `exam=` / `like=` 写在那一问上）；引考情写题号；考情的数字只用这一节给的，这一节没有的考情不说。

**预算**：这一节自己的上限 `EXAM_BUDGET` 16 KiB。它放进 `parts()`，在算「剩下多少给资料包」之前就在，资料包会自己让出来，**不改 `PACK_BUDGET`**。量过：数据结构、线代、计网那几份「说明 + 舞台写法」是 24～29 KiB，记忆 28 KiB，现在资料包最多约 91 KiB；加了这一节约 75 KiB，各门课都还 ≥ 64 KiB。要注意的一处：资料包超了时 `packText` 用 `fairShares` 先截最大的字段，被截的多半是「教材原文」——所以第 4 批要给教材原文留底（至少 32 KiB，资料包里先算它），并把考情一节算进 `tests/stage-class.test.js` 那条资料包下限的测试。放不下时这一节先压代表题的解析，再压目录；档案、考点、统计、我的情况、用法那几句一定在。

**速度**：`docs/smart-plan.md` 第 0 节要求讲课那一次调用不许变重。这一节让说明平时更长一点，但整份照旧在 `STAGE_SYSTEM_MAX`（150 KiB）以内；依据是 `docs/talk-plan.md` 的测速（说明 4～160 KB 出第一个字一样快）。不加工具（每调一次工具多跑一整轮），课上要的都由页面先放好。每一批上过真课，出第一个字的时间和基线比，变慢不合。

**黑板课不接**：新课一律开舞台（`memory/session.js` 的 `classForm`），黑板课和一问一答只剩接着上的旧课；而黑板课的说明本来就紧（不带资料包和记忆就有 61～71 KiB，黑板现状没有上限，再挤 16 KiB 黑板现状一长整份就超 160 KiB）。

## 五、评估：真题级、410 分、下一步

**真题级**（`bar.js`）：这一块的**原真题**（证据带 `exam=`，第一次做）或**教研室对标真题出的、过了检查的新题**（带 `like=`）在一节课里第一次碰到就做对、没看提示、没标没把握，算「真题级过了」；同时在建议用时以内，算「限时过了」。课上老师当场改数出的题不算（没人核过它是不是真题的难度）；原题再做对也不算（rule-rev-2）。结果存进 `exam_bar`，首页每次自检之后（`runSentry` 那一路）重算、变了才写；不写进 `mastery` 的五种状态，掌握照旧。

**410 分**（`memory/score.js`）：

- 目标和四科分配从 `exam/target` 读（没有档案时用原来的数）。
- 块的权重（`weights.js`）：一部分的分照旧按大纲分到这一部分，再分到块时不再平分，按 `占比 = 0.3 × (1 / 这一部分的块数) + 0.7 × (这一块的真题期望分值 / 这一部分所有块的真题期望分值之和)`，两项都是比例、加起来是 1；没考过的块至少拿到平均那一份的三成。这一部分一道真题都还没入库时照旧平分。
- 有真题的块，**真题级没过最多攒到七成**（复现通过第 30 天那档也一样）：只会教材题、不会真题的块，在考场上不算稳拿。还没有真题的块照旧。「这 7 天攒了多少」用 `bar.js` 的 `asOf` 退回 7 天前一起算。

**下一步学什么**（`priority.js`）：每块「还能攒多少分」= 这一块在考试里值多少 × (1 − 现在攒到几成)；前置的块（课程地图的 `requires`）还没过基础题的先排前置；到期的复现加权；复盘对上过坑的加权。出：每科前五块、四科的时间怎么分（按还能攒的分，每科有下限）、这一周哪一科偏了（实际学的时间不到它该占的一半）。用在首页「下一步」、备课（`sentry.js` 的「该备的课」优先排它）。不调用 Claude。

- 讲课的还是只能 Opus 5.5 high；这一轮不加任何上课时的调用、不加工具。
- 新加的调用（教研室的几种单子）一律在云端或 `lane: 'bg'`，不碰回话速度。

## 九、尺子（验收）

照仓库的习惯，先有尺子再说「做好了」。放在 `evals/exam/`：

1. **入库质量**：结构表 100% 对上；答案核对等级的分布（`engine` + `exact` + `double` 的比例）；双人打标签的主考点一致率 ≥ 90%；我抽查的 20 道主考点 ≥ 19 道对。
2. **考情问答**（`evals/exam/qa`）：从数据里自动出 60 道有标准答案的考情题（「近十年 408 哪几年考过 Dijkstra 的综合题」「这一块平均每年几分」「2019 年第 41 题考的什么」），照真课的拼法给这一块拼说明，让 Opus 5.5 high 答，页面判。要求：给了的答对 ≥ 95%；**没给的（留着的卷、别的块）说「这里没有」，编出来的算 0**。
3. **难度对齐**：挑 20 块，老师照真课的说明写「这节课结束时的确认题」，一个看不到说明的助手拿它和这一块的代表真题比难度、比考法；加考情前、加考情后各量一次。要求：加了以后判成「够得着真题」的 ≥ 70%，而且明显比加之前多。
4. **评估一致**：拿真课的证据重算真题级、410 分、下一步，每一条结论都能指到证据和题号；e2e 加一段 `exam`（带 `exam=` 的作答 → 真题级 → 410 分变了 → 首页「下一步」变了；留着的卷不出现）。
5. **速度**：舞台每一轮说明的字节数照旧在上限以内；真课出第一个字的时间不比基线慢。
