# 量从没在底座上量过的 5 块（D1、D3、D4、E1、L3）

背景：这个仓库是「学习台」，课在「舞台」上上（`kit/src/stage/`）：老师（Claude）每一轮写镜头指令，页面演出来，学生直接在画面上动手。之前请几个不看舞台的老师写了十块内容的理想演法（`evals/stage-gaps/ideal/{块}.md`），再拿舞台一幕幕去写、去演、打标，量出「想做做不到」的缺口。底座做了两轮以后，D2、L1、L2、E2、E3 重新量过（`evals/stage-gaps/try3/`、`report3/`）；D1、D3、D4、E1、L3 这 5 块只在底座动工以前量过一次（`try/`、`report/`）。现在要拿做完两轮底座的舞台把它们重新量一遍，结果用来决定下一步「三科铺开」先补什么，所以要准：不夸，也不漏。

你量的块在派给你的那一句里写了。

## 照这份说明做

先读 `evals/stage-gaps/brief-try.md`，整份照它做（工具怎么用、怎么打标、两条纪律、报告格式）。下面几条和它不一样的，以这里为准：

- 舞台说明用现在的 `evals/stage-gaps/stage-doc.txt`（已经是底座第二轮以后的）。先把它整份读一遍：和第一次量的时候比多了很多写法（`open … wrong= call= undo=`、`{式子}`、量、`ask pick`、`keep` / `back`、预写三层、`@ask.right`、`collect`、整张矩阵拖、句子的拉线 / ✕ / 拖一段……），旧的 `try/` 里的写法大多还能用，但理想里很多以前做不了的现在可能做得了，要照新说明重写，不要照抄旧文件。
- 指令写到 `evals/stage-gaps/try3/{块}/`，文件名照 `evals/stage-gaps/try/{块}/` 里的（`幕1.txt`、`分支1.txt`……；一幕要拆成几个文件时照旧的叫法加 b、c）。截图存各块的 `try3/{块}/shots/`（不进仓库）。
- 报告**加进**已有的（同一个文件可能有别的助手同时在加另一块：**绝不整份重写这个文件**。先把你这一节写在临时目录里，写好了用 `cat 你的那一节 >> evals/stage-gaps/report3/{科目}.md` 一次加到末尾；之后要改，只用 Edit 改你自己那一节里的字） `evals/stage-gaps/report3/{科目}.md`（线代、数据结构、英语各一个文件，里面已经有别的块的节）：在文件末尾加 `## {块}` 一节，别的节一个字不要动。格式和文件里已有的节一样，每块最后有「说明：」和「和上次比：」。
- 「和上次比」比的是 `evals/stage-gaps/report/{科目}.md` 里同一块的那一节（第一次量的）：这次每一项的标和上次的并排，逐条写什么变了（哪条 ❌ → ⚠️、⚠️ → ✅，标没变但往前走了多少），最后一行「还是不行：」列出仍然做不到的。
- 每一幕、每个分支都要量，主线每一幕六项（画面、动、老师说、学生做、页面当场、事实），每个分支一项（页面要提供什么）。
- 「说明：」里除了你觉得重要的发现，**专门列两张单子**：
  1. **页面的毛病**：页面说了假话（对的说成错、错的说成对、没做到说做到）、静默失效（写了不报错也不起作用）、报错的话让老师照着改不对、画面排坏了。每条写文件和行号、原文。
  2. **这一块最缺的东西，按要紧程度排**：哪些是「这种东西的规则」（页面不懂这个算法 / 这条语法规则，所以判不了、算不出事实）、哪些是「缺一种新的东西 / 画面」（时间轴、表、调用栈、三维……）、哪些是「学生的手」（做不了那一下）、哪些是「事实」（页面算得出却没写给老师）。每条写理想里哪几幕要它。
- 写完跑 `node tools/stage-gaps-check.mjs report3`，你那一科是 ✓ 再交。

- 提到学生就写「学生」。
