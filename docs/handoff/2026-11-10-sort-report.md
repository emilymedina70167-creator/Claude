## 做了什么

### 1. 规则文件（新）

- `kit/src/stage/types/array.sort.js`：排序的那一半，纯函数。每一趟的结果、常见错法都让黑板的引擎 `engines/sort.js` 跑（`planOf`），不另写一份排序；引擎的 `passes` 只有数，这里照引擎每一步的画面认出每一趟结束时是哪几张牌，所以 49′ 和 49 分得开。
- `kit/src/stage/types/array.rules.js`：照规则接口交 `next` / `check` / `facts` / `brief` / `predicates` / `measures` / `gestures` / `changed` / `standard` / `actOf` / `judges` / `doneBy`，在 `types/index.js` 登记。
- 老师用一条指令写明这一排在做什么：`sort a shell d=5`（记在 `o.sort`）。没写明时页面不猜：只判这个世界做不做得到，不判对错，现状里只多一行逆序对。
- 一趟的粒度（七种）：现状、事实里写「等于第几趟（快排是第几次划分）结束后的样子」；判断式 `a pass=k`；只判到一趟的三种和 `from=` 的一排，正好等于某种常见错法某一趟时写「像是：……」。
- 一下的粒度（直接插入、希尔、冒泡、简单选择）：`next` 从现在的样子算，学生走偏以后接着算；`check` 判对、不对、像哪种错、做不到。希尔各条链先后不管；插过去和对调着往前换都算对。
- 事实：这一下动了谁（不在一条链上也说）、隔 d 的链排好几条、坏在哪几对、这一趟做完没有、和照王道的代码做出来的一不一样、一共让了几格；直接插入和希尔一趟对上时写照王道的代码比较几次、后移几次。
- 量：`inv(a)`、`bad(a)`、`chains(a)`、`moves(a)`；判断式：`a pass=2`、`a chains=5`、`a mates a.1 a.6`。
- d 写拨数的名字跟着拨；舞台现状把每个能拨到的 d 扫一遍（2014 真题那一排：「d = 2 链上坏 3 对：9>4、20>15、13>8；d = 4 链上坏 1 对：9>7；d = 5 链上坏 1 对：9>8；别的每条链都递增」）。
- `@a.done`：希尔是这一趟做完，别的是整个排好，`from=` 的一排是等于该等于的那一趟。

### 2. 学生的手

- `open a move`：按住一张拖，放到另一张上是对调（`swap a#6 a#1`），放到两张之间是插入（`move a#6 -> a.2`），放到空格子上是挪进去。写明了希尔时沿自己那条链挪（`move a#10 -> a.4 d=3`，`move` 指令多了 `d=`）；分开排着时只在自己那条泳道里。
- `open a`（只能对调）一点没动；两项一起开当场报（都是按住再拖）。
- 画法交了把手 `cell` / `gap`（`array.view.js` 的 `grips`），手指的事全走底座的 `gesturedom.js`。
- 试演工具认 `学生: swap a#6 a#1`、`学生: move a#10 -> a.5`（也能写 `before a.5` / `after a.4`）、`学生: write h.1 38`，开着 `open a move` 时是真的触摸（按住 0.4 秒再拖）。

### 3. 空格子

- `array h = _ 49 38` 的 `_` 是空格子（值是空的，画成一个空位，现状写 □）；`write h.3 _` 空出来。
- `open h edit`：学生点一格、数字键盘写数（`write h.1 38`），写满了页面告诉老师；牌能拖进空格子，空格子自己拿不起来。
- 量、判断式、`a sorted` 碰到空格子照「还空着」判不了。

## 老师的新写法（每条一行，照抄能演）

```
array h = _ 49 38                        _ 是空格子
sort a insert                            写明在做哪种排序：insert shell bubble select 每一下都判，quick merge radix 只判到一趟
sort a shell d=5                         希尔写这一趟的增量（d=d 是拨数的名字，跟着拨）；下一趟再写一次
sort r shell d=5 from=a pass=1           另一排 r 该等于 a 做完第 1 趟的样子
sort a off                               不判了（让了几格归零）
move a#10 -> a.4 d=3                     在隔 3 的链上挪，链上中间的各跳 3 格
write a.3 _                              空出这一格
open a move wrong=mark undo=on           学生按住一张拖：到另一张上 = swap，到两张之间 = move
open h edit                              学生点一格、键盘写数 = write h.1 38
goal g1 "…" when="a pass=2"              等于第 2 趟做完的样子（希尔、from= 的写 a pass）
goal g1 "…" when="a chains=5"            隔 5 的每条链都递增
goal g1 "…" when="a mates a.1 a.6"       两格在同一条链上挨着
label n a "让了 {moves(a)} 格，还有 {inv(a)} 对前大后小"      量：inv(a) bad(a) chains(a) moves(a)
@a.done say "这一趟做完了。"              希尔是这一趟做完，别的是整个排好
@a.right say "对。"                       学生做对一步（每一下都判的四种）
```

## 没做成的、要知道的

- 「把相邻的当成一组」照引擎现有的那种错法认（n 个切成 d 段连续的）。理想演法里的「连续 d 个一段」是另一种读法，页面认不出，只写事实（哪几张出了自己的链）；要认得先在引擎里加一种错法。
- 直接插入、希尔里「后面的牌先动了」判成不是正确的下一步（简报那句可以读成「同链相邻前大后小都算对」）。要放宽改 `array.sort.js` 的 `nextOf` 一处，记在 rulings 里。
- 冒泡不记学生走到了哪，判得宽：挨着、前大后小、后面那张是它往后最小的都算对（不照先后的几下也会算对）。
- 比较 / 后移几次只有直接插入、希尔写（照王道的代码数），而且只在一趟对上引擎的结果时写；别的五种不写。「这一趟到现在比了几次」没做（比较是学生脑子里的事，页面数不出）。
- 页面照算法自己走（自动走、暂停）、逐趟的柱子、尾迹：没有。计数挂在贴的字上。
- 旧课重放和以前不一样的两处（都记在 rulings 里）：数字的一排现状多一行「页面算的：inv(a) = …」（有意加的）；以前写过 `array … _ …` 的那一格从「_」字变成空位。方括号的读法也换了（话里同时有 `A[i]` 和 `[词]`、`fly` 第 2 个以后的才受影响）。
- 第 11 条里「弧被上面的题卡盖住、拨盘留在泳道底下」没动（不在这一轮）。
