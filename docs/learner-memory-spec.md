# 需求：学习台的系统记忆（分类存储、各管一块）

给 Claude Code 的实现说明。这份是**地基**：后面想做的「从证据决定下一步」「认方法快练」「从错误长出讲解」都要读写这里。先把记忆做对，再在上面加教法。

## 0. 为什么要做

现在有两个 Claude 在教我：

- **对话里的 Claude**（claude.ai 项目对话）：有我的全部记忆，备课、课后读记录、判断我过没过、记错题。
- **课堂里的 Claude**（`mode: class`）：每节课都是空白的，只知道这节课的资料包和课上的对话。

问题：

1. **课堂里的 Claude 不了解我。** 它只拿到对话里的 Claude 手工抄进资料包的那一部分，是二手的，而且每节课都要重抄一遍。
2. **记忆只在 claude.ai 的项目记忆里**，是几份 Markdown 文件（「当前状态」「每讲记录」「执行细则」），全靠对话里的 Claude 手工维护。页面读不到，也不会自己更新。
3. **我在板上做的事没有长期记下来。** 每次作答、预测、拖动、手写截图，都只留在那一个课堂 artifact 里，下一节课谁也看不到。
4. **东西混在一起。** 规则、我的弱点、错题、进度、Claude 自己的失误写在同几个文件里，越写越乱。

目标：做一个**长期存在、分好类、每一类有明确负责人**的记忆库。两个 Claude 读的是同一份；课堂里的 Claude 每一轮都带着和这节课有关的那部分记忆；我在板上的每个动作自动留下证据。

## 1. 放在哪里：一个长期存在的「学习台」artifact

- 页面只能读写**自己那个 artifact** 的数据库，读不到别的 artifact。所以记忆库和上课必须在同一个 artifact 里。
- 做一个长期存在的学习台 artifact（下面叫「学习台」），它同时是：
  1. **记忆库**：第 2 节的那些集合都在它的数据库里。
  2. **上课的地方**：课堂模式从「每节课一个新 artifact」改成「学习台里开一节新课」。每节课是一个 `session`（会话），黑板段落、课堂轮次、观察、作答都带 `session` 字段。以前的课在课程列表里能翻回去看。
  3. **查看记忆的地方**：我能看到自己的弱点表、复现到期、课程地图上每一块的掌握情况（第 5 节）。
- 对话里的 Claude 用 `ArtifactData` 工具读写同一个数据库（它能读写任何 artifact 的数据库），不需要别的通道。
- 现有的单节课堂 artifact、实时黑板照常能用，不受影响。

## 2. 分类：每一类一个集合，各有负责人

原则：

- **一类一个集合，不混放。** 一个事实只写在它所属的那一类，别处用 id 指过去，不重抄。
- **每一类只有一个写入方**（下表「谁写」）。别的角色只读，或者只能写「提议」，由负责的一方采纳。
- **历史类只增不改**（证据、错题、课堂记录）：写错了追加一条更正，不改原条。**状态类**（掌握、弱点、复现、当前位置）可以改，但每次改都在它的 `log` 里记一条：哪天、谁改的、从什么改成什么、依据哪几条证据。
- **结论必须挂证据。** 状态类里的每个判断（「这一块基础题过了」「W19 回到 L0」）都要写依据的证据 id 或错题 id；没有依据的结论不写。

| 集合 | 装什么 | 谁写 | 谁读 |
|---|---|---|---|
| `rules` | 规则：我的项目指令全文（红线、掌握的定义、检验题三条、来源分工、讲解交付）、执行细则（复现档位、检验流程、出题标准）、**教法偏好**（我希望怎么教：交互优先、一块板一屏、话写在板上……）、黑板写法。每条有 id、分类、正文、定下的日期、来源（我哪天说的） | 对话里的 Claude，**只在我定下或改了规则时**写，写之前和我确认 | 课堂每一轮都带（替换内置的「角色与红线」）；对话里的 Claude |
| `profile` | 和教学有关的我：考研目标、在美国读大学（术语附英文）、用 iPad 和 Notability、喜欢先看具体例子、不想磨简单计算……只放和教学有关的，不放生活信息 | 对话里的 Claude | 课堂每一轮都带 |
| `curriculum` | 课程地图：讲 → 节 → 块。每一块：范围、详略、考试口径、文稿要点（按视频顺序）、对应的文稿原文段落、教材页（原图存 assets）、板书截图、依赖哪些块（准入依赖） | 对话里的 Claude，备课时写 | 课堂带当前块的完整内容、相邻块的范围；对话里的 Claude |
| `evidence` | 证据：我在板上的**每一个**动作——作答（对错、第几次、用时）、预测（猜的和实际的）、拖动达成目标、揭开步骤、放弃、手写截图（原图 id + 转写）、我说的话里的关键句。每条带 `session`、所在块、知识点标签、时间 | **页面自动写**（课堂、实时黑板都写），只增不改 | 对话里的 Claude（判断过没过的依据）；课堂可以查（第 3 节的工具） |
| `observations` | 课堂里的 Claude 当堂记的观察（「学生把内积说成零矩阵」「消去律那段没跟上」）和每节课的下课小结 | 课堂里的 Claude（现在的 `class_notes` 搬过来，加 `session` 和块） | 对话里的 Claude 课后看，采纳的转成错题、弱点 |
| `errors` | 错题档案：编号（沿用 L2-nn）、出处、题面、我怎么答的、错在哪一步、根因、挂哪个弱点、对应的证据 id。只增不改 | 对话里的 Claude（从证据和观察里整理） | 课堂带当前块相关的错题原文；对话里的 Claude |
| `weaknesses` | 弱点表：W 编号、错了哪一类、影响面（通用 / 链条 / 局部）、证据级（L0–L3）、最近一次、挂的错题、`log` | 对话里的 Claude。课堂只能在 `observations` 里提议 | 课堂带和当前块相关的弱点；对话里的 Claude；我在第 5 节的页面看 |
| `mastery` | 每一块、每个知识点的掌握状态：未学 / 讲过 / 基础题过 / 复现通过（第几档）/ 掉了，加依据和 `log` | 对话里的 Claude（**课堂不能宣布掌握**，这是红线） | 课堂带当前块和它依赖的块；我看课程地图 |
| `reviews` | 复现组：R 编号、组内容（机制族）、盯哪些弱点、上次日期和结果、档位（1→3→7→14→30 天）、`log`。**到期日由页面按档位算**，不手填 | 结果和档位：对话里的 Claude；到期：页面算 | 学习台首页「今天到期」；课堂开头的混练（以后）；对话里的 Claude |
| `position` | 当前位置：学到哪一块、欠账、下一节从哪接、下一节要先收的题 | 对话里的 Claude，每节课后更新 | 课堂开头读；对话里的 Claude 开课第一份读 |
| `slips` | 两个 Claude 的教学失误：比如「消去律那段没先说目的」「出的小问答案就印在板上」「一次写了五块板」。各自记各自的，带日期 | 对话里的 Claude 记自己的和它从课堂记录里看出的；课堂里的 Claude 可以记自己的 | 课堂每一轮带最近、最相关的几条（「别再犯」）；对话里的 Claude |
| `sessions` | 每节课的元信息：日期、哪一块、资料包快照、核验了几轮 / 作废了几轮、小结 id | 页面 | 课程列表；对话里的 Claude |

现有课堂数据（`steps`、`class_turns`、`class_pages`、`answers`、`events`）照旧，加 `session` 字段分开每节课。

## 3. 课堂里的 Claude 怎么用记忆

- **每一轮的说明里带一份「记忆摘要」**，由页面从数据库拼出来，纯函数、有字节预算（和现在的资料包一样受 `SYSTEM_MAX` 限制）。优先级从高到低：
  1. `rules` 全文（替换内置红线；内置的黑板指令说明、组件手册照旧）
  2. `profile`
  3. 当前块的 `curriculum`（范围、口径、文稿要点、文稿原文段落、教材原文）
  4. 和当前块有关的 `weaknesses`、`errors` 原文、`mastery`
  5. 最近、最相关的 `slips`
  6. `position`（上一节停在哪、这一节先收什么）
  
  放不下时按这个顺序从后往前截，截掉的部分说明「还有，用工具查」。
- **给它一个只读工具** `memory_read`：按集合和 id 查一条（某道错题原文、某条证据、某个弱点的 `log`、某一块的完整范围）。和现在的 `calc`、`component_doc` 一样，查看方式支持工具时才给。
- **它能写的只有** `observations`（观察、下课小结）和 `slips`（它自己的失误）。`evidence` 由页面写，不经过它。它不能改 `weaknesses`、`mastery`、`reviews`、`errors`、`rules`。
- 资料包（`pack/main`、`pack/problems`）照旧能用，作为「这节课的额外安排」（这节课的推进建议、备好的题），和记忆摘要一起带上。

## 4. 对话里的 Claude 怎么用记忆

- **备课**：读 `position`、当前块的 `curriculum`、相关的 `weaknesses` / `errors` / `mastery`；需要时补 `curriculum`（文稿要点、原文段落、教材原图、板书截图）；写这节课的资料包；在学习台里开一个新 `session`（或者让我点「开新课」）。
- **课后**：读这节课的 `evidence`、`observations`、课堂轮次；判断过没过、记错题、改弱点证据级、更新复现结果、写 `position`；把课堂里那个 Claude 的教学问题写进 `slips`。全部用一次 `batch` 写。
- **规则变了**：我在对话里定了新规则或改了旧的，写进 `rules`（带日期和来源），旧的标作废，不删。
- 需要一个简单的「写法说明」放进 `CLAUDE-PROJECT.md`：每个集合的字段、id 规则、谁能写、什么时候写、`log` 怎么记。

## 5. 我看得到的页面

学习台首页（不在上课时）：

- **今天**：到期的复现组、下一节从哪接、欠账。
- **课程地图**：讲 → 块，每一块按 `mastery` 上色（未学 / 讲过 / 基础题过 / 复现到第几档 / 掉了），点开看依据。
- **弱点表**：按影响面、证据级排，点开看挂的错题和证据。
- **课程列表**：以前每节课，点开翻黑板。
- 只读。改这些的是对话里的 Claude。

## 6. 迁移

- 现有的记忆在 claude.ai 项目记忆里：当前状态（弱点表 W、复现组 R、当前位置、欠账）、第1讲和第2讲的记录（授课记录、检验记录、错题档案）、执行细则（规则、教法、依赖表、失误流水）。
- 做好以后，对话里的 Claude 把它们逐类搬进学习台（用 `ArtifactData` 的 `batch`），编号原样保留（W、R、L1-nn、L2-nn、L2-Tnn）。
- 搬完之后，学习台是唯一的权威；claude.ai 的项目记忆只留一份指向学习台的说明和非教学的信息。项目指令第九条「每次开课先读 current-state.md」到时候由我改成「先读学习台的 `position`」。

## 7. 实现上的要求

- 纯函数部分（记忆摘要的拼接和截断、复现到期计算、`log` 记录、证据打标签）放进不碰 DOM 的模块，`node --test` 测。
- 页面写 `evidence` 要轻：批量、不阻塞作答；和现在的 `answers` / `events` 共用一条写入路径，不要写两遍。
- 数据库的访问规则：`rules`、`weaknesses`、`mastery`、`reviews`、`errors`、`position` 只有编辑者（我和对话里的 Claude）能写；课堂里的 Claude 的写入只落在 `observations`、`slips`，页面里代码层面就拦住别的集合。
- 硬性规定照旧：讲课只用 Opus 5.5、effort high；退路模型的输出作废；提示词里提到学生不用「他」「她」。
- `CLAUDE-PROJECT.md` 第六节（课堂模式）改成「在学习台里开一节课」的写法；版本号更新；做完重新发布组件库前先问我。

## 8. 分批

1. **记忆库本身**：集合、字段、访问规则、`log`、复现到期计算、`CLAUDE-PROJECT.md` 写法说明。对话里的 Claude 先能读写、能迁移。
2. **学习台里上课**：课堂模式多 `session`，证据自动写进 `evidence`，课堂每一轮带记忆摘要，`memory_read` 工具，观察写进 `observations`。
3. **我看的页面**：首页的今天、课程地图、弱点表、课程列表。

每一批做完，对话里的 Claude 用一节真课验一遍：课前读、课中带、课后写，三步都走通再做下一批。
