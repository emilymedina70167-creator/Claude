# 需求：实时黑板追上课堂模式的交互（标注、让图动、板顶的话）

给 Claude Code 的实现说明。实时黑板（`mode: live`，`docs/live-board-spec.md`）和课堂模式（`mode: class`，`docs/classroom-spec.md`、`docs/teaching-tools-spec.md`）都已经实现。这一份把课堂模式里老师用的三样教具接进实时黑板。

## 0. 为什么要做

我（学生）上课改用实时黑板。它的绝对优势是作答方便：我在对话框里打字，或者贴 Notability 的截图，比在页面里作答顺手得多。所以黑板上只放讲解和题面，不放作答框，作答都在对话里。

缺的是课堂模式的交互感。两种模式其实都是一轮一轮的：我说一句，老师做一轮。但课堂里的老师这一轮能做的事多三样：

1. **讲完回头标注**：把板上已经有的东西圈出来、框起来、划掉、旁边写一句；不用了再撤掉。实时黑板里对话里的 Claude 只能整段重写，用 `\boxed`、`\chalk` 这类静态写法凑。
2. **让图和矩阵动起来**：改图里的变量、播放一段过渡、让某一处闪一下。实时黑板里图照样能动，但只能我自己拖滑块、点播放，老师按不了。
3. **板顶那句话**：课堂里老师的话写在当前板最上面，我眼睛不用离开黑板。实时黑板里 Claude 的话只在对话框里，我要两边看。

画圈和让图动的代码两种模式本来就共用（`marks.js`、`markspec.js`、`markdraw.js`，图的 `session.scenes` 里的 `api`），实时黑板只是没有接收这些指令的入口。所以这次主要是补入口，不是新做画法。

**不做**：板书笔迹（Pencil 写在黑板上的字）自动发给对话里的 Claude。我用截图和打字交作业，用不上。

## 1. 指令：`ops` 集合

对话里的 Claude 往黑板数据库的 `ops` 集合写指令，页面执行。

### 1.1 写法

一条指令一个文档，`doc_id` 是 `o1`、`o2`……（对话里的 Claude 自己编号，不重复）：

```json
{ "seq": 7, "cmd": "mark target=s3 term=key note=\"只看这一条\"", "body": "" }
```

- `seq`：递增，决定执行顺序。和 `steps` 的 `seq` 是**同一条序列**：同一次 `batch` 里先写了段 `s5`（`seq: 6`），再写 `mark target=s5`（`seq: 7`），页面要等 `s5` 画出来以后再标（见 1.3）。
- `cmd`：和课堂模式 ```` ```board ```` 块的第一行**完全一样的写法**，只允许这三种：
  - `mark …`、`unmark …`（写法同 `docs/teaching-tools-spec.md` 1.1，`CLAUDE-PROJECT.md` 第六节「mark / unmark」）；
  - `figure target=… set … / play … / highlight …`（写法同课堂的 `figure`）。
  - 段的指令（`new` / `add` / `replace` / `hide` / `pin` / `unpin`）**不收**：实时黑板写段照旧用 `steps`。写了就报错，说明「段用 steps 写」。
- `body`：`mark` 块里的多行（一行一条，同课堂 ```` ```board mark ```` 块里的内容），没有就空。
- 解析直接用 `class/protocol.js` 的 `parseCommand`，`mark` 用 `markspec.js` 的 `parseMarkBlock(head, body)`，`unmark` 用 `parseUnmark`。不另写一套语法：对话里的 Claude 已经从说明书里学会了课堂的写法，两边一样最不容易错。

### 1.2 执行

- 页面订阅 `ops`，按 `seq` 从小到大执行**还没执行过的**指令（以「这个页面这次打开后执行过的 id」为准，见 1.4 的刷新）。
- `target=` 的规则和课堂一样：段的 id（实时黑板里是 `s1`、`s2`……，常驻栏的段也是段 id）或者组件的 `id:`。
- **只能标、只能动当前板和常驻栏上的东西**（和课堂一样，`onCurrent`）。当前板 = 板号最大的那块。目标在以前的板上就不执行、报原因（「s2 在第 1 块板上，不在当前板上」）。我翻回去看旧板时指令照常执行在当前板上，翻回当前板就看得到。
- 段被 `update` 改了内容、被 `hidden: true` 撤回、挪到别的板（改了 `page`）：段上的标注一起擦掉（同课堂的 `dropMarks`）。
- 动画（`mark` 的手绘动画、`figure play`）只在我正看着当前板时播放；我在看旧板时直接画成最后的样子，不播放（回来时看到结果就行）。
- 执行的代码尽量和课堂共用：把 `classroom.js` 里的 `placeMark` / `markOp` / `unmarkOp` / `dropMarks` / `figureOp` 抽成两边都能用的模块（比如 `class/boardtools.js`），参数是板视图（`boardview.js` 的 `bv`）、段表、`board` 根元素。课堂的行为一点不能变（现有测试和 `class-demo.html?dev` 的「测试:教具」「测试:幂」都要照旧）。

### 1.3 和段写在同一次 batch 里

对话里的 Claude 每一轮只想让我点一次允许，所以会把新段、标注、动画、板顶的话放在**一次 `batch`** 里写。页面收到时可能指令先到、段后到，或者段还在渲染。

- 指令指向的段或组件还不在黑板上时，**先等**：等到对应的 `steps` 段画出来（或者写法错误、画不出来）再执行。最多等 5 秒，还没有就报「s5 还没画出来」（或者「黑板上没有 s5」）。
- 同一次写进来的多条指令按 `seq` 依次执行，前一条在等，后面的也等（顺序不能乱：先 `set` 后 `play` 这类组合要按顺序）。

### 1.4 刷新和重新打开

刷新、关掉再打开：

- **标注要还原**：按 `seq` 把全部 `mark` / `unmark` 重放一遍（不播动画、不检查「在不在当前板」，同课堂刷新时的 `restore: true`），被擦掉的（段改了、撤回了、unmark 了）不再出现。
- **图的状态**：`figure set` 的最终值要还原；`play` 只还原终点的值（播放完的样子）；`highlight` 是一闪，不用还原。
- 已经执行过的指令不重复报结果。

### 1.5 结果写回给对话里的 Claude

对话里的 Claude 看不到页面，结果都写进**黑板现状 `meta/now`**（它每轮只读这一份）：

- 新字段 `ops`：最近的指令结果，一条一行，比如 `o7 mark target=s3：画上了 m2`、`o8 figure m-prod play t：没执行（m-prod 在第 2 块板上，不在当前板上）`、`o9 mark target=s5：没执行（s5 还没画出来）`。只留最近 10 条。
- 新字段 `marks`：现在板上有哪些标注，按段列：`s3：m1 term=key 圈「只看这一条」；m2 row=2 框`（写法同课堂黑板现状里各段下面的标注，`markspec.js` 的 `markText`）。对话里的 Claude 要撤标注、换讲法时靠它找 id。
- 新字段 `figures`：当前板和常驻栏上每张图能改的变量（同课堂黑板现状的 `figureVars`），这样 Claude 知道 `figure set` 能写哪些名字。
- 指令本身写错（看不懂的指令、段的指令、`mark` 写法错）：也写进 `ops` 那一行，说明原因。
- `statusRecord`（`live/layout.js`）要能带上这三项，纯函数，`node --test` 测；`sameStatus` 照常判断有没有变化。

## 2. 板顶的话：`talk` 集合

- 对话里的 Claude 写 `collection: "talk"`，`doc_id` 是板号（`"3"`），`data: { "page": 3, "md": "看第 2 行：它是第 1 行的几倍？" }`。
- 页面把它写在那块板最上面（课堂模式的 `class-talk` 那一行，`boardview.js` 已经有 `talkEl`），支持 Markdown 和 `$公式$`。同一块板再写一次就换成新的一句；`md` 写空字符串就去掉。
- 只是显示，不进作答、不进学习记录。不显示「Opus 5.5 ✓」那个模型标记（那是课堂模式平台核验用的，这里说话的是对话里的 Claude）。
- 刷新后照常显示。

## 2.5 一次写了好几块新板时，翻到第一块新板

现在页面总是停在板号最大的那块（当前板）。对话里的 Claude 一轮常常一次写好几块板（讲解 2～4 块 + 最后一块题），我打开就直接落在最后那块题上，前面的讲解要自己往回翻，第一次用时以为只写了题。

- 一次（同一批 `steps` 变化里，比如一次 `batch`）新出现了好几块板时，页面翻到**这批里板号最小的那块新板**，而不是最后一块。「当前板」的定义不变（还是板号最大的那块：标注、`figure` 只能动当前板的规则照旧），只是我眼前先停在第一块新板上，底部的「回到当前板」照常提示后面还有。
- 只新加了一块板，或者只是往当前板上加段，行为和现在一样。
- 刷新、重新打开时停在哪块板：和现在一样（当前板）。

## 3. 说明书和工具

- **`CLAUDE-PROJECT.md` 第五节**加一小节「标注、让图动、板顶的话」：`ops`、`talk` 的写法，`seq` 和 `steps` 共用一条序列，一轮的段、指令、话放进同一次 `batch`，结果在黑板现状的 `ops` / `marks` / `figures` 里看。标注、`figure` 的具体写法指向第六节（不重抄，避免两处不一致），只写实时黑板和课堂不同的地方（target 是 `s` 开头的段 id、只能动当前板、写在 `ops` 里）。
- 第五节「每一轮怎么走」的第 4 步改成：段、标注、动画、板顶的话放进同一次 `batch`。
- 第五节开头补一句：黑板可以只放讲解和题面，不放作答框，学生在对话里作答（我现在就这么用）。这时 Claude 读截图仍按原来的办法：对话里贴的图直接看；黑板「交截图」交上来的看 `uploads`。
- 版本号：`CLAUDE-PROJECT.md` 开头的「版本」改成新的日期。
- **`tools/check-lesson.mjs`**：`.board.json` 支持 `ops` 和 `talk` 两个字段（`{ "steps": […], "ops": [{ "id", "seq", "cmd", "body" }], "talk": [{ "page", "md" }] }`），按 `seq` 和段一起执行，报出没执行的指令和原因；`--shots` 截图里能看到标注和板顶的话。这样对话里的 Claude 写板之前可以先在云端检查一遍。
- **`live-demo.html?dev` 的开发面板**：能写一条指令（`cmd` + `body`）、写板顶的话，方便本地试。

## 4. 测试和验收

- 纯函数部分（指令解析和分类、重放时间线、结果行、`statusRecord` 新字段）配 `node --test`。
- 浏览器里实际走一遍（iPad 两种尺寸）：
  1. 一次写进新段 `s5`（里面有一个带 `split` 的 `matrix`，id `m-cut`）和三条指令：`mark target=m-cut block=1,2 note="右上块"`、`mark target=s5 term=key`、`figure target=m-cut highlight 1`，加一句板顶的话。段先画出来，再依次标、闪；板顶出现那句话。
  2. `unmark id=m1` 后那个圈消失；`update` 段 `s5` 的 `md` 后它上面的标注全部擦掉。
  3. 指令指向第 1 块板上的段：不执行，黑板现状 `ops` 里写明原因。
  4. 写一条 `new id=b1`：不执行，原因是「段用 steps 写」。
  5. 刷新：标注、图的状态、板顶的话都还原，指令结果不重复。
  6. 课堂模式的「测试:教具」「测试:幂」「测试:指图」照旧。
- `npm test` 全过，`npm run build` 后提交 `kit/dist/la-kit.js`，`npm run check:pages` 通过。
