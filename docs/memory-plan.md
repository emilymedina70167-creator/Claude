# 记忆系统化 + 省额度（2026-10-29）

## 我要的

1. 在不影响 Claude 拿到信息的前提下，省额度。
2. 记忆系统化：每次必须知道的必读；其余的分好类，Claude 知道「这里有它要的」，按需去取，不用每次从一大堆里找。
3. 第一位：Claude 记得住我、教得最好。不能为了省钱砍信息。

## Claude 实际怎么读

- 课堂里的 Claude 没有记忆：每一轮页面把整份说明（规则、组件说明、资料包、记忆、黑板现状）加上整段对话重新发一遍。**成本 = 每轮发多少 × 一节课几轮。**
- 它只会去查它知道存在的东西。没提到的，它不会想到去查。
- 按需查（工具）每用一次要多跑一整轮（整份再发一遍），所以只适合偶尔要的东西，而且要一次取够。

## 用真数据量出来的问题（修之前）

- 记忆 16 KB 被 68 条规则占满，这一块的范围、上一节停在哪、弱点、错题全被截掉（只剩一句「还有 N 条没带」）。
- 以前的课（报告、小结）课堂里的 Claude 看不到，工具也读不了。
- 408、英语的「关于我」、只给对话里 Claude 的规则（备课、读材料）每一轮都在付钱。

## 现在

**记忆分两层**（`memory/digest.js`，预算 `MEMORY_BUDGET` 32 KiB）：

- 全文（必读）：给课堂的规则全部（`rules.for` 不是 `chat`、这一科的）→ 关于我（这一科的）→ 上一节停在哪 → 这一块和相邻块 → 以前学这一块的两节课（报告一行、小结开头）→ 相关弱点 → 相关错题原文（这一块的、最近 8 条）→ 掌握 → 最近 6 条失误 → 等确认的改动 → 这一块的长原文（放得下才放）。
- 目录（`memoryCatalog`，≤ 7 KiB）：其余的一条一行（编号 + 一句话）：规则、关于我、以前的课（最近 8 节）、弱点、错题（挨着的写根因，远处的按块列编号）、掌握、复现组（到期）、较早的失误、课程地图、没放的原文。太长时从后往前收成只列编号。
- 按需：`memory_read` 一次取好几条（`ids`），能取以前的课（`sessions`：要点、课后报告、小结）。

**分科、分对象**：`rules.for`（`class` / `chat` / `both`）、`rules.space`；`profile`、`slips` 写 `space` 或编号带科目（`p-cs-…`、`S-0922-ds1`），课堂只带这一科的（`space.js` 的 `sharedFor`）。

**省额度（不丢信息）**：

- 对话里最近 6 轮以前 Claude 写的长段原文换成一行「[页面省略了这一段的原文……用 board_read 取]」（`prompt.js` 的 `stubBoardText`，`STUB_AFTER`），说的话、指令行、标注照旧；段还在黑板上，工具 `board_read` 按段 id 取回。不支持工具的查看方式不省。
- 说明的顺序按「一节课里多久变一次」排：组件说明、资料包、记忆、黑板现状。平台要是对重复的开头打折，最省。
- 给课堂的规则、这一科的「关于我」才带。

**对话里的 Claude 的开场简报**：学习台页面写 `meta/brief`（数学）、`brief-cs`、`brief-en`（`views.js` 的 `deskBrief`）：接手要知道的 + 这一科记忆库的目录（规则全列，含只给对话的）。开场 get 一份，不用一类一类 list。

## 我在记忆库里改了什么

9 条只给对话里 Claude 的规则加了 `for: "chat"`（文字没动）：`rule-bd-6`（实时黑板外部的做法）、`rule-i-mem`（旧的 current-state.md）、`rule-mat-1`（读材料）、`rule-out-1`（对话框不渲染 LaTeX）、`rule-pk-1`、`rule-pk-2`（资料包）、`rule-t-9`（分块、学习计划）、`rule-chk-4`（开讲前备草稿）、`rule-desk-1`（学习台是权威）。想让课堂也带，删掉 `for` 就行。
