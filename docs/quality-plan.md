# 计划：把教学环境做到优秀（线代和 408 两边）

这个仓库做的是**给 Claude 用的教学环境**：课堂里讲课的 Claude、对话里写课件和资料包的 Claude，都是它的用户。学生学没学会由 claude.ai 项目负责；这里负责的是让老师手里的东西足够好。

一句话的标准：**一个很强的老师想怎么教，环境都接得住，永远不是环境拖后腿。**

`docs/408-plan.md` 是上一轮（408 第 0～5 批）的计划，已经做完；它第 6 批的内容并进了这份。

## 0. 什么叫优秀

| 维度 | 优秀的样子 | 怎么量 |
|---|---|---|
| 1. 对 | 页面上每一个数、每一步都对，口径和王道 / 考研线代教材一致 | 每个引擎对过至少 2 道王道例题或真题；线代引擎用随机精确数自检（比如 $P^{-1}AP=\Lambda$、$Q^TQ=E$） |
| 2. 表达力 | 老师想演示的过程、想画的图、想出的题，都有办法表达；菜单外的变体也能演，而且仍然能判分 | 扮演老师的 Claude 写真题课件时报告的「想做做不到」逐条解决，或写明为什么不做 |
| 3. 作答方式 | 老师能让学生做出考试里的那种产出：填满一张表、在图上按顺序点、写通解、写一段代码；页面逐项批改 | 每个演示组件都支持「先猜」「写结果」「自己填整张表」三种；作答记录精确到第几格 |
| 4. 老师看得清 | 老师看不到屏幕，记录要告诉它「从哪一步开始错、像是按什么错法做的」 | 每个引擎至少能认出 2 种常见错法（FIFO 当成 LRU、next 当成 nextval、行列式换行忘了变号……） |
| 5. 写起来不出错 | 写法前后一致，报错带「应该怎么写」，老师第一次就写对是常态 | 扮演老师的 Claude 一次写对率 ≥ 90%；把报错给它，改一次 100% 改对；写错了 0 次静默 |
| 6. 成品品质 | 画面会动（格子交换飞过去、结点旋转移过去），所有组件看起来是一套，iPad 上手感好 | 全部组件 × 5 种风格 × 3 种尺寸截图：0 溢出、0 叠字；动画能关（减少动态效果） |
| 7. 覆盖 | 考研线代六章、408 大纲里能画、能算、能一步步走的考点都有组件 | 第 3～5 节的清单逐项打勾，或注明「用 `sketch` + `practice` 覆盖」 |

## 1. 现状（按上面打分）

| 维度 | 线代 | 408 |
|---|---|---|
| 对 | 好（精确分数，测试多） | 好（18 个引擎都对过王道例题） |
| 表达力 | 中：二维 / 三维的图很强（`scene`、`space`、`matrix`），但考研的「过程」几乎没有组件——手册里**二次型、对角化、施密特、逆矩阵、方程组通解一次都没出现**，行列式只有 2×2 的面积和 `det2` 练习 | 中：每个组件是固定的几种算法，菜单外只能退回静态 `sketch`；`trace` 不支持指针和链表 |
| 作答方式 | 中：`answer` 有基、特征向量、含 n 的式子；没有矩阵逐元判分、通解判分、含参讨论 | 弱：只有「猜下一步」和「写最终结果」，不能自己填整张表、不能在图上按顺序点、不能判学生写的代码 |

| 写起来不出错 | **没验证过**：从没让一个只看手册的 Claude 真写过 | 同左 |
| 成品品质 | 好（`matrix` 有飞行动画） | 中：每一步是整帧切换，没有过渡 |
| 覆盖 | 约四成（矩阵乘法、行化简、变换、特征方向） | 约一半（见第 5 节清单） |

## 2. 总思路

1. **先做尺子，再做东西。** 没有「扮演老师」的验收，「好用」只是我自己觉得。尺子留下来当测试集，每加一样东西都跑一遍。
2. **先做乘法器，再补覆盖。** 「自己填表」「错法诊断」「在图上按顺序点」「动画」「通用演示」做在步进器外壳上，现有 18 个引擎一起变好，后面新做的引擎天生就有。
3. **线代也引擎化。** 行列式、求逆、方程组、对角化、施密特、二次型都是「一步步走的过程」，用同一个外壳做（先猜、自己填、错法诊断、课堂里 `figure step` 都现成），和 `scene` / `space` / `matrix` 的图联动。
4. **手册会变长，要按需取。** 每门课的组件说明现在 24～33 KiB，阶段 3～5 加完会超。系统里放精简版（用途、最小例子、字段名），完整写法让课堂 Claude 用工具按组件名取；对话里写课件的 Claude 读主说明，再按需读组件参考。

### 阶段 2：外壳升级（所有演示组件一起变好）

- **2.1 自己填表 `mode: fill`**：引擎声明自己的表（页面置换：每次访问后的各帧和是否缺页；调度：每个进程的完成、周转时间；Dijkstra：每一轮的 dist 和 path；cache：组号、标记、命中；拥塞窗口：每一轮；行化简：每一步之后的矩阵……）。学生填，页面逐格批，标出第一处错，不给答案；`given:` 给出前几行，`cols:` 选填哪几列。记录到格。
- **2.2 错法诊断 `misread`**：每个引擎列出常见错法，用「错的算法」重算一遍和学生的答案比对，对上了就在记录里写「像是按 FIFO 换的」「像是用了 next 而不是 nextval」「像是非抢占式」。只告诉老师，不告诉学生（老师用它来追问，推学生自己发现）。
- **2.3 在图上按顺序点**：`ask` 加一种「按顺序点一串」——遍历顺序点顶点、Prim 依次点边、关键路径、散列表点位置、树上点出遍历序列。
- **2.4 动起来**：步与步之间有过渡——数组格子交换时飞过去、树结点位移、图上的点和边渐变、表格新的一行写出来。拖进度条、`figure set` 跳步不动画；系统开了「减少动态效果」时不动。
- **2.5 通用演示 `frames`**：老师自己写每一步的状态（数组 / 表 / 矩阵 / 树 / 图的字面量 + 一句话 + `ask`），共用画法、动画、先猜、填表。菜单外的过程也能演，也能判分。
- **2.6 手册按需取**：每门课的说明分两层：系统里的精简版（每个组件一句用途、最小例子、字段名），完整写法用课堂工具 `component_doc` 按名字取（查看方式不支持工具时退回整份）。对话里写课件的 Claude：`CLAUDE-PROJECT.md` 留总纲和精简版，完整的组件参考作为组件库的附带文件发布，按需读。标准：阶段 3～5 全加完，每门课系统里的组件说明仍 ≤ 40 KiB。
- **2.7 写法统一**：所有演示组件的字段名统一（`ask`、`mode`、`quiz`、`fill`、`show`、`from`），旧写法兼容；每条报错都带一个正确写法的例子。

### 阶段 3：线代补齐（考研线代六章）

| 章 | 现在有的 | 要做的 |
|---|---|---|
| 行列式 | 2×2 面积（`scene area`）、平行六面体（`space box`）、`det2` 练习 | `det` 引擎：化上三角（换行变号、倍加不变、提公因子都记下来）、按行 / 列展开（`ask` 挑哪一行最省事）、余子式和代数余子式；常见错法：换行忘了变号、提公因子只提了一行 |
| 矩阵 | `matmul`、`matrix`（幂、分块、乘积） | `inverse` 引擎：$[A\mid E]\to[E\mid A^{-1}]$；伴随矩阵；初等矩阵 ↔ 行变换（左乘、右乘对照）；秩 |
| 向量组 | `rref` | `rref` 加 `show: pivots / basis / combo`：标出主元列、极大无关组、其余向量怎么由它表示；线性相关判定 |
| 方程组 | `rref`（判断解的情况） | `solve` 引擎：行最简 → 自由变量 → 基础解系 → 特解 → 通解结构，和 `space` 的平面相交联动；**含参数讨论**（$a$ 取何值无解 / 唯一解 / 无穷多解）：精确计算扩展到含一个参数的有理式，按主元为 0 的取值分情况 |
| 特征值 | `scene eigen`（二维特征方向） | `eig` 引擎：特征多项式 → 特征值（有理根精确，其余注明）→ 每个 λ 的特征向量 → 代数重数和几何重数 → 能否对角化、$P$ 和 $\Lambda$；实对称矩阵接施密特得正交矩阵 $Q$ |
| 二次型 | 无 | `quad` 引擎：写出矩阵、配方法（每一步的可逆变换 $x=Cy$）、正交变换法（接 `eig`）、标准形和规范形、惯性指数、正定判定（顺序主子式 / 特征值）；图：二维二次曲线（`scene`）、三维二次曲面（`space` 加曲面） |

另外：

- **施密特** `schmidt` 引擎：一步步减去投影，配二维 / 三维图（投影那一段画出来）。
- **答案类型**：`type: matrix`（逐元判分，标出哪几个元素不对）、`type: general`（通解：基础解系、特解取得不一样也判对——比的是解集相同）、`type: poly`（特征多项式，展开与否都认）、`type: values`（特征值带重数）、`type: cases`（含参讨论：每种情况的取值范围和结论）。
- **`practice` 内置题型**：`det3`、`inverse`、`rank`、`eigen`、`diag`、`general`、`quadform`，随机出「好算的数」（特征值是整数、逆矩阵是整数……）。

验收：每章至少一个能「看过程 / 先猜 / 自己填 / 练」的组件；随机精确数自检；每章对过 2 道考研真题。

### 阶段 4：数据结构加深

- **4.1 `trace` 二期**：`struct`、指针、`malloc` / `free`、`->`、`NULL`。内存画成结点框和箭头（链表、二叉链表、邻接表）；空指针解引用、用了已经释放的结点、内存泄漏都报行号。
- **4.2 写代码判题 `code`**（对应 408 的算法设计题）：学生写 C（输入框适配 iPad：等宽、符号小键盘、自动缩进；也可以交截图由页面 Claude 转写），老师写 `tests:`。解释器跑：每个测试过没过、在哪一行出错；按几组规模跑出步数，估时间复杂度（「大约 O(n)」）和额外空间。记录给老师。
- **4.3 新演示**：
  - 栈和队列：出栈序列合法性、中缀转后缀和求值、括号匹配、循环队列的下标；特殊矩阵压缩存储的下标换算。
  - 树：AVL（LL / RR / LR / RL，插入和删除）、红黑树插入、哈夫曼树和编码（WPL）、线索二叉树、树和森林 ↔ 二叉树、并查集（按秩合并、路径压缩）、B 树和 B+ 树（插入分裂、删除合并）。
  - 排序：希尔排序并进 `sort`；外部排序（败者树、置换-选择排序、最佳归并树）。

验收：每个对过王道例题，进验收题库。

### 阶段 5：操作系统、组成原理、计网加深

- **操作系统**：
  - `mem` 综合链：虚拟地址 → 快表 → 一级 / 二级页表 → 物理地址 → cache → 主存，算有效访问时间（真题综合题的常见形状）。
  - 多级页表（页表项多大、页目录怎么拆、页表占几页）、改进型 CLOCK、动态分区分配（首次 / 最佳 / 最坏 / 邻近适应）。
  - 文件：混合索引的最大文件长度、读某一块要访问几次磁盘、位示图。
  - 死锁检测（资源分配图化简）。
  - PV 同步：几个进程交替执行，画出信号量的值和等待队列；老师给一种交替顺序，或学生自己排；判断会不会死锁、结果对不对（基于 `trace` 二期的多进程）。
- **组成原理**：指令格式和扩展操作码、寻址方式（算有效地址，接 `bits`）、存储器扩展（位 / 字 / 字位扩展、片选、各片地址范围）、乘除法（原码一位乘、Booth、加减交替除法）、浮点加减（对阶、尾数相加、规格化、舍入、溢出）、校验码（海明码、CRC）、大小端和对齐（内存布局）、中断屏蔽字和处理次序、机器级代码（x86 子集逐条执行：寄存器、栈帧、条件码，和 C 对照）。
- **计网**：CRC（和组成原理共用）、编码波形（NRZ、曼彻斯特、差分曼彻斯特）、CSMA/CD（最短帧长、退避）、交换机自学习、距离向量（RIP 表交换、坏消息传得慢）、链路状态（接 `net`）、IP 分片、NAT、ARP、TCP 传数据时的序号和确认号、DNS / HTTP 的 RTT 时间线、信道利用率。

数据通路、OSI 分层、文件系统结构这类静态的图，用 `sketch` + `practice type: custom` 覆盖，不单做组件。
