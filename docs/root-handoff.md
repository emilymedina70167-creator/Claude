# 第十二轮的交接（给接着做的新对话）

2026-11-16 写。上一个对话太长了，学生要换一个新对话接着做，也防止一个对话一直做下去跑偏。你读完这一份和 `CLAUDE.md` 里「回到根上（第十二轮）」那一条，就能接上。

## 一句话

这一轮把教学从「规定形式」改成从「考试要我拿这一块做什么」出发（三问：终点、差距、动作），黑板是课的底座。分四批。**第 0、1 批做完并发布了**（发布的版本号见 `CLAUDE-PROJECT.md` 开头）。**下一步是第 2 批**，但要先等学生上一节真课、读完那节课的记录。

## 学生定的做法（不要再问、不要改）

1. **每批发布以后停下来，叫学生上一节真课**（发推送），他上完，你先读那节课的记录，方向不对就先改，再做下一批。等的时候只做不受那节课影响的事（下一批的计划、数学一入库）。
2. **你自己一件一件做**，做完测完再做下一件。不要把实现拆给一群助手：助手每次从零读一遍，最烧每 5 小时的额度。独立审查每批只留一道（发布前的通读：找形式的规定、互相打架的话、页面说的假话）。
3. **不跑模拟课**（`tools/teach-run.mjs`、`teach-suite.mjs`）：太耗额度。学生要的是做完以后用真课查。他说了才跑。
4. 学生那边有一个 **Codex**（GPT-6.1 Sol）可以帮忙：只给它说明写死、能用测试验收的活，写成仓库里的一份说明（照 `docs/codex-queue.md` 的样子），它推到 `codex/…` 分支，你读它的报告和改动、跑测试、再并。验收它比自己做还费事的活不给它。老师的说明、课堂、记忆的改动不给它。
5. 额度：学生的总量够，但每 5 小时的窗口很快撞顶。撞了以后一切停下等恢复，所以省额度就是快。但**不许因为省额度降低质量**：该做扎实的做扎实。
6. 汇报要短，先说主线。旁支的事（考试收件箱、数学一入库）不要挡主线、不要反复汇报。
7. 合进 `main`、重新发布学习台不用问。别的分支不要推（除非学生说了）。
8. 这一轮学生最在意的一句：**不许又是换皮**。往老师的说明里加任何一句话之前先问：这是事实、判断，还是形式？是形式就不加。

## 你的第一件事：读学生的真课

学生上完第 1 批以后的第一节黑板课，会告诉你。然后：

1. 开工先读学习台的 `meta/errors`、`meta/health`（`CLAUDE.md`「防错的四道」第 3 条）。学习台的地址在 `CLAUDE.md`「发布」一节。
2. 把那节课的数据存到本地（私人数据，放 `.superpowers/` 下面，不进 git）：`ArtifactData` 的 `list`，带 `out_dir`，取 `sessions`、`evidence`，和 `sessions/{课号}/class_turns`、`sessions/{课号}/report`。
3. `node tools/lesson-audit.mjs <那个目录>`：这节课多少分钟、老师写了多少字、停了几次、几次是白停（封闭的、点一下一次对）、最长连着多久学生没有要想的产出、要拿下的事每件什么状态。和 `evals/teaching/results.md`「第十二轮基线：真课」里以前的课比。
4. **读老师每一轮写的原文**，不只看数。要看的：
   - 老师第一轮写没写 `board aims`？写的几件是不是「学生要能做的事」、照没照真题的难度？
   - 板上的题挂没挂 `aim=`？（没挂，状态就一直是「还没证据」。）
   - 还在不在处处停？有没有反过来：一口气甩一大板、学生一直没动笔？
   - 学生做错以后，老师是读过程找断在哪一步、只补那一处，还是整段重讲？
   - 老师说的话和页面显示的状态有没有打架（老师说「你会了」而页面写「带着做到」）？
   - 学生打的每一句话：有没有抱怨、要求？（记忆的「话的账」会记，你也自己读一遍。）
5. 把看到的告诉学生（短），该改的先改（多半是根本规则的措辞、`AIMS_DOC`、状态的算法），再做第 2 批。改根本规则只许改措辞、字节上限守住，不加形式规则。

隔天学生会在首页看到「验上次学的」：做完以后那节课的文档上有 `later`。这是这一轮最重要的一个数（隔天、没人带着、换一道没见过的题，还做不做得出来），攒几节以后才看得出东西。

## 数学一真题入库：不要主动提

学生说过三次它现在不重要，上一个对话还反复拿它问他，他很烦。**不要主动提、不要主动做**；学生自己说要入库时，照 `docs/exam-ingest.md` 从头做（上一个对话做了一半的东西没有留）。

## 上一个对话踩过的坑

- 估字节别按字数估：汉字 3 字节。
- 模拟课的花费、「写满 40 轮」两个数我都报错过（记账把累计数重复加了；课早就讲完了只是没人说下课）。数先核再说。
- 页面对学生说的话最容易说满：分步例题第一步点对就显示「独立做到」这种。每加一个状态、一行字，想一遍它在哪种真实的作答下是假的。
- 平台的安全检查偶尔不给结论，命令发不出去：等一下原样重试一次就行，不是被拒。
- 后台跑 `npm run e2e`（十来分钟）的时候不要 `npm run build`：它读的就是构建产物。
- 合并之后的冲突多半在 `desk.js` 开头的 import。
