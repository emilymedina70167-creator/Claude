# 第十四轮的交接（给接着做的新对话）

2026-11-17 写。读完这一份和 `CLAUDE.md` 里「学习台里的 Claude 就是 claude.ai 项目（第十四轮）」那一条就能接上。以前几轮的交接（第十二、十三轮）在 git 历史里。

## 一句话

学习台 = claude.ai 项目 + 更强的呈现 + 后台的教学团队，**而且由学习台里的 Claude 掌控**。代码只做重复的活、存储、呈现；所有决定（记什么、今天做什么、备课、复现、掌握、出题）归它。学生的原话：「我需要 Claude 来掌控这个学习台，而不是学习台去控制这个 Claude」「你不要替他做任何事情，这是底线啊」「直接你给 Claude 所有内容的操作权限不就行了吗？他用不用的好，这个我需要他能根据我与他的交流进行改进，而不是每次在 Claude code 进行」。

## 学生定的做法（不要再问、不要改）

1. **底线：开发不替它做任何事。** 不给它排岗位、不写「下课要整理」「每周通读」、不替它起草项目指令、不在说明里写怎么教。页面拼给它的只写事实（东西在哪、怎么读写、页面会怎么做）；`FORBIDDEN` 守着。往说明里加一句话之前先问：这是事实，还是替它定的做法？是做法就不加。
2. 保护靠「每一次写都记下来、能撤销」（`journal`），不靠拦。格式不对照写、告诉它哪里不对。
3. 以前做的只要和这个方向冲突，一律让路：被迭代、被替代的搬进 `archive/`（怎么清理学生以后定），能教学用的组件留着。
4. 不随便定上限（「为什么必须是 8kb，谁定的上限」）。整份说明 160 KiB 是量出来的（300 KB 平台就拒了）。
5. 每批发布以后停下来叫学生上一节真课，上完先读记录再做下一批；你自己一件一件做；汇报要短，一次别摆一堆问题。
6. 合进 `main`、重新发布学习台不用问。数学一真题入库不要主动提。

## 踩过的坑

- `npm test` 只跑 `tests/`（`archive/tests` 不跑）。
- `desk.js` 是带 DOM 的大文件，单元测试抓不到它的语法错：改完一定 `npm run build`（会报）再跑 e2e。

- 本地的 `main` 可能是旧的：推 `git push origin HEAD:main`（先确认是快进）。
