# 410 分的进度（2026-11-05）

> 2026-11-14 第十轮起，首页的 410 分换成测出来的预测分（如果今天考、范围、几成是测出来的），见 `docs/forecast-plan.md`。这一份的「攒分」算法（`memory/score.js`）只剩考情页还在用它的结构。

我说：考研倒计时和目标院校已经有了，想要一个「410 分达成进度」，放在首页；要用代码形成的系统，达成什么就加多少分，再加权重，而且要有依据。
条件照旧：页面按记录算，**不调用 Claude，也不进发给课堂 Claude 的说明**（不影响回复的快慢、不花额度）。

## 怎么算（`kit/src/memory/score.js`，纯函数，`tests/memory-score.test.js`）

不猜考多少分，只数**已经攒下的分**。

1. **410 分到四科**（`SUBJECTS` 的 `target`）：数学一 130、408 135、英语一 75、政治 70。
2. **一科按考试大纲的分值分到各部分**（`parts`，每部分写着依据 `basis`）：
   - 数学一 150：高数 90（约 60%）、线代 30（约 20%）、概率 30（约 20%）。
   - 408 150：数据结构 45、组成原理 45、操作系统 35、计网 25。
   - 英语一 100：语法和长难句 30（估：翻译 10 + 完形 10 + 阅读里的难句约 10）、阅读和新题型 40、写作 30。学习台的英语课是语法长难句，只挂第一部分。
   - 政治 100：学习台里还没有。
   部分的分按目标缩放（408 的部分 × 135/150），整科学满就是这一科的目标分，四科学满就是 410。
3. **一部分的分平分到课程地图里的各章**（章上写 `weight` 就按比例；「入门」「预备」那种不考的章、`weight: 0` 不分），**一章再平分到这一章的块**。课程地图里还没排块的章、学习台里还没有的部分：分照样占着，攒到的是 0——缺口在哪一眼看得到。
4. **一块攒到几成看掌握**（`LADDER`；掌握是 `mastery.js` 按证据算的，不是 Claude 说的）：

   | 达成 | 几成 |
   |---|---|
   | 讲过（上过这一块的课） | 10% |
   | 基础题过（两道不同的题一次做对） | 50% |
   | 复现通过，第 1 / 3 / 7 / 14 天那档 | 60% / 65% / 75% / 85% |
   | 复现通过，第 30 天那档（稳拿） | 100% |
   | 掉了（以前过了、后来又错了） | 10% |

   依据：考场在几个月以后，只会当场做的题考场上常丢；隔了 30 天还一次做对才算稳拿。
5. **这 7 天攒了多少**：按掌握的 `log` 把 7 天前的状态退回去（`stateAt`），用同一套算法再算一遍，相减；升档的、掉档的块分开列出来。
6. **还差多少**：410 减已攒，除以离考研的周数，就是平均每周要攒多少。

知识点（`L2.1.4#tr`）不单独算分，只算块。

## 画面（`desk.js` 的 `paintScore` / `fillScore` / `openScore`，`desk.css` 末尾「410 分的进度」）

- 首页主角卡下面一张卡：已攒几分 / 410、这 7 天的加减（一枚小标签）、四科一条分段的条（每段的长短是这一科的目标分，实的一截是攒下的，颜色跟科目走，政治是墨色）、每科攒了几分、还差几分每周要攒多少。小组件版式里占两格。
- 点开是面板：校徽和大数字、还差几分；这 7 天每一块从什么升到什么、加了几分（掉档的减分）；每一科每一部分一条，有课的部分能展开看每一章（上过几块、攒了几分、还没排课的章）；「怎么算的」：上面那张表和每一部分的依据。
- 数据是订阅的：掌握一变（课堂里、练一练、页面算的），首页跟着重算。
