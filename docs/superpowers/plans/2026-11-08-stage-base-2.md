## 要特别查的五种情况

1. **刷新以后接着上，碰上新的叫老师规则**：没发出去的那一段是照旧规矩攒的（`goal` 事件不带 `quiet`）。`resume` 只叫一次老师，不重复叫，也不因为现在学生手上有事就吞掉。新来的事件照 `hasWork` 办；`instant` 重放永远不叫。守在 Task 8 的测试「刷新以后的旧事件」。
2. **同一处开了几种按法**：同一句上开着 mark、fold、move，每一下按只认成一种。点一下不会同时拖起来；按法一样的两项照旧当场报错；只开一种时照旧按下就拖。守在 Task 9 的测试「每一下只认成一种」，以及 Task 11 的 `stage-touch` 一条「同一句上又拉又折又拖」。
3. **量算出来是 null**（没写 key、矩阵还空着、不是方阵）：
   - 挑战写「判不了」，不打 ✗，不算做到；
   - `answer={…}` 写「页面没判成」，`ok: null`；
   - 贴的字画「?」；
   - 舞台现状写「页面数不了：…」。

   守在 Task 1 的测试「量判不了」。
4. **存档点隔着老师的一轮、刷新**：学生最后那一下之前 → 老师写了一轮 → `back t`，照样回到那一下之前；整段 log 重放出来的舞台现状一字不差；学生按的 back 撤得了。守在 Task 7 的测试「隔着一轮、刷新」。
5. **压缩时错法那几下**：好几十下里夹着几下错法，又带着长事实。压完不超过 3 KiB；每一种错法都还在，并成 `×N` 时次数和部件都对。守在 Task 4 的测试「错法那几下一定在」。

**接口**：
- 产出（规则接口）：`measures: { 名字: (o, parts, scene) → number | null }`
  - `parts`：写了部件时是 `scene.parts(arg)` 的结果，写整样东西时是 `null`；
  - 这样东西本身数不了（句子没写 key）就抛错，错误的话给老师看；
  - 现在还数不了（矩阵还空着）给 `null`。
- 产出（`rules.js`）：
  - `parseMeasure(word) → { name, arg } | null`，正则 `/^([A-Za-z_]\w*)\(\s*([^()\s]+)\s*\)$/`。
  - `evalMeasure(scene, word) → { value: number | null, why: string | null }`：
    - 东西不在、这种东西没有这个量时抛错，原文举例：「树「t」没有量「size」，能写：count、height、tray」；
    - 量自己抛的错不往外抛，变成 `{ value: null, why: 那句错误的话 }`。
  - `measureLine(scene, o, extra = []) → string | null`：
    - 样子：`页面算的：count(t) = 6，height(t) = 4，tray(t) = 0；avl 否（最小不平衡子树的根是 50，LL 型），bst 是`；
    - 只算写整样东西的量；
    - 数不了的写在最后：`页面数不了：s2 没写 key`；
    - 这样东西没交量时是 null。
  - `extra` 来自那种东西模块上的 `pageBits(o, scene) → string[]`：树交 avl / bst 两句。规则接口照设计只多三项，判断式的那半句由东西自己交。
- 三种东西的量：

  | 东西 | 量 | 值 |
  |---|---|---|
  | 树 | `count`、`height`、`tray` | 结点数；层数（写部件时是那棵子树的高，用 `heightOf`）；托盘还剩几个（`o.tray.length`，没有托盘是 0） |
  | 矩阵 | `rank`、`rankA`、`free`、`det` | 整张的秩（增广的是 r(A \| b)）；竖线左边的秩；系数的列数 − rankA；行列式（只有方阵、不是增广的才有，别的给 null）。有空格的都给 null |
  | 句子 | `verbs`、`left` | 这一段（或整句）里 key 的谓语几段，key 的段整个落在范围里才算；key 还差几段（`leftOf`）。没写 key 时抛错「s2 没写 key」 |

- `goal.js` 的 `operand(scene, 'count(t)')` 给 `{ k: 'num', v }`；值是 null 时给 `{ k: 'null', why }`，这时比较一律不成立。
- 消费：`tree.js` 的 `heightOf`、`imbalance`；`matrix.rules.js` 的 `gridOf`、`rrefOf`；`sentence.rules.js` 的 `keySpans`、`leftOf`。

`inferRowOp` 的算法（只比两边都写满了的行）：

```
changed = G1 里和 G0 不一样的行
对每一个变了的行 i，候选（每个候选是一整行 cand）：
  swap：有 j ≠ i，G1[i] 和 G0[j] 一样（另一行也变了时看它是不是 G0[i]）
  scale：第一个 G0[i][c] ≠ 0 的列算 k = G1[i][c] / G0[i][c]，cand = k·G0[i]（k ≠ 0、≠ 1）
  add：对每个 j ≠ i、每个 G0[j][c] ≠ 0 的列 c，k = (G1[i][c] − G0[i][c]) / G0[j][c]，cand = G0[i] + k·G0[j]
  分数 = cand 和 G1[i] 一样的格数；挑分数最高的，一样高时 add 先于 scale、scale 先于 swap，再比 j 小、|k| 小
  最高分 < ⌈列数 / 2⌉：这一行猜不出（guess: null）
  bad = cand 和 G1[i] 不一样的格（want 是 cand 的，got 是写的）
same = rrefOf(G0).R 和 rrefOf(G1).R 一样（行等价，同解）
```

5. 还放不下：misread 一样的几行并成一行 `像是${misread} ×N（ref1、ref2、…）`，放在这一种第一次出现的地方。
