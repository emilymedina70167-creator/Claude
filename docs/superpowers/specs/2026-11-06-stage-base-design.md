# 舞台的底座：规则层、裁判、通用手势、跟着算的量

2026-11-06。这是「舞台底座」三个子项目里的第 2 个。

- 第 1 个：缺口尺子，已做完，产出缺口单 `docs/stage-gaps.md`。
- 第 3 个：三科铺开，在这个底座上补齐具体的新东西。

## 0. 为什么、要什么

**我要的**（原话的意思）：
- 核心是 Claude 当场判断怎么教。
- 视觉交互是支撑，要几乎接得住 Claude 想做的。
- 算法判定是辅助，要强而准。
- 现在只做线代、英语语法、数据结构，但底座要搭足。

**三条原则**（缺口尺子那份设计里定的，这里照旧）：
1. **页面不做教学决定**：只提供能力和事实。学生错了要不要标、要不要拦，由老师在那一轮写明。
2. **事实以页面算的为准**：数、步骤、对错由代码算，Claude 不心算。
3. **页面当场只做两件事**：画面后果，以及老师事先写好允许的反应。

**硬性规定**（`CLAUDE.md`）：
- 预写只收「做对了 / 做完了」。走偏以后说什么，永远等老师看着写。
- 讲课的只能是 Opus 5.5 high。
- 提示词里提到学生不用「他」「她」。

**底座不是组件库的加法。**
- **加法**：每加一种东西，判分、错法、挑战、事实、学生动作都再写一遍。
- **底座**：这些只写一次、所有东西共用。每种东西只交出它这个世界独有的知识，交了就自动拥有底座的全部能力。

**速度**：底座的东西全在页面里算，不多叫一次 Claude。发给老师的那一段有长度上限。

## 1. 整体结构：每种东西多交一份规则

每种东西在 `kit/src/stage/types/` 下多一个规则文件，比如 `tree.rules.js`，全是纯函数，有测试。规则文件交出下面几样，由 `kit/src/stage/rules.js` 定接口、统一调用：

| 交出 | 签名（意思） | 做什么 |
|---|---|---|
| `next` | `next(o, scene) → { acts: [可接受的动作], why } \| null` | 从现在的样子算出正确的下一步和理由；`null` 是已经做完 |
| `check` | `check(o, act, scene) → { legal, right, misread, why, next }` | 判学生或老师的这一下：合不合这个世界的规则、是不是正确的下一步、不是的话像哪种错、正确的是什么 |
| `predicates` | `{ 名字: (o, args, scene) → true \| false \| null }` | 给挑战用的「是不是」；`null` 是还判不了 |
| `facts` | `facts(before, after, act) → [一行行的话]` | 这一下以后写给老师的事实 |
| `gestures` | 手势表，见第 3 节 | 五种通用手势在这种东西里各是什么动作 |
| `standard`（可选） | `standard(o) → { steps, variants }` | 借 `kit/src/engines/` 的引擎，从现在的样子跑出整段标准过程和常见错法 |

**怎么分工**：
- **从任意状态往下算的部分**写在规则文件里：`next`、`check`。学生走偏以后也接得住，这部分通常很短，比如「找最小不平衡子树、判型」。
- **整段标准过程和常见错法**借引擎：`standard` 调 `engines/*.js` 的 `parse` / `run` / `variants`，和活板适配器 `kit/src/huoban/objects.js` 的 `makeProcess` / `judgeProcess` 一个思路。
- **两边算的结果互相对拍**：用王道的例子写测试守着。

**三个样板的规则：**

**树（AVL）** `types/tree.rules.js`
- `next`：
  - 失衡时：最小不平衡子树的根、型（LL / RR / LR / RL）、该在哪个结点往哪边转；
  - 还有托盘里待插的数时：插到哪。
- `check`：
  - 旋转是不是正确的下一步；
  - 错法：
    - 型从下往上读；
    - 只看离新结点最近的两步；
    - 修了离根近的那个、不是最小的那个；
    - 往旋转方向起名，比如把 LL 当「往左转」；
  - 插入的位置对不对。
- `predicates`：`avl`（平衡了）、`bst`（还是二叉排序树）、`height=h`。
- `standard`：`engines/balanced.js` 的 `avlEngine`。

**矩阵（消元）** `types/matrix.rules.js`
- `next`：照 `engines/elim.js` 的消元顺序，给出下一个该消的位置和可接受的行变换。可接受的不止一种，比如换不同的主元行也算对。
- `check`：
  - 这一步是不是合法的初等行变换，解集变没变；
  - 有没有往阶梯形走；
  - 错法：
    - 倍加时把别的行也改了；
    - 漏乘倍数；
    - 符号错；
    - 换行没跟着换。
- `predicates`：`stairs`（阶梯形）、`rref`（行最简形）、`rank=k`、`same-solutions B`（和 B 同解）。
- `standard`：`engines/elim.js`。学生自己做行变换的纯函数已经在 `elim.js` 的 `mode: do` 那一段（`doStart` 等），直接用。

**句子（拆成分）** `types/sentence.rules.js`
- **正确拆法由老师造句子时给出**，用黑板已有的括号写法：
  ```
  sentence s = "…" key="[S The man [RC who lives next door]] [V is] a doctor."
  ```
  页面不自己分析英语语法。
- `check`：用 `kit/src/entext.js` 的 `parseBrackets` / `judgeSpans` 逐词比。错法：
  - 谓语只圈一半，比如 is running 只圈了 is；
  - 把非谓语当成谓语；
  - 从句断早、断晚；
  - 把从句挂错主人。
- `next`：按 key 给出还没拉对的那一段。
- `predicates`：`parsed`（全拉对了）、`main`（主干对了）、`span s.2-5 = V`（这一段是谓语）。

## 2. 裁判和老师事先定的规则

**学生做一下，页面怎么走：**

1. 学生在画面上做一个手势，第 3 节的手势表把它翻成这种东西的一个动作（`act`），加上一行学生指令（`src`）。
2. **裁判** `kit/src/stage/referee.js`（纯函数）调规则层的 `check`，得到 `legal` / `right` / `misread` / `next`。
3. **`legal = false`**：这种东西本身做不到的，比如把一个词拖进它自己那一段。永远不做，弹回去，记一笔事实。这是这个世界的物理，不是教学决定。
4. **`legal = true`、`right = false`**：照老师写的 `wrong=` 处理：
   - `quiet`：照做，只记下。**这是默认，老师没写时就是它。**
   - `mark`：照做，在画面上那一处淡淡圈一下，不出字。
   - `block`：不让做，弹回去，记下。
5. **要不要马上叫老师**，照老师写的 `call=`：
   - `wrong`：一走偏就叫；
   - `done`：做完才叫；
   - 不写：照现在的规矩（`kit/src/stage/events.js`）攒着，等答了、做到了、试了 `TRY_MAX` 下、`QUIET_MS` 没动再叫。
6. **做完了**（规则层的 `next` 返回 `null`）：
   - 有老师预写的 `@t.done …`：马上演；
   - 没有：叫老师。
7. **做对了**：有预写的 `@t.right …` 就演。只收一句确认或揭开下一小问，和 `@g1` 同一条线。

**写法**（跟在 `open` 后面，`kit/src/stage/scene.js` 的 `open` 那一段扩展）：

```
open t rotate wrong=mark call=wrong undo=on
@t.done say "平了。"
```

- 预写只认 `@名字.done`、`@名字.right` 和原有的 `@挑战`。
- 写 `@t.wrong` 当场报错：「走偏以后怎么讲要等你看着学生写，不能预写」。

**老师自己做的也过一遍裁判**：照演不拦，老师可能是故意演错。不是正确的下一步时，下一轮发给老师的消息多一块：

```
[页面核过你上一轮的几步]
你在 50 右旋，现在正确的是先在 30 左旋（LR 型）。
```

**挑战**（`kit/src/stage/goal.js` 扩展）：
- `when=` 能写每种东西交出的判断式，比如 `when="t avl, t bst"`、`when="M stairs"`、`when="s parsed"`。
- 原来的写法照旧。
- 顺带修掉缺口单第 5 条里的三个错：
  - **49 和 49′ 不再算同一个数**：`=` / `!=` 比一格时连 ′ 一起比，49 ≠ 49′。比大小、`sorted` 照旧按数比，49 和 49′ 一样大，排在一起算排好了。
  - **只有学生做的才报「学生做到了」**：`loop.js` 的 `onGoal` 看 `by`，老师做到的报成「你这一轮让挑战 g1 成立了」。
  - **预写里写下就已经成立的挑战，照样不收**：和说明一致。

## 3. 通用手势

**底座只做一层手势**，五种，所有东西共用。手指的事都走 `kit/src/stage/pointer.js`，现在的 `dragSpec` / `affords` 改成由手势层统一驱动：

| 手势 | 意思 |
|---|---|
| `tap` | 点一个部件 |
| `drop-on` | 把一个部件拖到另一个部件上 |
| `drop-at` | 把一个部件拖到空处，包括托盘里的东西拖进来 |
| `span` | 从一个部件拉到另一个部件，拉出一段或一条线 |
| `write` | 往一个部件里写一个值：数字键盘（能写分数、负数）或文字 |

**加上通用的「撤一步」**：`open … undo=on`，学生能撤回自己的上一下。做法是去掉这一回合学生的最后一行，再照 log 重放。

**手势层在底座里写一次**：接住手指、跟着手动、放下以后变成一行学生指令、过裁判、演、记进 log、刷新放回。

**每种东西只交一张手势表**，写在规则文件里，说明五种手势在它这里是什么动作、翻成哪一行指令。三个样板：

| 东西 | 手势 | 动作 | 翻成的指令 |
|---|---|---|---|
| 树 | `drop-on`（结点拖到父亲上） | 在这条边上旋转 | `rotate t.30 …` |
| 树 | `drop-at`（托盘的数拖进树） | 插入，页面从根比下去 | `insert t 47` |
| 树 | `drop-at`（数拖到某个空位，`open t place`） | 学生自己摆 | `insert t.45 right 47` |
| 矩阵 | `drop-on`（一行的把手拖到另一行上） | 倍加，弹出倍数框 | `rowop M r3 + k r1` |
| 矩阵 | `drop-on`（把手拖到行号上） | 互换 | `rowop M r1 <-> r3` |
| 矩阵 | `tap`（点行号） | 倍乘 | `rowop M k r2` |
| 矩阵 | `write`（`open M edit input=keypad`） | 写一格 | `write M.2,3 5` |
| 句子 | `span`（从一个词拉到另一个词，再点成分标签） | 拉一段括号 | `mark s.2-5 V` |
| 句子 | `tap`（`open s fold`） | 折起一段 | `fold s.3-6` |

**老师的写法一律是 `open 东西 手势或动作`**：老师不用记每种东西各有哪些专门的指令，说明里每种东西列出它的手势表就够了。

原来的 `open B edit`（±1 拨数器）、`open a`（拖格子对调）、`open p.u drag` 照旧能用，意思不变：它们就是手势表里已有的几行。

## 4. 跟着算的量

**任何一个值都能写成 `{式子}`**：数、矩阵、向量、一格、一个边权都可以。

- **式子的计算**：用黑板已有的精确计算 `kit/src/exact.js`，入口 `evaluateExact(src, vars)`。支持分数、矩阵加减乘、数乘、转置、求逆、行列式；`algofuncs.js` 注册的函数也能用。
- **式子里能引用**：拨数（`k`）、舞台上东西的值（`A`、`B.1,2`、`a.3`、`p.u`）。
- **解析、求值、依赖追踪**：新模块 `kit/src/stage/value.js`，纯函数。

```
dial k = 1 range=-3..3
matrix M = 1 {k} / 0 1
matrix S = {A + B}
matrix P2 = {P^-1}
vec p w = {A v}
graph g = A-B:{w1} B-C:4
ask value "A⁵ 是？" type=matrix answer={A^5}
```

**用了 `{…}` 的东西是「跟着算的」**：
- **重算**：依赖的任何一样变了，不管是学生拨的、拖的，还是老师改的，页面当场重算，变了的部分闪一下。现在矩阵乘积的 `derive` 机制推广过来。
- **不能直接动**：学生拖不动跟着算的东西，就像现在的 `u + v`。
- **算不出来时**：依赖成环、矩阵不可逆、维数对不上，报给老师（「上一轮没演的行」或事实里），不默默失败。

**变了什么写进事实**：比如「学生把 B.1,1 从 1 拨到 2 → C.1,1 从 0 变成 1，C.2,1 从 0 变成 −1」。

**兼容**：
- 原来的 `product C = A B`、`vec p w = 2u - v` 照旧能用，意思不变。
- 旧课照 log 重放照旧：重算是确定的。

## 5. 判答案、写给老师的事实、说明、验收

### 判答案（新模块 `kit/src/stage/answer.js`，纯函数）

`ask value` 加 `type=`，接上黑板已有的判法，不重写：

| type | 判什么 | 用的现成代码 |
|---|---|---|
| `num`（默认） | 数、分数 | `exact.js` |
| `formula` | 含 n 的式子 | `formula.js` |
| `matrix` | 整张矩阵逐格 | `formula.js` 的 `matrixCells` / `compareCells` |
| `set` / `equation` | 数集、方程 | `anstypes.js` |
| `seq` | 序列 | `textcheck.js` |
| `en` | 英文答案、翻译要点 | `entext.js` |

- `answer=` 能写成 `{式子}`，由页面算出正确答案。
- `answer=` 能不写：只收不判。
- 常见错答照 `entext.js` 的写法预写，比如 `wrong="3=漏了 E"`。**只写进给老师的事实，不显示给学生。**

### 写给老师的那一段（`kit/src/stage/events.js`、`doc.js` 的 `turnMessage`）

照旧分块，每块都由页面算：

| 块 | 写什么 |
|---|---|
| **[学生]** | 做了什么。每一下跟着裁判的结论：对不对、像哪种错、正确的下一步。连着的几下照旧合并。 |
| **[页面核过你上一轮的几步]** | 新加。只在老师的哪一步不是正确的下一步时出现。 |
| **[跟着变的]** | 新加。哪几样变了、从多少变成多少。 |
| **[舞台现在]**、**[上一轮没演的行]** | 照旧。 |

**长度上限**：[学生] 一块不超过 2 KB。试得多时只留最近几下的细节，前面的并成一句，比如「之前又试了 7 下，都没做到」。

### 给 Claude 的说明（`kit/src/stage/doc.js`）

- **要加的写法**：`open 东西 手势`、`wrong=` / `call=` / `undo=`、`@名字.done` / `@名字.right`、判断式、`{式子}`、`type=`。
- **说明写得不清楚的地方**：缺口单里那 10 条顺手一起改掉。
- **长度**：说明总长守住 `STAGE_SYSTEM_MAX`（150 KiB）。按科目只带用得上的东西，照旧。
- **写对率**：先不量。
