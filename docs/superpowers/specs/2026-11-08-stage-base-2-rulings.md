# 舞台的底座第二轮：做的时候我自己定的事

2026-11-08。照第一轮的样子：做的时候碰到计划没写清、或者计划和设计对不上的地方，我自己定了。每一条写：定了什么、为什么、定错了要付什么代价。觉得哪条不对，告诉我，改起来都不大。

## 量（Task 1）

- **`{…}` 里 `det`、`rank` 照旧交给 exact.js；只有 `rankA`、`free`、`count`、`height`、`tray`、`verbs`、`left` 换成页面数的量。** 挑战（`when=`）里照旧都是量。
  - 规矩（`value.js` 的 `evalLive`、`script.js` 的 `parseRich` 同一条）：写成「名字(东西或部件)」、名字不是 exact.js 本来就认得的函数（`det`、`rank`、`inv`、算法函数、`sin` 这些，exact.js 新导出 `isExactFunc`）才当量。
  - 为什么：旧课里的 `{det(A)}` 一字不变；矩阵写满时两边算出来一样。
  - 代价：`{rank(M)}` 在 M 还有空格时报的是 exact.js 的错（「M.1,1 还空着」），答案照样写「页面没判成」，不是「判不了」；话里的 `{det(A)}` 照旧原样写出来，不画成数。
- **话、贴的字、挑战的字、题卡里的 `{count(t)}`：写下时查量名和括号里的东西。**
  - 哪些地方查：`say`、`label`、`ask`、`goal`、`card`、`addline`，还有改字的 `retext`、题卡的 `rewrite`。
  - 现在还空着的照收，画「?」；以后也数不了的当场报（见下面「以后也数不了」那一条）。
  - 重放旧课（`lenient`）不查量。`retext`、`rewrite` 以前不查 `{a.3}`，重放时照旧不查，新写的查。
  - 画的时候（`rules.js` 的 `measureShown`）：数不了画「?」。不是量的照原样写字，和以前当成拨数原样写出来一样：东西不在舞台上、名字不是这样东西的量，比如旧课重放进来的 `{f( x )}` 连空格都不变。
  - 为什么：`parseRich` 看不到舞台，只能照写法认。名字写错（`{size(t)}`）不当场说，学生看到的就是一个「?」，老师不知道为什么。旧课里 `{f(x)}` 以前是原样写出来的字，当时收下的照样收下、照样那样画；「?」只表示「页面数不了」。
  - 代价：
    - 旧课里要是写过 `{count(t)}` 这样的字（以前原样写出来），重放时画成数。
    - 贴的字里的量，东西后来拿下舞台了，画回原样的字（`count(t)`），不画「?」。
- **树的量写部件，是以它为根的那棵子树：`height(t.107)` 那棵子树几层，`count(t.107)` 那棵子树几个结点（`t.107*` 一样）。`tray` 写部件没有（托盘是整棵树的）。**
  - 为什么：计划只给了 `height` 写部件的意思；`count` 跟着它，同一个写法两个量不能一个指结点、一个指子树。
  - 代价：想数「这几个结点」的老师得自己数。
- **矩阵的量只写整张；写部件（`M.r1`）是「本来就没有」。`det` 先看形状：不是方阵、增广矩阵空着也是「没有」，不是「数不了」。**
  - 为什么：一行、一列的秩老师用不上；形状定了 det 有没有，空不空是之后的事。
  - 代价：不是增广的矩阵也列 `rankA`（和 `rank` 一样），每张矩阵每一轮多十几个字。没有为它特判。
- **句子的 `left` 写一段时，数 key 里整个落在这一段里、还没拉对的段（和 `verbs` 一样的范围规矩）。**
  - 为什么：计划只写了 `left(s)`；同一个写法的范围意思要一样。
- **量数不了时说什么，挂在量的函数上（`blank`：「还有空着的格」；`none`：「不是方阵，或者是增广矩阵」）。** 规则接口照设计只多三项，`measures` 还是「名字 → 函数」。
  - 为什么：通用的 `evalMeasure` 不知道每种东西为什么数不了；要说出「C 还有空着的格」「M 没有 det（…）」只能那种东西自己交。
  - 代价：没挂的量数不了时说「t 现在还数不了 count」，笼统一点。
- **句子没写 key 时，量抛的错是短的一句「s2 没写 key」（作废了是「s2 的 key 跟着 rewrite 作废了」），不是判断式那句长的。**
  - 为什么：「页面数不了」那一行同一句只写一次（`verbs`、`left` 都数不了，并成一句）。
- **挑战里量数不了的那一句写「判不了：原因」（`verbs(s2) = 1 判不了：s2 没写 key`）；判断式的「判不了」照旧不带原因。**
  - 为什么：老师要知道是没写 key 还是矩阵还空着，才知道下一步怎么办；判断式的旧样子不改（旧课放回一字不差）。
- **以后也数不了的量写下时当场报；现在还空着的照收，写「判不了」。**（控制者定的，照第一轮 I4 的规矩：这样东西本身永远判不了就写下时报，之后会变成判得了的 null 照收）
  - 以后也数不了：
    - 量自己抛错，也就是这样东西本身数不了：句子没写 key、key 作废了。key 只能重新造这句时带上，不算「之后会有」。
    - 本来就没有（`undefined`）：增广矩阵、不是方阵的 `det`，写部件的 `rank(M.r1)`、`tray(t.50)`。形状在写下时就定了。
  - 这两种 `evalMeasure` 都多给 `never: true`。挑战的 `when=`、话、贴的字、题卡、改字写下时，`checkMeasure(…, { run: true })` 碰到它就报「「det(M)」页面数不了，以后也数不了：M 没有 det（不是方阵，或者是增广矩阵）」。
  - 答案 `answer={…}` 照旧：写下时 `{…}` 要算得出，数不了的都报。
  - 量写错（名字不对、东西不在、部件不对）也是写下时报。
  - 写下以后才变成数不了的（key 后来跟着 rewrite 作废了），挑战写「判不了：原因」，贴的字画「?」。重放旧课照收。
  - 为什么：永远不成立的挑战、永远是「?」的字是老师写错了，当场知道比下一轮看现状才发现好。和判断式 `s parsed` 在没写 key 时写下就报是一个规矩。
  - 代价：和设计里「不是方阵是 null、挑战写判不了」的字面不一样，写下时就挡下了。还空着的乘积照旧收、写「判不了」。
- **量的值不是整数时（只有 `det` 会）写成分数：分母 1000 以内凑得上的写 `3/2`，凑不上的写小数。**
  - 为什么：规则接口照计划交数（number），舞台上的矩阵多是小分数。
  - 代价：分母超过 1000 的 det 写成小数（挑战里比大小照旧按数比，差不过 1e-9）。
- **`{count(t)}` 这样跟着量算的东西，依赖记整样东西（`t`），写部件也一样。**
  - 为什么：子树几层、几个结点跟着整棵树的结构变。
- **有意的不同**：现状里矩阵、树、句子下面各多一行「页面算的 / 页面数不了」。`stage-class` 的「旧 log 照放」和 `stage-value` 的「旧写法不变」逐行核过（只多了这几行，别的一字不差、先后不变），期望值跟着改了。
