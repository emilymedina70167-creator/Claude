# 舞台的底座第二轮：做的时候我自己定的事

2026-11-08。照第一轮的样子：做的时候碰到计划没写清、或者计划和设计对不上的地方，我自己定了。每一条写：定了什么、为什么、定错了要付什么代价。觉得哪条不对，告诉我，改起来都不大。

## 量（Task 1）

- **`{…}` 里 `det`、`rank` 照旧交给 exact.js；只有 `rankA`、`free`、`count`、`height`、`tray`、`verbs`、`left` 换成页面数的量。** 挑战（`when=`）里照旧都是量。
  - 规矩（`value.js` 的 `evalLive`、`script.js` 的 `parseRich` 同一条）：写成「名字(东西或部件)」、名字不是 exact.js 本来就认得的函数（`det`、`rank`、`inv`、算法函数、`sin` 这些，exact.js 新导出 `isExactFunc`）才当量。
  - 为什么：旧课里的 `{det(A)}` 一字不变；矩阵写满时两边算出来一样。
  - 代价：`{rank(M)}` 在 M 还有空格时报的是 exact.js 的错（「M.1,1 还空着」），答案照样写「页面没判成」，不是「判不了」；话里的 `{det(A)}` 照旧原样写出来，不画成数（Task 15 复核改了：引号里的 rank、det 也是量，见「给老师的说明和长度」那一节）。
- **话、贴的字、挑战的字、题卡里的 `{count(t)}`：写下时查量名和括号里的东西。**
  - 哪些地方查：`say`、`label`、`ask`、`goal`、`card`、`addline`，还有改字的 `retext`、题卡的 `rewrite`。
  - 现在还空着的照收，画「?」；以后也数不了的当场报（见下面「以后也数不了」那一条）。
  - 重放旧课（`lenient`）不查量。`retext`、`rewrite` 以前不查 `{a.3}`，重放时照旧不查，新写的查。
  - 画的时候（`rules.js` 的 `measureShown`）：数不了画「?」。不是量的照原样写字，和以前当成拨数原样写出来一样：东西不在舞台上、名字不是这样东西的量，比如旧课重放进来的 `{f( x )}` 连空格都不变。
  - 为什么：`parseRich` 看不到舞台，只能照写法认。名字写错（`{size(t)}`）不当场说，学生看到的就是一个「?」，老师不知道为什么。旧课里 `{f(x)}` 以前是原样写出来的字，当时收下的照样收下、照样那样画；「?」只表示「页面数不了」。
  - 代价：
    - 旧课里要是写过 `{count(t)}` 这样的字（以前原样写出来），重放时画成数。
    - 贴的字里的量，东西后来拿下舞台了，画回原样的字（`count(t)`），不画「?」。
- **树的量写部件，是以它为根的那棵子树：`height(t.107)` 那棵子树几层，`count(t.107)` 那棵子树几个结点（`t.107*` 一样）。`tray` 写部件没有（托盘是整棵树的）。**
  - 为什么：计划只给了 `height` 写部件的意思；`count` 跟着它，同一个写法两个量不能一个指结点、一个指子树。
  - 代价：想数「这几个结点」的老师得自己数。
- **矩阵的量只写整张；写部件（`M.r1`）是「本来就没有」。`det` 先看形状：不是方阵、增广矩阵空着也是「没有」，不是「数不了」。**
  - 为什么：一行、一列的秩老师用不上；形状定了 det 有没有，空不空是之后的事。
  - 代价：不是增广的矩阵也列 `rankA`（和 `rank` 一样），每张矩阵每一轮多十几个字。没有为它特判。
- **句子的 `left` 写一段时，数 key 里整个落在这一段里、还没拉对的段（和 `verbs` 一样的范围规矩）。**
  - 为什么：计划只写了 `left(s)`；同一个写法的范围意思要一样。
- **量数不了时说什么，挂在量的函数上（`blank`：「还有空着的格」；`none`：「不是方阵，或者是增广矩阵」）。** 规则接口照设计只多三项，`measures` 还是「名字 → 函数」。
  - 为什么：通用的 `evalMeasure` 不知道每种东西为什么数不了；要说出「C 还有空着的格」「M 没有 det（…）」只能那种东西自己交。
  - 代价：没挂的量数不了时说「t 现在还数不了 count」，笼统一点。
- **句子没写 key 时，量抛的错是短的一句「s2 没写 key」（作废了是「s2 的 key 跟着 rewrite 作废了」），不是判断式那句长的。**
  - 为什么：「页面数不了」那一行同一句只写一次（`verbs`、`left` 都数不了，并成一句）。
- **挑战里量数不了的那一句写「判不了：原因」（`verbs(s2) = 1 判不了：s2 没写 key`）；判断式的「判不了」照旧不带原因。**
  - 为什么：老师要知道是没写 key 还是矩阵还空着，才知道下一步怎么办；判断式的旧样子不改（旧课放回一字不差）。
- **以后也数不了的量写下时当场报；现在还空着的照收，写「判不了」。**（控制者定的，照第一轮 I4 的规矩：这样东西本身永远判不了就写下时报，之后会变成判得了的 null 照收）
  - 以后也数不了：
    - 量自己抛错，也就是这样东西本身数不了：句子没写 key、key 作废了。key 只能重新造这句时带上，不算「之后会有」。
    - 本来就没有（`undefined`）：增广矩阵、不是方阵的 `det`，写部件的 `rank(M.r1)`、`tray(t.50)`。形状在写下时就定了。
  - 这两种 `evalMeasure` 都多给 `never: true`。挑战的 `when=`、话、贴的字、题卡、改字写下时，`checkMeasure(…, { run: true })` 碰到它就报「「det(M)」页面数不了，以后也数不了：M 没有 det（不是方阵，或者是增广矩阵）」。
  - 答案 `answer={…}` 照旧：写下时 `{…}` 要算得出，数不了的都报。
  - 量写错（名字不对、东西不在、部件不对）也是写下时报。
  - 写下以后才变成数不了的（key 后来跟着 rewrite 作废了），挑战写「判不了：原因」，贴的字画「?」。重放旧课照收。
  - 为什么：永远不成立的挑战、永远是「?」的字是老师写错了，当场知道比下一轮看现状才发现好。和判断式 `s parsed` 在没写 key 时写下就报是一个规矩。
  - 代价：和设计里「不是方阵是 null、挑战写判不了」的字面不一样，写下时就挡下了。还空着的乘积照旧收、写「判不了」。
- **量的值不是整数时（只有 `det` 会）写成分数：分母 1000 以内凑得上的写 `3/2`，凑不上的写小数。**
  - 为什么：规则接口照计划交数（number），舞台上的矩阵多是小分数。
  - 代价：分母超过 1000 的 det 写成小数（挑战里比大小照旧按数比，差不过 1e-9）。
- **`{count(t)}` 这样跟着量算的东西，依赖记整样东西（`t`），写部件也一样。**
  - 为什么：子树几层、几个结点跟着整棵树的结构变。
- **有意的不同**：现状里矩阵、树、句子下面各多一行「页面算的 / 页面数不了」。`stage-class` 的「旧 log 照放」和 `stage-value` 的「旧写法不变」逐行核过（只多了这几行，别的一字不差、先后不变），期望值跟着改了。

## 矩阵的写法和摆法（Task 2）

- **有意的不同 1：`link` 写整样东西的那一头连到那样东西上，一道弧（以前把它的每一格连成一串）。** 不只两头都是整样东西（`link AB BA`），一头是部件、一头是整张（`link f.l1 AA f.r1`）也一样。只写一样东西（`link a`）照旧把它的部件依次连起来。
  - 为什么：设计第 9 节。缺口单里真出过的就是一头是部件的写法（L1 第 2 幕的方块图）：只管两头都是整张的话，那一条照旧满屏弧线，`unlink f` 也收不掉块里的那几道。
  - 连线的一项：整样东西那一头是 `{ obj, key: null }`，这条线记 `whole: true`；现状写成 `连线：AB–BA 蓝`、`f.l1–AA 蓝`。照新的数重新造（`remake`）时只剪「这一头是部件、部件没了」的线，整样东西那一头不算。
  - `unlink X`（整样东西）收掉一头在 X 上的线：连着 X 的、连着 X 里部件的都算；`unlink X.1,1`（部件）照旧只收连着那一格的。
  - 一排格子的分组（`group`）只收这一排格子之间的线，整样东西的那一道不收（`array.js` 的 `regroup`，计划的文件表里没有，顺手改的）。
  - 代价：照 log 放回的旧课里写过 `link a b`、`link f.l1 AA` 的，现状的连线一行和画面都和以前不一样（以前是一串格，现在是一道）。
- **有意的不同 2：同名重造留在原处。** 各种东西的 make 照旧位置留着（没写 `beside=`）时，在 `objects` 里的先后也不变；换了地方的（写了 `beside=`、乘积照 A、B 重新排、平面、换了一种东西）照旧排到最后，像新造的一样摆。
  - 为什么：设计第 9 节（`matrix P = {B A}` 掉到最底下）。只看「位置留着没有」：乘积另起一行（`BA =`）重造时 `makeProduct` 把它摆到最下面，要是先后还在最前面，`reflow` 会把它上面的东西全推到它下面（`stage-value`「旧写法不变」里的 `product A = C B` 就是这样，照这条它照旧排到最后，那条测试一字没改）。
  - `replaceObject(id, o)` 用 Map 换一个还在的键的值（不改先后、`objects` 还是同一个 Map），`dropObject` 多一个 `keepPlace` 留着键，只清连线、open 这些。连线照旧跟着清掉（整样东西的那一道也清，和以前一样）。
  - 代价：旧课里同名重造过、位置留着的那一样，现状里东西的先后和以前不一样（不再排到最后）。
- **整样东西的弧：一个在另一个上面时，从上面那一样的下沿中点连到下面那一样的上沿中点（竖着出去、竖着进来，走中间的空当）；横着排成一排的照旧从上沿拱一道弧。**（`layout.js` 的 `wholeLinkGeom`）
  - 为什么：照两格之间那样从两样的上沿拱，下面那一样的弧会竖着穿过上面那一样（截图里 `link A B` 是一根竖线从 A 的中间一列穿过去）；AB 一排、「BA =」另起一行摆在下面是 `link AB BA` 最常见的摆法。
  - 代价：斜着隔得远、中间夹着别的东西时，曲线可能从别的东西身上过（和两格之间的弧一样，不绕路）。
- **另起一列比的是镜头能用的那块屏幕，不是整块屏幕。** `scene.view` 照接口写整块屏幕大小；摆新东西时减掉四边留白（28）、顶上的话（102）、底下一条（76）再给 `columnSlot`（`layout.js` 的 `CAMERA_ROOM`、`cameraRoom`，`stage.js` 的镜头留白也改用 `CAMERA_ROOM.pad`，值没变）。
  - 为什么：拿整块屏幕比，横屏五张四行的矩阵叠起来，镜头已经缩到 0.4（一格 21 像素，学生点不着）才觉得要另起一列；按能用的那块比，三张就另起，镜头 0.64。
  - 代价：话很长、底下有好几排按钮时，真能用的地方比估的小，还是会缩小一点；横屏另起一列比按整块屏幕早。
- **已经另起过一列：「往下摆」是摆在这一列下面（左边和这一列对齐，不伸到左边那一列底下），缩得不比照旧往下摆更小就先摆它；这一列也满了再另起一列。**
  - 为什么：计划只写了「往下摆」和「摆到最右一列的右边」两种。照字面，另起一列以后下一张要么照旧摆到整块下面、横跨两列居中，要么一张一列。伸到左边那一列底下的话，`reflow` 会把它推到左边那一列的下面。
  - 怎么记：另起一列的那一样带 `o.colStart`；「这一列」是最后一个另起的和它后面摆的（`columnSlot` 多一个可选的 `last`，返回多一个 `start`）。只管各种东西自己照旧往下摆的那一样（`placeFresh` 按它造出来的真实大小再看一眼，整样挪过去）；`beside=`、和 A、B 排成一排的乘积、同名重造不动。
  - 代价：不知道屏幕多大（纯场景、测试、`scene.view` 还没写回）照旧往下摆；同一节课换了横竖屏，后面摆的东西照新的屏幕摆，前面的不重排。重放时照重放那一刻的屏幕摆。
- **藏起来（`hide=on`、`hide R` / `show R`）。**
  - `hide=` 只认 `on` / `off`，别的报错；同名重造不写 `hide=` 时照旧（藏着的还藏着，「留在原处」）；`hide=off` 摆出来。
  - 藏着的：不画；不进镜头；不推别人、也不被推（`reflow`）；摆新东西不给它留地方（`slotFor`）；贴的字不躲它。贴在它上面的字（贴的东西都藏着）不画；拨数照画（锚落到看得见的东西上）；连线一头藏着就不画。现状照写，第一行前面「（藏着，画面上不摆）」。
  - `show` 的时候：原来的地方压着画面上的东西、或者在所有东西下面（`hide=on` 造的从来没摆过，后来另起了一列的话该摆进那一列），照摆新东西的规矩重新摆、排到最后；夹在中间、没压着的（`beside=` 摆的、摆过又藏起来的）留在原处，先后不变。
  - 为什么：藏着的时候没人给它让地方，原来的地方可能已经被后造的占了；从来没摆过的，造的那一刻往下摆的地方没有意义。
  - 代价：`show` 以后可能不在 `hide` 之前的地方（压着别的东西的时候）。
- **看不全：只在镜头框着全部东西时写（老师 `camera` 对准了一处时不写：镜头外面的是老师自己选的）；比的是整块屏幕（出了屏幕两像素以上），藏着的、已经拿下舞台的不写。** 镜头每挪一次（`camera`、`keepInView`）写回一次。
  - 代价：老师对准一处时，别的东西学生看不到，现状里也不说。
- **`_` 只在造矩阵时认（`parseRows` 的 `blank`），判答案时不认。**
  - 为什么：答案里空着的格不是一个答案，照旧报「不是数」。
- **`coef(M)`、`rhs(M)`：`rhs` 是 n×1 的矩阵（竖线右边不止一列时 n×k），不是向量；只看用到的那一半（左边还空着不碍 `rhs` 的事）。** 依赖记 M。
  - 为什么：舞台上一列的矩阵（`matrix P = 1 / 2`）在式子里是 n×1，`coef(M) P` 也是 n×1；exact.js 里 n×1 的矩阵和向量不能相减。
  - 代价：和平面上的向量相减（`{coef(M) v - rhs(M)}`）报尺寸不同。
- **格里的式子算出来不是数，照实说是矩阵还是向量**：「「{2 A}」算出来是矩阵，格里要一个数」。名字不认得的报 value.js 本来那句（「「q」不是拨数，也不是舞台上的东西」）。
- **`vars=`、`from=` 写下时查**：`vars` 的个数要等于未知数的个数（增广的是竖线左边的列数，不是增广的是列数），不能重名，存成字符串数组 `o.vars`；`from=` 要是舞台上的矩阵、和这一张一样大、不是自己，存成名字 `o.from`。
  - 为什么：读回、比的时候对不上就没有意义，写下时说比下一轮现状里写不出来好。
  - 代价：`from=` 的那一张后来被拿掉或改了大小，Task 3 那边要自己照实说。
- **藏着的东西学生看不见：要学生点它、动它的写下就报「R 藏着，学生看不见：先 show R」；后来才藏起来的，现状里补一句「（R 藏着，学生点不到）」。**（评审的 Important，控制者定的）
  - 写下就报的：`open R …`（开放的东西藏着）；`ask` 要点、要拖的部件（连 `expect=`）落在藏着的东西上；`goal` 的条件里提到的东西学生一样都动不到、又是因为有东西藏着。「动得到」：摆着的、不是跟着算的；跟着算的看它跟着的东西（别的东西、拨数）有没有一样动得到——所以藏着的参照（`A same R`，R 是藏着的答案）、跟着看得见的东西算的（`S = {A + A}` 藏着，`S = O`）照收。预写（`@g1`）在今天的舞台上试，先 `show R` 再 `open R` 照收。重放旧课（`lenient`）照收。
  - 补一句的：「在等学生」那一行（点、拖的部件和 `expect=`）、「学生能直接动的」那一项、还没做到的挑战（同上「动不到」的算法）；`show` 以后就不补了。
  - 为什么：现状是写给老师的事实，不能说「在等学生点 R.1,1」而学生根本看不见 R，老师会等一个永远不来的回答。
  - 代价：老师想先藏着、等学生做到别的再亮出来，要么预写里先 `show`，要么挑战写在亮出来以后。
- **`link a.1 a`（一格和它自己那样东西）照连一道弧，不报错；`link a a`（两头是同一整样东西）新写的报，旧课重放时跳过这一对、这一行别的照连。**（评审的 Minor）
  - 为什么：照「写整样东西的那一头连到那样东西上」，`a.1` 连到 `a` 是一道弧，连得出来；旧课里这样写的以前连成一串格，现在不该被挡掉。两头是同一整样东西连不出东西。
  - 代价：旧课里写过 `link a a` 的（以前连成一串格），重放时那一对没有线。
- **重放时照重放那一刻的屏幕摆：另起一列、`show` 摆回来的位置跟着屏幕的横竖。** 同一节课横屏上、竖屏刷新（或者反过来），画面上的排法和刷新前不一样；位置不在现状的字里，老师看到的字不变，只有「画面上看不全」那一行可能不同。刷新那一刻要是页面还没排好版（量出来是 0），重放时不知道屏幕多大，照旧往下摆，排好版以后新摆的才可能另起一列。旧课在横屏上刷新，以前往下叠的东西可能另起一列（global.md 的「有意的不同」也列了这一条，Task 17 的回归算作预期的）。
  - 为什么：位置本来就该照学生现在的屏幕摆；记下当时的屏幕、重放时照它摆，换了横竖屏反倒放不下。
  - 代价：同一份 log 在横竖屏上放出来的画面不一样（截图对不上），回归只比现状的字。

## 每种东西多写的事实、扫一遍拨数（Task 3）

- **只有「增广、竖线右边正好一列」的矩阵算方程组**：读回、解的样子只写这种；`[A | E]` 这种右边好几列的不读成方程，`brief` 写秩（`r = 3`）。
  - 为什么：右边好几列（求逆、解矩阵方程）读成「x1 + 2x2 = 1 0 0」没有意义，r(A | b) 也不是那个意思。
  - 代价：老师用增广矩阵求逆时，现状里只有秩，没有「唯一解」这种话。
- **还空着的行不读，写满了的行照读**（`readBack`）；解的样子、`brief` 有一格空着就是 null。
  - 为什么：写满了的那一行读出来的方程是真的；解的样子要整张。from= 的那一张一行一行填的时候，写满的几行就能读。
- **from=M0：学生每写一格，写完这一行没有空着的了就比一次**（不只是从「没写满」变成「写满」的那一下）。
  - 为什么：简报的测试「改成写 5 7 9 | 11」是在已经写满的一行上一格一格改；只比变满的那一下，改完了老师就不知道现在像什么。
  - 代价：在写满的一行上一格一格改，每改一格都多一句（每一句说的是那一刻的样子）。
- **猜行变换（`inferRowOp`）补的几条**：加 0 倍不算一步（`k = 0` 的候选不要）；对调要两行一起变——另一行写满了就要正好是这一行原来的样子（另一行没变、只是抄了一份过来的不是对调），另一行还空着的照样像对调；两行正好换了位置先认成一下对调（不然单看一行可能像倍乘、倍加：`1 2 / 2 4` 两行对调，第 1 行单看也像 `r1 + (1/2)r2`）；还有空着的格时 `same` 是 null（说不了同不同解）。`k`、`want`、`got` 交字符串（和规则交出去的数一样）。多交三项：`each`（每个变了的行各自猜的）、`kept`（写满了、没变的行）、`blank`（还没写满的行）。
  - 变了好几行、凑不成一步：`guess` 是 null，`fromFact` 写「M1 第 2、3 行变了，凑不成一步：第 2 行像 r2 − r1，第 3 行看不出是哪一种初等行变换」。
  - **照猜的那一步对不上的格（`bad`）有这一行变了的格的一半或更多：也算猜不出**（复核后控制者定的，修第 1 轮）。列少的时候 ⌈列数/2⌉ 这道门槛太松：两列的矩阵、只改了一格的一行，凑一个 k 总能对上一格，以前会说「像 r2 − (3/2)r1；第 1 格该是 1/2，写的是 0」，靠 `bad` 列出对不上的格。
    - 怎么读的：控制者写的是「`bad` 超过这一行的格的一半」。在 ⌈列数/2⌉ 的门槛下 `bad` 永远到不了一行的一半以上，照字面就什么也没改；评审举的两列的例子是变了的两格对上一格，正好一半。所以比的是「变了的格」，一半也算（`bad × 2 ≥ 变了几格`）。
    - 量过（`node --test` 里有一条随机的 2000 组，草稿里又跑了 2 万组）：真的一步初等行变换（`bad` 是空的）全部还认得出；四列以上、变了三格以上的一行算错一格，98.7% 照旧认成原来那一步、标出算错的那一格。
    - 代价：两列的矩阵算错一格、三列里一格本来就是 0 的算错一格，只说「看不出」，不再猜。
- **两张都无解、又不是行等价的：不写「同解：否」，写「和 M0 不是行等价的（两个都无解）」。**
  - 为什么：两个都无解的方程组解都是空的，严格说是同解的；说「同解：否」是假话。行等价的照写「同解：是」，别的「同解：否」。
- **只有两张都是方程组（竖线在同一处、右边一列）才说「同解」；别的矩阵说「和 A 行等价：是 / 否」**，还空着时「和 A 是不是行等价还说不了」（复核后控制者定的，修第 1 轮）。
  - 为什么：不是方程组的矩阵没有「解」，说同解是把行等价换了个说法，老师可能当成方程组去讲。
- **M0 后来拿掉了、不是矩阵了、改了大小：写满一行时照说页面比不了**（「M1 是从 M0 化过来的，可舞台上已经没有 M0 了，页面比不了」「M0 现在是 2×3 的，和 M1 不一样大，页面比不了」）。没给场景的旧调用（facts 三个参数）不写。
- **改一格（`write`）现在也过裁判**：`actOf` 认它，`check` 永远是 `{ legal: true, right: null }`，学生的每一下 `act` 多了 `src`、`verdict`（`right` 是 null，现状、[学生] 的字和以前一样）。
  - 代价：`open M edit range=…` 的 ± 拨格子（动作的 `type` 是 `edit`）也带上了 from= 的那一句 `facts`，可 events.js 的 `tryLines` 不写 `edit` 的 `facts`，老师看不到；数字键盘写的（`type` 是 `write`）照常写出来。from= 本来就是配 `input=keypad` 用的，要 ± 拨的也写的话改 events.js（循环），这个任务没碰。
- **扫一遍拨数：能拨到的值照拨数器算**——一下 ±1、碰到两头停在头上，所以是从现在的值、从两头一格一格数过去的那些（整数的范围就是 lo～hi 每个整数）。只扫现状里「能拨的数」那一行有的（`shown`）。
  - 某个值上跟着算的东西（自己或上游）算不出来（`rec.error`：不可逆……），停在上一次算出来的数，那个值写「算不出来」，不拿旧的数说要点；每个值都说不出（矩阵还空着）整行不写。值最多的那一种一样多时取先出现的。
  - 「太多，页面没扫」一个拨数只写一次（不管多少样东西跟着它）。
  - 代价：老师 `set l 0.5` 以后，拨数器拨到的是 0.5、1.5……，扫的也是这些（和学生真能拨到的一样）。
- **学生的括号（`bracketFacts`）**：拆散了的不算进「学生的括号」那一行，只在「拆散的」那一行说；谓语跨着学生括号的边（一半在里面）的不算里面也不算外面，有的时候另说「跨着括号边的 N 个」；没写 key、key 作废了只说拆散的。
  - **key 里没有同一段词的分两种**（复核后控制者定的，修第 1 轮）：key 标过这种成分（`fits` 对得上）的才叫「多拉的：s.1-2 S（The man；key 里没有这一段）」；key 一道这种成分都没标的写「key 里没有的：s.8-9 O（a doctor）」。同一段、成分不对的是标错了，两种都不算。
    - 为什么：key 可以不全（老师只拉了要讲的几段）。key 没标宾语，学生拉的宾语页面不知道对不对，叫「多拉的」等于说学生拉错了。简报原来写的 `多拉的：s.8-9 O（a doctor；key 里没有）` 正是 key 没标 O 的那一句，现在写成「key 里没有的」。
  - **key 一个谓语都没标：「学生的括号」那一行整行不写**（复核后控制者定的）。写「里有 key 的谓语 0 个」字面不假，可读起来像页面数过谓语、数出来是 0。
- **`tally s V`**：成分要认得出（`roleName`）；没写 key、key 作废了写下就报（Task 1 的规矩：以后也数不了的当场报，重放旧课照收）；只能写整句（`tally s.3-6 V` 报错）。`o.tally` 存老师写的字。
- **括号记 `by`**：同一段再标一次（`had`）换成这一回标的人（学生把老师的括号改了成分，就是学生的括号了）。
- **两对模块互相 import**：`matrix.js` ↔ `matrix.rules.js`、`sentence.js` ↔ `sentence.rules.js`（现状要写规则那边算的）。两边都只在函数里用对方的东西，加载的先后不碍事（esbuild 打包、node 直接跑都试过）。
  - 代价：以后谁在模块顶层（不是函数里）用了对方的东西，会拿到还没初始化的值。

## 发给老师的 [学生]、拨数的路、跟着变的（Task 4）

- **题卡一行的部件写那一行的字（截到 20 个字加「…」），不再写「第 k 行」——有意的不同。** `学生点了 f.3（laughing）`；话里的小块 `{f.3}` 也画这几个字。字里的 `{a.1}` 写成 `a.1`、`$x$` 写成 `x`（照画出来的样子去掉记号），`rewrite` 改了字跟着换。
  - 为什么：设计第 4 节。「第 3 行」老师得回头数是哪一句，学生点错了也看不出点的是什么。
  - 代价：照 log 放回的旧课，[学生] 里点题卡的那一句和以前不一样（存档里已经写好的那条学生轮不变，只有刷新以后重新拼的那一段会不一样）；题卡的一行在挑战里拿去比（`q.2 = …`）比的是这几个字，以前比的是「第 k 行」。
- **[学生] 压的五步照简报**，几处简报没写的：
  - 第 3 步并成「接着 N 下」时，并进去的那几下里有留着「正确的是」、事实的（这样东西的最后一下），照样接在这一行后面；第 5 步并成「像是… ×N」时不接（那一行放在这一种第一次出现的地方，接上去先后就乱了）。
  - 第 5 步只并两下以上的同一种错法；下数多的先并，并一种量一次，放得下就停（不一下子全并：能留着细节的就留着）。
  - 并成 ×N 时括号里写这一下指令里的部件（`mark s.8 V` 写 `s.8`、`rotate t#30 right` 写 `t#30`，几个就空格连着）；指令里没有带 `.` / `#` 的部件（`rowop M r3 - 2r1`、`insert t 47`）写命令后面那一截（`M r3 - 2r1`）。
  - 「每样东西只有最后一下留」：哪样东西照这一下的指令（`src`、`line`）认，拨数是那个数、拨格子是那张矩阵；认不出在哪样东西上的各留各的。最后一下按这一下在这一段里的先后算，拨格子的路按它最后一下算。
  - 「之前又试了 N 下（页面判了 R + W 下）」里判对判错只数真判了的：没演上、页面没判成的那一下不算（以前算进去）。撤一步、点开看照旧算在 N 里。
- **拨数、拨格子的路**：
  - 没让做、没演上、页面没判成（`blocked` / `error` / `failed`）、页面判了对错的一下不算路上的一步，单独写一行（以前没演上的一下也接在路上，等于说拨到了那个数）。
  - 路上的数负号写 −（和 `gridText`、舞台上画的一样）。代价：以前拨格子拨到负数写 `-1`，刷新以后重新拼的那一段写 `−1`。
  - 括号里挑战每一句：一个挑战时只写句子（`Dd = O：✗ ✗ ✗ ✓`），几个挑战时前面带挑战名（`g1 Dd = O：…`）；某一下没带这一句的结果写 `?`。
  - 一条路从哪一下开头：`stage.js` 记在 `dialRuns`，老师每一轮开头（`begin`）清掉，和课堂循环攒的那一段对齐（叫老师之前 `finalize`、紧接着 `teach` 就 `begin`）。开头那一下没演上就不算开头，下一下重新开头。
  - 代价：刷新以后接着拨同一格，舞台是新的，刷新后那一下又当开头、照那时还没做到的挑战判；刷新前已经做到的挑战那一句在刷新后几停写 `?`（不说假话，只是少了几个 ✓）。
  - 旧的存档（刷新时放回没发出去的那一段）里回答那一下还带着 `tries`：这一段里有拨数的试，回答那一下就不再写一遍。
  - `stage.js` 不再有 `this.pending`（等着时攒拨数的那一个数组），撤一步也不用再存它。
- **[跟着变的] 按东西写**：
  - 写整张要这张矩阵至少两格变了、而且变了的格 ≥ 一半（只变了一格照旧一格一行，1×1 的也一样）；有一格不是这张矩阵现在的行列里的（`relive` 换了尺寸）也照旧一格一行。
  - 行按东西第一次变的先后排、同一样东西的几行挨着（以前按格子第一次变的先后，几样东西交错着）。
  - 算不出来的那几句一直写、放在后面，不并进「也跟着变了」的名字（只写名字就成了「跟着变了」，是假话），它们先占着 1.5 KB 的地方。
  - 没给 `grids`（旧的调用）照旧一格一行。`tools/stage-try.mjs` 攒着的那一段也照课堂循环给 `grids`（`window.LAStageDev.gridsOf`）。
- **取样**：`tests/fixtures/stage-tries-e2.json` 取的是竖屏那一份（两份一样）。两段真的样本原样、重复三遍都在第 2、3 步就放下了，测试多加了「重复十遍」，让真的错法文字也走一遍第 4、5 步。
- **复核修正（修第 1 轮）**：
  - **页面照 `wrong=block` 拦下、照 `wrong=mark` 圈了的那一下，和错法一样不并进「之前又试了 N 下」**（控制者定的）；同一种（错法连同拦没拦、圈没圈）只并成一行：有错法的 `像是… ×N（部件…）；照你写的 wrong=block 没让做，弹回去了`，没有错法的 `不是正确的下一步 ×N（部件…）；照…`。这个世界做不到、弹回去的（`legal: false`）不算，照旧能并。
    - 为什么：页面替老师拦了、圈了哪几下，老师得知道（只剩「W 下不是」，老师以为学生只是走偏了、画面没动过）。
    - 代价：开了 `wrong=block` / `wrong=mark` 的课，[学生] 里能并的少了，更容易压到第 5 步。
  - **一条路从几拨起要接得上上一下停在哪**（`from` 对不上就另起一条）：中间这个数、这一格被别的动过（页面判了对错、不并进路的一下，或者行变换改了这一格），路上的数是假的。没写 `from` 的（旧的拨数事件）照旧接上。
    - 代价：另起的那一条开头的一下没有 `marks0`（舞台那边还当是同一条路），这一条不写 ✓ ✗。
  - 拨数也要页面没判对错才并进路（和拨格子一样）；不并进路的拨数没有 `src` 时写「学生把 t 从 0 拨到 −1」。没写从几拨起的路，✓ ✗ 也不写「拨之前」那一个（一个停下的值一个符号）。
  - **题卡一行全是空白：`value` / `label` 写「第 k 行」**；**扣着的一行，小块（话里的 `{q.3}`、贴的字、比大小的牌子）写「第 k 行」，不写那一行的字**（`stage.js` 的 `chipTextOf` 看部件的 `coverLabel`，现在只有题卡的行交它）；学生点了扣着的一行，写给老师「学生点了 q.3（第 3 行，扣着）」（`tapValueOf`）。
    - 为什么：扣着的一行常常是答案、提示，小块写了它的字就提前给学生看了。
    - 代价：话里写 `{q.3}` 的那一刻 q.3 还扣着，那一句话里的小块一直是「第 3 行」（话里的小块说的那一刻是多少就是多少，翻开以后不变）；贴的字里的小块翻开以后跟着换成字。别的东西扣着的部件（一排格子扣着的一格）小块照旧写值，这一条没管。

## 句子：拉一条线、照 key 比得更全（Task 5）

- **句子现状里括号写两种名字：`s.2-6 定语（Attr），紫`、`s.1-6 主语（S），第 2 层，蓝`——有意的不同。** 中文在前、缩写在括号里，后面跟第几层、颜色（以前是 `s.1-6 主语（第 2 层，蓝）`）。老师写的缩写也补上中文（`V` → `谓语（V）`，`V1` → `谓语1（V1）`）；本来就是缩写的照老师写的（`Adv` 还是 `Adv`）；认不出的成分（插入语）照写，不加括号。事实（`bracketFacts`、这一下的事实）、括号上画的字照括号上写的，一个名字。

  - 为什么：key 只说了那一段是什么，没说它里面一层是什么。第一版只要求「一类、大半」，复核找到了假话：`[P directing these funds]` 里学生拉 `these funds` 标宾语（正是 directing 的宾语），被说成「成分标错了，范围也差一点」，开着 `wrong=mark / block` 还会圈、拦掉学生对的一步。不从同一个词起头的里层常常正好是一个成分；从同一个词起头、又只差一两个词的多半是学生在拉这一段、尾巴拉错了。成分不是一类的（`[O to pay attention]` 里拉 `to pay` 标非谓语，说的是动词的样子）也不说：控制者的裁定只要求同一个词起头，这一条是我多加的，少说不说错。
  - 量过（`460cca0` 和修完以后，七句带 key 的句子 × 每一段连着的词 × 18 种成分写法 = 5832 下）：null → false 剩 24 下，都是从同一个词起头、成分同一类的：`to direct these`、`to direct these funds`（简报的例子）标宾语、`to pay` 标表语、`a small-scale`、`a small-scale study in (operant)` 标表语、`directing these`、`helping small` 标宾语——拉的都不是一个成分，学生真错了。false → false 227 下只是多了一句像哪种错（以前都没有 misread），没有对↔错翻过来的。复核的两个反例照旧 null（测试钉住）。
  - 代价：整个套在里面、不从同一个词起头的两错（主语贴成宾语、少了开头一个词），和从同一个词起头、成分不是一类的，页面照旧什么都不说（`right` 是 null）。
- **key 的一段写几种（`[Attr/NF …]`）：判哪一种都算对；给老师写成「定语或非谓语」**（「成分标错了：这一段是定语或非谓语，不是主语」）；按钮颜色、`role` 照第一种。数谓语（`verbs(…)`、学生括号里的谓语、`tally`）、「把非谓语当成了谓语」看写了的每一种：`[V/NF …]` 算一个谓语，也算非谓语。同一段写两次（`[Attr …]` 套 `[NF …]` 正好同一段）照旧报错，报错里说「两种都算对写 [Attr/NF …]」。

  - 代价：老师想让「舞台上一道多余的都没有」得自己先收掉自己的。
- **`refer` 指到一段**：`refer s.6 -> s.1-2` 以前是指到 s.2（取最后一个词），现在是指到这一段（`toKeys`）——旧写法意思变了的一处。说明一直只写 `refer s.3 -> s.2`（一个词），旧课里写成一段的应该没有。指到一个词照旧（`toKeys` 是 null，fx、画法、现状一字不差，测试钉住了）。指到的那一段不能含钩上的词自己；要连着（挪开以后不连着了，画面改在词头上写「→ The books …」，不拱一道穿过别的词的线）。

- **老师拉的时候就不连着的括号（`mark s.3 s.5 谓语`，did … realize）记 `apart`，画面不当成拆散的画虚线**；`brokenMarks` 照 Task 3 没动（学生拉的括号永远是连着的一段，事实那边不受影响）。

## 一次点几样 `ask pick`；expect 写整样东西或一段（Task 6）

- **`ask pick` 一次只点一样东西里的**（`ask pick t a "…"` 当场报「一次只点一样东西里的：分成几问」）；`pick` 那一行同样。
  - 为什么：`scene.picked` 照接口是 `{ obj, keys, … }`，圈、和真变了的比（`changedKeys` 比的是一样东西的前后）都按一样东西算。
  - 代价：要学生在两样东西上一起点（A、B 两张矩阵哪几格会变）得分成两问。
- **一个都没点时「猜好了」按不了**（按钮淡着），觉得一个都不是的学生在下面的输入框里写一句。
  - 为什么：交的那一行要是「一个都没点」只能写成 `pick t`，可 `t` 在别的指令里是「整样东西 = 全部部件」，同一个写法两个意思。
  - 代价：「一个都不会变」这种答案走打字（老师收到的是 `学生说：「…」`，页面不和 expect 比）。
- **学生交的那一行用那种东西自己的写法**（`pick t.45 t.40`、`pick a#3 a#5`、`pick s#2`、`pick M.2,1`：`refOf`，跟着部件走），**写给老师的名字照 ask tap 的写法**（有位置的写第几个：`a.3`、`s.2`；`tapRef`）。
  - 为什么：那一行是交给场景的，学生点完到交之间、前面排着的学生的一下还可能挪动位置，跟着部件走的写法不会点错人；老师写 ask、expect 用的是位置写法，回答照它写才对得上。
- **expect 里写一段、整样东西，pick 时是「里面每一个都要点到」**，tap 时是「点到里面哪一个都算」（`expectHit`）。交的那一刻预期的部件不在舞台上了（学生动过）：`same: null`，写「页面比不了（…）」；tap 的 expect 不在了 `right: null`，写「页面比不了」——都不当学生点错。
- **`changed` 的口径：**
  - 树：前后都在、平衡因子 / 父亲 / 哪一边 / 第几层 **/ 值**变了的（`write` 改了值也算变了）。
  - 矩阵：**按位置比**（同一个位置前后的数不一样），交现在在那儿的格。为什么：`rowop M r1 <-> r2` 时格子整个挪走、key 跟着格走，按格比就「都没变」。代价：点着的圈跟着格走（对调两行以后圈在另一行，说的名字也是现在的位置），点了再对调两行时名字和学生点的那一刻不一样——这种问法少见，没另做。
  - 句子：**这一行真挪了的词，加上字变了的；给它让位的不算**（`move s.3 after s.5` 只有 three；挪了却落回原处的不算）。挪了哪几个照这一行指令交的 `fx.moved`（`move`、`rewrite` 都交，画面的动画本来就用它）：`changed(before, after, fx)`，规则接口第三个参数是这一行的 fx，别的东西不看它。
    - 为什么（复核修正）：设计写的是「句子是挪了的词」；第一版按位置算，让位的 four、five 也成了「变了的」，学生只点了挪的那个词，会看到「变了却没点的：four、five」，读起来像那两个词被动过。只有前后两份时分不出哪一段是挪的那一段（`move s.1-5 after s.6` 和 `move s.6 before s.1` 挪完一模一样），所以要指令自己交。
    - 代价：没有这一行 fx 的时候（只拿前后两份比）位置变了不算变了，只算字变了的。
- **变过以后写部件，有位置的带上它现在的字**：`学生先点的 2 个里，这一下以后变了的：s.5（three）；没变的：s.3（four）`（现状里圈着的那一行也是）。挪过以后位置变了，光写 `s.3` 会被读成学生交的时候点的那个 s.3（three）。扣着的写牌子，不漏字。交的那一刻的回答（`学生点了 2 个：s.3、s.4`）位置还没变，照旧不带。
  - 没交 `changed` 的（一排格子、图……）：比部件的值，**有位置的也比位置 `slot`**。为什么：一排格子换位置时值跟着格子走，只比值永远说「没变」，`pickDiff` 永远出不来（静默）。
- **点过的部件这一下没了也算「变了的」**（写成 `t.45（没了）`）；点着的那样东西拿下舞台、同名重造，点着的就不算了（`dropObject` 清 `picked`）。
- **点了还没交就刷新，点的那几个就丢了**：没交之前只是画面上亮的圈，不进 log；刷新以后那一问由页面重新挂上（`resume`，不收已经交了的圈），学生重新点。只有交了的 `pick` 那一行记进 log、刷新照它放回。
  - 为什么：点一下、取消一下都记进 log，log 里就多出一串学生没决定的半截动作，老师也会被告诉一堆不算数的点击。
  - 代价：点到一半刷新要重点。
- **老师那一轮演完自动 `unpick`：只在真是老师的一轮。** `stage.begin({ unpick })` 默认收；`loop.resume`（刷新以后重新挂那一问）、连不上 / 不是指定模型时页面挂的「再试一次」「再要一次」（`stage.play(…, { unpick: false })`）不收。这一轮里才交的（上一问还挂着、老师在演时学生交的）也不收。
  - 为什么：那几种不是老师看过学生点的几样以后的一轮，收掉的话老师真来那一轮演示时圈已经没了、`pickDiff` 也出不来。
- **页面记下的一句（`{ kind: 'note' }`）**：老师的一下改了学生点的几样时，交给课堂的是 `pickDiff` 后面加「（你演的 insert t 47）」——[学生] 一块里「这一下」说的是哪一下要写明。loop 里这件事记 `quiet: true`（不挡提前想：发出去的整条照样带着它，对得上）、带 `turn`：「再看一遍」重演同一行不重复记；那一轮作废（不是指定的模型、调用出错）退回去时，它演的时候记的几句一起去掉（不然告诉老师一个已经退回去的变化）。
- **学生的一下：`pickDiff` 进 `act.facts`，另记一份 `act.pickDiff`。** 拨数连着几下并成一条路时 events.js 只写最后一下的事实，这一句只说一次、落在路的前几下就丢了；`pathRow` 把前几下的 `pickDiff` 留着。[学生] 一块放不下要压时（第 2 步「事实只留每样东西的最后一下」）它照样可能被压掉，没另做。
- **舞台现状多一行 `圈着学生点的：t.45、t.40、t.20（你这一轮演完页面收掉；reveal=on：…）`**：画面上圈着，现状得对得上画面。`在等学生：点几样 t`。
- **`reveal=` 写在别的 ask 上当场报**（「reveal= 只用在 ask pick 上」）；只认 on / off。
- **画法**：点了的、交了的是 3px 实线的圈（`--st-brand`，离部件 6px，`outline`），reveal 以后没变的虚线、淡到 38%。平面上的点、向量是 SVG，`outline` 画不出来：照亮它本来就有的那一圈 `.pl-ring`（`plane.view.js`），虚实一样。
- **证据**：tap 的 `right` 现在可能是 null（预期的不在了，比不了），学习台的证据照 `ask value` 的规矩记 `ok: null`（以前 `!!a.right` 会记成答错、算进掌握）。ask pick 的回答照旧记成一条动作（`stage-pick`，`same` / `extra` / `missing` 都在 detail 里），不记对错：和老师预期的「一样不一样」算不算学生会了，没定，先不进掌握。

## 存档点 `keep` / `back`（Task 7）

- **`keep t "插入后" after=insert` 只登记、当场不存**：学生做完第一次 insert 才存成「插入后」；在那之前 `back t "插入后"` 报「t 没存过「插入后」（存着：…；学生做完一次 insert 才存）」，`open t back="插入后"` 照收、按钮淡着按不了（现状写「还没存，按不了」）。
  - 为什么：设计写的是「以后学生每做完一次 insert，页面替你存」。当场也存一份的话，「插入后」这个名字在学生插之前存的是插之前的样子，按钮一按回到的不是名字说的那一刻。
  - 代价：老师想「先存一份、以后再替我更新」得写两行（`keep t "插入后"` 再 `keep t "插入后" after=insert`）。登记了就没法单独撤掉（只有 `remove t` 一起清）；要的话以后加 `after=off`。
- **after= 认指令名，也认从哪一项 open 来的**（`after=place` 认 `open t place` 交的 `insert t#6 right 47`）；写的不是这样东西的指令、也不是 open 的动作名当场报，报错里列学生能做的（open 的动作名）。登记的名字也算进 6 个。
  - 为什么：老师写的多半是 open 那一行的动作名（place、drag），学生真交出的是指令（insert、swap）。只认一种，另一种就默默不存。所以 stage.js 的 exec 把学生这一下的 open 也交给 `scene.apply`。
- **`back` 也算动了那样东西**：淡淡圈着的（wrong=mark）收掉，和别的指令改了它一样（`restoreSnap` 本身照 key 留着部件上的 `slip`，是场景照「那样东西再变就收掉」的老规矩收的）；学生按的 back 也是「学生最后那一下」——之后老师写 `back t` 回到按之前。
  - 为什么：现状里那一行写着「那样东西再变就收掉」；回去以后还圈着已经不在了的那一下，对老师是假话。
  - 代价：老师想留着那个圈给学生看，得回去以后自己再 glow / paint。
- **「学生最后那一下」只算改了一样东西的行**：落在哪样东西上照 `ownTarget`（rotate、insert、rowop、swap、mark……）和 back；拨数（`set k 3`）、`pick` 不算，跟着拨数变的东西上的 `back t` 照旧报「学生还没动过」（除非学生直接动过它）。没让做（wrong=block）、没演上的不算。
- **回去以后没了的部件：连到它的线剪掉**（连同跟着那道弧的字，和 unlink、删掉结点、照新的数重新造一样）。贴在部件上的字照设计不动（`label n t.47`：47 回去以后没了，字照旧在，画面找不到锚就摆在舞台边上）。
  - 为什么：连线的一头没了画不出来、现状里写成 `t:7` 这种编号；字只是找不到锚，画面本来就会退回去摆。
  - 代价：回去以后又插回 47，那道线不会自己回来。
- **显示的状态不倒回**（F22）：`origin`、`id`、`type`、`hidden`、`colStart`、`ext`、`heights`、`tally`、`bf`，部件上的 `pick`、`slip` 照现在的留着；别的（含 `live` / `unlived`、矩阵的 `stairs`、访问号、托盘、key、links=）都是数据，跟着回去。现在是跟着算的东西 `back` 当场报「是跟着算的，回不去」。
  - 为什么：阶梯线、访问号是跟着那时候的数画的，数回去了它们跟着回去才对得上；`live` 只可能在 `lastBefore` 里（`ask drag` 拖了跟着算的一排格子、它不再跟着算），回到拖之前就是又跟着式子算——那一刻本来就是这样。
- **「跟着算的」**：整样东西用了 `{…}`（`o.live`，矩阵格里有 `{k}` 的也算）或者是乘积（整样跟着 A、B）——`nodesOf` 里有这样东西自己那一个结的。平面上只有几个向量跟着算的照样能存（回去以后跟着算的那几个照常重算）。
- **同名重造不清存档；换了一种东西才清**（`tree t` 重造成 `array t`）：树的样子放不回一排格子上。`back` 里另有一道：存的样子和现在不是一种东西就报。
- **学生按「回到……」是「试」、不算进「试了好多下」**（events.js 的 `eventOf` 记 `patient`，和撤一步一样）：攒着、跟下一条写给老师，不单独叫老师。
  - 为什么：回去几次不该凑出「试了 8 下还没做到」；设计没说按回去要马上叫老师。
  - 代价：老师想学生一按回去就知道，现在做不到（要的话以后给 `open … back=` 加 `call=`）。
- **`open t back="…"` 只写名字**：同一行写别的动作（`open t rotate back=…`）、`wrong=` / `call=` / `undo=` 当场报；写部件（`open t.30 back=…`）报「写整样东西」。学生按的 back 不管有没有 `undo=on` 都撤得了（`scene.undoable`，原来 stage.js 里的判断挪进场景，测试和撤一步同一处）；可「撤一步」按钮照旧只在有一项写了 `undo=on` 时出现。
- **按钮**：右上角「撤一步」那一排，「↺ 回到插入后」排在「撤一步」前面，窄了往下折；44px 高，还没存时淡着按不了；按下去到演完之前两种按钮都按不了（`backBusy`）。字是「回到插入后」（↺ 是 CSS 画的），e2e、试演工具照字找。
- **现状**：`t 存着：插入后、转平后`，有登记的接 `；学生每做完一次 insert 页面存成「插入后」`，一样东西一行，跟在「学生能直接动的」后面；`lastBefore` 不写（学生动过的每样东西都有，写出来太多）。
- **（复核修正，控制者裁定）做到过、现在不成立的挑战照实写**：`g.met` 照旧是粘的（预写的行已经演了、也告诉了老师，撤不回来；又做到时不再庆祝、不再演预写的），可 `goalStatus` 写给老师的那一句照现在的样子：做到过、现在有一句不成立写「做到过；现在不成立（t height 4 ✗）」，现在判不了写「做到过；现在判不了（…）」，都成立才写「做到了」。
  - 为什么：back 以后老师读到「做到了」、看到的却是没做到的树，是假话。
  - 有意的不同：不只 back——学生做到以后接着拨走了的旧课，放回来那一行也从「做到了」变成「做到过；现在不成立」（`tests/stage-class.test.js` 旧 log 的 matrix 那一课：做到 g2 以后 C 不再是 O）。学生那边的挑战条照旧打勾（做到过）。
- **（复核修正）同名重造清掉「学生最后那一下之前」**（`lastBefore`）；`keeps`、`autoKeep` 照旧留着。
  - 为什么：学生插了 47、老师重造 `tree t = 1 2 3`，一句 `back t` 会回到重造之前的树，把老师的重造悄悄抹掉。
- **（复核修正）`keep t "名字" after=off`**：不再替老师存这个名字；已经存下的照留着，`back t "名字"` 照样回得去。这个名字没写过 after= 时当场报「t 的「名字」没写过 after=，用不着 off」（列出页面在替它存的）。写在 `after=` 上是因为停的正是那一行登记的；不另加指令。

## 预写、挑战和叫老师（Task 8）

- **预写的行只在学生的一下演（`by === 'student'`，或裁判说是学生的一下）**：老师的行、舞台演预写的行（带 lenient、prewrite）、不给 by 的（检查一行、dryRun、测试里直接 `apply`）一律照老师的行办——挑战成立、东西做完时预写的行拿掉不演，交 `fx.unplayed`，舞台跟着下一条告诉老师「你这一轮让挑战 g1 成立了，@g1 的行没演」。刷新重放带 `replay: true`：照样拿掉、不说（当时演了的行在 log 里）。

- **收集型 `collect=B n=3`**：只收学生的一下；老师的一下只记下「看到了」（不替学生收，也不让学生动别的时把老师那一张算进去）。比的是「上一次看到的」：B 没变就不算又做到一次。写下时现在就成立照旧报（老师先把 B 换成不成立的样子）。n 写 1～12 的整数，collect 和 on 不能写在一个挑战上（收集型每做到一次就收一张）。收齐那一下 @g1 的行拿走（之后不再演），没收齐时每收一张都演（只看不拿）。左上角挑战条后面带「（2 / 3）」，学生看得到还差几张。
  - 代价：学生按「回到……」回到一张没收过的、成立的样子，也算学生找到的一张。
- **学生手上还有什么事（`hasWork`）**：挂着的 tap / pick / drag / value / say、没做到的挑战（连 on= 的）、交给了学生还没做完的东西——只算规则算得出下一步（`next` 给得出动作）的；页面判不了的（没写 key 的句子永远等不到做完）不挡着，不然永远不叫老师。

## 同一处的三种按法、✕、摘叶子 / 删、拖一段、套着折（Task 9）

- **画面还没做的先不对老师说学生能做（`ARMED_GRIPS`、`ARMED_PRESS`）**：照 Task 5 的 `ARMED_GESTURES` 再加两个开关。`ARMED_GRIPS` 是画法现在交得出的把手（树的 node / parent / tray / tree / slot，矩阵的 row / label / cell，句子的 word / bracket）；一种手势的起点、落点都交得出才算挂得上（`kindArmed`），所以 `open s move`（落在 gap 上）在 Task 11 以前写在「开着、页面还画不了的」，`open s.6 refer` 要 line 和 hook 都有了才算。`ARMED_PRESS.mixed` 是画面分不分得清同一处的几种按法（choosePress 接进 pointer.js 以后 Task 11 改成 true），分不清时合成的那一行后面带「（页面还分不清同一处的几种按法：学生在同一处只按得出其中一种）」。`gesturedom.js` 也照 `kindArmed` 只挂挂得上的那几种（不然 `open s move` 把词拎得起来放不下，还抢了 mark 的手指）。
  - 为什么：一种手势开得了（不报错）以后，现状不能说学生能做画面还做不了的事。
  - 代价：Task 11 要把 hook、gap、pill、xmark、xrefer、sentence 加进 `ARMED_GRIPS`、line 加进 `ARMED_GESTURES`、`ARMED_PRESS.mixed` 改成 true；Task 10 的整张把手 whole 同样要加。Task 5 那条「画面做好了」的测试多加一个 hook。
- **按法冲突照「地方 + 按法」比**：两项都在同一处（部件照旧叫 part，写的部件要重叠）、按法也一样才报，报错改成「…也要在同样的部件上按住再拖：两项都是按住再拖，学生只做得了先开的那一种；先 close t drag 再 open t rotate（同一处按法不一样的才能一起开：点、滑、按住再拖）」，不再说「一次开一种」。不走手势表的照 `AFFORD_PRESS`：drag 按住再拖、edit / explain 点（每种东西能开的 affords 都要在里面，测试守着；万一漏了按住再拖算）。
- **现状里合成一行**：只在一样东西真有「同一处按法不一样」的两项时合成，（复核修正）自己一行、跟在「学生能直接动的：」那一行后面：`s 开着：mark（滑）、fold（点）、move（按住再拖）`（开着就是学生能直接动的；以前放在「学生能直接动的：」里，一行两个冒号）。每一项只写按法（不再写「拉一段」「拖到空处」），后面照旧带范围、`wrong=` / `undo=`，写了部件的写部件，「回到……」按钮那一项照它原来的写法。同一处只有一种按法的照旧一项一项写在「学生能直接动的：」里，旧课的现状一字不变。

## 树按中序排、角标分开、旋转时描出换父亲的那棵子树（Task 12）

- **（控制者裁定，改了设计的「堆也是」）排法造的时候定下，两种**（`o.layout`）：造的那一刻是二叉排序树（中序递增，空树、一个结点也算）的按中序排，别的（堆、表达式树、遍历用的字母树……）照旧紧凑排（第一轮的按子树宽度、左右对称、根在 origin）；老师写 `layout=inorder` / `layout=compact` 自己定，别的值当场报「layout= 只能写 inorder（照中序一个结点一列）或 compact（紧凑、左右对称），没有「…」」。造好以后不换：换值、插、删、转、跟着算的重新造都不重排（`back` 也不倒回它，`layout` 进了 AS_IS）；同名重造不写 `layout=` 照旧（和 `hide=` 一样），写了照写的（换了排法时照原来那一棵的左边对齐，还在原处）。
  - 为什么：一个结点一列只在中序有意思的树上值得——插入只挪右边、旋转只上下移；堆按中序排宽一倍，15 个结点的堆竖屏从约 1.06 倍缩到约 0.58 倍，旧课的堆还会变样。
  - 代价：堆、表达式树看不出中序（不按列排）；一个结点造的堆（`tree h = 10` 再 append）是二叉排序树、会按中序排，要紧凑写 `layout=compact`；同名重造把堆换成二叉排序树不写 `layout=inorder` 照旧紧凑。
- **按中序排：横坐标是中序名次 × 86（`COL = SEP`），纵坐标是层 × 92；`o.origin` 是第一列、根那一层的中心**，造的时候照 `slotFor` 摆好（整棵树居中在已有东西下面），以后不动：插入只挪新结点右边的（插一个最小的，它占第一列、别的整体右移一列），删掉的右边回一列，旋转不改中序、只上下移。紧凑排的照旧：origin 是根，旋转沿弧转过去。
  - 为什么：学生盯着的结点不左右乱跑；黑板 `engines/treeview.js` 本来就这么排。
  - 代价：旧课里二叉排序树的截图样子变了。**宽度**：一个结点一列比按子树宽度排宽——15 个结点的二叉排序树竖屏镜头约 0.58 倍，结点在屏幕上约 32 像素（手指检查量过：按在中心偏 21 像素、44 见方的角上照样拎得起来，pointer.js 按偏 30 以内挑近的）；超过 25 个结点时竖屏（820 宽）镜头到了最小的 0.35 倍还放不下，两边各切掉几列，舞台现状照旧写「画面上看不全」。横屏 31 个都放得下。没有为树把镜头的下限压低：0.29 倍时结点 16 像素、字 7 像素，看不清也点不准，不如切掉一点、告诉老师。
- **角标的位置**（`cornerRect`，画面的 CSS 照它的数写）：老师写的 `tag` 左上、`bf t` 的平衡因子右上、`heights t` 的子树高右下（小方角，和平衡因子的胶囊分得开）、访问号照旧正下方。以前 tag 和平衡因子挤一个角（写了 tag 就看不见平衡因子），现在一起开着各在各的角。
  - **上面两个浮在结点正上方两侧**（下沿离圆顶 6 像素，中间留 4 像素的缝），不贴在圆的斜角上：照中序排，父结点在左上或右上隔一列到好几列，进来的树枝从 47° 到很平，贴在斜角上一定压着它（左孩子的右上、右孩子的左上）；提到正上方两侧，隔几列的树枝都碰不到（测试量了隔 1、2、3、5 列）。为此树上面让出来的地方 `TAG_TOP` 30（以前 18），树占的地方高出 12 像素。
  - **右下那个会压着右孩子的树枝开头**（右孩子隔一列时）：右下要让开正下方的访问号，躲不开所有角度的树枝；小方角有底色，盖在树枝上读得出来。代价：右孩子那根树枝起头一小段被它盖着。
  - 紧凑排的树也用同一套角标位置：它的叶子离父亲只有半个间距，进来的树枝陡（约 65°），上面两个里有一个会压着进来的树枝（左孩子的右上、右孩子的左上），胶囊有底色盖在上面；以前单个角标翻到外侧躲开，现在角固定了躲不开。
  - 挨着的结点不碰（按中序排）：同一层的两个结点中间至少隔一列（中序挨着的两个一个是另一个的祖先，不在同一层），挨着的两列差一层，测试量过角标碰不到邻居。8 个字的长 tag 往左长出 100 多像素时照旧可能压到左边的树枝。
- **旋转的动画**：按中序排的结点直上直下（以前沿弧转；紧凑排的照旧沿弧），转上来的往上、转下去的往下。换了父亲的那棵子树（`movedSubtree`；rotate 的每一步多一项 `moved`）按中序排时**自己不挪**——它的列不变、层也不变，是新父亲转下来接住它；紧凑排时它跟着挪，橙圈跟着滑过去。画面：先在它外面描一道橙色的圈（`--st-g6`，子树占着连着的几列、下面几层，框里没有别的结点）、原来连着它的树枝染橙；结点上下移、树枝换到新父亲上（新的那根也染橙）；接上以后整棵闪两下（0.9 秒，减弱动画时不闪），圈淡掉。双旋两下各描各的。圈是这棵树的 decor（中途清舞台、拿掉树时跟着收），只是画面后果，场景里什么都不记、现状不写。
  - 代价：没有「整棵沿弧转过去」的感觉了；旋转的方向靠两个结点一上一下和橙色那一棵换到另一边的父亲下面看出来。
- **`movedSubtree(before, after)`**：换了父亲的结点里，去掉「原来 a 是 b 的父亲、现在 b 是 a 的父亲」那一对，剩下正好一个就是它，否则 null（没有中间那棵子树、或者 before → after 不是一次旋转）。
- **按中序排的托盘正中对着整棵树的正中**（以前对着根：根不在正中了，对着根会偏到一边）。插进一个、树长宽了，托盘跟着滑一点。紧凑排的照旧对着根。
- **按中序排的空位（open t place）画在半列的地方、下一层**（紧凑排的照旧）：放进去的结点会落在它和中序的邻居中间。那里上下挨着的两列都不在这一层，不压别的结点。（以前就有、这次没动的：最下面一层叶子的空位和托盘在同一个高度，拖的时候空位画在托盘上面；托盘的位置要往下挪一层，留给以后。）
- **贴字让开的树枝按长短取点**（`tree.obstacles`，以前每根取 3 点）：照中序排，靠近根的树枝常横跨好几列（两三百像素），3 点中间隔五六十像素，字会落在两点中间压着树枝；现在隔不到 36 像素一点。
  - 试演（`tools/stage-try.mjs`）的「压着：obj:t 和 label:…」在旧的树课里变多了（try/D4 第 5、7 幕的 `cnt`、try2/D2 分支 1 的 `q1`）：量法把一根斜的树枝算成它的外框，横跨几列的树枝外框很大，贴在结点旁边的字落进这个三角形的空白里就算「压着」。逐个看过（页面里沿线取点）：字和树枝本身都不碰，截图上也不压。Task 17 回归时算作预期的不同；要量准得改 `tools/stage-measure.mjs` 对 `<line>` 的量法，没在这个任务里动。

## 判答案：按格的含 n 矩阵、省乘号、五条现算的常见错答、数集的大括号、重放旧课照字面（Task 13）

- **一格对不上写哪一组 n**：挑 n（几个变量时每个）都 ≥ 2、学生那一格算得出来的第一组（`第 1 行第 3 格不对：学生写 n²/2，代 n = 2 是 2，该是 1`）；没有这样的再退到算得出来的、再退到第一组（算不出来写「代 n = 2 算不出来（…）」）。值是整数、有限小数照写（4.5），别的写分数，负号写 −；学生写的照原样，只把 `^2`、`^(-1)` 写成上标。
  - 为什么：n = 1 时很多式子碰巧都是 0、1，两边一样或者看不出差在哪；`formula.js` 的 `compareFormula` 第一组也是挑 n > 1。
  - 代价：设计里的例子是「代 n = 3」，页面给的通常是 n = 2。
- **哪一格不对只告诉老师**：学生那边整块判对或不对（和一个输入框一样，不标红哪一格）。页面不替老师指错（标出那一格就是一句提示）。代价：学生要自己找是哪一格。
- **还空着、读不懂的格**：按格的式子框在页面上就挡住，不交、不算答错，在整块下面写「第 2 行第 2 列：还没写式子」（每格下面的预览也写着为什么读不懂）。从一行字交来的（试演工具、以后别的地方）照第一轮数字矩阵读不懂的样子：判不对，告诉老师「第 1 行第 2 格页面读不懂（…）」。
  - 代价：一行字交来、读不懂的那一格算答错（ok 是 false，不是 null）；画面上交不出这种。
- **`formulaRows` 的 /**：括号外面两边空着的 / 分行，两边都贴着的是除；只贴着一边的（`n(n-1)/ 2`）也分行，和造矩阵、数字矩阵答案同一套。`;`、换行也分行，逗号也隔格。
  - 代价：学生在一行字里写 `n(n-1) /2` 会被切成两行，大小对不上（页面告诉老师「学生写的是 …×… 的」）；按格的框里一格就是一格，不受影响。
- **按格交的写成一行字（`gridAnswerText`）时一格里的空格**：运算符、括号两边的去掉；两个字母数字中间的是省掉的乘号，写成 ·（`2 n` → `2·n`；函数名后面直接贴上，`tr A` → `trA`）；括号外面还有逗号的整格括起来；空格子写 `_`。这样写成一行字以后还是一格，`formulaRows` 读回来一样（没有空格的格一字不差）。
  - 代价：写给老师的字和学生敲的不完全一样（`2 n` 写成 `2·n`），意思一样。
- **type=formula 的 answer=**：先照学生的读法（`normalizeFormula`：2n、n(n-1)/2 都认）读；读不了、黑板原来的读法（`formulaSpec`）读得了的照旧收，以前收下的写法意思不变。报错换成舞台的说法（`free=`、`answer=`，不说黑板的 `formula:`、「在 let 里给出」）。以前 `answer=n(n-1)/2` 把 `n(…)` 当成函数，写下就报「算不出来」。
- **[[…]] 不写 free= 时**照旧按格比数（`free=-`）；按格的式子框只在写了 `free=` 时画，[[…]] 照旧认、不写进说明。
- **按格的框最大 4×4**：再大的照旧一个输入框写一行字（`formulaRows` 读，逐格判一样）。一格一个框在 iPad 上摆不下。
- **页面现算的常见错答认的写法**：`{X Y}` / `{X*Y}`（X、Y 都是矩阵；X 是数或拨数时是 `{k X}`）、`{3 A}` / `{3A}` / `{(-1/2) A}`、`{X^k}` / `{X²}`（k ≥ 2）、`{X^-1}` / `{X⁻¹}` / `{inv(X)}`、`{X'}` / `{Xᵀ}` / `{T(X)}`。`{X^T}` 本来就算不出来（T 不是舞台上的名字），不认。两条现算出来一样（只有一行时只乘第一行 = 只乘一格）留前面那条。不和答案比格数（`{C'}` 没转置的那张大小就不一样）。错答写成「1 2 / 3 4」照 type 造判法，和老师的 wrong= 一样比；老师的先比。
  - 代价：`{-A}`、`{A B C}`、`{2 A + B}` 这类不认，靠老师写 wrong=。
- **type=set 学生只写几个数、逗号隔开（`1, 5`）**：当成 `{1, 5}`。数集的写法里逗号是「且」，`1, 5` 原来读成「是 1 又是 5」（空集），对的也判错。光秃秃的几个数用「且」连没有意思，不影响不等式里的逗号（`x > 1, x < 3`）。
- **重放旧课照字面只给重放旧课的那一问**（`lenient` 且不是预写的行，`waiting.lenient`）：`{…}` 算不出来照字面比，照 type 造不出判法的也不报、判的时候按字比。预写的行舞台演的时候也带 lenient，可它写下时照新规矩验过：判的时候算不出来是学生把舞台拨成了算不了的样子，照旧「页面没判成」（照字面比会把对的判错）。
  - 代价：刷新以后课堂循环重新挂最后那一问（`loop.resume`）是照新规矩挂的；旧课最后那一问是字面写的 `answer={…}` 时照旧挂不上、页面替它挂 `ask say`（课堂循环不在这个任务，没改）。
  - **有意的不同**（Task 17 算预期的）：旧课里字面写了 `answer={…}`、刷新重放时那一问的话以前因为报错没写在上面，现在写上了。
- **写式子的符号小键盘**（`formulainput.js` 的那一块，整页共用、挂在 body 上，黑板也用它）：有舞台的页面照舞台的样子重画（`body:has(.st-stage)`：白卡、细线、南大紫的「完成」，键至少 46 像素）。开着时底下那一条量它压着舞台多少、让到它上面，镜头跟着让；离开焦点 0.4 秒后才落回去（按「对吗」那一下小键盘先收起，这一条要是马上落下去，手指抬起来时按钮已经不在手指下面）。写成公式的预览只在正在写的那一格下面（读不懂的格一直写着为什么）：3×3 九个预览摞起来，横屏时连同小键盘把舞台挤没了。Apple Pencil 点进来照旧用系统的随手写，不弹小键盘。
  - 代价：别的格看不到写成公式的样子，点进去才看得到；横屏 3×3 加小键盘时舞台上的东西缩得比较小。

## 第三次量缺口尺子找到的（修 A 批，控制者裁定的八条）

- **连着拨同一个拨数、同一格算一下「试」**（`events.js` 的 `tryCount`）：上一下也是这一条路（同一个拨数、同一格，`pathKey` 一样、从几拨起接得上，`pathGoesOn`），中间没有别的一下（连撤一步、按「回到……」都算别的），这一下不再数。和写给老师的「一条路」是同一套规矩。
  - 为什么：拨数 0 拨到 8 要按 8 下 ›，以前算 8 下「试」，叫老师「试了 8 下还没做到」，是假话（第一轮就这样，第二轮回归报告「还开着的」第一条）。
  - 代价：页面判了对错的那一下（以后拨数也过裁判时）不并进路，照旧单算；两格来回换着拨每换一格算一下。旧课叫老师的时刻会变（少了「试了好多下」那几次），记进 `global.md`。
- **键盘填的空格子写满算做完了**（`scene.js` 的 `fillOpen` / `checkDone`）：`open M edit input=keypad`、M 里有 `_`，最后一格填上算这一样做完了（和 doneBy 一样从没做完变成做完才算，open 那一刻就没空格子的不算），交 `fx.done`、`fx.filled`；课堂照「学生手上没事了才叫」：挂着的「写好了点下面」当按了、叫老师；还挂着一问、还有挑战没做到照旧攒着。还空着时算学生手上的事（`undoneOf`：「M1 还没做完」）。写给老师「学生把 M1 的空格子都写满了（页面不判写得对不对）」。
  - 为什么：以前写满了页面不知道，老师要马上接只能等 45 秒没动。只在键盘开着时算：± 拨数器是拨，不是填。
  - 代价：`@M.done` 不收键盘填的（只给规则判得了做完的 rowop），填满了没有预写；挑战还没做到（写错了）照 6.2 攒着，老师要马上知道得自己写 `ask next "写好了点下面"`。
- **reveal=on 还没揭晓时圈不收**（`stage.js` 的 `end`）：老师一轮演完页面替它写的 `unpick`，在学生点的几样 `reveal=on`、还没被第一下改过时不写；揭晓以后再下一轮演完才收。不写就没有那一行，刷新照 log 放回一样。现状那一行写「揭晓以前页面不收，不要了写 unpick t」。
  - 为什么：猜错是「答了」、当场叫老师，老师那一轮演完圈就没了，学生插进去以后看不到哪几个变了——猜错那一种最需要虚实（D2/幕1）。
  - 代价：学生一直不动它，圈一直在；老师换了话题要自己写 `unpick`（现状里写着）。
- **按格写的通解按集合判**（`answer.js` 的 `affineOf` / `affineJudge`）：`type=matrix free=…`、答案是一列或一行（至少两格）、每格是 free= 变量的一次式时，逐格比不上再按仿射集合比：方向张成的一样、学生的点在答案上就对。学生换了参数名（t）照单个字母再读一遍；学生写的不是一次式（k²、1/k）、读不懂：`ok: null`、「页面判不了：…」，不判错（`undecided`，不进出错记录）。判错时说为什么：维数不一样、方向不对、方向对点不在上面。方阵（Aⁿ）、不是一次式的一列照旧逐格比。
  - 为什么：换了参数、换了特解的同一条线以前判成错（对的判成错是假话）；Aⁿ 那种 n 是有意思的，换了就是错的，所以只放宽到「一列 / 一行的一次式」。
  - 量的报告里那一下（L2/幕6 第 66 行学生打的「2-4k / -k / 1-k」）其实不在 L 上：(2, 0, 1) + k(−4, 1, −1) 展开是「2-4k / k / 1-k」（第 2 格是 +k），量的助手展开错了一个号。测试里两种都有：「2-4k / k / 1-k」判对，「2-4k / -k / 1-k」照旧判错，写给老师的是「方向不对：学生的方向 (−4, −1, −1) 不在答案的方向 (4, −1, 1) 那条线里」（以前是「第 1 行第 1 格不对」）。
  - 代价：一列的、是 n 的一次式的「函数」答案（Aⁿv = (n, 1)）也按集合判，学生写 (2n, 1) 会判对；这种题要逐格判得写成方阵或别的式子。
- **wrong= 能列一个数的错答**（`answer.js` 的 `numberWrong`）：矩阵、方程的答案，wrong= 里一条是一个数（「0=写成数字 0」「3=只写了数」），照矩阵 / 方程的读法造不出来或大小对不上时，按「学生写的就是这一个数」对。别的写错的矩阵错答照旧当场报（`;` 把一条切成了两条）。
  - 为什么：第一轮能写，Task 13 加了「错答要和答案一样大」把它也挡掉了（L1/分支 2）。
  - 代价：`wrong="1; 2=…"` 这种想写一列的、被 `;` 切开的两条一个数，现在照两条一个数的错答收下、不报。
- **空格子上能挂跟着算的**（`value.js` 的 `evalHoles`，`matrix.js` 的 `cellLive` / `wholeRows` / `relive`）：`{A D}`、`{coef(M) Eta - rhs(M)}`、格里的 `{P.1,1 + 1}` 用到的有空格子时，空格子换成三组不一样的数各算一遍，三组都一样的格照写，跟着空格子变的格空着（画「?」），量、判断式照空格子的规矩判不了；空格子填上了跟着重算。不是因为空格子算不出来的（维数对不上、没有这样东西、不可逆）照旧当场报原来的错。现状「还空着」那一行后面写「（跟着算的：用到的还有空格子，填上了跟着算出来）」。
  - 为什么：以前一算就报「还空着」整行不演，说明写的是「填满以前判断式、量都判不了」，老师只好退回写 0（L1 第 1、7 幕，L2 第 6 幕）。
  - 代价：三组数凑巧都一样、其实跟着空格子变的格会照写成试算的数（三组是不一样的大分数，几乎碰不上）；收集用的矩阵空着（1×1）时大小对不上，跟着它算的照旧停在上一次的数（现状写「现在算不出来」）。
- **@ask.right 跟着写在预写里的那一问**（`scene.js` 的 `bindPlan` / `bindRight` / `pull`，`stage.js` 的 `react`）：这一轮写了 `@ask.right`、还没被一问拿走，接着写的预写行（`@g1`、`@t.done`、`@t.right`、还没出的 `@g2`）是一问、页面判得了对错：@ask.right 跟着这一问（`scene.preRight`，进 `clone()`）；那一组预写演出来、这一问挂上时拿走（舞台交 `preRight`），学生答对才演。跟着以后比那一组深一层，里面套着的跟着深一层，超过三层当场报（还没改任何东西）。那一组拿掉（老师的行让挑战成立、ungoal、东西拿掉）、那一问演不上：整组拿掉；那一问挂上以后照 Task 8 的规矩（答错、被换掉……整组拿掉）。现状写「g1 做到时出的那一问，学生答对时页面马上演你预写的 N 行」。
  - 为什么：E3/幕3 写在 `@g1` 里的那一问没法预写「答对了」，这一轮演完报「@ask.right 要跟着一个页面判得了对错的 ask」丢掉。跟着「下一个 ask」走：写在前面、紧接着的那一问在预写里就跟它。
  - 代价：`@ask.right` 后面先写了 `@g1` 的一问、又写了这一轮直接的一问，直接的那一问拿不到（跟了先写的）；判不了对错的预写一问（ask next）不跟，照旧报。
- **@t.done 写在已经平了的树上**（规则新加可选的 `reopen`，树交了）：现在就做完了，可学生开着的动作还能把它改回没做完——树开着删、摘（delete / pluck），或者开着插、托盘里还有没插的数——照收，学生删了再修平时演；现状写「（现在就是做完的样子：学生动了它、又做完时才演）」。改不回去的（只开了转、托盘空着；已经是阶梯形的矩阵）照旧报。
  - 为什么：D2/分支 3「删完再修平」预写不了，只能拿结点数当挑战。
  - 代价：别的东西（矩阵）没交 reopen，照旧报；学生转一下把平的树转歪再转回来不算「改得回去」（转是 doneBy 的动作本身，这种绕路不该触发预写）。

## 第三次量缺口尺子找到的（修 B 批，控制者裁定的六条）

- **同名重造的乘积翻在原来那一排上**（`matrix.js` 的 `makeProduct` 带 `old`，`scene.js` 照 `sameRow` 留着先后）：`product P = B A` 重造一个排成一排的乘积（不是另起一行「BA =」的），新的一排从原来那一排的左边起、上下照原来那一排居中：两个因子换槽、乘积留在原处；乘积在 `objects` 里的先后不变（因子大小不一样、乘积挪了一点也不变）。排版检查（`stage-measure.mjs`）多一项「乘积那一排散了」：排成一排的乘积，两个因子和「= P」不在一排上、不是从左往右就报；内置的一批多一段「同名重造乘积:AB 翻成 BA」。
  - 为什么：以前照新的第一个因子原来的地方重新居中（整排往右挪了半排），乘积又按 Task 2 的规矩（换了地方）排到最后，reflow 把「= P」推到后造的 AC、AD、题卡下面，那一排散了（L1 第 1 幕）。Task 2 的「同名重造留在原处」照旧：乘积这样摆就是留在原处。旧的另起一行（因子已经排在别的乘积里）照旧。
  - 代价：老师想让重造的乘积换个地方（照新的第一个因子重新居中）做不到，要换个名字；旧课里同名重造过乘积的（try/L1/幕7 的 `product A2 = A A`）放回时那一排不再往左挪半排，现状里 A2 的先后跟着变（记进 `global.md`）。
- **藏着造的东西不出场**（`stage.js` 的 `choreoOf`）：`hide=on` 造的东西不画，也不走出场动画（以前句子的出场找画好的词，报「画面没演好：…reading '__box'」，句子照样藏住了）。藏着的不占地方照 Task 16 的规矩（`slotFor`、`reflow` 不算它），镜头只框看得见的。
  - 代价：没有。
- **事实里带括号的词括号配成对**（`sentence.js` 的 `phraseOf`）：一段词照原句写时，段头的开括号、段尾的关括号，段里有和它配对的（或者头尾正好一对）就带上：「(that) they would learn …」「productivity. (that)」「(that)」；开引号、尾巴上的逗号句号照旧不带。
  - 为什么：以前段头的 lead 一律不带，「(that)」挪到句首以后引成「that) they would learn …」（E2 第 5 幕，第二次量就有）。所有写给老师的一段词（学生的括号、key 里的段、错法、收掉的括号）都走 `phraseOf`；一个词的写法（`w.value`）不带括号，本来就配得上。
  - 代价：方括号、花括号一样处理；引号不管（弯引号和撇号分不清）。
- **往空位上摆不按托盘的先后判**（`tree.rules.js` 的 `checkInsert`，裁判把学生这一下从哪一项 open 来的交给规则：`check(o, act, scene, { by, open })`）：从 `open t place` 来的一下只看摆完还是不是二叉排序树（落的位置是不是从根比下去该落的地方），不按托盘的先后、不管转没转平；对了就是正确的下一步，不圈。拖进树（`open t insert`）照旧按托盘的先后（第一轮的规矩）。挑战（`w avl`、`count(w) = 6`）照老师写的判。
  - 为什么：摆调完的树时 34 当根是对的，以前照托盘的先后说「该先插 15」、淡淡圈了 34（D2 第 5 幕）——把对的圈红是假话。
  - 代价：摆的时候页面不再提醒「还没转平」（开着 rotate 也一样），摆出来平不平只看老师写的挑战；老师自己写的 `insert t.70 left 65`（不是从 place 来的）照旧按托盘先后核。
- **摘叶子、删结点写删了哪个、删完的样子**（`tree.rules.js` 的 `checkDelete` / `deleteFacts`，`actOf` 认 `delete`）：学生 `delete` 这一下过裁判但不判对错（`right: null`），写给老师「学生摘了叶子 12」「学生删了 30（只有一个孩子：40 顶上来）」「学生删了 20（两个孩子：中序后继 40 的值顶上来）」，后面是事实：删完失衡了写「删完失衡：最小不平衡子树的根是 …（+2），LL 型」，再写「现在 N 个结点、M 层」。只看形状的树（值都是 ·）写「·（#7）」。
  - 为什么：以前只有光秃秃的「学生 delete s#7」，摘到根红了（+2）没写（D2 第 6 幕、分支 3）。
  - 代价：`open t pluck` / `open t delete` 照旧不收 `wrong=` / `call=`（页面不判对错）；老师自己删的一下不写事实（老师的一下只在走偏时核）。
- **轮流拨的几条路并成一条照先后的路**（`events.js` 的 `interleaved` / `multiRow`）：同一张矩阵的几格、几个拨数，一条路还没拨完另一条就插进来了（先后交错），这几条按先后并成一行：「学生拨了 B 的几格：B.1,1 1 → 2 → 3，B.1,2 0 → 1，B.1,1 3 → 2（拨到 B.1,1 = 2 时做到了 g1；Df = O：✗ ✗ ✗ ✗ ✓）」「学生拨了 t、s：t 1 → 0 → −1，s 1 → 0，t −1 → 0（停在 t = 0、s = 0；…）」。一段是同一条路上连着的几下；✓ ✗ 照先后一停一个。一格拨完再拨另一格（不交错）的照旧一格一行；不同的几张矩阵不并；数「试」照旧；3 KiB 的压法照旧（并成的一行算一条路）。
  - 为什么：L1 第 3、4 幕 B 的四格各一行、t 和 s 各一行，哪一停时别的格是几、那一刻的合计是多少拼不出来。照控制者的裁定「同一样东西的几格」，几个拨数算一样（拨数器那一排），第 3 幕要的就是 t、s 的先后。
  - 代价：交错拨了很多格时一行很长（照旧受 3 KiB 管着压）；中间被别的动过、另起的一段在并成的一行里另起一段，从它真正的起点写。
