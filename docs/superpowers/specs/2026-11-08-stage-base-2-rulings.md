# 舞台的底座第二轮：做的时候我自己定的事

2026-11-08。照第一轮的样子：做的时候碰到计划没写清、或者计划和设计对不上的地方，我自己定了。每一条写：定了什么、为什么、定错了要付什么代价。觉得哪条不对，告诉我，改起来都不大。

## 量（Task 1）

- **`{…}` 里 `det`、`rank` 照旧交给 exact.js；只有 `rankA`、`free`、`count`、`height`、`tray`、`verbs`、`left` 换成页面数的量。** 挑战（`when=`）里照旧都是量。
  - 规矩（`value.js` 的 `evalLive`、`script.js` 的 `parseRich` 同一条）：写成「名字(东西或部件)」、名字不是 exact.js 本来就认得的函数（`det`、`rank`、`inv`、算法函数、`sin` 这些，exact.js 新导出 `isExactFunc`）才当量。
  - 为什么：旧课里的 `{det(A)}` 一字不变；矩阵写满时两边算出来一样。
  - 代价：`{rank(M)}` 在 M 还有空格时报的是 exact.js 的错（「M.1,1 还空着」），答案照样写「页面没判成」，不是「判不了」；话里的 `{det(A)}` 照旧原样写出来，不画成数。
- **话、贴的字、挑战的字、题卡里的 `{count(t)}`：写下时查量名和括号里的东西。**
  - 哪些地方查：`say`、`label`、`ask`、`goal`、`card`、`addline`，还有改字的 `retext`、题卡的 `rewrite`。
  - 现在还空着的照收，画「?」；以后也数不了的当场报（见下面「以后也数不了」那一条）。
  - 重放旧课（`lenient`）不查量。`retext`、`rewrite` 以前不查 `{a.3}`，重放时照旧不查，新写的查。
  - 画的时候（`rules.js` 的 `measureShown`）：数不了画「?」。不是量的照原样写字，和以前当成拨数原样写出来一样：东西不在舞台上、名字不是这样东西的量，比如旧课重放进来的 `{f( x )}` 连空格都不变。
  - 为什么：`parseRich` 看不到舞台，只能照写法认。名字写错（`{size(t)}`）不当场说，学生看到的就是一个「?」，老师不知道为什么。旧课里 `{f(x)}` 以前是原样写出来的字，当时收下的照样收下、照样那样画；「?」只表示「页面数不了」。
  - 代价：
    - 旧课里要是写过 `{count(t)}` 这样的字（以前原样写出来），重放时画成数。
    - 贴的字里的量，东西后来拿下舞台了，画回原样的字（`count(t)`），不画「?」。
- **树的量写部件，是以它为根的那棵子树：`height(t.107)` 那棵子树几层，`count(t.107)` 那棵子树几个结点（`t.107*` 一样）。`tray` 写部件没有（托盘是整棵树的）。**
  - 为什么：计划只给了 `height` 写部件的意思；`count` 跟着它，同一个写法两个量不能一个指结点、一个指子树。
  - 代价：想数「这几个结点」的老师得自己数。
- **矩阵的量只写整张；写部件（`M.r1`）是「本来就没有」。`det` 先看形状：不是方阵、增广矩阵空着也是「没有」，不是「数不了」。**
  - 为什么：一行、一列的秩老师用不上；形状定了 det 有没有，空不空是之后的事。
  - 代价：不是增广的矩阵也列 `rankA`（和 `rank` 一样），每张矩阵每一轮多十几个字。没有为它特判。
- **句子的 `left` 写一段时，数 key 里整个落在这一段里、还没拉对的段（和 `verbs` 一样的范围规矩）。**
  - 为什么：计划只写了 `left(s)`；同一个写法的范围意思要一样。
- **量数不了时说什么，挂在量的函数上（`blank`：「还有空着的格」；`none`：「不是方阵，或者是增广矩阵」）。** 规则接口照设计只多三项，`measures` 还是「名字 → 函数」。
  - 为什么：通用的 `evalMeasure` 不知道每种东西为什么数不了；要说出「C 还有空着的格」「M 没有 det（…）」只能那种东西自己交。
  - 代价：没挂的量数不了时说「t 现在还数不了 count」，笼统一点。
- **句子没写 key 时，量抛的错是短的一句「s2 没写 key」（作废了是「s2 的 key 跟着 rewrite 作废了」），不是判断式那句长的。**
  - 为什么：「页面数不了」那一行同一句只写一次（`verbs`、`left` 都数不了，并成一句）。
- **挑战里量数不了的那一句写「判不了：原因」（`verbs(s2) = 1 判不了：s2 没写 key`）；判断式的「判不了」照旧不带原因。**
  - 为什么：老师要知道是没写 key 还是矩阵还空着，才知道下一步怎么办；判断式的旧样子不改（旧课放回一字不差）。
- **以后也数不了的量写下时当场报；现在还空着的照收，写「判不了」。**（控制者定的，照第一轮 I4 的规矩：这样东西本身永远判不了就写下时报，之后会变成判得了的 null 照收）
  - 以后也数不了：
    - 量自己抛错，也就是这样东西本身数不了：句子没写 key、key 作废了。key 只能重新造这句时带上，不算「之后会有」。
    - 本来就没有（`undefined`）：增广矩阵、不是方阵的 `det`，写部件的 `rank(M.r1)`、`tray(t.50)`。形状在写下时就定了。
  - 这两种 `evalMeasure` 都多给 `never: true`。挑战的 `when=`、话、贴的字、题卡、改字写下时，`checkMeasure(…, { run: true })` 碰到它就报「「det(M)」页面数不了，以后也数不了：M 没有 det（不是方阵，或者是增广矩阵）」。
  - 答案 `answer={…}` 照旧：写下时 `{…}` 要算得出，数不了的都报。
  - 量写错（名字不对、东西不在、部件不对）也是写下时报。
  - 写下以后才变成数不了的（key 后来跟着 rewrite 作废了），挑战写「判不了：原因」，贴的字画「?」。重放旧课照收。
  - 为什么：永远不成立的挑战、永远是「?」的字是老师写错了，当场知道比下一轮看现状才发现好。和判断式 `s parsed` 在没写 key 时写下就报是一个规矩。
  - 代价：和设计里「不是方阵是 null、挑战写判不了」的字面不一样，写下时就挡下了。还空着的乘积照旧收、写「判不了」。
- **量的值不是整数时（只有 `det` 会）写成分数：分母 1000 以内凑得上的写 `3/2`，凑不上的写小数。**
  - 为什么：规则接口照计划交数（number），舞台上的矩阵多是小分数。
  - 代价：分母超过 1000 的 det 写成小数（挑战里比大小照旧按数比，差不过 1e-9）。
- **`{count(t)}` 这样跟着量算的东西，依赖记整样东西（`t`），写部件也一样。**
  - 为什么：子树几层、几个结点跟着整棵树的结构变。
- **有意的不同**：现状里矩阵、树、句子下面各多一行「页面算的 / 页面数不了」。`stage-class` 的「旧 log 照放」和 `stage-value` 的「旧写法不变」逐行核过（只多了这几行，别的一字不差、先后不变），期望值跟着改了。

## 矩阵的写法和摆法（Task 2）

- **有意的不同 1：`link` 写整样东西的那一头连到那样东西上，一道弧（以前把它的每一格连成一串）。** 不只两头都是整样东西（`link AB BA`），一头是部件、一头是整张（`link f.l1 AA f.r1`）也一样。只写一样东西（`link a`）照旧把它的部件依次连起来。
  - 为什么：设计第 9 节。缺口单里真出过的就是一头是部件的写法（L1 第 2 幕的方块图）：只管两头都是整张的话，那一条照旧满屏弧线，`unlink f` 也收不掉块里的那几道。
  - 连线的一项：整样东西那一头是 `{ obj, key: null }`，这条线记 `whole: true`；现状写成 `连线：AB–BA 蓝`、`f.l1–AA 蓝`。照新的数重新造（`remake`）时只剪「这一头是部件、部件没了」的线，整样东西那一头不算。
  - `unlink X`（整样东西）收掉一头在 X 上的线：连着 X 的、连着 X 里部件的都算；`unlink X.1,1`（部件）照旧只收连着那一格的。
  - 一排格子的分组（`group`）只收这一排格子之间的线，整样东西的那一道不收（`array.js` 的 `regroup`，计划的文件表里没有，顺手改的）。
  - 代价：照 log 放回的旧课里写过 `link a b`、`link f.l1 AA` 的，现状的连线一行和画面都和以前不一样（以前是一串格，现在是一道）。
- **有意的不同 2：同名重造留在原处。** 各种东西的 make 照旧位置留着（没写 `beside=`）时，在 `objects` 里的先后也不变；换了地方的（写了 `beside=`、乘积照 A、B 重新排、平面、换了一种东西）照旧排到最后，像新造的一样摆。
  - 为什么：设计第 9 节（`matrix P = {B A}` 掉到最底下）。只看「位置留着没有」：乘积另起一行（`BA =`）重造时 `makeProduct` 把它摆到最下面，要是先后还在最前面，`reflow` 会把它上面的东西全推到它下面（`stage-value`「旧写法不变」里的 `product A = C B` 就是这样，照这条它照旧排到最后，那条测试一字没改）。
  - `replaceObject(id, o)` 用 Map 换一个还在的键的值（不改先后、`objects` 还是同一个 Map），`dropObject` 多一个 `keepPlace` 留着键，只清连线、open 这些。连线照旧跟着清掉（整样东西的那一道也清，和以前一样）。
  - 代价：旧课里同名重造过、位置留着的那一样，现状里东西的先后和以前不一样（不再排到最后）。
- **整样东西的弧：一个在另一个上面时，从上面那一样的下沿中点连到下面那一样的上沿中点（竖着出去、竖着进来，走中间的空当）；横着排成一排的照旧从上沿拱一道弧。**（`layout.js` 的 `wholeLinkGeom`）
  - 为什么：照两格之间那样从两样的上沿拱，下面那一样的弧会竖着穿过上面那一样（截图里 `link A B` 是一根竖线从 A 的中间一列穿过去）；AB 一排、「BA =」另起一行摆在下面是 `link AB BA` 最常见的摆法。
  - 代价：斜着隔得远、中间夹着别的东西时，曲线可能从别的东西身上过（和两格之间的弧一样，不绕路）。
- **另起一列比的是镜头能用的那块屏幕，不是整块屏幕。** `scene.view` 照接口写整块屏幕大小；摆新东西时减掉四边留白（28）、顶上的话（102）、底下一条（76）再给 `columnSlot`（`layout.js` 的 `CAMERA_ROOM`、`cameraRoom`，`stage.js` 的镜头留白也改用 `CAMERA_ROOM.pad`，值没变）。
  - 为什么：拿整块屏幕比，横屏五张四行的矩阵叠起来，镜头已经缩到 0.4（一格 21 像素，学生点不着）才觉得要另起一列；按能用的那块比，三张就另起，镜头 0.64。
  - 代价：话很长、底下有好几排按钮时，真能用的地方比估的小，还是会缩小一点；横屏另起一列比按整块屏幕早。
- **已经另起过一列：「往下摆」是摆在这一列下面（左边和这一列对齐，不伸到左边那一列底下），缩得不比照旧往下摆更小就先摆它；这一列也满了再另起一列。**
  - 为什么：计划只写了「往下摆」和「摆到最右一列的右边」两种。照字面，另起一列以后下一张要么照旧摆到整块下面、横跨两列居中，要么一张一列。伸到左边那一列底下的话，`reflow` 会把它推到左边那一列的下面。
  - 怎么记：另起一列的那一样带 `o.colStart`；「这一列」是最后一个另起的和它后面摆的（`columnSlot` 多一个可选的 `last`，返回多一个 `start`）。只管各种东西自己照旧往下摆的那一样（`placeFresh` 按它造出来的真实大小再看一眼，整样挪过去）；`beside=`、和 A、B 排成一排的乘积、同名重造不动。
  - 代价：不知道屏幕多大（纯场景、测试、`scene.view` 还没写回）照旧往下摆；同一节课换了横竖屏，后面摆的东西照新的屏幕摆，前面的不重排。重放时照重放那一刻的屏幕摆。
- **藏起来（`hide=on`、`hide R` / `show R`）。**
  - `hide=` 只认 `on` / `off`，别的报错；同名重造不写 `hide=` 时照旧（藏着的还藏着，「留在原处」）；`hide=off` 摆出来。
  - 藏着的：不画；不进镜头；不推别人、也不被推（`reflow`）；摆新东西不给它留地方（`slotFor`）；贴的字不躲它。贴在它上面的字（贴的东西都藏着）不画；拨数照画（锚落到看得见的东西上）；连线一头藏着就不画。现状照写，第一行前面「（藏着，画面上不摆）」。
  - `show` 的时候：原来的地方压着画面上的东西、或者在所有东西下面（`hide=on` 造的从来没摆过，后来另起了一列的话该摆进那一列），照摆新东西的规矩重新摆、排到最后；夹在中间、没压着的（`beside=` 摆的、摆过又藏起来的）留在原处，先后不变。
  - 为什么：藏着的时候没人给它让地方，原来的地方可能已经被后造的占了；从来没摆过的，造的那一刻往下摆的地方没有意义。
  - 代价：`show` 以后可能不在 `hide` 之前的地方（压着别的东西的时候）。
- **看不全：只在镜头框着全部东西时写（老师 `camera` 对准了一处时不写：镜头外面的是老师自己选的）；比的是整块屏幕（出了屏幕两像素以上），藏着的、已经拿下舞台的不写。** 镜头每挪一次（`camera`、`keepInView`）写回一次。
  - 代价：老师对准一处时，别的东西学生看不到，现状里也不说。
- **`_` 只在造矩阵时认（`parseRows` 的 `blank`），判答案时不认。**
  - 为什么：答案里空着的格不是一个答案，照旧报「不是数」。
- **`coef(M)`、`rhs(M)`：`rhs` 是 n×1 的矩阵（竖线右边不止一列时 n×k），不是向量；只看用到的那一半（左边还空着不碍 `rhs` 的事）。** 依赖记 M。
  - 为什么：舞台上一列的矩阵（`matrix P = 1 / 2`）在式子里是 n×1，`coef(M) P` 也是 n×1；exact.js 里 n×1 的矩阵和向量不能相减。
  - 代价：和平面上的向量相减（`{coef(M) v - rhs(M)}`）报尺寸不同。
- **格里的式子算出来不是数，照实说是矩阵还是向量**：「「{2 A}」算出来是矩阵，格里要一个数」。名字不认得的报 value.js 本来那句（「「q」不是拨数，也不是舞台上的东西」）。
- **`vars=`、`from=` 写下时查**：`vars` 的个数要等于未知数的个数（增广的是竖线左边的列数，不是增广的是列数），不能重名，存成字符串数组 `o.vars`；`from=` 要是舞台上的矩阵、和这一张一样大、不是自己，存成名字 `o.from`。
  - 为什么：读回、比的时候对不上就没有意义，写下时说比下一轮现状里写不出来好。
  - 代价：`from=` 的那一张后来被拿掉或改了大小，Task 3 那边要自己照实说。
