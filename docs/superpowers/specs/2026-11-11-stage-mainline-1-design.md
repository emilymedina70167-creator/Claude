# 舞台主线第一轮：一把量「搭」的尺子、页面不说假话

2026-11-11。接底座两轮（`2026-11-06-stage-base-design.md`、`2026-11-08-stage-base-2-design.md`），词和原则照它们。交接在 `claude/teaching-mode-code-review-vcz66v` 分支的 `docs/handoff/2026-11-11-舞台交接.md`。

## 0. 为什么、要什么

**终点**（2026-11-11 我说的）：页面把重复、反复、困难的代码做得很好，教学的 Claude 不用从 0 搭，一轮的耗时几乎只有决策。底座的方向差不多是对的。

写成能量的两件事：

1. **老师一轮写的字里，「搭」占多少**。回话的时间基本就是写字的时间，搭的字就是白等的时间。
2. **页面说的话有没有假的**。事实错了，老师在上面做的决定全错。

**线画在哪**：不是「通用的」和「按内容的」，是**事实**和**教学**。

- 事实归页面：画、排、动、学生能上手的一切、算得出的数、这一下对不对、判答案、把学生怎么试的整理好交回去。「这一趟希尔对不对」「是不是堆」「这根箭头是不是特征方向」都是事实，而且正是最难、最反复的代码。
- 教学归老师：拿哪个例子、让学生做什么、什么算做到、做到或走偏以后说什么、下一步问什么。页面不替老师决定；预写照旧只收答案固定的。
- 事实怎么做：先接现成的（黑板的 54 个引擎 `kit/src/engines/registry.js`、精确计算 `exact.js`），接不上的才手写。树、矩阵那两份手写的规则方向没错，是做法贵。

**主线拆成四个子项目**，每个一份设计、一份计划：

| | 做什么 | 这一份 |
|---|---|---|
| ① 尺子 | 量老师的字花在哪；读真课的记录 | 做 |
| ② 不说假话 | 修量出来的 50 条页面毛病 | 做 |
| ③ 页面算事实 | 通用地接引擎和精确计算，老师不再藏辅助矩阵、手算死字 | 不做，顺序等 ① 的排行榜 |
| ④ 补通用件 | 字跟着拨盘变、图能交给学生、能放字的表、时间轴、三维、底座第二轮留下的 10 条 | 不做，顺序等 ① 的排行榜 |

**这一轮不加新能力**。只有两处多了写法（`ask pick … order=on`、`span … stay` 能留几条），都是为了不说假话。

**不做的**：排序那个提交（`68ff091`）留在它的分支上不动；里面几处通用的修法照着重做（第 3 节标了「照排序提交」的），不带排序的规则。英语词形不做。模拟真课不做（我自己上课，见 2.2）。

**成功标准**：

1. 第 3 节的 50 条每条有一个会失败的测试或一份最小的试演文件，修完都过。
2. 旧课照 log 放回：`try/`、`try2/` 的 154 个文件和动工前一模一样；`try3/` 不一样的地方每一处都对得上第 3 节的某一条。
3. 静态尺子跑出 341 份试演的「搭占几成」和搭的写法排行榜，写进 `docs/stage-mainline.md`。
4. 读真课的脚本量出 11-06 以后我上过的舞台课，当修之前的基线。
5. `npm test`、`npm run check:stage`、`npm run e2e` 全过；合进 `main`；发布学习台和舞台试课。

## 2. 尺子

### 2.1 静态的一半：老师的字花在哪

`tools/stage-cost-lib.js`（纯函数，`tests/stage-cost.test.js`）加 `tools/stage-cost.mjs`（脚本）。不开浏览器、不调用 Claude。

**输入**：试演文件（`学生:` 行把老师的行切成一轮一轮；`#` 注释不算），或者一节真课里老师每一轮的原文（2.2 用同一套）。

**每一行归一类**：

| 类 | 是什么 | 算 |
|---|---|---|
| 说问 | `say`、`ask`，`@…` 后面跟的话和问 | 教 |
| 交给学生 | `open`、`close`、`goal`、`keep`、`back`，`@…` 的挂法 | 教 |
| 例子 | 造一样看得见的东西（`matrix`、`array`、`tree`、`graph`、`sentence`、`plane`、`vec`、`card`、`tex`……） | 教 |
| 指给学生看 | `label`、`mark`、`paint`、`glow`、`dim`、`tag`、`ptr`、`camera`…… | 教 |
| 老师演 | `swap`、`move`、`write`、`rotate`、`transform`…… | 教 |
| 藏着的辅助 | 带 `hide=on` 的东西 | 搭 |
| 收拾 | `remove`、`unlabel`、`unglow`、`unmark`、`ungoal`…… | 搭 |
| 同名重造 | 重造一个已经有的名字（为了改它） | 搭 |
| 写死的数 | 话、贴的字里有字面的数，这一行没有 `{…}` | 只标「疑似」，单列，不进搭的合计 |

- 指令表从 `kit/src/stage/script.js` 认得的指令来；测试守着「每条指令都归了类」，以后加指令不归类测试会红。
- 分类有拿不准的（比如造一样看得见的东西只为了挂一个数）：照表机械地分，不猜意图。尺子要的是能反复量、前后能比，不是每一行都判准。

**输出**：

- 每块、每个文件：几轮，每轮平均多少字节，搭占几成（按字节）。
- **搭的写法排行榜**：每一类搭的写法出现多少次、多少字节、最典型的三处（文件和行号）。「藏着的辅助」再按它算的是什么细分（跟着算的格子里用了哪些函数、几张连着），这是 ③ 最直接的单子。
- `--json` 给以后比。

### 2.2 读真课的一半：老师会不会用

`tools/stage-lesson.mjs <存数据的目录> [课号…]`（库在 `tools/stage-cost-lib.js`，有测试）。数据是学习台 `ArtifactData list` 存到本地的（和 `tools/guard-audit.mjs` 一样的目录约定）：`sessions`、`sessions/{编号}/class_turns`。只读。

舞台课每一轮已经存着：老师写的原文 `text`、演上了的行 `log`、`cost`（`bytes`、`ms`、`first`）。脚本对 `kind: stage` 的课算：

1. **没演上**：每轮写了几行、演上几行；没演上的原文和页面报的话。
2. **字花在哪**：每轮多少字节、搭占几成（2.1 的分类）、等了几秒（`cost.ms`）、出第一个字几秒（`cost.first`）。
3. **能力用了哪些**：说明里的每一种写法（指令、`open` 的每个动作、`ask` 的每种、`@名字.done / .right`、`@ask.right`、`{式子}`、量、`keep` / `back`、`goal … collect=`……）在这节课用了几次；**一次没碰的列出来**。写法的清单和 2.1 的指令表同一份。
4. **学生动手多不多**：有几轮学生手上有事（开着的东西、挑战、要点要填的问），有几轮只有话和「继续」；最长连着几轮只有话。

「该让学生动手却自己讲掉」脚本判不了：脚本给第 4 条的数，我（开发的 Claude）读那几轮的原文，在 `docs/stage-mainline.md` 里写几句。

**怎么用**：

- 现在：把 11-06 以后的舞台课全量一遍，当基线。
- 以后：我上完课说一声，量那一节，和基线比。
- 量出「一次没碰」的能力，先看是不是说明没讲清什么时候该用；是就改 `doc.js`（`STAGE_TEACH + stageDoc(科目)` 不许超 24576 字节），改了以后等我下一节课再量。这一轮只改一次说明。

## 3. 不说假话：50 条

出处：`evals/stage-gaps/report3/` 每块「说明」里「页面的毛病」那张单子（D1 15 条、D4 11 条、D3 8 条、L3 8 条、E1 8 条），带文件和行号。编号「D4-1」是那一块单子的第 1 条。

每条的做法：先写一个会失败的测试——纯函数的写单元测试，要真舞台的写一份最小的试演文件放 `evals/stage-gaps/fix1/`，在 `tools/stage-try-lib.js` 的表里加一行「必须出现 / 不许出现」（`tools/stage-must.mjs` 的查法多一种「不许出现」）。
