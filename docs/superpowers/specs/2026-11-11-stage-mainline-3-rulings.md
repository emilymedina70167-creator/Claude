# 舞台主线第三轮：做的时候自己定的事

2026-11-11。设计是 `2026-11-11-stage-mainline-3-design.md`。

## 0 说明腾地方

拼说明时把三个以上连着的空格压成两个（`doc.js` 的 `stageDoc`）：每门课省约 1 KiB，内容不少。表六门都带以后，操作系统那一门又只剩 70 字节（24506 / 24576）：这一门带一排格子、图、题卡、式子、矩阵、表六种。下一轮要给共用的那一节、这六种里的哪一种加行，得先压。

## A 表

- **不做 `wrong=mark / block`、`@T.right`**（设计里写了要标就写 `wrong=mark`）：裁判说的话是「不是正确的下一步」，对「填一格」说不通。页面只在话里说「和答案一样 / 不一样（答案是几）」，`right` 永远是 null，学生那边什么都不标。
- 给定的格有两种：造的时候就有值的（答案不比它）、老师后来 `write` 进去的（照比）。老师 `write … _` 空出来的格等学生填、照比。学生写的格学生能再改。
- 学生那一行指令里的值，纯数和 ∞ 照写，别的一律加引号（箭头、花括号、和舞台上东西同名的字不加引号会被读成别的）。老师写 `write T.1,1 7 8`、`write T.1,1 A→B` 当场报「短语写在引号里」。
- 表的格、`key=` 里不能写 `{式子}`（不跟着算），当场报。
- 只开一列（`open T.c1 edit`）：写满这一列就算做完；事实写「开着的格写满了」。`wrong(T.c1)` 只数这一列。
- 没有行名 / 列名的表给一整行一整列打勾打叉：当场报（画面上没处画），打在格上可以。
- 和答案比：数按数比，但有前导 0 的（0011、02）照字比；上标不吃掉（n² ≠ n2）；弯撇号、几种横线两边一起规整；不管大小写、多余的空格、全角半角。
- `open … input=` 多认手势自己说的（表：`text`）；`open … choices=` 是新选项（手势写了 `choices: true` 的才收）。规则的 `ask` / `toAct` 现在拿得到这一项是怎么开的（`ctx.open`）。
- 「学生写的：…」不进现状（和每行的值重复）；`blank(T)` 有空格才列。
- **没做**：把东西拖进一格；一格里放一整排数；加列；超过 8×10。

## B 时间轴

- **事件点的指令叫 `event`**，不叫设计里写的 `point`：平面上的点是 `point`，两种东西认的选项对不上。
- 小人、条的一头的拨盘：`vars` 里 `owner` 是时间轴的名字、`shown: false`（不画 ‹ ›，现状「能拨的数」里不列）。时间轴拿掉、同名重造时拨盘跟着没了；跟着这些拨盘的句子不再跟（现状写「拨盘没了」），小人重新站上去、段数对得上就接着跟，对不上当场报是谁。
- **时间轴存不了档**（`keep` / `back` / `after=` 当场报）：存档只存东西自己，拨盘在场景里，回去以后两边对不上。要回到某一处就 `set`。
- 条的右端不能跑到左端前面：`set` 那一行当场报，学生拖的弹回去。
- 能动的条占满整条轴那一层（不知道会伸到哪）。
- 拨词的拨盘比先后：两边要是同一串词（同一条轴），或者另一边是一个停靠点；`=` / `!=` 照旧照词比（两个词表不一样的拨盘也能比）。普通的拨词拨盘也能比先后（照 `options` 的先后）——第二轮写的是「只能比一样不一样」，这一轮放开了。
- 小人不带字（要写字贴一个 `label`）。
- **没做**：灯光、波浪、印子、按住拉出一条新的、两条轴并排、停在两个停靠点之间（老师把那一处写成停靠点）、两个事件点在同一个停靠点时字会叠。

## D 排版留下的

四条都先让排版检查报得出，再修根子。量法在 `tools/stage-measure.mjs`，多三种：「括号的线穿过了字」「弧拱进了别的东西里」「拨盘没跟着它的东西」。

| 条 | 根子 | 改成什么 |
|---|---|---|
| E1-7 | 括号下的字只躲「套在外面的那道」的竖线，两道括号交叠（不是一道套一道）时没管 | 字在自己那道括号下面左右让一让：挑离正中最近、又不骑在深一层那道竖线上的位置；让不开的照旧（`sentence.js` 的 `layout`） |
| D1-11 弧 | 一样东西自己格子之间的弧（分组的连线、`hop` 的弧）不算它占的地方，拱到上面那样东西里被盖住 | 算进它自己占的地方（`stage.js` 的 `footprintBoxes`）：上面留不下时这一排往下让。连到别的东西的线不算 |
| D1-11 拨盘 | 贴的字、拨盘重不重摆只看贴着的东西的左上角和宽：东西变矮了（泳道 `merge` 回一排）不重摆 | 高变了也重摆 |
| 横屏挑战多 | 挑战摞在左上角一小列，镜头却把它们的高整排让出去：五条挑战 + 三行话，画面只剩半屏 | 横屏时再算一种摆法：挑战那一列留在左边，话和画面放在它右边。画面大一成以上才用（已经在用时差一点也不换回去，免得来回跳）；话跟着让到右边。竖屏照旧 |
| D3-6 | 四排格子是四样东西，摆第四样时往下摆会缩得太小，就另起一列——页面不知道它们是一张表 | 不改排版：现在有「表」，一张表是一样东西，拆不开。`evals/stage-gaps/new3/D3-6.txt` 守着图旁边一张表横屏竖屏都不压、不缩 |

自己定的：

- 弧算进去以后，一排格子分了组就比以前高一截（隔得越远弧越高，最多 100）。它被推下去以后**不会自己回来**（`reflow` 只往下推）：分了组、`split` 成泳道以后，那一排上面会空着弧原来占的那一截。`try3/D1/幕3b.txt` 横屏第 2～4 步因此从 6 成变成 5 成（照旧报「缩得太小」）。弧被盖住看不见比空一截要紧，留着。
- 「弧拱进了别的东西里」和「压着」分开量一遍：哪天弧又不算进自己占的地方了，「压着」量不出来，这一条还报得出。
- 横屏的新摆法只看挑战那一列多宽（不到屏幕四成才用）、画面是不是大一成，不看有几条挑战：一条挑战时让上面只少五六十的高，一般不会大一成，照旧在上面让。
- 旧课重放不比排版（只比演没演上、报没报错），这四条在重放里看不出不同；靠 `new3` 表和排版检查守着。
