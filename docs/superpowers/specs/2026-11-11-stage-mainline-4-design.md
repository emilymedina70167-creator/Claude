# 舞台主线第四轮：照引擎走、舞台上自己练——做完就开学

2026-11-11。接第三轮（`2026-11-11-stage-mainline-3-design.md`），主线见 `docs/stage-mainline.md`。这一份是和我一条一条谈定的：做完这一轮我就开始用舞台上课，问题从真课里看；质量要扎实，但检查要轻。

## 0. 为什么做、做成什么算成

**现状**（都是查过的事实）：

- 底座是通用的，三门课平面的内容今天就能上：老师摆、学生动手、页面如实告诉老师学生做了什么、老师写的条件页面当场判。
- 页面不懂任何算法（除了手写过规则的三样：树的插入和旋转、矩阵的行变换、句子照 key 比）。老师要「这一趟希尔做完该是什么样」「最短路表该是什么」只能自己算了写死；学生做完一趟对不对，要等老师一轮。
- 11 月 6 日起新课全是舞台课，舞台课里没有黑板的组件，下课时抄不出题：**从那以后新上的课不再往「练一练」的题库里添题**（`memory/drills.js` 的 `harvestDrills` 只读黑板的段）。舞台课上完，那一块就没有不花额度、换新数、页面自己判的复习手段。
- 黑板那边有 54 个引擎（`kit/src/engines/registry.js`），每个都交得出「每一步之后是什么样」（`run(spec).steps[].view`）和常见错法（`variants(spec)` → 换一份输入再跑一遍）。舞台一个都没接。

**这一轮做两个通用件，再接两类算法验证成本**：

1. **照引擎走**（`follow`）：老师写一行，页面让引擎把这个算法在这份数据上跑一遍，拿「正确的那条路」和「每种错法的那条路」去对学生做出来的样子。
2. **舞台上自己练**：舞台课里照引擎走过的东西，下课抄进题库；「练一练」里页面换一组新数、嵌一块舞台、没有老师、页面照引擎判，结果照常记证据、算掌握。
3. **头两类**：排序（引擎 `sort`，七种，接在一排格子上）、最短路（引擎 `net` 的 `dijkstra`，接在图和表上）。做完数每类写了多少行。

**做成的标准**：

- 希尔排序那节课能这样上：老师写 `follow`，舞台现状里就有每一趟做完该有的样子；学生做完一趟，页面当场知道对不对、像不像哪种错法，并演老师预写的那一句。
- 这节课下了课，首页「练一练」里就有一道希尔排序的舞台题：新的一排数，自己拖，页面判；一次做对算复现的新题。
- 每类算法的对应关系 ≤ 150 行（不算测试）。**超了就停下来告诉我**，不硬做。
- 我能直接开学：三节要上的课（希尔排序、时态、可交换和方阵的幂）在学习台里开得出来、上得下去；说明里有新写法；已发布。

## 1. 硬规矩（防止又滑回按章节做）

1. 这一轮不写任何「页面懂某个算法」的规则文件（`types/*.rules.js` 里不加 `next` / `check`）。算法的知识只从引擎来。
2. 不为某一节课新造一种东西、不加只有一节课用的指令。`follow` 和 `stage` 组件之外，老师的写法不变。
3. 每类算法只许写「对应关系」：引擎的字段怎么从舞台上的东西来、引擎每一步的 `view` 对应舞台上这样东西的什么状态。别的都在通用件里。
4. 不用按章节的那张缺口单（`docs/stage-gaps.md`、`evals/stage-gaps/ideal/`）定活。
5. 不做：英语的动词形式、三维、每一步手写的裁判、模拟课。

## 2. 照引擎走 `follow`

### 2.1 老师怎么写

```
array a = 49 38 65 97 76 13 27 49′
follow a sort shell gaps="5 3 1"     照引擎 sort 走：algo 是 shell，别的字段照引擎的写（gaps、pivot……）
follow a off                         不照了
```

通用形：`follow <东西> <引擎> [<引擎的第一个字段的值>] [字段=值 …]`。引擎要的输入从这样东西现在的样子来（一排格子的数、图的边），别的字段老师写。写的那一刻就让引擎跑：跑不了（字段写错、数据引擎不收）当场报引擎自己的那句话。

`follow` 记在东西上（`o.follow = { name, fields, start }`，`clone()` 带着）；数据是写下那一刻的样子（`start`），之后学生怎么动都拿它当起点。老师自己改了这样东西（`write`、同名重造）→ 从新的样子重新跑；跑不了就说「照不下去了」并停掉。

### 2.2 对应关系（每类算法写的那一小段）

```js
registerFollow('sort', {
  engine: 'sort',                       // registry.js 里的名字
  types: ['array'],                     // 能接在哪几种东西上
  subjects: ['数据结构'],                // 说明里哪几门课带它
  head: 'algo',                         // follow a sort shell 里那个不写名字的字段
  fields(o, opts, scene) → 引擎的字段     // 从舞台上的东西拼引擎的输入（array: '49 38 …'）
  stateOf(o, scene) → string            // 这样东西现在的样子，写成能比的一串（一排格子：按格的先后写每张牌一开始在第几格）
  frames(run, spec) → [{ state, mark?, text? }]   // 引擎的每一步 → 同样写法的一串；mark 是「一趟 / 一轮做完」的检查点名字（'第 1 趟'），text 是给老师看的这一步的样子
  unit: '趟',
  doc: '…',                             // 说明里的一两行
});
```

接在表上的是另一种、更简单的对应：引擎的结果直接当表的 `key`（`toKey(run, o) → 一张和表一样形状的答案`），之后照第三轮表的做法逐格比，不走下面的「路」。

### 2.3 通用的那一半（`kit/src/stage/follow.js`，纯函数）

- **路**：`frames` 去掉连着重复的，是「正确的那条路」；每种错法（`engine.variants(spec)` 的每一项 `{ label, input }`）照同样的办法跑出它的路。路和检查点按 `name + 字段 + start` 缓存。
- **现在在哪**（`whereOf(o, scene)`）：
  - `on`：现在的样子等于正确的路上第几个；`mark`：已经过了哪个检查点；`done`：到了路的最后。
  - `like`：不在正确的路上，但等于某种错法的路上某个检查点 → 这种错法的 `label`。
  - 都不是：`off`（不在引擎走的路上）。**不等于错**：一趟里先理哪条链、先写哪个顶点的距离，学生的先后和引擎不一样是常事。
- **这一下判成什么**（`check`，给裁判用）：
  - 到了下一个检查点、或者在正确的路上往前了 → `right: true`。
  - 到了某种错法的检查点 → `right: false, misread: label`。
  - 别的 → `right: null`（页面不判）。
- **下一步**（`next`）：到下一个检查点该是什么样（`text`）。走完了是 `null`（做完了）。
- **事实**（学生每一下以后给老师）：
  - 「到了第 1 趟做完的样子（和引擎算的一样）」
  - 「和第 1 趟做完该有的样子差 2 格：第 3 格（现在 49，该是 38）、第 5 格（…）」——只在学生动过、还没到检查点时说，差得多（超过一半）就只说差几格。
  - 「像是：把相邻的元素分成了一组……（引擎认得的错法）」
- **现状**里的一行：「a 照 希尔排序（增量 5 3 1）走：做完了第 1 趟（共 3 趟）。第 2 趟做完该是：13 04 49′ 38 27 49 55 65 97 76」——老师不用自己算下一趟。
- **量、判断式**：`pass(a)`（过了几个检查点）；`a pass=2`、`a done`、`a onpath`。能写进 `when=`、`{…}`。
- **做完**：照着走的东西、`open` 了任何一种动作，走到路的最后算学生做完了（`@a.done`、叫老师）。到每个检查点算「做对一步」（`@a.right` 每到一个演一次）。
- **怎么接进去**：`rules.js` 的 `rulesOf(o)` 是全舞台问规则的唯一入口——东西上有 `o.follow` 时，把 `next` `check` `facts` `judges` `doneBy` 和上面的量、判断式盖在那种东西自己的规则上面（手势、别的量照旧用它自己的）。裁判、预写、挑战、叫老师都不用改。
- **页面不做教学决定**：默认什么都不标（`wrong=quiet`）；老师写 `open a move wrong=mark` 才标，而且只标 `right: false` 的那一下（到了错法的检查点），`off` 的不标。

### 2.4 头两类

**排序 → 一排格子**（引擎 `sort`：insert / shell / bubble / select / quick / merge / radix）

- `fields`：`array` = 这一排现在的字（49′ 照写），`algo` 和别的字段老师写。
- `stateOf`：按格的先后，每张牌一开始在第几格（`a#k` 的 k）。引擎的 `view.A[].id` 就是一开始的下标，直接对得上；重复的数（49 和 49′）分得开。
- `frames`：每一步的 `view.A` 写成同样的一串。量过：引擎挪到一半的步里 `A` 有重复的牌（直接插入往后让、快排填坑），这些步不进路——只收每张牌都在的步。`run.passes` 是每一趟做完的数（不是编号）：检查点是路上数和它一样的最后一步。连着几趟做完是同一个样子（直接插入里本来就在位的牌）并成一个检查点，现状里写「第 2、3 趟没有牌要动」。
- 学生的手照旧是第二轮的 `open a move`（按住拖进两张之间 / 对调）。希尔分了泳道（`group` + `split`）时照旧只能在自己那一排里拖；状态照格位算，泳道不影响。

**最短路 → 图、表**（引擎 `net` 的 `run: dijkstra`；同一份对应关系里 `prim` `kruskal` `bfs` `dfs` 能顺带接上的就开，接不上不硬做，写进 rulings）

- 图：`fields`：`edges` 从图的边来，`from` 老师写。`stateOf`：每个结点牌子上写的数（学生 `open g tag`）和点过的结点（`open g visit` = 确定了）。`frames`：每一轮的 `view.table.dist` 和 `final`；一轮是一个检查点。
- 表：`follow T net dijkstra on=g from=1` → 引擎每一轮的 dist 填成 T 的 `key`（一行一个顶点、一列一轮，照 T 的行名对顶点）。行名对不上顶点当场报。

## 3. 舞台上自己练

### 3.1 黑板组件 `stage`（`kit/src/blocks/stagedrill.js`）

```stage
id: d-stage-DS-L8.2.3-sort-shell
pick: array a = ints(8, 1, 99)
---
array a = {a}
follow a sort shell gaps="5 3 1"
open a move
```

- `---` 上面是随机取数（照 `practicespec.js` 现成的 `pick`：`int` `choice` `seq`…；加一个 `ints(n, lo, hi)` 取 n 个不重复的整数），下面是镜头指令，`{名字}` 换成取到的数。每次打开重新取。取出来的数先让引擎跑一遍：跑不了、或者一上来就已经做完的，换一组（最多 12 次，照 `usespec.js` 的 `drawUse`）。
- 画面：组件里嵌一块舞台（`new Stage(host)`，固定高，照屏幕大小），没有老师、没有课堂循环。预写的行（`@a.right`、`@a.done`）照演。底下两个按钮：「看下一趟该是什么样」（用了记 `revealed`）、「做不出来」（`giveup`）。
- 结果（照黑板组件的规矩 `session.event` 交，`block` 是组件 id）：
  - 每到一个检查点记一步：第一次到就对 = `ok: true`；先到过错法的检查点、或者看了答案 = 记一次错再记对。
  - 全做完 = `final`。一道题在报告里的结果照旧由 `report.js` 算（一次对 `first`、改对 `ok`、看了答案 `revealed`、放弃 `giveup`）。
- 写错了的（指令演不上、引擎跑不了）照黑板组件的规矩在页面上报出来（`block-error`），「练一练」照旧把它标成坏题不再挑。

### 3.2 舞台课下课 → 题库

- `harvestDrills` 多一条路：这节课是舞台课时，从 `class_turns` 里老师演上了的行里找 `follow`（`parseScript`），每一种（引擎 + 字段，数据不抄）抄成一道题：
  - 编号 `d-stage-{块}-{引擎}-{字段的指纹}`：同一块同一种只有一道，上几次课都是它。
  - `md` 是上面那样的 `stage` 围栏：取数照那节课那样东西的大小（一排几格、数的范围；图照原样的边——图不随机，见下），指令是「造 → follow → open 那节课老师开过的动作」。
  - `block`、`space`、`kind: 'stage'`、`src: 'stage'`、`fromSession`。
- 图的题不换边（随机的图不保证好画、引擎不保证收），每次是同一张图：照现在的规矩算**原题**（做对了复现组不升档）。一排格子的题每次换数。
- 以前上过的舞台课首页打开时补抄（和黑板课一样走 `fixReports` 那条路）。

### 3.3 练一练、证据、掌握

- 「练一练」挑题、混练、判分、记证据、算结果都不改：`stage` 就是又一种黑板组件。
- 换数的舞台题每次都是新题：`closeDrill` 的 `fresh`、`mastery.js` 的 `markFresh` 把 `kind: 'stage'` 且写了 `pick:` 的题每次都算新题（`isOriginal` 不把它当原题）。所以复现组里有它、又都一次做对，档位升；这是我的规则 rule-rev-2「原题不算复现通过」本来的意思。
- 一道舞台题比一道填空长：一次练习里最多挑 2 道（`pickDrills` 里按 `kind` 限）。

## 4. 做完就能开学

- **说明**（`doc.js`）：`follow` 的写法按科目带（对应关系的 `subjects`），不进共用那一节——操作系统只剩 70 字节，不带。数据结构多一小节「照引擎走」（≤ 600 字节：通用形、两类各一行例子、事实和量各一句）。
- **试演工具**认 `follow`（老师的行，本来就认）和照着走时学生的写法（照旧是 `move` / `swap` / `tag` / `visit` / `write`）。
- **e2e 加一段** `stagedrill`：dev 里填一道舞台题 → 练一练做完（一次做对、一次先错再对）→ 证据、报告、掌握的改动单对得上。
- **开学那三节**：希尔排序用 `follow`；时态照第三轮的时间轴和跟着拨盘变的句子（动词形式老师写）；可交换和幂照旧（矩阵是做得最足的）。合并、发布以后我直接上课。上完我说一声，用 `tools/stage-lesson.mjs` 量。
- **发布**：学习台、舞台试课，说明书版本用发布那天的日期。

## 5. 检查怎么做（轻，但不漏）

- 每一件：先写会红的单元测试，再写代码；DOM 的那一半有一个最小的试演放 `evals/stage-gaps/new4/` + 表 `NEW4`。
- 合并前跑**一次**整套：`npm test`、`npm run check:stage`、`fix1` `new2` `new3` `new4` 四张表、`npm run e2e`、`npm run check:pages`。
- 旧课重放（282 份）只在最后跑一次：它在本机跑、不花额度；只看不同的。
- 只读的助手审一次，在最后，范围只限这一轮的新文件和改过的函数。
- 不跑模拟课。不为了「可能出错」多加检查；真课里看到的问题下一轮修。

## 6. 顺序

1. `follow.js` 通用的那一半（纯函数）+ `rulesOf` 的入口。
2. 排序的对应关系，接到一排格子上：现状、事实、量、判断式、做完、预写。
3. 最短路的对应关系：图、表。
4. **数一次**：两类各多少行。超过 150 行的那一类停下来告诉我。
5. `stage` 组件。
6. 下课进题库、练一练、新题的算法。
7. 说明、试演、`new4`、真手指（照着走时的拖还是原来的手势，补一段确认）。
8. e2e、整套检查、重放、审、文档（`docs/stage-mainline.md` 加「第四轮」、`CLAUDE.md`、rulings）、合并、发布。

## 7. 说在前面的限制

- 页面当场判得准的是**检查点**（一趟、一轮）：对、还是像哪种错法。检查点之间学生的每一下，页面只说「在不在引擎走的那条路上」「离这一趟做完差几格」，不说对错。
- 引擎没有的错法页面认不出，只会说「和该有的样子差几格」，像哪种错由老师看。
- 只管「动手走一遍过程」的内容。理解题、英语还是靠老师。
- 上课时每一步当场判比老师自己判好多少，要上了课才知道。
