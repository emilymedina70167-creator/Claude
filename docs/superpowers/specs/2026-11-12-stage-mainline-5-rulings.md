# 舞台主线第五轮：做的时候自己定的事

2026-11-12。设计是 `2026-11-12-stage-mainline-5-design.md`，计划是 `docs/superpowers/plans/2026-11-12-stage-mainline-5.md`。每条：定了什么 — 为什么 — 要是定错了会怎样。

## 首课走查（三节课）

走查出的问题和怎么办的三张表在本文末尾。这里是走查里定的、和设计或以前定的不一样的事。

- **到一趟就叫老师**（第四轮定的是攒着等学生点）；`follow … call=done` 走完才叫。— 走查里学生做完一趟只能对着「接着」等，老师要换分组也得等。— 错了：一节课多几次调用（每趟一次）。
- **一趟中间不再说「在 / 不在引擎走的那条路上」**，只说离这一趟做完差哪几格。— 引擎的步子比学生的粗（一组只留一步），学生一张一张插是对的也会被说成不在路上，是假话。— 错了：老师少一个「学生正照引擎的先后做」的信号（判断式 `a onpath` 还在）。
- 手上有没做完的东西时底下的按钮写「做好了」，不写「接着 →」。
- 真手指检查另写一个 `tools/stage-touch-first.mjs`（一节课一段，`--only`），不往 `stage-touch.mjs` 里加。— 那个文件是一条线跑到底的，拆段要动全部。— 错了：两处真手指脚本并存。
- 课的前后走查用的脚本不进 git；加了 `?dev&think=N` 让模拟老师先想 N 秒（只为截等的那一阵）。
- **一般不说的组合**（完成进行的被动）写下时不报错，画面上写「一般不这么说」，现状里说为什么；标准答案里写这种还是当场报。设计写的是当场报。— 走查里老师一带「被动」的拨盘整句就报错，要重写一轮，学生干等。— 错了：学生看到一个中文占位词。
- 拨词的拨盘画面上只写词，不写「t =」。— 代号对学生是多出来的字。— 错了：两个拨盘里的词一样时分不开（老师可以贴字）。
- 跟着拨盘变的句子，框照最宽最高的那种拨法算。— 拨盘和镜头不在手指下面跑更要紧。— 错了：短的时候句子靠左、右边空着。
- 时间轴停靠点少时摆开（3 个停靠点步长 220，7 个以上照旧 108）。— 字和小人太小。— 错了：旧课里三四个停靠点的时间轴变宽（重放里看得到）。
- 时间轴上把手的拨盘，停靠点写的是年份时照在 `now=` 之前 / 之后分过去 / 将来；现状里写明是照位置分的。
- **矩阵默认画名字**（左上角一条 22 高，算在它占的地方里）；整张跟着算的写式子（JX、Jᵏ），另起了名字的写「R = ab」；`name=` 能改、`name=off` 能关。— 走查里四张矩阵分不清。— 错了：旧课里的矩阵都多了名字、下面的东西低 22。
- **全是数的矩阵答案按格写**（≤ 4×4；以前定的是一个数字键盘的输入框）。— 学生不知道「2 0 / 0 2」的格式。— 错了：格子的个数透露了答案的形状。
- 矩阵那一批单独发布了一次（2026-11-12d）。— 修的都是第一次上课会碰到的。

没修、记着的：做到过的挑战一直挂在左上角（老师可以 `ungoal`）；三个拨盘两个在句子下面、一个在上面；整张矩阵拖去比以后要学生点「接着」老师才接（老师想马上接可以写 `watch` / `goal`）；学生动作里 `a#N` 是「一开始在第 N 格」，老师写第二趟时要换算（`a.4` 的写法本来就有）。

## 说明腾地方

- 拨词拨盘和 `{t: …}` 只给英语、`when=` 里写式子只给线代、操作系统和组成原理的矩阵只带第一段（`doc.js` 的 `ONLY_LINES`、`MATRIX_LITE`）。腾完以后每门课的字节见文末。
- 这一步没重跑四张老验收表。— 只动了说明的字，试演不读说明；`tests/stage-doc.test.js` 守着例子照抄能演。

## 动词形式

- 知识表 185 个不规则动词（设计写「约 200」）；短语动词变第一个词；有前缀的（overcome、undergo…）照词根变；表里没有的当规则动词，现状里写「（照规则变）」，老师可以写成 `原形/过去式/过去分词` 自己给形式。
- 情态写在「时间」那一格（`must` + `完成` → must have gone）；疑问句的倒装、虚拟语气不做（设计里就写了）。

## 引擎的过程表

- 判一格用 `stepperspec.js` 已有的 `cellOk`，不另起；错法单独一个 `variantsOf`（要多跑几遍引擎，用到才算）。
- 上限 10 行 13 列（设计写 12 列；散列表 p=13 是常见的题）。
- **不做 `on=a`**（数据从舞台上的一排格子来）。— 老师把数直接写进字段就行，少一条路少一处会错。— 错了：排序课上一排牌和表各写一遍数。
- `follow` 的 `known` 不换成 `trackFields`。— 现在的办法没坏，换了要动第四轮的对应关系。— 错了：再接一类算法要多写一行 `known`。
- 答案是「空着」的格（那一次没换出谁）留成能点的空格：不填才对，不算还空着；一组先后不论的格填够答案里不空的个数就判。设计没写这两种。— 画成横线会把答案漏给学生。— 错了：学生想不到「留空」也是答案时会卡住，老师看得到还空着哪几格。
- 打勾的格固定从 √ × 里挑；答案不是数的格自动给输入框。— 老师不用为这几格另开一种 `open`。
- 表下面单独的几格（`extra`，如平均查找长度）不在表里，写在现状里给老师（「表外的答案（学生看不到）」），老师自己 `ask value`。
- **抄成舞台题**：「同一种」= 引擎 + 值里没有数字的那几个字段（`algo=fifo`）；换数只换最长的那一串整数（≥ 4 个），不用黑板那边 `BUILTIN_USE` 的出题模板。— 模板是黑板字段的写法，换过来要另写一套。— 错了：数据不是一串整数的引擎（银行家）每次是课上的原数。
- 填表的自己练，填满了页面指出第一处不对（课上不给学生标）。— 自己练没有老师在旁边。
- 说明里每门课能造表的引擎和字段是手写的一张表（`doc.js` 的 `ENGINE_TABLES`）。— 引擎没有机器读得出的字段表；测试守着每条照抄能造出表。— 错了：引擎改了字段名测试会红。

## 散列表、堆

- **散列表不另接「照引擎走」的对应关系，走过程表**（`table H engine=hash …`：列名就是地址 0～12，关键字和比较次数两行，认得平方探测等错法，ASL 在表外的答案里）。— 一排格子的下标从 1 起、散列地址从 0 起，接上去学生和老师说的不是同一个号；过程表本来就是教材那张表。— 错了：散列表没有「把牌拖进槽」的手，只有点一格写。
- **树上对调不用新做**：树本来就有 `open t`（拖一个结点到另一个上，两个换值）。堆的对应关系 `follows/heap.js` 73 行，只接建堆 `build` 和堆排序 `sort`；插入、删堆顶要改树的形状，学生没有这只手，用过程表或老师演。
- 照着走的东西上老写法的 `open`（拖着换）也算学生的动作：`@h.right` 写得进去、走完叫老师。排序的 `open a` 也一样。

## 第四轮留下的 5 条

- 学生改写了照着走的数（同时开着 `edit`）：不重跑，现状写「照不下去了（学生把数改写了…）」，不算走完；学生自己改回改写以前的样子（写回去、撤一步）就接着照；老师重新 `follow` 或者改数据从新的样子重跑。设计只说「不算做完」，没说能不能恢复。
- 「做不出来」：放弃记在那道题的记录上；另外那条动作只在没有记录时才记。
- 题库编号里的中文写成码点（希尔 → `u5e0cu5c14`）；英文的编号不变。
- Dijkstra 并成一个检查点的几轮，每轮确定了谁都写出来。
- 下课抄题用课堂手上那份轮次；首页补抄时没有，才从数据库读。

## 收尾的只读审查（一次）

一个只读的助手看了设计、计划、账本和全部改动，实际跑了例子。没有「页面替老师做教学决定」的硬违规。查出来的修了 8 条，一条一个测试（`tests/stage-mainline5-review.test.js`）：

1. 一组先后不论的格（页面置换同一次访问的几个块）：以前一格错、整组都报错，还按位置说「答案是」。现在只有对不上的那一格算不一样，说「这一组该是 7 0 1，先后不论」。
2. `{verb: be able to …}`（be 后面带词）以前拼成 They be able to / does not be able to。现在照 be 变。
3. 话、贴的字、题卡、挑战、标准答案里的 `{verb: …}`，现状里以前不写拼成了什么（只有句子里的写）。现在都写在「页面拼的谓语」下面，照规则变的标出来——标准答案拼错了，学生写对的会被判错，老师要看得到。
4. 规则变化乱猜前缀：render → renderred、relay → relaid、offset → offseting、quiz → quizes、radio → radioes。改了：前缀 + 表里的单音节词才照词根双写；relay 不照 lay 变；quiz、radio 的第三人称。第一格写了不是原形的（went、is）当场报、说原形是什么。broadcast 加进了不规则动词表（185 个）。
5. 学生改写了照着走的数以后的状态：以前只认「排法回到改写以前」，改写中间挪过一下就一直卡在「照不下去了」。现在数回到原来那一组就接着照（排法不一样从现在的排法重新照）；直接写成做完的样子还是不算走完。
6. 认错法：以前只照引擎的「行」比、取第一个对得上的。现在舞台上另一个方向的整行也比（KMP 的 next 一整行照 PM 填认得出）；几种错法都对得上就都列出来；一组先后不论的照集合比。
7. 散列表的关键字 `01`，学生写 `1` 以前判错。现在答案和写的都是一串数字就按数比。
8. 引擎的报错还是黑板的写法（「要写 frames:」）；黑板外壳的字段（`title=` `q=` `note=` `vary=` `id=` `link=`）以前悄悄收下不起作用。现在报错里写成 `frames=`，外壳的字段当场报。

顺手：`follow` 接在表上时写 `call=` 当场报（以前悄悄丢掉）；`follows/heap.js` 里一句没有对应代码的注释删了；一般不说的组合画面上的字从「不这样说」改成「一般不这么说」（审查说前一个是页面对学生下的语法结论，has been being done 并非不成立）。

审查说测试只测了皮毛的三条：小数格（补了用例：7/4 写 1.75 对、写别的不对）；存档点回去（以前的断言恒真，改成真比）；大表的字认不认得（没有自动的办法：我演了一张 10 行 11 列的表、看了竖屏的截图，一格约 60×48、字认得、手指点得中）。

没修、记着的：

- `act.reached` 在两处是两个意思（做到的挑战的数组 / 到了一趟的 true），没验证出实害。
- 排序的过程表里两个 49 的答案都写「49」，老师从答案里看不出哪张带撇（照着走的那一排牌分得开）。
- 全是数的矩阵按格写、引擎的表按答案是不是数给键盘或输入框：格子的个数和键盘的种类透露了答案的形状（走查里定的，换来的是学生知道往哪写）。
- 「做不出来只记一道」的测试有一半是数源码里的字（另一半是报告的纯函数）；我在浏览器里点过三道，每道一条记录、没有多的动作。
- 「下课抄题用课堂手上的轮次」没有单独的单元测试（`desk.js` 要数据库）；e2e 的 `stagedrill` 一段里下了课的舞台课抄得进题库。

| 连点 − | 手 | 上一下还在演的时候再点不理：连点两下只走一格 | 修了：攒着，演完一次拨到位 |
