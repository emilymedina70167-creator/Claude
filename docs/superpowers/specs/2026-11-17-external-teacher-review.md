# 第十五轮设计的修改意见（外部主 Claude 审，2026-11-17）

审的是 `2026-11-17-external-teacher-design.md`（本分支）。写的人是以后要在学习台上课的外部主 Claude（claude.ai 项目对话）。**和原设计冲突的地方，以这一份为准。** 下面「学生定的」两条是学生 2026-11-17 的原话，不是我的建议。

## 0. 学生定的两条

1. **一步到位**：原设计的第 1～3 批一次做完、一次发布，不分批等真课。做完开发就停，开始上课。
2. **开发不约束外部怎么教**：学生原话「不能有他约束你怎么去教，怎么教是你的事情，我的偏好，需要这些，都会在你这里的记忆记着，不需要他有什么使用说明」。

第 2 条的边界：开发给外部的只有三种东西：**能做什么、写法是什么、页面会怎么做**（含平台的限制）。「什么时候做、先做什么、该怎么教、开工先读什么、下课要写什么」一律不写。学生的偏好在外部 Claude 的记忆和学生写的项目指令里，学习台不再存一份发给外部。

往手册、`ext_out`、`meta/catalog` 里加一句话之前，先问：这是写法 / 事实，还是做法？是做法就不加。

## 1. 总判断

- **方案 B 保留**（外部把整段回复写成一条 `ext_in`，走课堂原来的 `finishTurn`）。一轮一次写正好对上「Allow once」，组件、预案、标注、判分、报告都能用上。第 8.1 节那几处照做。
- 下面第 2 节删的、第 3 节加的、第 4 节手册的改法，是在 B 上的修改。

## 3. 要加 / 要改的

### 3.1 外部的板（原第 1 批，照原设计 + 8.1），另外：

- **一次 `db_write` 开课**：外部第一轮可以在同一次 `db_write` 里写 `sessions/{编号}`（开课的那几个字段）和 `ext_in/001`（两个 op，原子）。页面要能处理「两条同时到」和「`ext_in` 比 `sessions` 先被订阅到」。
- **下课也在 `ext_in` 里**：`text` 里一行 `board close`（或学生在页面点下课）。页面照「直接下课」处理，写 `status: closed`、出报告。这样下课不另写一次。
- **`ext_out` 的内容**：用 `buildSystem` 拼黑板现状的同一个函数（不另写一套）：作答行（带页面判分结果、第几次、用了多久）、没交的草稿、要拿下的事的状态、写法错误（排在最前）、板上现在有什么、助教给过的话、学生在每块板上停了多久。学生附的图、Pencil 写的字存 asset，列编号。**板的截图不自动存**（assets 上限 100 MB）：外部在 `ext_in` 里写一行 `board snap`，下一份 `ext_out` 才带当前画面的截图。
- **写法错误不能静默**：`ext_in` 里不认的块、组件写错、记忆块被守卫拦下，都要进下一份 `ext_out` 最前面，写清是哪一段、哪一行、为什么。

### 3.2 外部的预检工具（新加，最要紧的一件）

外部能跑代码，这是它比页面里的老师强的地方。实测（2026-11-17）：在外部的云端沙盒里 `node tools/check-lesson.mjs --shots … x.class.json` 能直接跑，Playwright 和 Chromium 是预装的，出了 iPad 两个尺寸的截图。

要做的：

- `tools/check-lesson.mjs` 认一种 `*.ext.json`（或者直接读一段 `ext_in` 的 `text`），带上当前这节课已有的板（从学习台导出的 `class_turns`），跑**和页面同一个**解析（`parseOutput`）、组件写法检查、`examLint`、题目答案验算（`problemLint` 那一套），出截图和问题列表。外部写进学习台之前先在自己的沙盒里跑。
- `kit/dist/la-kit.js` 和发布的学习台要是同一版：手册开头写版本号，工具跑的时候打出它用的版本，对不上外部看得出来。
- 工具不能要求 `npm install`（现在不用，保持）。
- 这个工具是给外部用的东西，不是规定外部每一轮都要跑。

### 3.3 练习教练（原第 2 批）

- 照原设计：`meta/today` 加 `kind: coach` 的项（`{ block, why, focus, ids }`），学生点开是页面里老师带的课。
- 教练的说明里，外部写的 `why`、`focus` 原样放进去，标明「主讲写的」；开发不另写教练该怎么教。

### 3.4 板边助教（原第 3 批）

- 照原设计：默认关；外部在 `ext_in` 里写 `board coach target=题号 upto=…` 才开那一题。助教只写一句，写在题下面，标「助教」，进下一份 `ext_out`。
- 助教的说明里只有：这一题的范围、外部写的 `upto`、学生这次的作答。不改板、不换讲法是页面限制住的（它没有写板的指令），不是写给它的话。

### 3.5 首页

- 班主任收起来，改成一行「在 claude.ai 对话里找主讲」（照原设计）。
- 首页「今天」照外部写的 `meta/today` 画；外部几天没来时，夜班照外部的 `计划/夜班.md` 写（第 9 节第 2 条照原设计的建议）；都没写，首页只列 `meta/facts` 的事实。

### 3.6 数据和记录

- 写入身份多一个 `ext`：`schema.js`、`memcheck`、`journal`、`log.by` 的枚举都认它（现在 `memcheck` 已经在报 `by` 不在枚举里的问题：W43、K23–K26）。
- 外部直接改数据（`meta/today`、`mastery`、`reviews`、`drills`……）时可以在同一次 `db_write` 里多写一条 `journal/j-…`。`journal` 的格式写进数据格式那一节；学生在「Claude 改过的」里看、撤销。页面不拦外部的写，格式不对照存、在 `meta/health` 里照实报。
- 现在挂着没下课的三节（`c-20261117-1`、`-2`、`-3`）：照「直接下课」收掉，报告照出。
- 学生的偏好、旧规则（`asks`、`lessons`、`rules`）不删、不再发给任何 Claude；外部要读自己去读。

### 3.7 量

- 来回时间照原设计（`ext_out` 写好 → 对应 `ext_in` 到达），下课写进报告。
- 学生定的及格线（外部建议，学生核）：真课里一个来回的中位数超过 60 秒，算外部主讲失败，回来再议，不靠加功能补。

## 4. 手册（`CLAUDE-PROJECT.md`）改成纯参考

**留**：

- 组件写法（`components/*.md`，现成）。
- 黑板指令写法（`PROTOCOL_DOC` 那一段搬进来，删掉规定形式的句子，第十四轮已经删过一遍的照它）。
- 数据格式：第七节现有的 + `ext`、`ext_in`、`ext_out`、`meta/today`（含 `coach`）、`meta/facts`、`notebook`（doc_id 怎么算，能不能按 `path` 字段查）、`journal`、日期按哪个时区。
- 页面会怎么做：判分、预案当场接、写错了怎么报、什么情况下翻板。
- 平台事实：外部每一轮第一次写会弹一次「Allow once」，没有「一直允许」；删除要带 `shared_live: deletes_rows`，不弹窗（2026-11-17 实测）；预检工具怎么跑。

**删**：

- 开头那段「我用学习台学习……你把内容拆成知识单元……每次只讲一个单元……」：是教法。
- 第一节（自学单元，已停用）、第五节（实时黑板，已停用）。
- **第二节「怎么设计一个单元（最重要）」整节**：全是教法（「让我自己得出结论，而不是看你讲」等）。外观那几条如果是写法事实（标题会画成圆圈、粗体显示成黄色）挪进组件写法。
- 组件说明里的教法建议：「最推荐」「先……再……讲」「一般先……」这类，逐句过；写法上的「必须写某个字段」留。

**守着**：手册里非组件写法的部分加关键词测试（照第十四轮的 `FORBIDDEN`：「你应该」「必须先」「最重要」「推荐」「照做」）。

## 5. 不归开发的（外部和学生自己做）

- 项目指令：学生自己写。
- 学生的偏好：在外部的记忆里，外部和学生一起整理；学习台里的 `asks` 等是原始记录。
- 往 claude.ai 项目知识放教材文字：外部自己做。

## 6. 验收

- `npm test`、`npm run build` 全过；e2e 照原设计加 `ext` 一段（模拟外部开课 + 三轮 + 一次写错 + `board snap` + `board coach` + `board close`），再加 `coach` 一段（首页点开教练课）。
- 预检工具：对一段 `ext_in` 文本跑出截图和问题列表的单元测试；故意写错一个组件，工具报出来、页面也报进 `ext_out`，两边说法一致。
- 手册的关键词测试。
- 发布以后学生用外部上一节真课；量来回时间。
