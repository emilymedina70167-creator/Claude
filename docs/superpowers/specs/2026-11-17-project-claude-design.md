# 第十四轮：学习台里的「项目 Claude」（设计）

2026-11-17 和学生商量定的。**这一份和以前任何一轮冲突时，以这一份为准；以前做的只要和这里冲突，一律让路（删掉，或者降成 Claude 可用可不用的工具）**（学生的原话：「之前做的什么只要和现在冲突了，一律给现在的方向让路，要么删除，要么其他处理办法」）。

## 1. 为什么

学生的话（2026-11-17）：

- 「我需要 Claude 来掌控这个学习台，而不是学习台去控制这个 Claude。我一直的初衷就是给我教学的 Claude 提供呈现能力和教学团队体系能力，而最近的开发越来越将 Claude 束缚，学习台是提供给 Claude 的工具。」
- 「我需要和 Claudeai 的记忆能力，我需要 Claude 项目能力进入我的学习台，在我的学习台里，他可以看到任何信息，可以进行信息检索，收集，整合……然后自己写记忆，摘要这些内容。」
- 「繁杂重复的活可以交给代码，但是决定决策类的所有……特别是记忆，都由 Claude 自己来记。」
- 不要开发这边替 Claude 设计它该怎么用这些能力：「怎么处理不应该是 Claude 自己去决定吗？」
- 「那个班主任不就是我要的 Claudeai 项目吗？」

开发这边查到的（第十三轮检查和 2026-11-17 的对话）：

- 记忆里「把一句建议写成必须」，字是 Claude 写的，框架是代码搭的：一类叫「学生的要求」、每轮全文放最前、写明「冲突时以它为准」、另派一个只看一句话的 Claude 去判「是不是要求」。
- 现在的记忆摘要由一个后台 Claude 照开发写的提示词重写，它只看得到一节课；错题、掌握、真题、预测分、教材它都看不到，提示词还不让它抄这些。整合是页面代码按规则挑着拼的，没有哪个 Claude 在整合。
- Claude 被拆成了很多个固定岗位（讲课、写摘要、复盘、归类知识点、出留题、课后助手、教研室、班主任），每个只看一片。
- 班主任最接近 claude.ai 项目：能按路径读任何一条数据、列任何一类、翻以前的对话；但它看到的是页面拼好的简报，开头是开发写的身份和做法，记忆只能写固定格式的一行，搜不了内容，不上课，建不了页面。

## 2. 要做成什么

**学习台 = claude.ai 项目 + 学习台的存储和教学呈现。** 班主任做成完整的「项目 Claude」，课堂里讲课的也是它：同一份学生写的项目指令、同一本它自己写的笔记、同一套工具；课堂里多一块黑板和板上的工具。

代码只做三件事：**工具**（读、搜、算、判、存）、**存放**（记录不丢、每一版留着）、**呈现**（板、画面、学生看得到改得了）。决定一律归 Claude。

## 3. 目标、不做、怎样算失败

**目标**

- G1 **项目指令只有学生写的。** 学生在「管理」里写、改；每一轮原样给 Claude。开发写的「怎么教、怎么判断、怎么记」不再发给它。
- G2 **项目知识库**：学习台里的一切（教材、真题和考点画像、每一次作答、每节课的记录和报告、错题弱点掌握、预测分、和班主任的对话、它自己的笔记）都能读、能搜。
- G3 **笔记本**：Claude 自己的长期记忆，它决定写什么、怎么分、什么时候改；学生看得到、改得了、退得回。
- G4 **一个身份**：班主任和每节课的老师是同一个项目 Claude（同一份指令、同一本笔记、同一套工具）。
- G5 **它能建页面**：它要给学生整理什么（复习页、知识体系、计划），自己建，学生在学习台里打开看，页面照样能放组件。
- G6 **它有机会做事**：课后、开课前、学生和班主任说话时，页面给它一轮带工具的调用；做不做、做什么它定。
- G7 回话不变慢：课上常用的东西页面先放好（由 Claude 指定哪些），课上不为检索多等。

**不做**

- 不替 Claude 设计它该产出什么（不规定笔记的格式和分类、不规定它要建哪些页面、不规定课后要写什么）。
- 不删任何旧数据。旧的十几类记忆、摘要、错题、作答都留着，成为它能读的原始记录。
- 不改舞台课、一问一答：它们和这一轮要让路的东西一起挪进废弃目录（6.9），学生以后决定怎么清理。
- 这一轮不动首页「今天」的挑题、复现排期、掌握的算法、预测分（第 8 节，下一轮交给 Claude）。

**做成这样就算失败**

- 页面又在替 Claude 定内容：给它的说明里出现开发写的「你应该……」「要先……再……」。
- 页面把 Claude 写的笔记当成命令（「冲突时以它为准」「必须照做」这类包装）。
- 旧数据丢了。
- 课上回话比现在慢。
- 笔记每一轮都要带的那部分悄悄变得很长、挤掉别的，没人知道。

## 4. 约束（学生定过的，代码卡住）

- 讲课、班主任、课后那一轮：只能是 Opus 5.5、effort high；回的不是就作废（不加退路）。
- 教学不预制（学生 2026-11-03 定的；页面不预写教学，只有答案固定的确认能预写）。
- 页面发给 Claude 的字里提到学生不用「他」「她」（页面拼的那部分；Claude 自己写的笔记存的时候不改，发出去时照旧换成「学生」）。
- `la-kit.js` 自包含；不用 `window.confirm` / `alert` / `prompt`；界面以 iPad 为准。
- 平台的事实：学习台里的 Claude 只在学生开着页面时被调用；同时最多跑两三个调用；每调一次工具多跑一整轮（课上大约多等十几秒）；Claude 通过 artifact 的 `sample` 能力调用，工具由页面实现（不能直接接 Anthropic 的记忆工具，做法照它）。

## 5. 做法的选择

- **A 在学习台里把 claude.ai 项目的几样能力做出来（选了这个）**：课堂里的老师就是项目 Claude，看得见板，当场接住作答；要我们自己写工具。
- B 直接用 claude.ai 项目本身，学习台只当黑板：记忆、知识库现成；但它在对话框里，看不见板，学生在板上作答它不当场知道。就是冻结的实时黑板那条路。排除。
- C 在现在的十几类记忆和摘要上继续修：修的是症状，代码替 Claude 定内容的结构还在。排除。

## 6. 设计

### 6.1 项目指令

- 新文档 `meta/instructions`：`{ text, at, by: 'me', history }`，不设长度上限（学生 2026-11-17：「为什么必须是 8kb，谁定的上限」——是开发拍的数，删了）。学生在「管理 → 项目指令」里写、改、看以前的版本。
- 每一轮给项目 Claude 的说明里，项目指令放在最前面，原样，不加任何包装（不写「以它为准」之类）。
- **第一版**：开发这边只把学生自己说过的话（带日期的原话，主要是第十二、十三、十四轮里的）列在一个草稿里给学生看，学生删改后存成第一版。草稿不自动生效。学生不写，就是空的。
- 第十二轮的根本规则（`charter.js` 的 `CHARTER`、`DIAGNOSE`）不再自动发；它的全文在「管理 → 项目指令」旁边能看到，学生想要哪句自己抄进指令。

### 6.2 项目知识库：读和搜

都是只读工具，班主任和老师同一套（在 `kit/src/project/tools.js` 里一处实现，两边都用）：

- `read path`：按路径读任何一条文档（班主任现有的，放大到 32 KiB；超了给前一段并说明还有多少、怎么接着读 `offset`）。
- `list collection [field value] [cursor]`：列任何一类，能翻页（现有的只给前 50 条）。
- `search q [in=…]`：按字找。范围：教材条目、真题和考点画像、作答证据、每节课的轮次（老师和学生的原话）、和班主任的对话、笔记本、旧记忆的十几类。返回命中的路径和那一小段原文，按相关程度排，最多 30 条。实现：页面已订阅的类在内存里找；每节课的轮次、对话按需读、读过的这一次打开页面内缓存。不做向量检索（学习台里没有；按字找加 Claude 自己换说法再找，先够用）。
- `textbook_read` / `textbook_page`、`view_image`、`calc`、`component_doc` 照旧。
- 页面已经算好的事实（课后报告、要拿下的事的状态、隔天验、掌握、预测分、真题统计 `meta/exam`）都是可读的文档，用 `read` 取；页面不再挑好拼进说明。

### 6.3 笔记本（Claude 的记忆）

照 Anthropic 记忆工具的做法：一个文件夹，Claude 自己管。

- 数据：`notebook/{id}`：`{ path, text, pin, show, at, by, v, history }`。`path` 像文件路径（`学生/底子.md`、`408/操作系统.md`，Claude 自己起）；`id` 是 path 的稳定编码。`history` 留最近 20 版（`{ text, at, by, v }`）。
- 工具 `notebook`（照记忆工具的几种操作）：`view [path]`（不写 path 列目录：每个文件的路径、大小、pin/show、最后改的时间）、`create path text`、`str_replace path old new`、`insert path line text`、`delete path`、`rename path new`、`set path pin=on|off show=on|off`。写之前页面不审内容；只有这几件机械的事：
  - `str_replace` 的 old 要在文件里恰好出现一次，不然不改，告诉它。
  - 每一次写都存一版；`delete` 只是标删除，学生能恢复。
  - 引号里的原话：页面按第十三轮的 `quoteFound` 查它在记录里有没有，没有的**不拦**，在那个文件的这一版上记一条「这几句引号在记录里没找到」，学生在管理页看得到，下一轮 `view` 那个文件时 Claude 也看得到。
- **每一轮带哪些**：`pin=on` 的文件页面每一轮原样放进说明（放在项目指令后面）。pin 不设单独的上限。唯一的限制是整份说明的总量（9.1 第 8 条）：页面每一轮在说明里照实写「这一轮说明一共多大、项目指令占多少、pin 的笔记占多少、资料还剩多少、总量的上限是多少」，学生在管理页也看得到。放不下时页面不替它挑：先放项目指令，pin 的按 Claude 给的先后（`set path pin=on order=…`，没写按最近改的）放，放不下的列出路径和大小。
- **怎么写、写什么、要不要 pin、要不要分科，全由 Claude 定。** 页面给它的说明里只写事实：这些工具、会留每一版、学生看得到改得了、pin 的上限、读一次要多一轮。
- **学生看和改**：「管理 → 笔记本」：目录、每个文件全文、直接改（存成 `by: me`）、看以前的版本、退回、恢复删掉的。`show=on` 的文件另外出现在导航新的一页「笔记」里，照课件渲染（Markdown + 组件，判分照常，作答照常记成证据，`session: 'note'`）。这就是 G5 的「它能建页面」：页面就是 show 的文件。
- **第一次**：笔记本是空的时，第一次项目 Claude 被调用之前，页面先给它一轮「整理」（6.5），说明里写明：笔记本还是空的，以前的记录在这些路径（列出旧的十几类、四份摘要、每类多少条）。它自己读、自己写第一版。学生在管理页看结果。

### 6.4 一个身份

- 新模块 `kit/src/project/`：`system.js`（纯函数，拼项目 Claude 每一轮的说明）、`tools.js`（6.2、6.3 的工具）、`notebook.js`（纯函数：路径、版本、pin 的装法、引号核）、`notebookdesk.js`（数据库那一层）、`notebookview.js`（管理页和「笔记」页）。
- 说明的结构（班主任和老师共用前几段，按多久变一次排）：
  1. 一句身份事实：你是学生学习台里的 Claude；学生在准备的考试（`target.js` 的考试档案）；今天、距考试几天、学习台版本。**只写事实，不写做法。**
  2. 学生的项目指令（原样）。
  3. 笔记本里 pin 的文件（原样）和笔记本的目录、pin 的总量。
  4. 工具手册：每个工具做什么、读一次多一轮（事实）。
  5. 课堂多这几段：组件写法和黑板指令（手册，删掉规定形式的句子，见 6.7）、这节课的上下文（这一块的教材原文、这一块在考试里——页面现在就在放，照旧先放好，因为课上检索要多等）、黑板现状、板的截图（第十三轮的 `eye`）。
- 班主任：`head/context.js` 的 `WHO`、`HOW`、`MEMO_HEAD*`、三科简报、预测分那几段换成上面 1～4；对话照旧存 `chats`。班主任能建、改笔记本，能写项目指令吗？**不能**：项目指令只有学生写（`by: me`）。
- 老师：`buildSystem` 有学习台时改走 `project/system.js`；第一节「角色和根本规则」、「你对学生的了解」、`DESK_DOC` 里的记忆块说明都换掉。
- 两边都写笔记本，同一个文件同时被两边改的：照现有的写库出口排队；`str_replace` 对不上就失败、告诉它，不会互相盖掉。

### 6.5 它有机会做事（页面给的几轮调用）

页面只负责「给它一轮」，不规定这一轮做什么。每一轮的提示只说发生了什么（事实）：

- **课后那一轮**：一节课下课（或挂着 12 小时当它下课，照现有的 `idleClose`）以后，首页后台（`lane: 'bg'`）给项目 Claude 一轮，带全部只读工具和笔记本工具；提示只说「这节课（编号、标题）结束了，课后报告和记录在这些路径」。它想整理笔记、建页面、什么都不做都行。这一轮替换掉第十三轮的摘要重写、复盘（`debrief.js` 的固定流程）、课后的助手（`aide/after.js`）。一节课只给一次（`sessions/{编号}.after = { at, model }`），没成（不是 Opus、出错）下次打开首页再试，试满 2 次停，管理页写着。
- **开课前**：学生点「开新课」时，第一轮本来就是项目 Claude 自己（它可以先读要的东西再开讲）；页面不另加一轮。
- **和班主任说话**：每一轮都是。
- **每周一次换一双眼睛**（开发的推荐，学生没反对；见第 9 节）：一个没有对话历史的项目 Claude，读笔记本和原始记录，回一份「哪些过时了、哪些互相矛盾、哪些可能是从一句话推广出来的、哪些原话找不到出处」，存成 `notebook_review/{日期}`。它不改笔记本；下一次项目 Claude 被调用时说明里带一句「上周的通读在这个路径」，改不改由它定。学生在管理页看得到。

### 6.6 页面替它放好的（速度）

- pin 的文件、项目指令：每一轮都在。
- 课上：这一块的教材原文和考情照现在的做法先放（`bookroom.js`、`examroom.js`），学生正在上的那块板的截图（`boardeye.js`）。
- 以前的课：开课时页面先取的「以前的课」（`classroom.js` 的 `fetchEarlier`）不再由页面挑，改成：笔记本里 Claude 自己 pin 的东西就是它要的背景；要更多它自己 `read`。

### 6.7 冲突的东西怎么处理

照「决定归 Claude、繁杂的归代码」逐一过（清点的依据：2026-11-17 列出的每个调用模型的地方、每个往记忆写的地方）：

| 现在的 | 处理 | 哪一轮 |
|---|---|---|
| 根本规则 `CHARTER`、`DIAGNOSE`（开发写的怎么教） | 不再发；全文在管理页给学生看，学生要的自己抄进项目指令 | 这一轮 |
| `SUBJECT_FACTS`（每门课的口径、板上有什么组件） | 留：是事实和手册 | — |
| 黑板指令说明 `PROTOCOL_DOC` 里规定形式的句子（「板顶的话只是一两句招呼」、常驻栏「要短……不放题」、卡住时「只轻轻问一句」等） | 删这些句子，留指令怎么写、页面会怎么做 | 这一轮 |

## 9.1 读过以后定的（建造者读设计时问的，开发定，学生核）

1. **学习的账这一轮照旧转**：工具手册里留着 memo 块写 `error` `weakness` `review` `position` `recall` `todo` 的写法（是手册，不是做法）。下课时说明里写事实：「学生点了下课」；是复现课的再写「这节课复现的组是……（编号、题目），复现结果要写 `review id=… result=…` 页面才会记」；有开头复现的同样写。不再要求写小结、整理单、守则。这样首页的复现、错题本不会停摆，下一轮再整体交给 Claude。
2. **课上写笔记本用输出里的块，不用工具调用**：`board note` 块（`create` / `str_replace` / `insert` / `delete` / `rename` / `set` 一行一条，和 memo 块一样在这一轮讲完后由页面执行），不多等一轮；对不上的下一轮第一句告诉它。课上读笔记本、读和搜知识库仍是工具。首页（班主任、课后那一轮、整理、通读）不赶时间，笔记本直接用工具。平台不支持工具时（`tools: false`）只剩块和 pin 的内容，照实写在说明里。
3. **清掉开发写的做法，范围是页面拼给项目 Claude 的全部文字**：身份、黑板指令说明、`EYE_DOC`、`CANVAS_DOC`、`AIMS_DOC`、`stuck.js` 的提醒、`actionText` 等系统消息里的措辞，逐句过：讲「怎么写、页面会怎么做」的留，讲「该怎么教、该先做什么」的删。组件手册（`CLAUDE-PROJECT.md` 第三节）这一轮只删明显的教法建议（「最推荐」「先……再……讲」这类），写法照留。关键词守卫只守 `project/system.js` 自己拼的那几段（身份、工具手册、下课那句、整理和通读的提示），不守组件手册（手册里「必须写某个字段」是写法上的事实）。
4. **第一次整理放后台，不挡开课**：笔记本空着时首页后台先做（`lane: 'bg'`）；还没做完学生就开课，照空笔记本开，说明里写一句事实「笔记本还是空的，以前的记录在这些路径」。
5. **资料包这一轮照发**：放在「这节课的资料」一节（复现课的 `reviewPack`、备好的教案、`carry`），标明来源（页面拼的 / 以前备课的 Claude 写的），不标「照着做」。备课本身下一轮交给 Claude。
6. **别处读记忆的路径**：舞台课、一问一答挪进废弃目录，不再有。教研室补收尾（`lab.js`）、备课 `prepMemory`：笔记本不空时改读 pin 的笔记，空时照旧。
7. **「笔记」页上的作答**：只记成证据（`session: 'note'`），这一轮不进掌握、课后报告、题库。
8. **长度**：不给项目指令、笔记本单独设上限（学生 2026-11-17 问「谁定的上限」，那是开发拍的数）。只有整份说明一个总量：每一轮整份重发，越长越慢、越挤资料。现在的 160 KiB（`SYSTEM_MAX`）也是开发定的；以前量过 4～160 KB 回话一样快（`docs/talk-plan.md`），模型一次能读 100 万 token。动手的第一件事是量：用学习台的真接口发 160 / 300 / 500 KB 的说明各几次，看出第一个字的时间，照量出来的定这个总量，写进代码的注释和这里。每门课资料包至少 96 KiB 的测试（`tests/subject.test.js`）跟着改成照新的总量算。

## 10. 风险

- **它不写或者写得乱。** 这是放开以后真可能发生的。挡它的不是代码，是学生看得到、每周通读、和真课以后开发读笔记。开发不往说明里加做法；看到问题和学生说，学生决定要不要写进项目指令。
- **它在课上查太多，回话变慢。** 工具手册写明读一次多一轮（事实）；课上要用的它可以先 pin。量真课的等待。
- **pin 的东西越来越长。** 有上限，超了照实写在说明里，学生管理页也看得到。
- **两边同时改一个文件。** `str_replace` 对不上就失败；同一个文件的写排队。
- **旧的学习的账还在用 memo 写，和笔记本里写的同一件事两处说法不一样。** 下一轮整体交给 Claude 时一起收。
