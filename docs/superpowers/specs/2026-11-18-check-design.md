# 计划 2：二类组件（学完以后的吸收检验）· 先做数学 —— 设计

2026-11-18 写。需求是学习台 `dev_requests/dr-plan2`（外部主讲写的任务书，`status: design`）。和计划 1（`dr-batch4`，另一个 Claude Code 对话在做）同时改同一个仓库。这份是设计；执行计划在 `docs/superpowers/plans/2026-11-18-check.md`，写进 `dr-plan2` 的 `plan` 字段，外部同意了才动手。

## 一、为什么

学生原话：「学完要面对什么样的测验，决定了我学的时候怎么想」「测了之后我就能懂，不求一下子完全掌握，但要明白、吸收成功」「不管难度怎么样，二类的作用不能不行，简单内容也有精准打击的点」。

现在组件库的组件是「一类」：讲解、演示、课中的小练习（能看提示、能反复试、答完马上出答案）。它们的作答只说明「当时跟着做出来了」。「二类」是一节课学完以后的吸收检验：

1. **测得出真证据**：学生自己生成答案（不从选项里认），结构换了的新题也做得出，第一次、不看板书、不靠提示。
2. **测完就懂**：错了精确指出错在哪 → 只补那一个点（一两句）→ 马上一道同构小题自己做对。
3. **不浪费时间**：深浅按内容分档，每一档都有一道对准这一块典型错法的题。

## 二、目标、不做、做坏了是什么样

**目标**
- 外部能用六种探题（recall / construct / claim / solve / discriminate / locate）写一次检验 `board check`，页面合书呈现、当场判、按外部写好的接法接、记录。
- 每块出一个页面判的「吸收」（成功 / 部分 / 未 / 待核），外部核过才算定。
- 学生能在检验里用 Apple Pencil 直接写，过程（停顿、划掉、分步）给外部看得见。
- 1 天、7 天的复测按到期排进「今天」的事实，从题库里没见过的同类题出。
- 外壳、判、记录不绑数学：408、英语以后只加探题类型。

**不做**
- 选择题、演示动画、防作弊（合书靠学生自觉）。
- 页面或页面里的 Claude 自己出题（缺新题照实报）。
- 改现在的掌握状态那一套（讲过 / 基础题过 / 复现通过 / 掉了）和 `mastery` 文档。
- 408、英语的探题类型。

**做坏了的样子（哪怕功能都在）**
- 判得宽：页面里的 Claude 拿不准时放过，「吸收成功」是假的。拿不准一律 `unsure` → 待外部核。
- 补讲变成一大段讲解、直接给出整题答案。补讲只放外部写的 `teach`；外部没写到的错法，页面里的 Claude 只照外部写给它的话做（第五节 5.3）。
- 一次检验拖很久：每次交都等很久、判不出来卡住。机器能判的不调 Claude；要调的一次调用转写和判一起出。
- 检验的作答混进练习、练习的作答冒充检验。来源分开（`src: check`）。

## 三、约束

- 页面调用的 Claude 只用 Opus 5.5 high（`classroom.js` 的 `TEACH`），回的不是它整次作废——判分那一次也一样：作废时这道题标「待外部核」，不重试第二次（不让学生多等）。
- 开发不约束外部怎么教：手册、提示词、`ext_out` 里只写写法、事实、页面会怎么做；不写「你应该怎么判宽严」。
- 计划 1 的 `solve` 组件、`board judge` 指令、证据的 `steps: [{ id, ok: true | false | 'missing' | null, why, tag }]` 三样照计划 1 的名字用，不改名（外部 2026-11-18 的 review 要求）。`unsure` 的步 `ok: null`，画「？待外部核」，不进错题本。
- 手写作答板（`features.js` 的 `handwriting`）照旧关着；检验里的手写板是另一块，只在检验里出现。
- 一个数据库文档最多 256 KiB；一次调用的文字（说明加对话）一共最多 256 KiB。
- 不用 `window.confirm` / `alert` / `prompt`；触控目标 ≥ 44px，输入框 16px。

## 四、做法对比

| 做法 | 是什么 | 好处 | 坏处 |
|---|---|---|---|
| **A（选这个）**：六个组件名 + 一条 `board check` | 每种探题一个组件（`recall` `construct` `claim` `discriminate` `locate`，加计划 1 的 `solve`），共用一组检验字段；外壳是一条 `board check`，块里内联写全部探题，几行写每块的必做 / 可选 / 备用 | 名字和任务书、计划 1 一样；每道题能单独预检、单独存进题库、复测时按「同类没见过」单挑；外壳和题型分开，408、英语只加题型 | `board check` 的块会长（一次十几道题）；组件单独写在板上（不在检验里）时要有个说法 |
| B：一个大组件包全部 | ```` ```check ```` 里写全部题 | 写起来集中 | 一道题不能单独预检、存题库；外壳和题型缠在一起；和计划 1 的 `solve` 是两套 |
| C：一个 `probe` 组件 `type:` 分六种 | 一个名字 | 解析器一个 | `probe type=solve` 和计划 1 的 `solve` 又是两套；任务书写的是「每一种独立的写法」 |

选 A。组件单独写在板上（不在 `board check` 里）时只画成预览（「这是检验题，放进 board check 才能作答」），预检和页面检查都能画它、查写法；这样不会出现「检验题当练习做了、记成练习」。

## 五、设计

### 5.1 写法

**外壳**（外部的课和页面里的老师都能写；第四节黑板指令）：

````
````board check id=k1 title="第二讲第一节 检验" limit=15m pause=30s
block L2.1.1 must=p1,p2
block L2.1.4 must=p3,p4,p5,p6 optional=p7 fast=90s
spare p8,p9
<<<
（可选）外部没预料到的错法时，给页面里的 Claude 的话。
>>>
```construct
id: p1
…
```
```recall
id: p3
…
```
…
````
````

- `block 块 must=… optional=… [fast=]`：一块一行，按写的先后做；块里先做必做、再做可选。
- `spare`：备用题，不出现在这次检验里，只存进题库给复测。
- 块里每道题的 `retry:` 指到的题（同构小题）也写在这个块里，开始时不出现。
- 没排进任何一行、也不是谁的 `retry` 的题报写法错误。
- `limit=`：第一次作答部分一共多久（不写不限时）；`pause=`：手写停多久算「停顿」（默认 30s）。
- `<<< >>>`：可选，外部写给页面里的 Claude 的话（5.3）。

**六种探题共用的字段**

| 字段 | 必填 | 意思 |
|---|---|---|
| `id` | 是 | 这一次检验里唯一 |
| `q` | 是 | 题面（Markdown，可以有 `$公式$`） |
| `target` | 是 | 打的是哪个典型错法：错题、误解的编号或一句话（`L2-56`、`AB 和 BA 先后混`） |
| `level` | 是 | `基础` / `方法` / `核心` |
| `facet` | 否 | 测的是吸收的哪一面：`重建` / `能用` / `边界` / `能辨`。不写按题型：recall 重建、construct 能用、claim 边界、solve 能用、discriminate 能辨、locate 能辨 |
| `teach 键: 话` | 必做题至少一条 | 判出这一项失败时显示的一两句补讲。键是失败的那一项的编号（`if2`、`m1`、`s3`、`tag=规则用错`、`truth`、`can`、`line`、`giveup`），`default` 兜底 |
| `retry` | 必做题至少 2 道 | 同构小题的 `id`，按先后用；同构题和本题同一种题型 |
| `family` | 否 | 同类的键，复测按它挑没见过的题。不写是 `块/target` |
| `let 名字 = 式子` | 否 | 题里用的量（写法同 `answer`） |

**各题型自己的字段**

- **recall 重建**：`must m1: 要点`（每题最多 3 条）、`may m4: 可选要点`、`wrong w1: 常见错说法`、`answer: 参考答案`（判完给学生看）。作答：打字，或检验手写板（5.4）。判：页面里的 Claude 照要点判（5.3）。过 = `must` 全写到、没写 `wrong` 里的错说法。
- **construct 构造**：`slots: A=mat(2) B=mat(2)`（`mat(r,c)` `vec(n)` `num`）；`if: 条件 => 不满足时说的话`，一行一条，编号 `if1` `if2`…（条件写法同 `answer` 的 `check:`，名字是 slots 里的；平凡答案不算也写成条件：`if: A != O => 零矩阵不算`）；`expr 标签: 标准式子`（可选：要学生再写一个用 slots 名字的式子，比如「两边差的那一项」，按非交换多项式判相等，`ncalg.js` 的 `equivalent`，严格模式）；`example: A=[[0,1],[0,0]] B=[[1,0],[0,0]]`（必填：页面先拿它验一遍每一条，不满足报写法错误）。作答：每个名字一个矩阵 / 向量 / 数框（`answer` 现在的输入框）。判：页面逐条核，**每条不满足的显示那一条自己的话**，全部列出来（不是只报第一条）。
- **claim 判断加依据**：`claim: 命题`、`truth: 真 | 假`。学生先点「真」或「假」，再：判假要给反例（字段同 construct：`slots` `if` `example`）；判真要写证明要点（同 recall：`must` `may` `wrong`），或 `proof: derive` 配 `start` `goal` `vars` `let`，照 `derive mode: do` 逐行核（`derivedo.js`）。判：真假页面判；反例页面核；要点页面里的 Claude 判。过 = 真假对 **而且** 依据过；只判对真假不算。
- **solve 全过程**：计划 1 的 `solve`（`q` `steps` `judge` `upload`），加上面共用的字段。在检验里：`judge` 一律是 `claude`（立刻的反馈只能页面给），作答多一种「检验手写板」（5.4）；判照计划 1 的逐步判，结论是 `steps`。过 = 每一步 `ok: true`。
- **discriminate 辨**：`can: 能 | 不能`（这节方法能不能用）、`must m1: 理由要点`（「为什么」「能用怎么用 / 不能用用什么」都写成要点）、`result: 式子`（可选：最后结果，照 `answer` 的写法精确判）。判：能不能页面判，理由页面里的 Claude 判。过 = 能不能对、理由过、`result` 对；**能不能对、理由没过 = 没过**。
- **locate 找错**：`line: 解答的一行`（几行）、`bug: 第几行`（同 `findbug`）、`must m1: 为什么错的要点`、`fix: 式子`（可选：改成什么，按 `ncalg` / 精确值判；判不了的改正写成 `must`）。判：点哪行页面判，理由页面里的 Claude 判，`fix` 页面判。过 = 三样都过。

### 5.2 外壳：一次检验怎么走

开始：执行 `board check` 时页面先在当前位置出一张卡「检验：第二讲第一节 · 2 块 · 6 道必做 · 15 分钟」和「开始」。学生点开始以后：

- **合书**：板、常驻栏、翻板条、整页板书收起来，检验占满黑板那一块；做完（或学生点「先停下」）放回来。外部这时写来的 `ext_in` 照常执行，画好的板做完检验才看得到。
- **一道题**：题面 → 作答 → 点信心「很确定 / 大概 / 蒙的」（必点，点了才能交）→ 交 → 判。没有提示、没有「看答案」；「想不出来」一直在（记成失败，键 `giveup`）。
- **判出来以后**（5.3 的结论）：
  - 过、信心不是「蒙的」：✓，下一道。
  - 过、信心是「蒙的」：写「蒙对的不算」，出 `retry` 的第一道确认；做对算补上。
  - 没过：列出失败的每一项（构造的那一条自己的话、漏的要点、错的步）→ 显示对上的 `teach`（先按键找，再 `default`）→ 出 `retry` 的下一道 → 学生自己做 → 过了这一点算**补上**；又错接着下一道；`retry` 用完记**未吸收**。
  - 外部没写到的错法（失败的项没有对上的 `teach`，也没有 `default`）：叫一次页面里的 Claude（5.3），它写的话当补讲，然后照样出 `retry`。
  - 拿不准（`unsure`、判分那一次作废）：写「这一处页面拿不准，主讲会核」，**不补讲、不出 retry**，下一道；这道题待核。
- **可选题**：这一块必做题都一次过、信心都是「很确定」（写了 `fast=` 的还要每道第一次作答在这个时间里）就跳过；否则做。
- **时间**：`limit` 只算第一次作答（题在屏幕上、页面在前台的时间；补讲和 retry 不算）。到了写「时间到」，没做的照样能做，但记 `late`：做对最多算补上。每题记 `ms`（第一次交用了多久）、`msTotal`（连 retry 一共）。
- **结束**：每块一行「吸收：部分（页面判，待主讲核）· 重建 ✓ 能用 补上 边界 ✗」，点「回到黑板」放回板书。

外壳是一个和黑板分开的控制器（`kit/src/check/shell.js`），三处能开：外部的课（`board check`）、页面里的老师的课（同一条指令）、复测的课（`kind: check`，整页就是它，5.6）。

### 5.3 判

**页面机器判的**（不调 Claude，当场出）：construct 的每一条 `if`（条件写法和容差照 `anscheck.js`，但列出全部不满足的）、`expr`（`ncalg.js` 严格判相等）、claim 的真假和反例、`proof: derive` 的逐行、discriminate 的能不能和 `result`、locate 的哪一行和 `fix`。

**页面里的 Claude 判的**（要点、证明要点、理由、solve 的步骤）：每交一次调一次 Opus 5.5 high（前台，学生在等），给它的只有事实：题面、外部写的要点（`must` `may` `wrong` 的原文和编号）或参考步骤、学生这次交的（打的字；手写的整页图）、错法词表（计划 1 的 `STEP_TAGS`）、写法。要它回：

```
[转写]                      （只有手写时有）
L1: …
L2 [划掉]: …
[判]
m1 ok
m2 missing
w1 wrong why="写了 (A+B)²=A²+2AB+B² 对所有方阵成立"
m3 unsure why="第 3 行看不清是 AB 还是 BA"
```

`[判]` 的行和计划 1 的 `board judge` 同一种写法（`ok` / `wrong` / `missing` / `unsure`、`why=`、`tag=`），用计划 1 的解析函数读；结论都是 `{ id, ok: true | false | 'missing' | null, why, tag }`。手写的转写和判是同一次调用（少等一轮）。提示词里写一句事实：「看不清、拿不准对错的写 unsure，页面会标待主讲核」（外部 review 要的那句）。漏了的要点（没写到那一行）当 `unsure`。

**外部没写到的错法**时的那一次调用：给它题面、外部写的要点和 `teach`、学生这次交的、这次失败的项、`board check` 里 `<<< >>>` 外部写给它的话；它回一段话，页面原样显示成补讲。外部没写 `<<< >>>` 时，页面用外部在任务书里写的那句（「指出错在哪、只补缺的那一点，不给整段答案」）当默认的话——这是外部定的，手册里写明「默认给它的话是这一句，写了 `<<< >>>` 就换成你写的」。

**外部改判**：之后任何一轮 `board judge target=p3`（计划 1 的指令，target 可以是检验里的任何一道题），行的编号是那道题的项（`m1`、`s3`、`if2`），加一行 `result=pass | fail` 改整道题。页面追加一条判定证据（不改原来那条），重算这块的吸收；外部也可以直接写 `absorb/{块}`（5.5）。

### 5.4 检验手写板

`kit/src/check/inkpad.js`（画面）+ `inktime.js`（纯函数）。在 recall、claim 的证明、solve、discriminate 的理由、locate 的理由里，作答区有「打字 / 手写」两个页签，默认手写。

- 每一笔带 `t0`、`t1`（从这道题出现开始的毫秒）；引擎的笔画结构不改，多两个字段。
- 没有橡皮：「划掉」工具，笔在写过的字上划过，碰到的笔画记 `struck: 时刻`，画成淡灰加一道线（留痕）。「撤一笔」只撤最后一笔、而且是 5 秒内写的（笔误）；划掉也能撤（3 秒内）。
- 「下一步」按钮：记一个分步的时刻（solve 用）。写满了「加一页」往下加 600px。
- **交的时候页面从数据算**（不当场截图）：
  - 行：按笔画的上下位置聚成行（`inktime.js` 的 `linesOf`），从上往下编号 L1、L2……；整页图左边空白处淡淡写上行号，转写按这个行号写，时间线也用它。
  - 整页图：白底，划掉的灰色带线，左边行号。
  - 关键时刻：停顿超过 `pause` 的、每次划掉之前、每次「下一步」；最多 6 张（先划掉，再最长的停顿，再分步），每张是「那一刻写在纸上的」重画出来的图。
  - 时间线一段字：「0:00–1:20 写 L1；停 45 秒；1:35 划掉 L2（划前见快照 2）；2:10 下一步」。
  - 快照的文字不另调用 Claude：快照里有哪几行是从数据算的，文字照整页的转写取（划掉的行整页图上看得见、转写里标了）。任务书写的是每张快照先转写，那样一道题要多调好几次、多等好几轮。
- 整页图和快照传进 assets（这节课的 `uploads`），证据里写 asset 编号；笔画存一份 `sessions/{编号}/ink/{证据编号}`（坐标取整、超过 200 KiB 只留最后的样子）给回放。课后在「以前的课」里那道题下面有「回放」（照时间重画）；外部看快照和时间线。

### 5.5 记录

**证据**：每道探题（含 retry）一条，`src: "check"`（照现在的习惯：`src` 是来源、`kind` 是题型），`kind` 是题型，另有：
`check`（检验 id）、`probe`（题 id）、`retryOf`（retry 的才有）、`block`、`target`、`level`、`facet`、`first`（第一次交的作答原文；手写的是转写和 asset 编号）、`items: [{ id, ok, why, tag }]`（每一项的结论：if / m / s / truth / can / line）、`steps`（solve 的，和计划 1 一样）、`outcome: pass | fail | pending`、`sure: sure | maybe | guess`、`late`、`giveup`、`ms`、`msTotal`、`teach`（显示了哪一条补讲的键，Claude 写的存全文）、`judgedBy: page | claude | ext`、`ink: { final, shots: [{ at, why, asset }], timeline }`、`retest`（复测的才有：1 / 7）。

**吸收**：新集合 `absorb/{块}`（`#` 换 `~`），状态类，改 `state` / `checked` 记 log：

```
{ block, space, state: "成功" | "部分" | "未" | "待核", facets: { 重建: "ok" | "fixed" | "fail" | "pending", … },
  by: "page", checked: false, check: "k1", session: "c-…", at, probes: [证据编号], confidentWrong: [题 id], debt: [target…],
  retests: [{ due: "YYYY-MM-DD", days: 1, done: null }, { due, days: 7, done }], retryOwed: [题库编号],
  history: [{ check, session, at, state, facets }]（最近 5 次）, log: [{ at, state, checked, by, note }] }
```

- 页面判（每块）：必做和做了的可选都一次过、不蒙、不 `late` → **成功**；有补上的（retry 做对、蒙对了再确认、`late` 做对）→ **部分**；有 retry 用完的、想不出来又没补上的 → **未**；没有「未」但有拿不准的 → **待核**。
- `checked: false` 是「页面判，待外部核」。外部核：直接写 `state`、`checked: true`、`by: "ext"`，log 加一行。
- 「很确定却错了」的题记在 `confidentWrong`，`meta/state` 单独写一行。
- 欠账：未吸收的 `target` 记在 `debt`，`meta/state` 和简报里写着；**不替外部写进 `position.debts`**（下节课开头做什么是外部定的）。
- `meta/state-{科}` 每块多一行「吸收：部分（页面判，待核）· 11-18 · 重建 ✓ 能用 补上 边界 ✗ · 复测 11-19、11-25」；最近的作答分开写「检验」和「练习」两组。

**练习和掌握**（任务书：一类的作答记成练习，不改吸收和掌握）：吸收只看 `src: check`。页面算的掌握参考（`mastery.js` 的 `masteryCalc` → `meta/mastery-calc`）分两种情况：这一块有了检验的证据以后，只数检验和复测（第一次作答；「蒙的」当没把握）；还没有的块照旧数练习，`meta/state` 写「（按练习算，这一块还没检验过）」。不这样分的话，所有没检验过的块参考掌握全部停住，练一练、隔天验也跟着失效。`mastery` 文档照旧由外部写。`forecast`（预测分）这一批不动。

**题库**：新集合 `probes/{pr-…}`：`{ fence（原文）, type, block, target, level, facet, family, src: "ext" | "lab", from: { session, check }, seen: [{ at, session, as: "first" | "retry" | "retest" }], at }`。`board check` 执行时页面把里面每道题（含 retry、spare）存进去，同一道题（原文一样）不存两份；学生见过就记 `seen`。外部、夜班也可以直接往里写题（写法同 `board check` 里的一道）。

**`ext_out`**：开始时一行「[页面] 检验 k1 开始（2 块、6 道必做、限时 15 分钟）」；做完一份整体的：每块的吸收、每道题一行（第一次的作答、每一项、信心、用时、补讲、retry 的结果、谁判的、拿不准的）、手写的 asset 编号和时间线。中途不一道一道写（外部这时接不上，写了也只是刷屏）。证据照旧进 `since-analysis`（`trail.js` 的 `evidenceLine` 多一种 `check` 的写法）。

### 5.6 复测

- 每块检验完写两次复测：1 天、7 天（上海的日期）。到期的写进 `meta/facts` 和「今天」的事实一行「复测：L2.1.4（隔 1 天）」；`meta/today` 的 `kind` 多一种 `retest`（外部写今天时能排它）。
- 点了开一节 `kind: check` 的课（`sessions/{编号}`：`{ kind: "check", retest: [{ block, days }], items: [题库编号], … }`）：整页是检验外壳，没有主讲；题从题库里挑——这一块每个必做的 `family` 挑一道没见过的；没有没见过的就不挑，`meta/facts` 写「缺新题：L2.1.4 的 L2-56 那一类」（页面、页面里的 Claude 都不出题，外部或夜班补）。
- 复测的证据带 `retest: 1 | 7`，进掌握参考，不改吸收（任务书：「掌握是以后隔 1 天、7 天……跟这次分开记」）。补讲、retry 照常有。

### 5.6′ 判分不让学生干等

页面里的 Claude 判一次（带手写整页图）要几十秒。一次检验里要它判的题常有四五道，一道一道等就是好几分钟。所以：

- 交了要它判的题，学生**马上做下一道**；判完回来的结论排进队里。
- 每做完一道（交了，或补讲、retry 走完）先看队里：有判出没过的，先做那一道的补讲和 retry，再往下做新题。同一块里前后颠倒一下（p4 做完才回头补 p3），可以接受。
- 一次判分最多等 90 秒，到了当这道题待核（`unsure`）。
- 到了某一块的可选题时，这一块的必做还有没判完的：当作不是都一次过，可选题照做。
- 最后一道交完、还有没判完的：结束那一屏写「还在判 2 道」，最多等到各自的 90 秒；那时没判出没过的就没有补讲。

### 5.6″ 中断、接着做

- 每走一步（交一道、判回来、补讲、retry、结束），页面把进度存进 `sessions/{编号}/check/{检验 id}`：`{ id, spec（原文）, state（flow 的状态）, visibleMs, startedAt, endedAt }`。没交的手写笔画存在这台设备上（`localStorage`，键带课号和题号），交了就删。
- 刷新、熄屏、切走以后回来：照存的状态接着做。看过题面、还没交的那道照旧算第一次作答（合书靠自觉），证据记 `resumed: true`。`limit` 只数页面在前台、题在屏幕上的时间，接着算。
- 「先停下」：板放回来，检验那一块变成一条「检验 k1 · 做到第 4 道 · 接着做」；接着做照上面。
- 没做完的块不出吸收（不写 `absorb`）；`ext_out` 和 `meta/state` 写「检验 k1：L2.1.4 没做完（做了 2/4 道必做）」。外部写 `board close` 或学生点「下课」时检验还开着：照「先停下」存着，下课照常；那一块没做完。
- 同一块以后又做一次检验：`absorb/{块}` 的 `state` 照最新的一次，前几次留在 `history`（最近 5 次）；复测按最新的一次重新排。

### 5.7 和计划 1 的接口

计划 2 用到计划 1 的只有纯函数和字段名，不用它的画面：

| 计划 1 交出来的 | 计划 2 怎么用 |
|---|---|
| `solve` 的写法解析（`q` `steps`（`s1 setup: …`）`judge` `upload`）——函数名照计划 1 | 检验里的 solve 先用它读题，再读共用的检验字段 |
| `board judge` 的行的解析（`s3 wrong tag=… why="…"` / `missing` / `ok` / `unsure`）→ `[{ id, ok, why, tag }]` | 页面里的 Claude 判要点、判步骤回来的 `[判]` 那几行；外部改判 |
| `STEP_TAGS`（错法词表） | 给页面里的 Claude 的事实；证据的 `tag` |
| 证据 `steps` 的形状、`unsure` → `ok: null` | 检验证据的 `steps`、`items` |
| `timing.js`（题在屏幕上的时间，切走、锁屏不算） | 检验的 `ms`、`limit` |

计划 1 的计划只写了写法和字段、没写函数名，替身只能猜接口。所以**不做替身**，改成排顺序：

- 不碰 solve 的先做（外壳、五种题型、判、手写、记录、复测）。判要点回来的 `[判]` 行先用检验自己的 `parseVerdict`（写法和 `board judge` 一样，测试照计划 1 的写法写）；看题在屏幕上多久先用检验自己的一个小计时（页面在前台、外壳在屏幕上才走）。
- 检验里的 solve 放在最后一件，**等计划 1 合进主干再做**：那时照计划 1 真的函数接上；计划 1 有同样的行解析就删掉 `parseVerdict` 改用它（测试照跑），`timing.js` 有了就换掉小计时。
- 计划 1 的 `board judge` 是去板上找组件执行的：`target` 是检验里的题时，`classroom.js` 先交给检验（一处分流）。

名字对不上时以计划 1 为准，计划 2 改自己。

## 六、自己定的事（外部看计划时可以改）

1. 写法选 A（第四节）；组件单独写在板上只画预览。
2. 「蒙的」做对：出一道 retry 确认，做对算补上。
3. 拿不准（`unsure`、判分那一次作废）：不补讲、不出 retry，待核。
4. 可选题怎么跳：必做都一次过、都「很确定」，写了 `fast=` 的还要都在时间里。
5. 时间到了不收卷，记 `late`，做对最多算补上。
6. 证据用 `src: check`（任务书写的是 `kind: check`）。
7. 快照的文字不另调用（5.4）；手写的转写和判是同一次调用。

10. `ext_out` 只在开始和做完各写一次。
11. 复测在 1 天、7 天；缺新题照实报，不自动出题。
12. 外部没写 `<<< >>>` 时，页面里的 Claude 的默认话用任务书里外部写的那句。
13. 判分不让学生干等：交了先做下一道，判回来没过的在下一道做完时插进来补；一次最多等 90 秒，到了待核（5.6′）。
14. 中断了能接着做，看过没交的照旧算第一次；没做完的块不出吸收（5.6″）。
15. 外部事后把待核的判成没过：这一项照「未」算（学生没机会补，但也没做出来）；这道题的 retry 排到下一次复测的最前面（`absorb.retryOwed`）。
