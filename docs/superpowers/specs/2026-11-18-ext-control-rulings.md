# 外部主讲的完整操控权：自己定的事（2026-11-18）

需求原文在学习台 `dev_requests/dr-ext-control`，执行计划 `docs/superpowers/plans/2026-11-18-ext-control.md`。学生说「写完执行计划直接开始，不用再回来问我」，下面是做的时候自己定的，都可以改。

1. **R6（预案收 wrong / giveup / stuck）、R7（一轮几块新板）只在 `kind: ext` 的课里开。**页面里的老师照旧只收 right / done、一轮一块新板：那两条是学生 2026-11-03 对页面里的老师定的（教学不预制、一下子给好几块板很影响学习）。外部的预写是外部当场看着题写的，第十五轮学生定了「开发不约束外部怎么教」，所以外部的课照收。协议读的时候放宽（`parseReact(…, { lenient: true })`），页面里的老师写了照旧在课堂执行时拦下、说为什么。
2. **不做模板库**（需求补充二，学生定的）：`save=` / `use=` 不做；同一种写法第二次用到，外部写 `dev_requests`，开发提进底座。
3. **底座选舞台**（补充三）：舞台引擎从 `archive/` 恢复进构建，黑板上是一个组件 `stage`，`board stage` 把一段包成它；不恢复舞台课（`kind: stage` 的课堂循环）。新能力加进底座，不再新做组件——`widget` 不算新组件，它是让外部在底座上写设计逻辑的那一层。
4. **`board widget` 用 `new Function` 在页面里跑**，不另起 iframe：外部是这节课的主讲，代码和它写的板一样可信；隔离靠「一上来跑不起来这一段不显示、后来出错只记一条动作」。claude.ai 的 artifact 要是不让运行动态代码，组件会报「代码跑不起来」，外部在 `ext_out` 里看得到。
5. **`board claude` 的结果一律进下一份 `ext_out`**（全文、执行了哪些、越权的、用量）；写进学习台数据的（`to=db:`、后台活的 `out`）记 `journal`（`by: ext-delegate`），学生在「管理 → Claude 改过的」能撤销；它写的 `memo` 走原来的记忆改动单（「最近记下的」能撤销）。
6. **`see:` 的 `books=`** 不由页面预取条目原文，只告诉它用 `textbook_read` 取：条目范围的写法外部不一定照教材编号写，预取错了比不取更糟。
7. **`ext_jobs` 首页跑全局的、课堂跑全局的和这节课的。**数据库订阅不了所有课的子集合；学生不在那节课里时，那节课的活等下次进那节课再跑（手册写明）。
8. **`board add … from=`** 是 R2「结果文档能直接被 board add 引用」的做法：执行前页面把那一条的 `text` 换进块里，课堂记录里存的是换好的全文（刷新照放）。
9. **`ext_out` 一份一份写**（`extWrite` 排队）：叫主讲、预备板、助手、作答同时来时以前会算出同一个序号、后一份盖掉前一份（e2e 抓到的）。
10. **R8 的提醒**放在板上方那一小条（和「叫主讲」「停掉助手」「下一块 →」一起），不弹窗；学生点了翻过去，提醒收起。
