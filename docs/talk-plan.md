# 一对一的课：活板和一问一答（技术路线）

2026-11-05 我试了活板测试版（`proto/live-lang/`，https://claude.ai/artifact/WEnxSDMkeNC393tFRRAajR）以后定的方向：上课像一对一的老师，一直推着我想，不甩出一堆内容。**不是限制 Claude 一次只能说多少，而是让它明白一对一怎么教，它自然就一问一答。** 最要紧的两件事：**回话的速度**和**交互画面的质量**。这份是怎么把它做成学习台里真正的课。

## 0. 一句话的路线

一个底座，三件事并行，第 0 批先量速度：

1. **活板的内核**：几行描述 → 量和依赖 → 画、动、判。老师写「例子是什么」，页面负责画法、动画、判分、替老师找例子。
2. **对象库**：现在的 61 个演示引擎、矩阵、推导、英语那一套都变成活板里的「对象」（算什么 + 怎么画 + 学生能怎么动），不再是一个个组件 × 一种种模式。
3. **一对一的课**：课堂换成一问一答的节奏，发给 Opus 的说明从一百多 KB 的组件手册换成「怎么教」的本质 + 几 KB 的写法；记忆、证据、报告、守卫照旧接上。

## 0.5 质量先于功能：怎么算「这个技术撑得住我的学法」（2026-11-05 我说的：要的是质量，技术要强到完全撑得住我的学习方法、学起来更好）

「强」不靠说，靠量。每一条都有尺子，做完一批量一次，哪条最差先补哪条：

| 要的 | 尺子 | 现在的课堂 | 目标 |
|---|---|---|---|
| 学得会：误解被问出来、针对着讲、换题确认 | 教学尺子（`evals/teaching/`，模拟带误解的学生）在一问一答上重跑同样的场景，加一项「结论是谁说出来的」 | 总体 4 分，误解多在第 2～5 轮暴露 | 总体 ≥ 4.5，结论多数是学生说出来的 |
| 一直在想：不是看老师讲 | 真课里：学生每轮都有事做的比例、老师每轮写多少字、学生回了几次 | 一轮约 1100 字 | 大多数轮学生有事做，老师一轮几十到两百字 |
| 等得短 | 真课每一轮 `cost.first` / `cost.ms` | 中位 27～34 秒 | 中位 ≤ 10 秒 |
| 画面好 | 组件画廊（每个对象 × iPad 竖横 × 白天晚上），我在 iPad 上看过；画完量一遍不冲出、不压字 | — | 每个对象都过我这一关 |
| 写得对 | 验收（`evals/`）：模拟老师用活板写几十块板，一次写对率；页面检查报的错 | 写对率 76% → 97%（组件） | ≥ 95%，学生看不到写错的板 |
| 够得着每一块内容 | 课程地图三科每一块：能不能用现有的对象写出一个好例子；写不出的列成缺口 | — | 缺口清单清零（缺的对象补上） |
| 接得上：记忆、复现、复盘照旧 | e2e 加一问一答的一整节课 | — | 和现在的课堂一样全过 |

做法：先把一问一答的课在学习台里接通（没接通什么都量不了），再按上表一项项量、一项项补。表里的数字每量一次填一次。

## 1. 速度：时间花在哪、怎么省

一轮的时间 = 读进去（说明 + 资料 + 对话）+ **先想**（Opus high，大头）+ 写出来（一问只有一两百个字，几秒）+ 页面画（毫秒）。

基线（`docs/smart-plan.md`）：现在一轮 27～34 秒，出第一个字前 25～45 秒；调一次工具再加 20～60 秒。

省的办法，按把握从大到小：

| 办法 | 为什么快 | 和硬性规定 |
|---|---|---|
| 不调工具 | 每调一次工具平台再跑一整轮。一问一答里正常的一轮一个工具都不用：记忆、教材、教案、以前的课开课前页面都放好 | 不碰 |
| 说明短 | 一百多 KB 的组件手册换成几 KB 的写法（测试版 4 KB）；少读、少在「哪个组件哪种模式」上想 | 不碰 |
| 页面先算好事实 | 学生答了什么、对不对、像哪种错法（引擎的 `variants`）、试了几次、犹豫多久，页面写成几行事实给它，它不用自己推 | 不碰 |
| 一问本来就短 | 写出来的字少；它不用排一整块板 | 不碰 |
| 先说话、后定义 | 引擎不管行的先后（量是按名字找的），让它先写那句话、再写 `let`；页面边写边画，话先出来 | 不碰 |
| 对话只往后追加 | 前面的部分每一轮一模一样，平台有前缀缓存时读得快；太长了后台（`lane: 'bg'`）压缩 | 不碰 |
| 页面当场接住对错 | 填完马上打勾 / 打叉、图马上变，等 Opus 的那几秒不是干等（判对错不是教学） | 不碰 |
| 抢跑一问的几种回答 | 学生作答前，页面替最可能的两三种回答（选择题的几个选项、空的对 / 错）各请 Opus 当场写好下一句；学生答了哪个用哪份 | **要我定**：每一份都是 Opus 看着这一刻写的，但写在我作答之前。第 0 批的数字出来再说 |
| 换低一档的 effort | 想得少 | **不做**：课堂只用 Opus 5.5 high（硬性规定）。第 0 批只拿来对比 |

**第 0 批先量清楚，再定预算**：在学习台里加一个测速页（不进课），同一个问题按说明 4 / 16 / 40 / 100 / 160 KB、对话 2 / 10 / 30 轮各调 Opus 5.5 high 几次，记出第一个字、写完、写了多少字。看出「说明长短」「对话长短」各占几秒，才知道记忆摘要（现在 28 KB）、教案、教材原文能带多少。真的一问一答课再按轮记（`cost.first` / `cost.ms` 照旧）。

目标先定成：**一问一答一轮中位数 10 秒以内**（现在 27～34 秒），第 0 批量完再改。

### 第 0 批的结果（2026-11-05，学习台「管理 → 测速」，iPad 上跑了快速一次 + 完整一次，共 21 次，全是 Opus 5.5 high 回的）

| | 出第一个字 | 写完 |
|---|---|---|
| 全部 21 次 | 中位 7.8 秒（5.8～10.2） | 中位 8.4 秒 |
| 说明 4 / 16 / 40 / 100 / 160 KB | 7.9 / 8.3 / 7.4 / 7.5 / 8.0 秒 | |
| 对话 2 / 10 / 30 轮 | 8.1 / 8.9 / 6.9 秒 | |

- **说明长短、对话长短都看不出影响**（4 KB 和 160 KB 一样，差别在抖动以内）。一问一答一轮约 8 秒，写字只占半秒，其余都是先想。
- 所以现在课堂一轮 27～34 秒，慢不在读得多，而在**要它做的事**：排一整块板、在组件和模式里挑、调工具（每次再一整轮）。一问一答本身就把这几样去掉了。
- 定下来的预算：**每一轮照样带全文的记忆、教案、教材**（160 KB 以内不用为了速度省），省下的心思放在「不调工具」和「一次只推一小步」上。目标「中位 10 秒以内」在测速里已经做到，真课再量（真课要读真的记忆、判断更难，可能多想几秒）。
- 写法上的一个问题：有一次写了 `goal f = 4`（少一个等号）。页面会报这一行、自动让它重写；说明里要把 `==` 写清楚。

## 2. 交互画面的质量

### 内核（`kit/src/huoban/`，纯函数为主，`node --test`）

测试版的 `engine.js` 搬进来、做扎实：

- 值用 `exact.js` 的精确分数（现在是浮点），含参数照 `paramcalc.js`；表达式和现在 `\calc`、`let` 块同一套写法。
- 量和依赖：现在每次全部重算；换成按依赖增量重算（量多了、拖动时也是 60 帧）。
- 正文里的公式用 KaTeX 排，`{…}` 能写在公式里（活的值、空）；`\hl`、`\chalk`、`==…==` 照旧。
- 写法检查：读的时候就查不认识的名字、函数（测试版已经有），画完量有没有冲出版面、一屏放不放得下（`check-lesson` 那一套）；写错了页面自动让它重写那一轮（测试版已经有，课堂的写法自检也是这样）。边写边画的时候，后面才定义的名字先不报错。
- `find`：按条件的差模拟退火（测试版：Belady 反例几十毫秒）；范围加上计算机课的 `bits`、`word`，线代的含参矩阵。

### 对象库：现在的组件全部拿进来

现在的组件 = 引擎（算）+ 画法 + 一种种模式（ask、quiz、fill、do、vary、use……各写一遍）。活板里只留前两样，模式变成通用的动作：

- **61 个演示引擎**：一个通用的适配器。`let r = sched(…)` 拿到整个过程（`engine.parse` + `run`），`draw r` 用引擎现有的 `view` 画当前这一步，「第几步」是一个能拨的量；引擎每一步现有的 `ask`（答案）变成能取的值（`{r.faults?}`、`{r.next#2?}`），`variants`（常见错法）照旧让页面看出「像是按 FIFO 换的」写进给老师的事实。先整批接上，再一个个换成按状态画的图元（格子、树、表、时间轴、位）好做动画。
- **线代**：平面（`scene.js` 的向量、网格、拖动）、三维（`space.js`）、函数图（`graph.js`）、会动的矩阵（`matrixspec.js`）、推导（`derivespec.js`）都变成对象；`elim` 这类过程走上面的适配器，`mode: do` 的手做行变换变成一种动作。
- **英语**：句子是对象（`entext.js`）：能折（主干）、能断（意群）、能标成分、能点词改错、空能写能选。
- **通用**：示意图（`sketch`）、讲义原图（`image`）、标注（`mark`）照旧能用在任何对象上。
- 作答的方式也是动作，放在任何对象上：写（空，`formula`、`bin`、`seq` 这些答案类型照旧）、选、拨、拖、点、排序、折、Apple Pencil 手写。

说明书跟着变：每个对象写清「有哪些量、能怎么动」，动作只写一遍；说明从对象的代码里生成（文档、写法检查、例子、测试一个来源）。

### 画面

- 一问一答的版式（测试版已经有）：画的东西留在中间、在原地变；当前这一问在下面、字大；前几轮缩小，更早的收起来；我的作答在下面回显。
- 变化都滑过去：同一个东西换了值不是整张重画（`morph.js` 的按名字过渡，测试版平面上已经有）。
- iPad 为准：触控 44px、输入框 16px、Pencil、软键盘、横竖屏；紫藤的两种样子；组件画廊每个对象截一张。

## 3. 让 Claude 知道怎么教（本质，不是条数限制）

发给 Opus 的说明按这个顺序：怎么教（本质）→ 写法（几 KB）→ 这节课的资料（教案、记忆、教材，页面放好）→ 板上现在有什么 → 对话。

「怎么教」写的是一对一老师在做什么，不写「每次最多几行」：

- 学生在想的时候，老师不说话；学生想完了，老师才接。所以一次推一小步，问一个学生现在够得着、又非想不可的问题。
- 学生的回答是线索：对了，看是真懂还是碰巧（换个数、问为什么）；错了，先弄清是怎么想的，问一个能让学生自己撞上矛盾的问题，或者改一个数让学生再看，不直接给答案。
- 东西让学生自己动：能拨的给学生拨，能拖的给学生拖，结论从学生手里出来。
- 讲解是学生卡住以后的事，而且只讲卡住的那一点。

现在的教学守则（`lessons`）、`TEACH_PROBE`、各科的教法照旧带上，只是改写成这个口径。**验收用教学尺子**（`evals/teaching/`）改成一问一答的版本：模拟学生带着误解上课，量多少轮问出误解、确认题能不能分开两种想法，另外记每一轮老师写了多少字、等了几秒（是量出来看的，不是限制）。

## 4. 接进学习台

- 新的一种课 `kind: talk`（开课、复现课、练一练都能选它）。控制器 `kit/src/talk/`：调用、核验（返回的不是 `claude-opus-5-5` 整轮作废）、边写边画、排队（我还在动时攒着、老师写完再发）、计时、写错重写，用的都是课堂现在那一套（`classroom.js` 里能拆出来的拆出来共用）。
- 证据、memo 块、下课小结和整理单、课后报告、知识点归类、复盘、守卫照旧接上：作答写进 `evidence`（组件 id 换成对象名 + 动作），老师的话和板一轮一条进 `class_turns`。
- 现在的课堂先不动；一问一答的课量过、用过、比现在好，再换成默认。整块板不是不许写：要讲一大段时（推导、总结）老师照样写，只是不再是主要的样子。

## 5. 分批

| 批 | 做什么 | 怎么算做完 |
|---|---|---|
| 0 | 测速页：说明长短、对话长短各量几次（Opus 5.5 high）；测试版里的一问一答真上几轮 | 有表：每多 10 KB 说明、每多 10 轮对话各多几秒；定下说明和资料的预算 |
| 1 | 内核进 `kit/src/huoban/`（精确值、KaTeX、增量重算、写法检查）；`kind: talk` 的课接上调用、核验、证据、下课 | `npm test`、e2e 加一段；一节真的一问一答课从开到下课、报告 |
| 2 | 对象库：演示引擎的通用适配器（61 个一次接上）、线代、英语、作答动作 | 每个对象一个能照抄的例子过检查；组件画廊每个截一张 |
| 3 | 「怎么教」的说明；教学尺子的一问一答版 | 三门课各一个场景，和现在的课堂比 |
| 4 | 画面：按状态画的图元换掉 HTML 快照、过渡动画、Pencil 作答、版式打磨 | iPad 上过一遍；画廊联系表 |
| 5 | 按第 0 批的数字再提速：先说话后定义、抢跑（要我定）、对话压缩 | 一轮中位数达到目标 |
| 6 | 一问一答成为默认的课；说明书第三节换成对象说明 | 我说可以 |

每一批照老规矩：`npm test`、`npm run build`、改了学习台或课堂跑 `npm run e2e`，合进 `main`、重新发布学习台。
