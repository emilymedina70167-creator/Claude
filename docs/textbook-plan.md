# 教材板块和学习台自己备课（2026-10-29）

## 我要的

学习台完全自给自足：教材、记忆、备课、上课都在里面，不用对话里的 Claude 先读项目知识库、再塞进资料包。教材不能一上来全塞给 Claude，要按需读，而且读得准、取得快。我的 PDF 没有文字层（扫描版），在 claude.ai 的项目知识库里读得很慢。

## 事实

- 页面里的 Claude（`sample`）只收文字和图片，不收 PDF、Word。所以由页面把文件变成它能读的：Word / PowerPoint 页面自己解压取字（不花额度）；PDF 用 pdf.js 一页画成一张图，交给 Claude 看图转写（2026-11-04 起用 Haiku 5.5：一本书三四百页，Opus 转太费额度；课堂讲课照旧只用 Opus 5.5）。
- 扫描版没有文字层，只能看图转写。看图的成本主要在**一次**：每页一张图（约一两千 token）加上转出来的字。转一次存起来，以后每节课按编号取几条，不用再看图。claude.ai 项目知识库里的扫描 PDF 是每次用到都要重新处理，慢、也贵。
- 一次最多附几张图由平台定（`limits().images.maxCount`），一次转 3 页（`PAGES_PER_CALL`），两批同时转。

## 做了什么

**存放**（学习台数据库，不进记忆库的 13 类）：

- `books/{B1}`：一本资料：`title`、`kind`（textbook 教材 / transcript 视频文稿 / slides 讲义 / notes 笔记）、`space`、`subject`、`status`（importing / partial / ready）、`toc`（章、节、小节，指向后面第一条）、`chunks` 条数、`pagesDone` / `pagesLeft`、`cost.calls`。
- `books/{B1}/pages/{页码}`：每页的原页图（assets 的 id，1200 像素宽 JPEG）、PDF 的文字层、转写结果 `items`、`status`（todo / done / error）。停了、关了页面，下次从没转的页接着转（不用再选文件）。
- `books/{B1}/chunks/{B1-23.1}`：一条：`kind`（定义、定理、性质、推论、公式、例题、习题、方法、说明、图表、文稿、讲义）、`title`（书上的编号和名字）、`chapter`、`section`、`page`–`pageEnd`、`text`（Markdown + LaTeX，忠实原文）、`img`（原页图）、`checked`（我核对过）、`fixed`（我改过字，重拼时保留）。编号按「从第几页开始的第几条」，重转别的页编号不变，课程地图挂的不会错位。

**入库**（`books/importer.js`，学习台「教材」页）：

- PDF：每 12 页「画图存原页 → 转写」一轮，边存边转；选页码范围（先转这一讲要用的），选文件时就算出要调用几次。有文字层的 PDF 把文字层也给 Claude 对照汉字、数字，公式以图为准。
- 截图、照片：每张一页，可以加到已有的书里（写起始页码）。
- Word 文稿：页面自己切成一千多字一条，不调用 Claude。
- PowerPoint 讲义：只有字的页直接成一条；带图的页（板书截图）交给 Claude 看图转写。
- 转写的规矩（`ingest.js` 的 `transcribePrompt`）：忠实、看不清写【看不清】、公式 LaTeX、例题连解答、定理连证明、跨页标 `cont`、标题带层级。拼条目（`assembleChunks`）：跨页接上、碎的说明并起来、太长的按空行切开。

**少花额度、转得快（2026-11-04）**：看图的钱按像素算（宽 × 高 / 750 个 token），一页 1200 × 1697 的图约 2700 token，其中页边、页眉页脚外的空白占两三成，什么字都没有。所以入库时页面先做三件不调用 Claude 的事，转写的质量不变：

- **裁白边**（`books/crop.js` 的 `contentBox`，`pdf.js` 的 `renderScan`）：在缩小的图上找出这页的内容（宽松的阈值：比纸色暗一点就算，淡色的字、铅笔字、页码都算内容；孤立的噪点、扫描时贴边的一道黑边不算），四周留 2% 再裁。只裁不缩：留下来的字每个还是原来那么多像素，Claude 看到的和以前一样清楚。存进学习台的原页图也是裁过的（核对、课堂里 `textbook_page` 看原页都更省）。
- **空白页不调用**：整页认不出一点内容、也没有文字层的页，直接记成转好了（`blank: true`）；万一认错了，「重新转写这几页」会照常交给 Claude。
- **边画边转**：以前每 12 页先全画完再转、转完再画下一段；现在画一页存一页，凑够一批（3 页）马上转，同时转 3 批（被限流就少一批）。画得太靠前就等一等，iPad 上不囤图；转好的页的图马上从内存里放掉。

没做的：一是本地 OCR（Tesseract 一类）代替 Claude。扫描的数学书满是公式、矩阵、上下标，本地 OCR 认不出来，质量会掉，而且要额外带十几 MB 的识别模型。二是把 effort 从 medium 再降到 low。思考的 token 也算钱，但降了以后切条、判断「接上页」可能变差，要拿真书比过才能定。

**在 Claude Code 里转（2026-11-04 起，学习台里不再转）**：学习台里的 Haiku 觉得「整页照抄教材」涉及版权、回一句不肯转（第 64–81 页都是这样），Opus 又太费额度。所以改成：

- 学习台的「教材」页只**存**：选 PDF（截图、讲义同样）→「存进学习台」，每页裁好白边存原页图，页标成等转写，不调用 Claude。书上写「等转写」，等转写的页连成页码段显示。`importer.js` 的 `TRANSCRIBE_HERE = false`（改回 true 就是原来那样在页面里转）。
- 我回 Claude Code 说「转 B3」：外部 Claude 用 `ArtifactData list` 把书和页存到本地，`node tools/books.mjs plan` 分批（一批 4 页，每批一份转写的规矩，就是原来的 `transcribePrompt`，开头说明这是学生自己的书、只存进私人学习台），每批交给一个转写助手（自己取那几张原页图、看图、写成 `bNNN.out.txt`），`node tools/books.mjs apply` 读回、拼成收件箱记录，`ArtifactData batch` 写进 `book_inbox`。
- 收件箱：每批一条新记录 `book_inbox/{书-页-时间}` = `{ book, pages: { 页码: items }, by }`，不改已有的页、不用管版本号。学习台打开时（`bookview.js` 的 `takeInbox`）并进各页（`status: done`、`via: claude-code`），删掉这条，再把这本书拼一遍条目（`rebuild`，纯代码）。
- 条目的「标成要重转」把那几页标回等转写，下次一起转。
- **并的时候看得见、屏幕不熄**（2026-11-05 我说「两个都显示没转写」：其实正在并，只是一整本并完才拼条目、书目才变，中途关了页面就停在半路）：书目和书页写「正在并入转写（还剩 N 批）」（`bookview.js` 的 `inboxLeft`），并的时候请求屏幕常亮（`holdAwake`），每并完一批重画一次。e2e 的 `inbox` 一段。并之前在书上记 `needsRebuild`（数据库里），拼完条目（`importer.js` 的 `rebuild`）去掉；页面关了、熄屏了，下次打开看到还记着就接着拼，已经写好的条目跳过（同一天解析册拼到第 294 页时页面关了，收件箱已经空了，内存里的「要拼」丢了，书一直停在「等转写」）。书目写「正在拼条目」。
- **中途退出能接着存**：浏览器不让网页记住选过的文件，所以存 PDF 时页面在这台设备的浏览器（IndexedDB）里暂存一份（`books/stash.js`），书上记 `storing`（哪个文件、哪几页）。回来教材页显示「上次没存完 · 接着存」：有暂存就直接接着存，没有（清了数据、换了设备）就让我再选同一个 PDF；已经存过的页跳过。存完清掉 `storing`、删暂存。存的时候请求屏幕常亮（`navigator.wakeLock`），屏幕熄了页面会停。
- **让电脑上的 Codex 转**（省 Claude 的额度）：照 `docs/codex-transcribe.md` 把那段话贴给 Codex，它看图转写、按同样的格式写成文本推进我的私有仓库；外部 Claude `node tools/books.mjs text` 读回、检查（缺页、【看不清】、字太少）、写进收件箱。学习台「存进学习台」能选已有的书：已经存过原图的页不再存，转好了还没原图的页只补图。
- **PDF 放在我的私有仓库里**（更快，不用在学习台里存页；不要放进公开的开发仓库）：外部 Claude 把仓库接进会话，`node tools/books.mjs render` 在云端画页（`pdftoppm`，1200 像素宽，按 `crop.js` 同一套规则裁白边、认空白页，有文字层就一起取），原页图用 Artifact 的 asset 上传（一次 25 张）、「页码 → id」记进 `assets.json`，`plan --local` 直接用画好的图，`apply` 时收件箱带上书的信息 `info` 和每页的原页图 `meta`，学习台的 `takeInbox` 连书带页一起建（空白页记成转好了、没有内容）。

**核对**：教材页一条条展开，左边转出来的字（KaTeX 渲染），右边原页图；「核对过了」「改字」「重新转写这几页」。

**课堂里按需读**（`books/textbook.js`）：

- 资料包点名的条目（备课时挑的 `chunks`）全文并进资料包的「教材原文」；没点名就用这一块挂着的。
- 资料包里多一节「教材目录（按需取）」：这一讲的条目，一条一行。
- 工具：`textbook_read`（按编号，一次几条）、`textbook_search`（按词找，中文两个字一组比，标题命中算得多）、`textbook_page`（把原页图附给它看）。`image` 组件写条目编号就能把原页贴上黑板。

**学习台自己备课**（`books/plan.js`、`planview.js`）：

- 挂课程地图：教材页「挂到课程地图」：Claude 看这本的目录和现有的课程地图，提出每块挂哪些条目（可以写范围 `B1-23.1~B1-25.2`）、缺的块怎么加；我勾了才写（课程地图的写入方加了 `me`）。
- 备课：首页「上课」卡选一块 →「让 Claude 备课」：带这一块的范围、要点、挂着的原文、文稿、全部规则（包括备课和资料包的规矩）、和课堂里同一份记忆、最近几节课 → 写这一科的 `pack/main`、`pack/problems`（`by: "desk"`），我看过推进计划再开课。

**备份**：导出备份带上 `books` 和每本的 `chunks`（转写花了额度，丢了不划算）；原页图在 assets 里不进备份。

**pdf.js 不进 la-kit.js**：一百多万字节，平时上课用不着。构建时拷到 `kit/dist/pdf/`（pdf.js、worker、扫描版要的 JBIG2 / JPEG2000 解码器和不支持 wasm 时的 js 版、GB 的 cmap），作为学习台的附带文件 `pdf/…` 发布，导入 PDF 时才取。学习台的附带文件不收二进制的 `.bcmap`，也不收带原样控制字符的文本：构建时 cmap 拼成一个 `cmaps.json`（`books/pdf.js` 的 `DeskData` 交给 pdf.js，没嵌字体的中文 PDF 才下载），worker 里的控制字符换成等价的 `\xNN`（`books/jsescape.js`；换前换后同一份 PDF 渲染、文字层一样）。
