## ds-quick　快速排序的一趟划分

**理想的教法**：学生自己在数组上「填坑」：先点 high 这次停在哪格、再把它拖进坑，low 同样，每一步页面判对错；划完一趟，在一棵「划分区间树」上点出下一次划分哪一段，数出一共几次；最后让页面跑一个相同关键字会颠倒的例子，学生指出哪一次填坑把它们弄反了。

**现有组件做到的**：
- `sort algo: quick` + `ask: pivot` 演示填坑（换了一组数，免得直接看到题目答案）；`mode: quiz` + `pass: 1` 让学生写题目这一组的第一次划分，`pass: 2` 练「第 2 次划分是哪一段」。
- 稳定性：`sort array: 3 2 2'` + `ask: partition`，再配 `conjecture`。
- 「一共几次划分」：没有现成的问法，我把王道的 QuickSort 加了一个 `int &cnt` 计数，放进 `trace` 的 `mode: quiz`（`quiz: output`），让页面跑出 4。

**想做但做不到的**：
- `quick` 的 `ask` 只有 `partition`、`pivot` 两种。这一课的核心技能是「high、low 轮流停在哪、填进哪个坑」，正好问不了。想要 `ask: high` / `ask: low`（在图上点它这次停在哪格）、`ask: fill`（这个数填进哪个坑）。
- 「一共几次划分」：sort 不画递归区间，也没有 `ask: count`。用 trace 绕过去以后，学生面对的是 27 行代码，一屏多半放不下，而且考试要的是画出每次划分的区间，不是读代码。想要快排的「区间树」画法（每次划分一个结点，写出区间和枢轴位置）和 `ask: count`。
- 稳定性没法让页面判：没有「排完后相同关键字的次序变没变」的问法，`qz-st` 的正确选项是我手推的。
- 练熟：`practice type: custom` 的 `answer:` 只能是表达式，没有「对随机数组做一次划分」的函数，出不了排序题；只能写死一组数据再出一个 `sort mode: quiz`。想要由引擎出题的随机练习（随机数组 → 引擎算答案）。
- **题库本身的问题**：「教到什么程度」写「能说出不稳定的原因（49 和 49′ 的相对次序变了）」，但按王道的 Partition 手推，这一组数据 49 始终在 49′ 前面（第一次划分后 49 在第 4、49′ 在第 8；排完 49 在第 4、49′ 在第 5，共 4 次划分：[1,8]、[1,3]、[5,8]、[5,6]）。所以我在课里把它反过来用：「这一组没变，但 (3, 2, 2′) 变了 → 不稳定指存在反例」。题库这句要改，或者换一组真的会颠倒的数据。（这是我手推的，没法让页面验证；sort 的 `start: end` 那块板上学生能看到最终序列。）

**写法上拿不准的**：
- `sort` 的 `mode: quiz` 只举了 `pass: 2`，不知道 `pass: 1` 合不合法。
- 学生怎么输 49′：写 `49'`、写 `49′`、只写 `49` 算不算对？`type: seq` 和 sort quiz 的判分对撇号怎么处理，说明没写。我在题面里让学生写 `49'`。
- `ask: pivot` 在整个快排里问几次：每次划分都问？长度为 2 的段也问？问得太多会很烦，没法控制只问第一次（写步号要先知道第几步是什么，见文末「通用」）。
- `start: end` 和 `ask` 同时写会怎样（s-full 没写 ask，但别的组件我想这么用）。
- `trace` 的 `q:`：演示组件通用字段里有 `q`，trace 的例子里没写；`mode: quiz` 时代码显示不显示；`quiz: output` 比较时空格、换行怎么算。
- 引用参数 `int &cnt` 递归传下去能不能跑；`int pivotpos=…` 写在 `if` 块里行不行。
- `draft` 要不要写 `id:`（实时黑板说「会作答的组件都写 id」，draft 算不算）。我没写。

## ds-build　由遍历序列构造二叉树

**理想的教法**：先序、中序两条序列摆在板上；学生在先序上点根，再在中序上点同一个根，页面把中序切成左右两段着色、把先序也对应切开；递归下去时，旁边的树由学生自己搭（点空位置加左 / 右孩子、写结点名），每加一个结点页面判对错。最后对「先序 + 后序」，页面列出所有符合的树（比如先序 A B C、后序 C B A 有 4 棵），学生自己看出「只有一个孩子时分不出左右」。

**现有组件做到的**：`steps`（找根、切左右、递归，逐步撤脚手架：第一棵全揭开，后两步 `do: true`）；`answer type: seq` 判后序 `C B E H G I F D A`；`tree nodes: … walk: postorder ask: visit` 在正确的树上把后序走一遍；`quiz` + `sketch`（两棵树）+ `conjecture` 讲先序 + 后序。

**想做但做不到的**：
- **没有「由遍历序列构造二叉树」的引擎**：`steps` 里每一步的 `show`、`tree` 的 `nodes: A(B(, C), D(E, F(G(, H), I)))` 全是我手推的。这和「页面算、不要自己算轨迹」正好相反，写错一个括号页面也不会说。
- **学生画树没有作答方式**：只能画在 `draft` 或 Notability 里，页面不判。实时黑板里 `draft` 的内容我看不到（「拿给 Claude 看」关着），只能靠学生「交截图」，我再读图。想要 `tree` 的搭建作答：学生在页面上搭一棵树，页面和标准树（最好由 `pre:` + `in:` 页面自己构造）比对，指出哪个结点挂错了。
- 想在序列上点：「在中序里点出根」这类操作没有组件，只能用 `choices`。
- 先序 + 后序列出所有可能的树：只能手画 `sketch`，而且只画了最小的两结点例子。

**写法上拿不准的**：
- `B(, C)`、`G(, H)` 嵌在逗号后面的写法对不对（说明只举了 `C(, F)`）。
- `tree` 只想显示一棵树、不遍历时能不能不写 `walk`；`ask: visit` 每个结点都问，9 个结点问 9 次，能不能只问后几步。
- `steps` 的 `choices` 里能不能带冒号、括号（我改成了「先序第一个 A」这种不带冒号的写法，怕被当成 `字段: 值`）；`show:` 里能不能放一个小组件（想在揭开时出现那一层的树）。
- `sketch` 在横屏时会不会和别的内容排成左图右文（说明只说 scene / graph / space 会）。

## ds-avl　平衡二叉树的插入

**理想的教法**：一个平衡二叉树演示：每插一个结点，结点旁标出平衡因子（页面算）；失衡时停下，学生先点出最小失衡子树的根、再选 LL / RR / LR / RL，然后看旋转的动画（结点挪过去、子树换父亲）；`mode: quiz` 让学生写最后那棵树的先序 / 层序；随机插入序列练熟。

**现有组件做到的**：
- `tree bst:` 画「按排序树插入、还没调整」的样子，`ask: insert` 练插在哪；旋转后的形状靠**换一个插入顺序**骗 `bst` 画出来（`bst: 7 3 15 10 9` 就是 LR 转完再插 10、9 的样子，`bst: 7 3 10 9 15 8` 是 LL 转完再插 8）。
- 平衡因子用 `answer`（单个）和 `steps do: true` 的向量 `[1, 1, -2]`（三个）判；类型用 `steps choices` 和 `quiz`；`recognize` 认 LL / RR / LR / RL；`answer type: seq` 判最后的先序 `9 7 3 8 10 15`。
- 旋转前的树用 `sketch` 手画一张。

**想做但做不到的**：
- **tree 没有平衡二叉树**：不算平衡因子、不找失衡结点、不会旋转、没有旋转动画。所有平衡因子、失衡结点、旋转类型、旋转后的形状都是我手推的，页面一个都不验算。
- 用插入顺序骗 `bst` 有副作用：下一块板 `ask: insert` 时，学生得把 7、3、15 这些「转完就在那」的结点重新点一遍，我只能在文字里说「照着点就行」。
- 三个平衡因子只能当成一个列向量填（`[1, 1, -2]`），学生看到的是带括号的竖排格子，不是树上每个结点旁的一个空。想要「在树的结点旁边填数」的作答。
- 旋转后的树：想在 `steps` 揭开「谁当新根」时同时出现转完的树（`link:` 只给 scene / graph / space / matrix / derive），做不到，只能放到下一块板。
- 练熟：没有平衡二叉树的随机练习。

**写法上拿不准的**：
- `bst` 配 `start: end` 是不是直接显示建好的树（我用来显示「插入 8 之后」）。
- `steps do: true` 的向量答案在 iPad 上长什么样、能不能输负数 −2。
- `recognize` 用来认「旋转类型」而不是「方法」合不合适（我觉得能用）。
- `sketch` 里 `<circle>` 不写 `fill` 时是空心的吗？文字压在圆上看不看得清。

## ds-dijkstra　最短路径

**理想的教法**：学生自己填王道那张表：每一轮一列，在格子里写 dist（可以点 ∞）和 path，选顶点在图上点；页面和引擎逐格比对、指出哪格错。负权边那一问，让页面在一个带负边的图上照样跑 Dijkstra，再和真正的最短路（比如 Floyd）并排，学生看到它错在哪一轮。

**现有组件做到的**：`net run: dijkstra ask: next`（题目的图，页面算表）；换一个图后用 `steps` 一轮一个 `do: true`（向量判 dist）；`net mode: quiz` 判加入 S 的顺序，做完看页面的表对照；`net start: end` + `answer type: seq` 判从 path 倒推的路径 `V1 V5 V2 V3`；负权用 `sketch` + `steps` + `conjecture`。

**想做但做不到的**：
- **没有表格作答**：教学目标是「能自己填出每一轮的 dist / path 表」，但 dist 只能拆成 `steps` 里一个个列向量；∞ 写不进 `answer`（所以只挑了全是有限值的那几轮问）；path 那一列根本没法判。
- `steps` 里的答案是我写的式子 `[min(5, 1+2), 1+6, 1+9]`：页面只算加法和 min，「哪条边能更新谁」是我决定的，和 `net` 引擎不是同一个来源。想要能引用组件结果的写法，比如 `answer: dist(g-d2, B, 2)`（第 2 轮后 B 的 dist）。
- `net` 不接受负权：负权的反例只能手画，「Dijkstra 在这里算错」也是我手推的。想要 `negative: allow`，让引擎照样跑、标出哪一轮定错了。
- `net mode: quiz` 只判顺序，不判 dist、path。
- 想让学生在图上点「这一轮用哪条边更新了谁」，没有这种问法。

**写法上拿不准的**：
- 不写 `pos:` 时图摆在圆上，和王道书上的图对不上；我没有原图坐标，不敢乱写 `pos`。
- `start: end` 时表里有没有 path 那几行（说明写「还有 dist、path」，不知道是画在哪）。
- `type: seq` 的元素是 `V1` 这样的多字符时，学生写 `V1→V5→V2→V3` 能不能认。
- `net mode: quiz` 时图画不画出来（题面全靠图）。

## ds-hash　散列表

**理想的教法**：学生在表上点地址放关键字（已有）；每个关键字旁边写它查找成功要比几次（页面判）；查找失败时，对每个起点 H 拖一条「从 H 比到哪」的条，页面判停的位置和次数；ASL 的分子分母分开判，错了指出是哪个关键字 / 哪个地址数错了。

**现有组件做到的**：`hash` 演示 + `ask: place`（先用一组小数据 key % 7 走一遍）；`mode: quiz` 写整张表；`quiz: asl` 写 ASL成功；`steps` 讲「为什么按 13 个地址」「比到第一个空位置、这次也算」；演示 + `ask: aslfail` 让页面判 ASL失败。

**想做但做不到的**：
- **演示一走到最后就把 ASL 算出来**：想让学生先自己数，所以第一块板不能用题目数据演示（会提前看到答案），只好换一组小数。没有 `end:` / `stop: before asl` 这类「停在 ASL 之前」的写法。
- 没有 `quiz: aslfail`：ASL失败只能用演示 + `ask: aslfail`，学生得先点「播放」把 12 个插入走完。
- 「数出每个关键字的比较次数」是教学目标，但没法单独作答判分：想要 `ask: count`（这个关键字查找成功比几次）和「地址 H 查找失败比几次」。`steps` 里「H = 1 时比 13 次」的 13 是我手数的。
- 想把表和比较次数并排成王道那种两行表，学生直接在第二行填。

**写法上拿不准的**：
- `01` 在表里显示成 `1` 还是 `01`；quiz 里学生写 `1` 算不算对。
- `mode: quiz` 写整张表：是 16 个格子逐格填，还是写成一串序列？「空的写 #」像是一串。
- `ask: aslfail` 的那一步之前，ASL成功那一步会不会直接亮出来（学生在上一块板已经做过，问题不大）。
- 点「播放」时遇到 `ask` 会不会自动停；`speed: 0.4` 太快还是太慢。

## ds-list　算法设计：链表重排

**理想的教法**：链表画成方框加箭头；学生写自己的指针版 C 代码，页面在 n = 0、1、2、6、7 上跑，一步一行画出 p、q、r、s 指着哪个结点、哪根箭头被改了；空指针、成环、死循环都停在那一行说清楚。再让学生在图上「改箭头」模拟一次头插。

**现有组件做到的**：`answer type: seq`（n = 7 时的目标序列）；`quiz`（为什么要逆置后半段）；`steps`（三步思路）；`trace` 跑 2019 年 408 第 41 题王道答案的**数组模拟版**（`nxt[i]` 当 next，0 当 NULL），`predict` 问两处 q；`findbug`（漏了 `p->next = NULL`）；`trace mode: quiz` 写 n = 7 的输出；`conjecture` + `quiz` 对应答卷的设计思想和复杂度。

**想做但做不到的**：
- **trace 不支持指针、结构体、`malloc`**：链表是 408 算法题最常考的一类，现在只能改写成 `nxt[]` 数组。学生看到的是一排下标数字，不是「结点 + 箭头」，和考试要写的 `p->next` 对不上，下标和指针之间的换算本身就是负担。
- **没有链表的画法**：想看 a1 → a2 → … 的方框箭头，逆置时箭头一根根翻过来，合并时一个个插进去。
- **学生写的代码没法运行、判分**：没有代码输入框，也不能把学生的代码交给 trace 跑测试用例；只能交截图让我逐行读。这一题（2）问的就是写代码，页面完全帮不上。
- `findbug` 只能点「错的那一行」，而这里的错是「漏了一行」：我只好把第 2 行写成「`q = p->next;`　取出后半段，接着直接开始逆置」来凑。
- 设计思想是文字题：实时黑板里 `conjecture` 不批改，要我来读。
- 两个 `trace` 各 35 行代码，一屏肯定放不下（还要加变量、数组面板）。

**写法上拿不准的**：
- `predict: 9 -> q` 的行号是不是从 `code:` 下面第一行数起；空行算不算。
- `p = h; q = h;` 一行两句算一步还是两步。
- `pointers: p, q, r, s` 能不能画在 `nxt` 下面（参数里的数组）。
- `quiz: output` 时末尾的空格（`printf("%d ", i)`）怎么比。
- 不写 `#include` 行不行；注释 `//` 支不支持（我没敢写注释）。

## 通用：说明里不清楚、前后矛盾的地方

1. **演示组件的步号**：`ask: 3, 7`、`start: 5`、课堂的 `figure set step=` / `play step 0 12` 都要知道「第几步是什么」，但说明没写每个引擎怎么切步（快排是一次填坑一步，还是一次划分一步？hash 是一次探测一步？）。我看不到页面，所以全课没用一个步号。
2. **「一块板只放一件要动脑的事」和演示组件冲突**：带 `ask` 的演示本身就是一道题，再配一道 `quiz` 就是两件。好几块板我只能这样。
3. **「数让页面算」在数据结构里大多做不到**：树的形状、平衡因子、比较次数、路径都不是表达式；能让页面算的只有演示组件的 `ask` / `quiz` 覆盖到的那几种结果，其余只能手填，而且没有自检。
4. **实时黑板的板书 / 草稿我看不看得到**：第五节只说「交截图」进 `meta/now`；`draft` 写的东西、「⋯」里的板书会不会进 `meta/now` 没说（课堂模式说了会导出成图）。
5. 一次写完整条路径时，常驻栏里的结论会一开始就亮着，和「结论不要早于猜想」冲突，所以我只 pin 了规则、记号，没 pin 结论（真上课时会等学生答完再 pin）。
6. 第二节原则 7「术语第一次出现附英文」和「计算机课的术语用中文，不附英文」写在一起，后者是例外，读得懂，但容易误用。

## 如果组件库只能再加三样

1. **树的搭建作答 + 平衡二叉树**：`tree` 加一种作答——学生在页面上搭一棵树（点空位加左 / 右孩子、写结点名），页面和标准树比对、指出哪个结点挂错；标准树由页面自己算：`pre:` + `in:`（或 `in:` + `post:`）构造、`avl:` 依次插入（带平衡因子、`ask: unbalanced` 点失衡结点、`ask: rotate` 选类型、旋转动画）。理由：ds-build、ds-avl 两题现在的核心步骤全是我手推、页面不验算，学生画的树也没法判；同一个作答还能用在二叉排序树、堆、哈夫曼树、线索树上。

2. **trace 支持指针 / 结构体 / malloc，并加链表画法和「跑学生的代码」**：结点画成方框箭头，每一步看出哪根 next 被改了；学生在代码框里写函数，页面在几组测试数据上跑、给出输出和出错的行。理由：408 的算法设计大题大半是链表，这一类现在只能改写成数组下标、学生的代码只能截图给我读，是数据结构里缺口最大的一块。

3. **演示组件的「填表作答」+ 由引擎出题的随机练习**：`mode: table` 让学生按轮填引擎画出的那张表（Dijkstra 的 dist / path、散列表每个关键字的比较次数和每个地址的失败次数、Prim 的 lowcost、快排每次划分的区间……），页面逐格判、∞ 可选；`practice` 加一种由引擎出题的题型（随机数组 / 随机图 → 引擎算答案），比如 `type: engine` 配 `engine: sort`、`algo: quick`。理由：王道的题大多是「填一张表」，现在只能拆成一个个向量或只判最后的序列；自定义练习只能出表达式题，排序、散列、图都练不熟。
