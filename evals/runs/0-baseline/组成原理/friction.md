## co-arith　补码加减和标志位

**理想的教法**
- 学生自己写竖式：两行 8 位格子，学生逐位填和、在每一位上方填进位（Pencil 点 0/1 就行），页面逐位判；写完再填一张 OF / SF / ZF / CF 的小表，页面判。
- 一张「数轮」：模 256 的一个圆，外圈刻 0～255（无符号），内圈刻 −128～127（补码）。加法就是在圆上往前走。走过 127 / −128 那道缝就是 OF，走过 255 / 0 那道缝就是 CF。学生拖 x、y 两个滑块，看结果点在圆上跑，自己找出两种溢出的边界。OF 和 CF 的区别一张图就能说清，这是这节课最想要的东西。
- 同一个 8 位串旁边有一个开关「当无符号读 / 当补码读」，学生切换着看。

**现有组件做到了哪些**（6 块板）
- `bits num: -50`（`show: 原码 反码 补码`，`ask: twos`）：从原码走到补码，补码那一步让学生先写。
- `bits add: 100 + 50`、`bits sub: 100 - 50`：竖式、进位、四个标志都由页面算；`ask: result, of, sf, zf, cf` / `ask: neg, result, of, cf` 让学生先写再揭晓。这是这节课的主体，组件够用。
- 第 4 块板用一张 `\calc` 的表（`bin` / `mod` / `signed`）把「无符号读 / 有符号读 / 应该是」并排列出来，加一个 `conjecture`（实时黑板默认 `grade: off`，我来看）。
- 第 5 块板 `bits add: 0x64 + 0xCE` 让学生看到：8 位结果和 x − y 一样，加法的 CF = 1、减法的 CF = 0（王道 CF = Cout ⊕ Cin）。
- 第 6 块板 `practice type: custom`：随机 x、y 算 x − y，答案写成向量 `[OF, SF, ZF, CF]`，判断全部用表达式（比较式得 0/1、`bit(r, 7)`、`mod`）。

**想做但做不到的**
- **学生自己写竖式做不到。**`bits` 的竖式是页面画好的，学生只在 `ask` 的地方填结果和标志，进位那一行学生没法写，也就判不了「哪一位进位算错了」。
- **换一组数从头写，没有对应的题型。**`bits` 的 `add` / `sub` 用法说明里没写 `mode: quiz`（只有 `num` 写了 `quiz: 补码`），所以练习只能用 `practice` 拼。`practice` 一道题只能有一种答案：8 位结果（`check: bin`）和四个 0/1 标志放不进同一题。我只问了四个标志，结果放在 `explain` 里，所以「机器数写对没有」在练习里没判。
- **练习只能练减法。**`practice` 的题面没法按随机到的情况换字（加 / 减二选一时，「+」「−」写不出来），只能固定一种运算。
- **数轮做不到。**`scene` 标的是线代专用；就算能用，也画不出带两套刻度的圆、标不出「过缝」的地方。`sketch` 只能画一张不能动的。
- **`bits` 的输入不能引用 `let` 变量**（至少说明没写可以）：x、y 在 `let` 里定义过，`bits` 里还要再手写 `100 + 50`。x + (−y) 那块板只能写成我自己换算好的 `0x64 + 0xCE`，这正是「不要自己算好再填」想避免的。

**写法上拿不准的**
- `add:` 能不能写负的操作数（`100 + -50`、`100 + (-50)`）？说明里只有 `0x7F + 0x01`、`5 - 7` 两个例子。
- `ask: result` 要学生写二进制还是十六进制、要不要写满 8 位？「我写二进制，要写满 width 位」这句话只写在 `num` 的用法里。`neg` 大概只对 `sub` 有意义，我只在 `sub` 里用了。
- 向量答案的输入框是竖的一列还是横的一排？`before:` 我写成竖的 `bmatrix`（OF / SF / ZF / CF）去对齐，纯属猜测。作答记录里向量写成 `(9, 3, 4)`，看着像横的。
- `bin(x+y, 8)`：x + y = 150，超出了 8 位补码的范围。说明只说「负数写成补码」，没说 128～255 是照无符号写出来还是报错。`signed(150, 8)` 应该得 −106，但说明的例子只有 `0xFF`。
- 加法的 CF：我照说明写的「CF = Cout ⊕ Cin（王道）」设计了第 5 块板，结论是加法 CF = 1、减法 CF = 0。如果组件给加法另用一套 CF 定义，这块板就讲反了。

## co-float　IEEE 754 单精度

**理想的教法**
- 32 个格子分成 1 | 8 | 23 三段上色，学生用 Pencil / 点击把位填进去，页面分段判（哪一段错了）。
- 一个滑块拖动十进制数：三段实时变化，阶码跟着 2 的幂一格一格跳，尾数在两个 2 的幂之间均匀变。学生自己看出「阶码管数量级、尾数管精度」。
- 「乘 2 取整」做成一张竖表，学生一行行填（0.375 → 0.75 → 1.5 → 1.0，取出 0、1、1），页面逐行判。

**现有组件做到了哪些**（6 块板）
- 两个 `answer type: bin`：10 → 4 位、0.375 → 小数点后 3 位（答案写成 `0.375 * 8`，让页面算）。
- `steps`：小数点挪几位（选择）→ 阶码字段（自由回答，揭开时 `\calc{bin(3+127, 8)}`）→ 尾数存哪部分（选择，考隐藏位）。
- `bits float: -10.375`（`ask: sign, exp, hex`）编码，`bits float: 0xC1260000`（`ask: exp, value`）解码，都由页面算。
- `findbug`：把隐藏位也存进尾数的错解，错解的十六进制用 `\calc{hex(…)}` 算出来。
- `practice type: custom` + `check: hex` + `width: 8`：随机出 ±n.fff，答案用字段拼出来：`s*2^31 + (E+127)*2^23 + m*2^23`。

**想做但做不到的**
- **二进制小数没有答案类型。**`type: bin` 只认整数位串，学生写「1010.011」判不了，我只好拆成「整数 4 位」「小数点后 3 位」两道题。
- **`\calc` 写不出十进制小数。**精确分数显示成分数，−10.375 会写成 −83/8。课件里的十进制数只能手写；练习的题面我用 `\calc{(1-2*s)*n}.\calc{f*125}` 硬拼出「−10.375」这种样子（f 只能取 1～7，保证正好三位小数）。这是凑出来的。想要 `dec(x, 3)` 这样把数写成小数的函数。
- **没有算 IEEE 754 编码的函数**（比如 `f32(x)` 求编码、`f32val(h)` 求值）。练习只能反过来，先随机字段再拼出数，指数用 `(n>=2)+(n>=4)+(n>=8)+(n>=16)` 凑。所以练不了「除不尽、要舍入」的数，解码方向的练习还得另写一套模板。
- **`bits float` 没有「尾数字段」的 ask**，也没有 `mode: quiz`。尾数恰恰最容易错（隐藏位、补 0 补到 23 位），只能靠 `steps` 的选择题和 `findbug` 补。
- **`steps` 的 `do: true` 不能判二进制**：说明里 `do: true` 能判的只有数 / 向量 / 矩阵 / 式子，没有 `type: bin`。「写出 8 位阶码」只好做成自由回答，不能自动判分。

**写法上拿不准的**
- `\calc{hex(x, 8)}` 的输出带不带 `0x`、带不带 `H`？我不敢在后面加「H」，只好在文字里写「（十六进制）」。`\calc{bin(…, 23)}` 的分组是不是从右往左四位一组？
- `bits float:` 写十进制 `-10.375` 应该精确（能除尽），解码写 `0xC1260000` 是照说明抄的。

## co-cache　组相联映射和 LRU

**理想的教法**
- **学生自己填那张表**：一次访问占一列，学生填组号、标记、命中 / 缺失；缺失时把主存块拖进这一组的某一路，组满时拖走要换掉的那一块；页面逐格判。
- **地址条**：16 位地址画成一条，学生拖两根分隔线切出「标记 | 组号 | 块内」，页面判切得对不对。拖行数、路数、块大小的滑块，分隔线跟着挪，学生自己看出「组号位数只跟组数有关」。
- 把王道的 LRU 计数器（LRU 位）每一步都显示出来。

**现有组件做到了哪些**（6 块板）
- `steps`，四步 `do: true`：块内地址、组数、组号位数、标记位数，答案都是表达式（`log2(B)`、`L / W`……）。
- `answer`，答案是向量 `[组号, 标记]`：拆 0x0090。
- `cache`（`lines: 8`、`ways: 2`、`replace: lru`、`refs` + `block: 16B` + `addr: 16`，`ask: set, hit, victim, hits`）：主体演示，地址拆分、表、命中都由页面算。
- `quiz`（别的组空着为什么还要换）+ `conjecture`（第 4 次访问 LRU 换 0x0050 那块、不换先进来的 0x0010 那块，和 FIFO 区分开）。
- 同一串访问 `replace: fifo` + `mode: quiz`（命中次数），让学生自己走一遍再对照。
- `practice type: custom`：行数、块大小、路数、地址都随机，答 `[组号, 标记]`。

**想做但做不到的**
- **`cache` 的 ask 没有 `tag`（标记）。**题目明确要求「写出每次访问的组号、标记」，可标记只能看页面画好的拆分，学生没法先写再看。我只好另出一道 `answer` 问一个地址的标记。
- **`mode: quiz` 只能问命中次数。**学生写不了整串组号 / 标记 / 命中情况。`type: seq` 能判序列，可那样答案就是我手写的，不是组件算的。
- **不知道 `cache` 画不画 LRU 的先后顺序或计数器。**王道就是用 LRU 位讲的，说明只说表里有「有效位、标记、存的主存块」。如果不画，学生在 `ask: victim` 时只能自己记。
- **地址条拖分隔线做不到**（`scene` 是线代专用的）。
- **想把 LRU 和 FIFO 两张表并排对比**（或者 2 路和直接映射对比）：两个 `cache` 组件一屏放不下，也没有「对比」模式。只好放到两块板上，学生来回翻。

**写法上拿不准的**
- `ask: set` 学生写的是十进制组号吗？`victim`「点出来」，是点表里的那一行，还是点主存块号？`hits` 是不是在最后一步问？它和 `mode: quiz` 有什么区别？
- 组号、标记用向量答，只能填十进制。408 里标记常写成二进制（如 00 0000 0010），向量做不到。
- `steps` 的 `do: true` 那一步还显示不显示 `ask:`？说明只说「这一步不揭开，要我自己做出来」。我每一步都写了 `ask:` 当题干，要是不显示，学生就只看得到 step 的小标题。

## co-pipe　流水线的数据冒险

**理想的教法**
- **学生自己画时空图**：每条指令一行，学生把 IF / ID / EX / MEM / WB 拖进周期格，或者点格子插入阻塞，页面逐格判。画错的地方标出原因，比如「sub 的 ID 不能早于 add 的 WB」。
- 学生从 add 的 WB 拖一条箭头到 sub 的 ID，画出数据相关，页面判它是不是写后读、是哪个寄存器。
- 有转发时把转发通路（EX/MEM → EX）画成箭头，两张图上下对齐比较。

**现有组件做到了哪些**（5 块板）
- `quiz`（多选）：找写后读相关。
- `sketch` 画「不停顿的话」add / sub 的理想时空图（WB 和 ID 上色，加一条倒着走的箭头），配 `steps`：sub 最早第几周期 ID（选择）→ 停几个周期（`do: true`）→「写完才能读」时停几个（选择）。
- `pipe`（不转发，`ask: stall, cycles`）+ `quiz`（and 也读 r1，为什么不用再停）。
- `pipe`（`forward: yes`，`ask: stall, cycles`）+ `answer`（省了几个周期）。
- 换一段代码的 `pipe mode: quiz`（总周期数）：故意让 I3 同时依赖距离 1 和距离 2 的两条指令。

**想做但做不到的**
- **学生自己画时空图做不到。**没有可以填的网格；`mode: quiz` 只问总周期数，学生画的图我只能看「交截图」。这节课「能画时空图」那个目标，页面判不了。
- **`pipe` 的 ask 只有「停几个周期」「一共几个周期」**，没有「和谁相关 / 哪个寄存器」「ID 推到第几个周期」。
- **「转发省了几个周期」只能我手写 `answer: 2`。**别的组件引用不到 `pipe` 算出来的周期数，违反了「数让页面算」。希望演示组件能把结果导出成变量（比如 `p-stall.cycles`）。
- **`sketch` 不能跟着 `steps` 一步步出现**：它没有 `link` / `from=`。理想时空图上那条提示箭头一开始就全画着。
- **转发之后还有 load-use**（`lw` 后面紧跟着用，转发了也要停 1 拍）：说明没说 `pipe` 处理不处理，我没敢用 `lw`。所以「转发能省多少、省不掉哪一拍」只教了一半。

**写法上拿不准的**
- **`instrs:` 怎么写多行**：说明说「一行一条（或用分号隔开）」，又说「可以带标号 `I1: …`」。可续行上写 `I1: add …`，会不会被当成名叫 `I1` 的字段？我只好用分号写成一行、不带标号。这样组件里的指令名可能和我板上、常驻栏里说的 I1～I4 对不上。
- 阻塞画成 ID 重复，还是 IF 后面插气泡？说明没说，王道两种画法都有。我的文字只写了「原地不动」。
- `ask: stall` 是每条指令都问，还是只问有冲突的那几条？

## co-mem　存储器扩展

**理想的教法**
- **连线题**：芯片阵列、2-4 译码器、地址线、数据线都摆在板上，学生用 Pencil 或拖动把线连起来（A10～A0 → 每一片，A12A11 → 译码器，Yi → 每组的片选，D7～D4 / D3～D0 → 各片），页面逐根判。
- **地址探针**：拖一个地址滑块（0000H～1FFFH），图上亮出被选中的那一组、片内第几个单元，学生自己看出地址范围是怎么来的；反过来，学生写一个地址，页面亮出它落在哪一片。
- 四组的地址范围做成一张 4 行的表，学生逐格填十六进制，页面判。

**现有组件做到了哪些**（6 块板）
- `steps`，四步 `do: true`：片数、几片一组、几组、每片几根地址线，答案都是表达式。
- `recognize`：位扩展 / 字扩展 / 字位同时扩展，5 道小题，要写理由。
- `steps` 的选择题：低位地址线、高位地址线、数据线各接哪里。
- `sketch`：8 片 + 译码器的静态连线图，配一个 `key`。
- `derive` 写第 1 组的地址范围（`\calc{hex(…)}`），两个 `answer type: hex` 让学生写第 2 组的起点和终点；常驻栏放四组范围（`\calc` 算的）。
- `practice type: custom`：芯片大小、组数、地址都随机，判地址落在第几组。

**想做但做不到的**
- **存储器扩展 / 地址译码没有专门的组件。**连线只能用选择题一项项问；图只能静态画，学生连不了线，也判不了分。
- **地址探针做不到。**`scene` 是线代专用的，也不认芯片图。「由地址判断落在哪一片」只能靠练习题去算，学生看不到。
- **地址范围表**要么一格一个 `answer`（8 格，一屏放不下），要么只问一组。我只问了第 2 组，其余三组直接给了。
- **`sketch` 不能跟着 `steps` 逐步出现。**连线图只好挪到下一块板，不然会提前把答案露给学生。
- 片选是低电平有效（$\overline{CS}$、$\overline{Y_i}$），`sketch` 的 `text` 写不了上划线。`tex` 可以写，可说明没说 `tex` 的 y 是基线还是中心，我不敢在图里用。

**写法上拿不准的**
- `polyline` 要不要写 `fill="none"`？默认会不会把折线围成的区域填上颜色？说明没说。
- `recognize` 的说明只举了线代的例子，用在这里我认为合适，但 `methods` 里能写什么名字没有说明。
- `derive` 一行里有 `\underbrace{…}_{…}`，后面再接 `//` 旁注，左栏 `\text{最小}` 会不会挤，看不到。

## co-asm　机器级代码

**理想的教法**
- **x86 逐条执行器**：左边是汇编（行号和题目一致），右边是寄存器（eax、ebx、ecx、edx、esp、ebp、eip、标志位）和一段栈内存（地址从高往低排，esp、ebp 两个箭头）。每执行一条，变化的地方亮一下，每一行旁边有执行次数的计数。`ask:` 能问「执行完这一条 esp 是多少」「这一条访问哪个地址」「jge 跳不跳 / 下一条执行第几行」「这一行一共执行几次」。
- 从调用者开始执行（`push n`、`push a`、`call sum`），学生看着栈一项项长出来，参数为什么在 [ebp+8] 就不用讲了。
- 汇编和 C 对照：点一行 C，亮出对应的几行汇编，反过来也行；或者学生把 C 语句拖线连到汇编行，页面判。

**现有组件做到了哪些**（6 块板）
- `steps` 的选择题：参数谁先压、`call` 压了什么、ebp 指向哪里。
- `sketch` 静态栈帧图 + `answer type: hex`（给定 esp 初值，求 ebp）。
- `steps` 的选择题：ecx、edx、eax、ebx 各是 C 里的谁；两步自由回答讲循环结构。
- `answer type: hex`（i = 2 时第 9 行访问的地址，`0x00401000 + 2*4`）+ `quiz`（为什么乘 4）。
- `trace` 跑 C 版本（`call: sum(a, 3)`，`let a = [5, 7, 9]`，`ask: cond`），学生数出「i < n 判断 4 次」，再对回「汇编第 7 行执行 4 次」；配一个向量 `answer`。
- `practice type: custom`：随机 n（含 0），答第 7、9、11 行各执行几次。

**想做但做不到的**
- **没有汇编的执行 / 跟踪组件，这是最大的缺口。**这道题的主体就是汇编，可 `trace` 只认 C，还不支持指针，连「C 里的 a 其实是个地址」都演示不了。我只能拿 C 版本绕着讲，让学生自己把 C 的一步对回汇编的一行。
- **栈帧图是死的。**esp、ebp 怎么随 push / call / mov 变化，没法一步步动起来；栈上的地址也没法跟学生给的 esp 初值联动。
- **执行次数**：没有「这一行执行了几次」的问法（`trace` 的 `predict` 只能问变量的值，`ask` 只有 `cond` / `line`），也不显示计数。答案只能我写成 `n + 1`、`n`。
- **汇编 13 行，好几块板都要用**，可常驻栏只放两三行。我只好每块板重贴一段，很占地方。
- **汇编和 C 的对应**只能用选择题一项项问，没有连线 / 配对题型。

**写法上拿不准的**
- **普通代码块会不会被当成组件。**说明只说「组件就是带特定语言名的代码块」，没说普通代码怎么写：写 ```` ```c ```` 会不会被当成一个叫 `c` 的组件，报「不认识」？我一律用了不写语言名的代码块。
- **`trace` 改了题目的代码。**`int a[]` 作参数，配 `call: sum(a, 3)`、`let a = [5, 7, 9]`，应该能跑（说明的例子是 `ElemType A[]`）。可 `for(int i=0; …)` 这种在 for 里声明变量的写法支不支持，说明没说，我改成了先写 `int i;`，代码就和题目不完全一样了。另外 `trace` 的代码只有 7 行，行号和汇编的第 7、9 行撞在一起，学生可能看混（我在题面里写了「汇编第 7 行」）。
- `ask: cond` 对 for 那一行，是不是每次判断都问（这里会问 4 次）？

## 每题都碰到的（通用）

- **一次写完整条路径，后面的内容会剧透前面的 ask。**常驻栏里的结论、后一段 quiz 的选项和前面的题同时摆在页面上。真实上课我会看着作答一轮轮写，这里只能用 `seq` 表示先后。说明里没有「这一段等学生做完上一段再显示」的写法。
- **`let` 块放在哪一段说不清。**说明说「定义一次，之后所有的段都能用」，但没说「之后」是按 `seq`、按板号，还是按渲染的先后。常驻栏的段在另一个容器里，能不能用正文段里 `let` 的变量？我把 `let` 放在第一段，常驻栏的 `seq` 排在它后面，全靠猜。
- **计算机课缺「多格作答」。**组号 + 标记、四个标志位、地址范围的起点终点、三行的执行次数……都是好几个小格，类型还常常不一样（二进制、十六进制、0/1、十进制）。现在只能用向量凑（只能填数，标签也对不齐），或者拆成好几个 `answer`（一屏放不下）。
- **演示组件和别的组件不通。**组件的输入不能用 `let` 变量或 `\calc`，同一组数要在 `let` 和组件里各写一遍，改数容易对不上；组件算出的结果（周期数、命中次数）也不能被别的组件引用，对比题只能手写答案。
- **408 没有能拖的交互。**`scene` / `predict` / `graph` 都标着线代专用，408 的交互全是点选和填数。「拖滑块看位串变化」「拖地址探针」这类最直观的东西都做不了。
- **`practice` 的 `check:` 没有 `seq`**，练不了「写出整串的命中情况 / 置换序列」。
- **说明里有两处前后不一致：**
  - 第二节原则 7 说「术语第一次出现时附英文」，紧接着 408 小节又说「计算机课的术语用中文，不附英文」。我照后者写了，但两条并排放着，读的时候会犹豫。
  - 课堂说明说「一块板只放一件要学生动脑的事」，实时黑板只说「一句引导 + 一张图 + 一道题」。有几块板我放了两道很小的题（比如整数部分 + 小数部分），不知道算不算超。
- **课堂模式：** 第二轮的 `board mark target=b1 term=ways`，我把 `\hl{ways}{…}` 写在了 `answer` 的 `q:` 里面。说明没说 `mark` 能不能找到组件字段里的 `\hl`，例子里的 `\hl` 都在正文公式里。

## 如果组件库只能再加三样

1. **`asm`：汇编逐条执行器（x86，最好也支持王道用的简化 MIPS）。**画出寄存器、标志位、一段栈内存和 esp / ebp 箭头，每一行带执行计数；可以从调用者开始执行（压参数、`call`）。`ask:` 能问寄存器的值、访问的地址、跳不跳转、某一行执行几次，`mode: quiz` 写出最后的寄存器 / 栈。
   为什么：机器级代码是组成原理大题的常客（栈帧、寻址、循环次数、标志位，一道题全占了），现有组件完全覆盖不到。`trace` 只能跑 C，我只能绕着讲，学生最该看的「栈怎么长、寄存器怎么变」一步也看不到。
2. **表格作答（`grid` / `table`）。**我写表头，每一格写一个答案表达式，每格可以是数、0/1、`bin`、`hex`、序列；学生逐格填，页面逐格判，标出哪格不对。最好能直接指定「答案来自某个演示组件」（比如 `from: c-lru`），让学生填 cache 那张组号 / 标记 / 命中表、`pipe` 的时空图、存储器的地址范围表、标志位表。
   为什么：408 组成原理一大半题的答案本身就是一张表（cache 访问表、时空图、地址范围、标志位）。现在要么用向量凑，要么拆成一屏放不下的一串 `answer`，要么只能看截图。有了它，co-cache、co-pipe、co-mem、co-arith 四节课都能让学生「自己写出整张表」再判分，而不是只猜几个点。
3. **`memexp`：存储器扩展 / 地址译码。**给芯片规格、目标容量和片选方式（线选 / 2-4、3-8 译码），画出芯片阵列、译码器和连线；有一个地址探针（拖动或输入地址，亮出选中的芯片和片内单元）；`ask:` 能问片数、每片地址线、某组的地址范围（`hex`）、某地址在哪一片。学生还可以自己连线，页面判每一根。
   为什么：这一类每年都考，现在只能用静态 `sketch` 加选择题讲，学生最需要的「地址 ↔ 芯片」的对应根本看不到；连线这个核心动作也没法让学生自己做。

（没排进前三、但很想要的：`dec(x, k)` 把数写成十进制小数；`cache` 的 `ask: tag`；演示组件的输入能用 `let` 变量，结果能导出给别的组件引用；408 也能用一个能拖的滑块。）
