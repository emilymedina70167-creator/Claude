# 摩擦报告 · 操作系统（第二批，1-phase5）

总体：这一批五道题，组件库都有对口的专门组件（`mem`、`bitmap`、`paging eclock + init/ptr`、`alloc best`、`pv swap/find`），比第一批顺手得多。下面的问题主要是「学生自己动手的那一步」还缺：页面会把过程演示出来、会判最后结果，但「中间状态由学生自己写、页面逐格批」的地方不全，还有几处写法只能猜。

## os-mem　快表、页表、缺页的整条链（2009-46）

**理想的教法**
1. 学生自己把三个地址拆成「页号 | 偏移」（最好是在二进制位上自己划一刀）。
2. 学生把每一次访问的路径**自己拼出来**：从一排积木（查快表、查页表、缺页处理、更新快表、重新执行、访存）里拖出这一次真正经过的段，按顺序排好，页面再给每段标时间、加总。
3. 缺页那次单独停下来问「重新执行时快表命中吗」，再问 LRU 换谁、换到哪个块、物理地址。
4. 换一组数，学生自己填整张表。

**现有组件做到了**
- `answer` 向量 + `div(0x2362, 4096)`：页号让页面算；偏移用 `\calc{hex(mod(…), 3)}` 写在解析里。
- `mem` 组件照搬 2009 年口径走整条链，`ask: tlb, inmem, victim, time` 先猜再看；`mode: fill` 让学生换一组数自己填页号、命中、缺页、物理地址、用时。这一题它几乎就是为这道题写的。
- `answer type: hex` 判 1565H 的物理地址，`answer:` 写成 `0x101 * 0x1000 + 0x565` 让页面算。
- 「重新执行为什么命中」只能用 `quiz` 选择题问。

**想做但做不到的**
- **让学生自己拼「这次访问经过哪几段」**：想要一个「拖积木排顺序」的操作（或在 `mem` 里加 `ask: path`：给出所有段，学生依次点出这次经过的段）。现在只能用 `sketch` 画一条固定的路，再让学生填总时间——学生是在加三个数，不是在想「这一次走了哪几段」。缺页那一次（查快表 → 查页表 → 缺页 → 重新执行 → 快表命中 → 访存）最需要学生自己排，恰恰排不了。
- **在地址的二进制位上自己划页号 / 偏移的分界**：`addr` 画好了拆开的位，但没有「学生点一下在哪一位切开」的问法（`ask: page` 是问页号的值）。
- `mem` 的 `ask:` 能问的种类我只在精简说明里看到一串名字（`page tlb inmem victim paddr time`），每种问的是什么（选择？点？填数？在第几次访问前问？）没有说明，只能猜。

**写法上拿不准的**
- `mem` 的 `resident: 2` 和 `order:`：默认「驻留的页从老到新 = 页号从小到大」。这题第一次访问的是页 2，LRU 结果不受影响；但如果题目给的初始驻留顺序不是按页号，就得写 `order:`，它的写法（`order: 2 0`？）说明里没有例子。
- `mem` 的 `mode: fill` 里「快表命中」「缺页」是打 √ 的格子，变式里页 2 被换出以后快表里那一项是否作废（页面是否自动把被换出页的快表项删掉），说明里没写，我只能相信页面会处理对。
- `\calc{10 + 100 + 10^8 + 10 + 100}` 写出来是 100000220，不知道会不会自动写成科学计数法；考研答案一般写 $10^8+220$，想要「按这个样子写」的格式控制。
- `answer: 10 + 100 + 100` 这种其实是我把路径想好了再写算式，算不上「页面算」：页面能算的是「给定路径的时间」，路径本身没有组件能算（除了 `mem`，但它是演示，不是判学生的路径）。

## os-bitmap　位示图（2015）

**理想的教法**
1. 学生自己算「一块管多少盘块」（1 KB × 8）。
2. 用除法和取余一步步定位：块 → 实际盘块号（加 32）→ 块内字节 → 字节内的位。最好画面上有一块「1 KB 的盘块展开成 1024 个字节、每个字节 8 位」的示意，学生的数算出来，对应的那一格亮起来。
3. 对比编号从 0 和从 1：同一个盘块号，两种口径各算一遍，并排看公式里多了哪个 −1 / +1。
4. 换数练熟。

**现有组件做到了**
- `answer` + 本段 `let` 块（`n = 1024 * 8`）算一块管多少。
- `steps` 四步 `do: true`，每步 `answer:` 写 `div(b, n)`、`32 + div(b, n)` 这样的表达式，`show:` 里全用 `\calc`。
- `bitmap` 有 `at: 32`、`block: 1KB`、`ops: free 409612` 正是 2015 年这道题；`base: 1` + `mode: quiz` 做从 1 编号的对照。
- `derive` 写一般式 $i=\lfloor(b-b_0)\div n\rfloor+i_0$。
- `practice type: custom` 随机取起始块、块大小、盘块号，答案是二元向量，精确判分。

**想做但做不到的**
- **从 0 / 从 1 两种口径并排**：想要同一个 `bitmap` 里一键切换 `base`，或者两个口径并排算同一个盘块，差的那一步标出来。现在只能放一个 base: 1 的 quiz，再用 `derive` 写一般式，学生看不到「差在哪一步」是怎么一步步冒出来的。
- **磁盘上的位示图画面**：说明说「位示图存在磁盘上：ops 只能用 where、free」，没说这时画面画什么（画 1 KB 的整块？只画那一个字节？）。我想让学生在一个字节的 8 个格子里点出要改的那一位，不知道 `ask: bit` 在磁盘模式下是不是点格子。
- `practice` 的二元向量答案，输入框前面我用 `before:` 写了 `(\text{盘块号}, \text{字节号}) =`；想给每个格子单独贴标签（「盘块号 □  字节号 □」），现在没有写法。

**写法上拿不准的**
- **`let` 块在实时黑板里的作用范围**：说明说「定义一次，之后所有的段、组件都能直接用」，但实时黑板的段是数据库里分开的文档、可能按顺序以外的方式重画。我不敢只在第 1 段写一次，于是每段都重复写了同一个 `let` 块。希望说明明确：live 里 `let` 是整块黑板共享，还是只在本段。
- `steps` 的 `do: true` 配 `answer: div(b, n)`：说明说「answer 能算出数时页面判对错」，例子只有 `[1, 2]` 这种字面量，表达式和 `let` 变量能不能用没写死，我猜能。
- `bitmap` 磁盘模式 + `base: 1`：`at: 32` 这时是不是还按「第 32 号」理解、`base: 1` 是不是同时改了块内字节号，说明没说；`mode: quiz` 写「盘块号 字节号」这个顺序我是照说明猜的。
- `bitmap` 的 `ask: disk` 是问什么（实际盘块号？）没解释。

## os-eclock　改进型 CLOCK

**理想的教法**
1. 先让学生说出四类页面的淘汰优先级、为什么。
2. **学生自己拨指针**：画面是四个物理块围成一圈，每块上标（访问位, 修改位），学生一下一下点「指针前进」，每到一块自己决定「选它 / 不选，访问位改不改」，页面逐步批（第 1 轮改了位当场指出）。
3. 走完整道题，第三次访问前先猜换谁。
4. 换一组会扫到第 3 轮的数据，学生自己走完。

**现有组件做到了**
- `quiz` 问四类页面谁先换。
- `steps` + `choices` 问第 1 轮改不改位、第 2 轮停在哪块（但每一步的 `show:` 是我自己写的状态）。
- `paging algo: eclock` + `init:` + `ptr:` + `refs: 5 2w 6` 正好是这道题的开始状态，`ask: victim` 先猜；变式用 `mode: quiz`、`quiz: victims`（我挑的数据会扫到第 3 轮）。错法诊断认得「第 1 轮就清了访问位」，正好是这一题最想抓的错。

**想做但做不到的**
- **一格一格的指针扫描**：`paging` 是「一列一次访问」的表，一次访问里指针扫了几圈、每一格的位怎么变，看不出来是逐格演示还是一步就跳到结果。教这一题的关键恰恰是「每一次指针怎么动」。想要 `paging eclock` 有一种按「指针每走一格算一步」的视图（圆环画法），配 `ask: scan`（这一格选不选、访问位改不改）。
- **学生自己走扫描、页面逐格批**：`mode: fill` 只填每次访问后各块的页、缺页、换出谁，不填访问位 / 修改位和指针，所以「自己走出每一次指针怎么动」页面判不了。我只能在变式板上放一个草稿区让学生自己写、只判最后的换出序列。
- 课堂第三轮我用 `frames` 手写了「第 1 轮就清 0」的错走法，每一帧都是我自己算的——这正是规矩里说的「不要自己算轨迹」。如果 `paging` 能接一个 `variant: clear-first`（按某种错法跑给学生看），对比错法和正确做法就不用手算了。错法诊断已经认得这个错法，说明页面里有这条跑法，只是不能拿出来演示。

**写法上拿不准的**
- `init:` 写成 `1 1 0, 2 1 1, …`，「页 访问位 修改位」——引用串里的 `2w` 是写操作，开始状态里的页如果是被写过的，就是修改位 1，这一点对上了；但 `ptr: 1` 是从 1 数的块号还是从 0，说明写「指针指着第几块」，我按从 1 数。
- 「写页 2」命中以后修改位置 1、访问位置 1、指针不动，这些口径说明没写，我在资料包 `textbook` 里自己补了，不知道和页面一致不一致。
- `steps` 的 `choices:` 选项里带全角括号「块 3（页 3）」、选项里有逗号（「没找到，访问位都不动」）：选项用 `|` 分隔，逗号应该没事，但不确定。
- `frames` 的格子值大量重复（访问位一排都是 0 / 1），「重复的值按出现的先后对应」滑动动画会不会乱飞，看不到。

## os-alloc　动态分区分配：最佳适应

**理想的教法**
1. 学生**自己维护空闲分区表**：每次分配 / 回收之后，在一张表里改写空闲区（起址、大小），按容量从小到大排好；页面逐行批，回收时问「和上邻、下邻哪块合并」。
2. 在内存条上点出这次分到哪块空闲区。
3. 最后对比首次适应，看碎片。

**现有组件做到了**
- `quiz` 讲清「按容量从小到大找第一个放得下的」，故意让首次 / 最佳 / 最坏三种答案不同。
- `alloc` 演示（`used: OS 0 40K`，自编的小例子覆盖「不合并 / 和下邻合并 / 上下都合并」三种回收），`ask: where, merge`。
- `alloc mode: fill` 让学生填这道题七个作业的起始地址。
- `alloc algo: first` + `start: end` 并排看首次适应的结果，`conjecture`（`grade: off`）问为什么留小碎片。

**想做但做不到的**
- **自己维护空闲分区表**：`mode: fill` 只填起始地址，不填空闲分区表。这一题「教到什么程度」第一条就是「自己维护空闲分区表」，现在只能让学生在草稿区手写，页面不批。想要 `alloc` 的 fill 加 `cols: holes`：每一步之后填整张空闲分区表（起址、大小，按算法要求的顺序排），页面逐格批、标出第一处错。
- **最佳适应的「排序」这一步**：想让学生每次分配前把空闲区拖成从小到大的顺序，页面看顺序对不对。没有拖动排序的操作。
- 首次适应 vs 最佳适应同一串请求并排对比：现在是两个组件上下放，没有「同一张内存条两种算法并排」的画法，也没法让页面算出「两种算法最后的碎片总量」给我写进说明（`ask: max` 只问最大的空闲区）。

**写法上拿不准的**
- `ops:` 的作业名能不能是数字（`alloc 1 130K`）：说明的例子就是数字，照抄了；但 `free 1` 和「释放 1K」会不会混，不知道。
- `start: end` 是演示组件通用字段，`alloc` 是不是演示组件（stepper）说明里没明说，我猜是。
- `alloc` 的 fill 里分配失败写 ×，这题没有失败，不影响。

## os-pc　生产者-消费者，P 操作的顺序

**理想的教法**
1. 学生写对三个信号量和初值。
2. **学生自己写出两个进程的 P、V 代码**，页面判：放进 `pv` 里跑，自动找有没有死锁、有没有越界、互斥对不对。
3. 在一个具体的交替顺序下跟踪信号量的值（填表）。
4. 把 P 反过来，学生自己点进程，找出死锁的走法；再说清谁拿着什么、等什么。

**现有组件做到了**
- `answer` 向量判初值（取 n = 2）。
- `pv problem: 生产者消费者` + `run: C P+` + `mode: fill`：跟踪每个 P / V 之后的信号量。
- `pv swap: P` + `find: deadlock`：学生自己点「下一步让谁走」找死锁，还能点「我觉得不会死锁」由页面穷举判。这一块正好是这题最想要的操作。
- `conjecture grade: off` 让学生说死锁时谁拿着什么、等什么；`solution` 折起来放结论。

**想做但做不到的**
- **学生自己写的 PV 代码由页面跑**：`pv` 的 `code:` 是老师写的；学生写代码只能交到 `conjecture`（`grade: off`），由我看。想要一个「学生在框里写 `P×1: while(1){…}`、页面用 `pv` 的引擎跑 `find: bad` 判有没有死锁 / 越界 / 互斥被破坏」的作答组件（类似数据结构的 `code`，但跑的是 PV）。
- `run: C P+` 的 fill 我不确定一共几行，也就没法保证这块板一屏放得下（buffer 取 2 是为了行数少，这和题目的 n 个缓冲区只是凑出来的）。

**写法上拿不准的**
- `problem: 生产者消费者` 时进程叫什么名字（`P`、`C`？还是「生产者」「消费者」）说明里没写死；`run: C P+` 和 `swap: P` 都是按 `P` / `C` 猜的。`swap: P` 里的 P 到底是「生产者进程 P」还是「P 操作」，读了两遍才理解成「换进程 P 的头两个 P 操作」。
- `run: C P+`：消费者先 P(full) 阻塞；生产者 V(full) 唤醒消费者以后，`P+` 是继续只走生产者、直到它自己阻塞吗？我按这个理解写的说明文字。
- 「生产一个产品」这种非 PV 句子在 `run:` 里算不算一步、在 fill 里有没有一行：说明说 fill 是「每个 P / V（和改共享变量）之后」一行，那么 `run:` 计步和 fill 行数不一致，`P×3` 这种写法要数句子，很容易数错。
- `find: deadlock` 和 `ask: block` 能不能一起用（学生自己点进程时，执行 P 前先问会不会阻塞）：说明说「ask: 写了的种类，点了进程以后、执行之前先问我」，应该可以，但没有例子。

- 第三轮我用 `frames` 手算了错法的每一帧（见上面 os-eclock）。课堂里最需要「把学生的错法当场跑给学生看」，现在只有作答记录里的「页面看出来：像是……」给老师看，不能演示。

## 如果组件库只能再加三样

1. **演示组件的「学生自己走中间状态」（fill 能填过程，不只填结果）**：`paging eclock` 填每一次扫描后各块的（访问位, 修改位）和指针，`alloc` 填每一步之后的空闲分区表。这一批五道题里有三道（eclock、alloc、mem 的路径）「教到什么程度」写的都是「自己走出 / 自己维护过程」，而现在页面只判最后结果、过程只能在草稿区手写没人批。这是把「看页面演示」变成「学生自己做、页面逐格批」的最后一步。
2. **用错法跑给学生看（`variant:` 或 `ask` 之后的「按你的做法走一遍」）**：错法诊断已经能认出「第 1 轮就清了访问位」「缺页处理完以为快表没命中」「按 FIFO 换」，但只写给老师。学生答错时，能一键把「按你的做法」跑出来、和正确的并排，是纠正错误最有力的方式；现在要我手写 `frames`，既慢又违反「不自己算轨迹」。
3. **学生写 PV 代码、页面用 `pv` 引擎判**（同步互斥题的 `code`）：同步互斥是 408 操作系统的大题，现在学生写的 PV 只能交截图给老师看。`pv` 已经能穷举状态找死锁、越界、互斥破坏，缺的只是把学生写的代码接进去当输入，并告诉学生「按这个顺序走会死锁」。
