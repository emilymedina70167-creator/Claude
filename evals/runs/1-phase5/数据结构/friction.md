# 摩擦报告 · 数据结构（第二批题库，1-phase5）

写了五节实时黑板（`ds-btree` `ds-huffman` `ds-postfix` `ds-nextval` `ds-reverse`），课堂挑的是 `ds-postfix`（中缀转后缀）。总的感觉：这五道题都有专门的演示组件，「看过程 + 关键一步先猜 + 换数自己做」这条路走得通；做不到的主要是**学生自己动手画结构**（树、链表指针），还有**课件里引用演示组件算出的结果**。

---

## ds-btree　B 树的插入

**理想的教法**
1. 先让学生自己从「m 阶 = 最多 m 棵子树」推出 4 阶结点最多 3 个、非根最少 1 个关键字。
2. 插 5 6 9 13，到第 4 个时停下猜：要不要分裂、哪个上移。
3. 学生**自己在页面上搭出**每次分裂后的树（拖关键字进结点、点「分裂」、把中间那个拖到上一层），页面每一步判对错，错了指出是「上移错了」还是「该分没分」。
4. 换 5 阶（奇数阶，上移的是正中间）再做一遍。

**现有组件做到了**
- `answer` + `let m = 4` 让学生算最多 / 最少关键字个数，`\calc` 写解析。
- `btree` 的 `ask: split, up` 在每次分裂前先问；`mode: quiz` 写最后的树（按层、方括号）；`mode: fill` 每插一个填上移的关键字和根。
- `draft` 让学生画每次分裂后的树。

**想做但做不到的**
- **学生自己画出每次分裂后的树、页面判分**：题目要求「自己画出每次分裂后的树」，现在只能在草稿区 / Notability 画，页面不判（只有截图转写，且 B 树的形状转写不出来）。想要一个「搭树」作答：在画面上点结点插入关键字、点「分裂」选上移的那个，页面逐步比对。
- `mode: quiz` 只能判最后一棵树；中间每次分裂后的整棵树没法让学生写出来判（fill 只填「上移谁、根是谁」，不含每一层）。想要 `mode: fill` 有一个「每次分裂后按层写整棵树」的选项。

**拿不准、只能猜的**
- `mode: fill` 的表长什么样（每插一个一行？只在分裂时一行？），「没有分裂」的格子是写 `-` 还是空着——我在题面里让学生写 `-`，是猜的。
- `ask: split` 是每插一个都问，还是只在结点满的时候问？如果每插一个都问，8 个关键字要问 8 次，有点多，想按步号只问分裂的那几次，但我看不到步号（说明里说先 `start: end` 看几步，可我看不到页面）。
- `quiz` 组件能不能写 `id:`、`title:`：说明的例子里没有，但「会作答的组件写 id」，我写了，不知道会不会报「不认的字段」。
- `draft` 要不要 `id:`：它不判分，我没写。
- 常驻栏 k2（分裂规则）在实时黑板里一上来就全部可见：我按 `seq` 排在第 2 块板后面，但一次写完时它还是比学生的猜测早出现，违反「结论不要早于猜想」。真实上课时会等学生答完再写；一次写完的这份做不到「答完第 2 块板才出现」。

## ds-huffman　哈夫曼编码

**理想的教法**
1. 先问「权大的离根近还是远」建立直觉。
2. 学生每次点出最小的两棵合并（页面算新权）。
3. WPL 两种算法：学生自己按「叶子 × 路径长度」算一遍、按「非叶结点之和」算一遍，再想明白为什么相等。
4. 用编码表译一段码，体会前缀码；说清为什么不会有歧义。
5. 换一组权值独立做。

**现有组件做到了**
- `huffman` 的 `ask: pick, wpl`：每次合并点哪两棵、建完先猜 WPL。
- `steps` 推「为什么非叶结点之和 = WPL」（盯住一个叶子、数祖先）。
- `huffman start: end` 给出编码表，`answer type: seq` 译码；`quiz` + `conjecture` 讲前缀码；`huffman mode: quiz` 换数练 WPL。

**想做但做不到的**
- **两种 WPL 算法分别判分**：`ask: wpl` / `quiz` 只判一个数，看不出学生是按哪种方法算的、哪一项算错。想要 `mode: fill` 里有「每个叶子的路径长度」一列 + 「非叶结点权」一列。
- **译码题的码串得我自己算**：`010010011` 是我按「小的放左、左 0 右 1」手算的 c、a、f、e 的编码拼出来的。想要表达式里能拿到演示组件的结果，比如 `\calc{huffcode("a:6 b:3 …", "c")}` 或 `answer: decode(...)`，这样改了权值，题面和答案跟着变。
- 学生自己画哈夫曼树（同 B 树）：只能截图。
- 想让学生在树上点一个叶子、页面高亮它的所有祖先（「数祖先」那一步），`steps` 里只能用文字描述，没法把 `huffman` 的图绑到 `steps` 上（`link:` 只对 scene / graph / space / matrix / derive）。

**拿不准的**
- `start: end` 停在哪一步：说明说最后几步是「算 WPL」「编码」，我猜最后一步是编码表，所以拿它当译码的参照；如果最后一步是 WPL，学生看不到码。
- 同一块板上两个 `huffman`（不同板）不冲突吧？我用了 `hf-build`、`hf-code`、`hf-quiz` 三个 id。
- `quiz: code` 是「写某一个字符的编码」还是「写全部编码」？说明（完整写法）说 `ask: code` 问码最长的那个，`quiz: code` 没说清，所以我没用。
- `ask: pick` 时学生点的是森林里的根；合并出来的新根是不是也能点？（说明说并列时选哪个都对，本题没有并列。）

## ds-postfix　中缀转后缀

**理想的教法**
1. 先给规则，但「同级弹不弹」空着；用 a − b + c 让学生猜。
2. 猜错的话，让学生看不弹会得到 a b c + −，代数算出它是 a − (b + c)，自己说出「左结合、先来的先算」。
3. 整题自己填王道那张表（每读一个符号：栈、后缀）。
4. 对照过程，重点是 `)` 之后读到 `−`：要把 `*`、`+` 都弹出。
5. 换一个式子独立写。

**现有组件做到了**：几乎全部。`stack` 的 `ask: pop` 正好是「这次弹出哪些」，`mode: fill` 正好是王道那张表，`mode: quiz` 换式子；`quiz` + `let` + `\calc` 代数对比；`conjecture` 让学生一句话说清。错法诊断「同优先级的没弹栈」也正好对上这道题的考点。

**想做但做不到的**
- **让学生自己操作栈**：理想是学生每读一个符号自己点「入栈 / 弹出 / 输出」（像 `elim` 的 `mode: do`），页面判每一步对不对。`ask: pop` 只是选择题，`fill` 是填文字，都不是「动手操作」。
- 想在 `fill` 的表里把学生写错的那一行和「不弹同级」那种错法的那一行并排给学生看（现在错法诊断只给老师看，这点是对的，但想在讲评时由老师一键把「错法的表」放出来）。

**拿不准的**
- `fill` 里栈的写法：栈底→栈顶用空格隔开？`(` 怎么写？我在题面里只写了「栈底 → 栈顶」，不知道学生能不能写对格式。
- `infix:` 用大写字母（`A + B * …`）可不可以，例子里都是小写。
- 课堂第二轮里我编的作答记录「第 4 步：这次弹出哪些，选了『不弹，+ 直接入栈』」：`ask: pop` 的选项具体是什么字（「不弹」「弹出 −」？）、记录里写不写「第几步」，说明里都没有例子，是猜的。
- 课堂里 `figure target=st-b1 set step=3` 是「读完 b、还没读 +」：我按「第 0 步是开始、每读一个符号一步」数的，没把握。
- `board mark target=st-b1`（整个组件画框）能不能对 stack 组件用：说明说 `target=` 可以是组件 id，stack 的 `item=` / `label=` 按什么数没写，所以我只框了整个组件。

## ds-nextval　KMP 的 next 和 nextval

**理想的教法**
1. 从「在 j 失配时，已经对上的 T[1..j−1] 能保留多少」引出 next[j] = 最长相等前后缀 + 1。
2. 学生一格一格算 next（页面标出前后缀）。
3. 拿一个主串匹配，让学生亲眼看到「退回去比的还是同一个字符，白比一次」。
4. 再算 nextval，最后换一个模式串独立填。

**现有组件做到了**：`quiz` 讲 next 的含义；`kmp show: next ask: next`、`show: nextval ask: nextval`；`kmp text: … ask: slide` 演示匹配；`mode: fill` 换串填两行。

**想做但做不到的**
- **在匹配演示里标出「白比的那一次」并对比 next 和 nextval 的比较次数**：想要两条匹配并排（`use: next` 和 `use: nextval`），下面写各比了几次。现在得放两个 `kmp`，比较次数还得学生自己数，页面不汇总。
- **让学生在模式串上自己框前缀、后缀**（拖两个框），页面判「是不是相等、是不是最长」：现在只能填一个数。
- 题面里「abaa 的最长相等前后缀是 a，next[5] = 2」是我自己算的（写在 `quiz` 的选项和解析里）。想要表达式 `next("abaabc", 5)` 让页面算。

**拿不准的**
- `ask: slide` 是每次失配都问还是只问第一次；我设计的主串 abaacabaabc 在 j = 5 失配后会连续退（2 → 1 → 0），可能问三次。
- `mode: fill` 配 `show: nextval` 是不是 next、nextval 两行都填（说明写「kmp 填每个 j 的 next、nextval」，我理解是都填）。
- `kmp` 写了 `text:` 时 `show:` 要不要写 `match`：说明说「写了 text: 就是 show: match」，我没写 show。

## ds-reverse　单链表就地逆置

**理想的教法**
1. 先让学生发现：头插法插 1 2 3 4 得到 4 3 2 1 → 逆置 = 摘下来头插。
2. 在一个具体链表上跟踪每一步：p、r、L->next 怎么变，关键处先猜。
3. 去掉 r 再跑一遍，亲眼看到链断了、结点丢了。
4. 学生自己写代码，页面跑测试。

**现有组件做到了**：这一题工具最强。`answer type: seq` 发现规律；`trace` 跑带结构体的 C 代码、结点画成框、`predict` 问指针指向；去掉 r 的版本页面会提醒「没有指针指着、没有 free：内存泄漏」，正好是「为什么要先记下 p->next」的证据；`code` 让学生写代码跑测试。

**想做但做不到的**
- **学生自己拨指针**：最想要的是在链表图上让学生自己做这四句（拖 r 指到 p->next、拖 p->next 指到头结点后面……），页面判每一步，拨错了马上看到链断了。`trace` 只能看、只能在 predict 的地方猜。
- **`code` 的链表测试写法没有说明**：我写的 `L = list [头, 1, 2, 3, 4] -> L = list [头, 4, 3, 2, 1]` 是照 `trace` 的 `let L = list [...]` 猜的。说明里 `tests:` 只有数组和 `return =`、`out =` 的例子；期望是链表时怎么写、比较的是不是整条链、头结点要不要写都不知道。
- `code` 的复杂度估计（`scale:`）对链表的输入怎么生成（`rand(n)` 只给数组），我没写 `scale:`，不知道没写会怎样。

**拿不准的**
- `code` 的 `starter:` 能不能放 `typedef`（`fn:` 里的 `LinkList` 要先有定义）；starter 是多行续行，里面空行会不会把字段截断（我去掉了空行）。
- `trace` 的行号：从 `code:` 下面第一行（typedef）开始数 1 吗？我是这么数的（第 8 行 `L->next = NULL;`、第 11 行 `p->next = L->next;`、第 13 行 `p = r;`）。数错了 predict 就问到别的行上。
- `predict: 13 if p->data == 3 -> p`：条件是「走到这一行、执行之前」判，还是执行之后？我按执行之前写（这时 p 是 3，执行完 p 指向 4）。
- `predict: 8 -> L->next` 的答案是 NULL，学生写 NULL / ∧ 都认，这个说明写了，好。

## 课堂（ds-postfix）

- 课堂的三轮写下来顺手：`board pin` 先放规则留一个空，`stack ask: pop` 先猜，答错后 `figure set step=3` 退回到那一刻、`mark` 框住、`add` 一道 `quiz`；「没懂」时换板代数进去。
- 拿不准：`ask: pop` 答错以后组件自己是不是已经揭晓、往下走了；我在第二轮 `set step=3` 把它拨回去，不知道会不会和组件的「已问过」状态冲突，学生再点下一步会不会再问一次。
- 第三轮本来想用 `stack postfix: 5 3 1 + - ask: value` 让页面一步步算后缀式（更直观），但这样第三轮就换了一种组件，学生要重新看懂画面，所以用了一个 `answer`。两种都行，说明里没有建议。
- 资料包 `plan` 里点了名的组件会带完整写法，这个很好；但 `system-数据结构.md` 里 stack 只有精简版，`fill` 的表格格式（栈怎么写）在精简版里看不到，课堂 Claude 要用 fill 得先调 `component_doc` 多等一轮。

## 如果只能再加三样

1. **「自己搭结构」的作答模式（树 / 链表）：`btree` `huffman` `avl` 的 `mode: do`、链表的拨指针。**
   这批五题里有三题的「教到什么程度」写的是「自己画出」「自己一步步合并」「跟踪每一步指针」，现在只能看演示 + 选择 / 填一个结果，画的部分全在 Notability 里、页面判不了。像 `elim` 的 `mode: do` 那样：学生在图上点「插入 / 分裂 / 合并 / 把这个指针指到那里」，页面逐步执行、判对错、记录错在哪一步，是 408 数据结构最缺的一块。

2. **表达式里能调用演示引擎的结果**：`next("abaabc")`、`nextval(...)`、`huffcode(权值, 字符)`、`postfix("a-b+c")`、`btree(…, 4)` 这类函数，能用在 `\calc`、`answer:`、`practice` 的 `type: custom` 里。
   现在凡是题面、解析、译码题里要引用「组件算出来的东西」，我都得自己手算（本批的 `010010011`、`next[5]=2` 都是），违反「数让页面算」；也没法用 `practice` 换着数出 next / 后缀式 / 哈夫曼编码的题。

3. **一次写完的实时黑板里「答完才出现」**：段或常驻栏写 `after: q-five`（某个组件作答以后才显示）。
   验收（以及真实里我想一次多写几块板时）要整条路径提前写好，但常驻栏的结论、下一块板的提示会比学生的猜测先露出来。再加上演示组件能按「种类 + 第几次」问（比如 `ask: split` 只问真正分裂的那几次），不用我猜步号——这两件让提前写好的课也守得住「结论不早于猜想」。
