# 摩擦报告 · 组成原理（第二批）

总的感觉：这一批五道题，组件库里都有现成的演示组件（`fadd`、`mul`、`div`、`hamming`、`layout`），而且说明里的例子用的就是题里的数，所以「过程」这部分几乎不用凑。难的是两头：
- 前头「为什么」（小阶向大阶、为什么看两位、为什么不恢复余数、为什么 2^k ≥ n+k+1、为什么对齐）只能用 `steps` 选择题、`quiz`、`conjecture` 来推，没有能让学生在图上动手的东西。
- 后头「换着数练」只能用 `practice` 自定义题型，自己用表达式把整个算法再算一遍（左规位数、海明码、Booth 乘积），题面的二进制写法也要硬拼。演示组件本身不能随机出题。

## co-fadd　浮点加法

**理想的教法**
- 对阶：画两根尾数的位串，学生把小阶那根拖着右移，移出去的位掉进「括号」里；再试着把大阶那根左移，看最高位被挤掉、数值变了多少（页面算出误差对比），自己得出「小阶向大阶看齐」。
- 尾数相加：竖式，学生自己逐位写和，页面逐位批。
- 规格化：学生点「左规 / 右规」按钮一次次移，页面实时显示阶码跟着变，直到 00.1 / 11.0；−1/2、−1 这两个特殊情况让学生自己撞上。
- 舍入、溢出：先猜再揭晓。
- 最后换着数练：页面随机出 x、y，学生用 `fadd` 的 fill 表走一遍。

**现有组件做到了**
- `fadd` 演示把五步全走了，`ask: code, shift, sum, norm, round, of` 每一步先问，正好是「自己走五步」。
- `fadd mode: fill` 换一组会右规的数（0.1101 + 0.0101(1) 溢出到 01.xxx）让学生填整张表。
- `quiz` 问对阶方向、问哪些尾数是规格化的（含 −1/2、−1）；`conjecture` 让学生说为什么不能大阶向小阶看齐。
- `practice type: custom` 出「要左规几位」，用 `floor(log2(…))` 算出位数。

**想做但做不到的**
- 对阶的「对比」：想让页面把「大阶向小阶看齐」也算一遍、显示错成多少，和正确的放一起。`fadd` 只走正确的路，错法诊断只在作答里出现，不能主动演示错法给学生看。
- 拖动 / 点按钮做移位：没有「学生自己做移位、页面跟着算」的 do 模式（`elim` 有 `mode: do`，`fadd` 没有）。
- `fadd` 不能随机出题：`practice` 不能套演示组件，只能我自己拿表达式把规格化重写一遍（`pr-left` 里那串 `(1 - s)*(7 - floor(log2(f))) + s*(f >= 128)*…`），很容易写错，而且学生练的只是「数前导位」，不是整道浮点加法。
- 想在题面上写「双符号位补码尾数 11.0101 0000」：只能拼 `\calc{bin(3*s, 2)}.\calc{bin(f, 8)}`，没有直接写定点补码（带小数点、双符号位）的函数。

**拿不准、只能猜的**
- `log2` 是不是精确的：说明说「精确计算用的是大整数」，但 `log2(128)` 这类结果再 `floor` 会不会因为浮点误差变成 6？没说。
- `bin(0, 2)` 会不会写成 `00`（补前导 0），`\calc{…}.\calc{…}` 两个紧挨着放在一个公式里行不行。
- `pick s = int(0, 1)` 当布尔用、`(f >= 128)` 乘进式子里是不是允许（说明里比较得 1/0，应该可以）。
- `fadd` 的 `ebits` / `mbits` 不写是「按 x、y 里最长的」，题里阶码 3 位、尾数 8 位，我显式写了；写了和不写有没有区别不确定。
- `mode: fill` 那一道我没法确认右规后舍入、阶码会不会再溢出，只是心里估了一下数据会触发右规（这正是说明让我们别自己算的地方，但挑数据时又不得不算）。

## co-booth　Booth 补码一位乘

**理想的教法**
- 先推出「后一位减前一位」：学生拿几组具体的 y 自己把补码真值展开、拆项、合并，页面验每一步。
- 再填王道那张表：部分积、乘数、附加位三栏，学生每一行自己写（包括这一步看哪两位、加什么、右移后的样子），页面逐格批；特别要看「最后一次不移位」。
- 最后随机出题练，学生直接写 [x·y]补。

**现有组件做到了**
- `steps` 四步：补码真值 → 拆成相邻两位之差 → 10 加什么 → 加几次（`do: true` 判数字）。
- `mul` 演示换一组数（`ask: code, op`），`mul mode: fill` 填这道题的表，错法诊断能认出「最低两位读反」「最后一次也移位」。
- `answer type: bin width: 9` 判 [x·y]补，答案写成 `unsigned(-0b1101 * 0b1011, 9)` 让页面算。
- `practice` 自定义：`[x]补 = \calc{bin(a, 5)}` 出题，答案 `unsigned(a*b, 9)`。

**想做但做不到的**
- 推导那部分只能用选择题，学生没法自己写一个含 y_i 的式子让页面判（`formula:` 只认 n / λ 这类变量、是线代的写法，下标变量 y_i 不行）。
- `mul` 的 fill 只填「每次右移后的部分积和乘数」，不填「这一步看哪两位、加了什么」这一列，而这一列正是「说清看哪两位决定加什么」的证据。
- 题面写不出 x 的真值（`-0.1101`）：`bin()` 只写补码位串，没有「写成带符号的定点小数」的函数，所以练习题面只能给 [x]补、[y]补，还得写一句「小数点在最高位后面」。
- `practice` 不能直接用 `mul` 引擎出随机题（`mul mode: quiz` 是固定数）。

**拿不准、只能猜的**
- `answer type: bin` 学生写 `1.01110001`（带小数点）算不算对？说明里 bin 只说了能带 `0x`/`0b`/空格，没说小数点；`fadd` / `mul` 自己的输入说了「小数点写不写都行」。我只好在题面写「不写小数点」。
- `steps` 里 `choices:` 和 `answer:` 是按原文逐字比的吗？选项里有 TeX 时要不要一模一样（我照抄了）。
- `do: true` 的 `answer: 4 + 1` 这种表达式算不算「能算出数」——应该算，但没例子。
- `mul` 的 `ask: op` 是每一步都问，还是只问一次？题里一共 5 次加，每次都问会不会太多？说明没讲。

## co-div　原码加减交替除法

**理想的教法**
- 先让学生看到恢复余数法的两步（加 |y| 恢复、左移减 |y|），自己把它们代数合并成「左移加 |y|」；再在同一组数上把两种方法并排走，看余数序列一样、少了几次加法。
- 自己写每一步的余数和上商（表），页面逐格批。
- 最后余数：学生自己决定要不要恢复、写成 r × 2^−n、符号跟谁。

**现有组件做到了**
- `steps` 三步：写出恢复法的 r_{i+1} → 化简成 2r_i + |y| → 最后余数为负怎么办。
- `div` 演示换一组数（`ask: q`），`div mode: fill` 填这道题每次的余数和上商；错法诊断认得出「最后没恢复」「余数符号跟了商」。
- `quiz` 问真正的余数是 −r×2^−4 还是别的；`practice` 自定义练商（`div(16*a, b)`，`check: bin width: 4`），explain 里用 `\calc` 写出余数。

**想做但做不到的**
- 恢复余数法和加减交替法并排对比：`div` 只有 `orig` / `comp` 两种（加减交替），没有恢复余数法，没法在同一组数上并排给学生看「余数一样、步数少了」。
- `div mode: fill` 不知道包不包括最后的「恢复余数」那一步和最终余数；如果不包括，「最后余数怎么处理」就只能靠 `quiz` 选。
- 练习只能判商（一个 answer 一个值），不能同时判商和余数；想要一题两格（商、余数）的 `answer`（或答案是一组二进制串）。
- 符号单独处理那一步（x_s ⊕ y_s）没地方让学生作答，只能写在常驻栏里。

**拿不准、只能猜的**
- `div` 的演示用 `x: 0.1001`、`y: -0.1011`，一正一负可以吗？说明只说 |x| < |y|。
- `practice` 里 `pick a = int(1, b - 1)` 上界用前面取的数，说明「完整写法」里说可以；`check: bin` 配 `width: 4` 时学生写 `1101` 还是 `0.1101`？小数点能不能带同样不确定。
- `div mode: fill` 的余数格子要学生写成什么样（带不带双符号位、带不带括号）没说。

## co-hamming　海明码

**理想的教法**
- 位置编号写成二进制排成一张表，学生在表上点出 P1、P2、P3 各管哪几位（点格子，页面判），再自己按位异或算出每个 P_i。
- 纠错：学生在收到的 7 位上点出每个 S_i 要异或的位，页面一格格亮，最后把 S3S2S1 读成位置、点出那一位翻过来。
- 换着数练：编码和纠错各几题。

**现有组件做到了**
- `quiz` 问要分几种情况（推出 2^k ≥ n+k+1）、`answer` 算 k（表达式写成「试 k 的个数」）。
- `quiz` 多选 P2 管哪几位；`hamming` 演示 `data: 1010`（`ask: p, code`）和纠错 `recv: 1000010`（`ask: s, pos`）。
- 两个 `practice` 自定义：随机信息位求海明码（`bit`、`xor` 拼出 7 位，`check: bin width: 7`），随机错一位找位置。

**想做但做不到的**
- 「点出每个校验位管哪几位」：`hamming` 的 `ask: p` 是问 P_i 的值，不是让学生在位置表上点出它管的格子；只好用 `quiz` 多选凑，而且只能问一个 P2。
- `practice` 自定义题型里要把海明码整个用表达式重写一遍（P1、P2、P3、拼 7 位），对 n=4 还行，换成 n=8（12 位海明码）几乎写不动；想要 `practice` 能直接用 `hamming` 引擎随机出题（`practice type: hamming`），或者表达式里有 `hamming(d)` 这类函数。
- 想要 S 的计算让学生在 `fill` 里一格格写 S1、S2、S3（`hamming` 的 fill 写没写这个，说明没有讲 hamming 的 fill 填什么——只有 crc 写了）。

**拿不准、只能猜的**
- 纠错只写 `recv: 1000010` 不写 `data:` 行不行？说明是「`recv:` 改成纠错」，像是 `data` 的替代，但没有例子。
- `hamming` 的 `ask: k`、`code` 学生写的时候 7 位从哪边开始（H7…H1，左边高位），我按说明写了。
- `practice` 里给变量起名 `P1`、`h`、`r` 会不会和保留名冲突。出错位置本来想叫 `e`，想起 `e` 是常数（说明里 `n`、`E` 可以当普通名字，`e` 没说能不能），改成了 `w`。哪些名字能用，最好列一张表。
- `shl(1, max(e - 1, 0))` 乘 `(e > 0)` 这种写法能不能算；`answer` 里写 `(2 < n + 2) + …` 比较相加是不是允许。

## co-align　结构体的对齐（32 位）

**理想的教法**
- 一排 12 个字节格子，学生把成员拖进去（char 1 格、int 4 格、short 2 格），页面按对齐规则判能不能放在这里、哪些格子是填充；放完自己点 sizeof。
- 为什么对齐：画出存储器按 4 字节一行，学生把 int 放在不同的起点，页面数出要访存几次。
- 重排：学生自己拖顺序，页面实时算 sizeof，找最省的排法。

**现有组件做到了**
- `sketch` 画 int 跨两个字的示意图 + `quiz` 填「访存几次」。
- `layout` 演示 `ask: offset, size`（页面画出成员表和填充字节）；换一个结构体用 `layout mode: quiz` 写 sizeof（原顺序、重排后各一个）。
- 「自己画出内存布局和填充的字节」用 `frames` 的挖空凑：8 个字节格子一格一个 `{{…}}`，填 b/c/a/空。

**想做但做不到的**
- 真正「画布局」：`layout` 的 fill 只填偏移、地址、sizeof，不能一个字节一个字节地填（哪个成员 / 填充）。我用 `frames` 挖空凑，但 `frames` 的内容是我自己算的（违背「让页面算」），而且学生要逐格打字，iPad 上很慢。想要 `layout mode: fill` 加一种「每个字节点一下选成员 / 填充」的表。
- 拖成员调顺序、页面实时算 sizeof：没有。只能出两个固定顺序的 `layout quiz`。
- 「访存几次」的示意图是静态 `sketch`，int 放在哪个起点不能让学生拖着试；`sketch` 不能互动，`scene` 是线代的。
- 「省几个字节」只能写进 `frames` 的挖空（`{{4}}`），数是我算的。

**拿不准、只能猜的**
- `layout` 不写 `at:`（首地址）行不行，偏移会不会照样问；`ask: offset` 是每个成员都问吗。
- `frames` 的 `{{空|-|无}}` 学生写「空」能判对吗；`>` 说明行里挖空（`{{8}}`）可以吗——说明说「文字里都行」，但 `>` 行算不算「文字」不确定。
- `frames` 第 2 帧挖空、第 3 帧揭晓：学生填对第 2 帧才能往下走，第 3 帧的 `{{8}}` `{{4}}` 又是一处要填的，顺序是不是这样理解的。
- 示意图里 `class="gray faint"` 两个 class 能不能一起写，`rect` 默认是不是只画边框。

## 课堂（class.class.json，Booth）

**写的时候拿不准的**
- 第二轮的作答记录我照说明里的例子编：「[作答] b1 里的 steps ex-b1「Booth 看哪两位」第 2 步：选了「…」（错），用时 48 秒」。`steps` 的选项作答记录具体长什么样（带不带组件 id、选项里的 TeX 会怎么写出来）说明没有完整例子。
- `board mark` 块：开头一行只写 `target=` 时，它自己算不算一条（会不会把整个 derive 框起来）？说明的 `m-b6` 例子开头一行也只有 target，后面才是 row。我为了保险把第一条写在开头一行上。
- 同一轮里先 `figure set step=2` 再 `mark term=a`：第二行刚写出来（有动画）时 mark 找不找得到 `\hl{a}`？`\hl` 放在 `derive` 的行里能不能被 mark 找到，说明里只举了正文公式的例子。
- 资料包：system 文件里说「资料包里点了名的组件，完整写法已经放在下面」，但 CLAUDE-PROJECT.md 第六节没写点名用哪个字段，所以我没点名。
- 第三轮学生说「没懂，为什么？」，我判断是「缺思路」（推导看不懂），换 n=2 的小例子拆项；这对不对只能看课堂里学生下一步的反应。

## 如果组件库只能再加三样东西

1. **演示组件能随机出题（`practice` 套演示引擎）**。比如 `practice type: mul`、`type: fadd`、`type: div`、`type: hamming`，写上数值位数、取值范围，页面每题随机出 x、y（或信息位），学生写结果，判分和错法诊断都用现成的引擎。现在只能在 `practice type: custom` 里拿 `bit` / `xor` / `log2` 把整个算法重写一遍：容易写错（这次的左规位数、海明码各写了一长串），换个规模（12 位海明码、8 位尾数的 Booth）就写不动，而且学生练的是我写的近似，不是真算法。这一批五道题都有这个需要。

2. **按格子作答的「填格子」表（尤其是位串 / 字节格子），答案由页面算**。一排或一张格子，学生一格格点选或填（成员 / 填充、某个 P_i 管不管这一位、这一步看哪两位、加什么），答案用表达式或组件算出来，逐格批、标出第一处错。用在：结构体布局（每个字节属于谁）、海明码的覆盖表、Booth 表里「看哪两位 / 加什么」那一列、对阶时移出去的位。现在只能用 `frames` 挖空凑，内容要我自己算，学生在 iPad 上逐格打字也慢。

3. **定点数 / 补码的写法函数和答案格式**：`fix(x, 4)` 写出带符号的定点小数（`-0.1101`）、`fixcode(x, 4, 2)` 写出双符号位补码（`11.0011`），能放进 `\calc{…}` 和 `practice` 的题面；`answer type: bin` 接受小数点和双符号位（`1.01110001`、`11.0011`）。现在题面只能拼 `\calc{bin(3*s, 2)}.\calc{bin(f, 8)}`，答案只能请学生「不写小数点」，组成原理里几乎每道定点 / 浮点题都会碰到。
