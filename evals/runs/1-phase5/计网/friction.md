# 摩擦报告 · 计网（第二批题库，1-phase5）

只读了 `CLAUDE-PROJECT.md`、`system-计网.md` 和题库。五道题都有现成的专门组件（`frag`、`tcp`、`csma`、`encode`、`util`），比用 `frames` 硬凑顺手得多。下面写的是还差的地方，以及我拿不准、只能猜的写法。

## cn-frag　IP 分片

**理想的教法**
- 画出原数据报：20 字节首部 + 3980 字节数据的一条。学生自己拖「刀」切数据部分，刀只能停在 8 的倍数上（停在 1480 能停，停在 1481 停不住），切完页面自动长出每片的首部，算出总长度、片偏移、MF。
- IP 首部画成 32 位一行的字段图，13 位的片偏移字段亮起来，学生自己看出 2¹³ 不够数字节，所以单位得是 8 字节。
- 第二段 MTU 576：学生点原数据报的第 2 片再切一次，页面把小片的片偏移写成「原起点 + 小片里的位置」，两层刻度并排显示。

**现有组件做到了的**
- `frag` 一个组件把分片的过程、先猜（`max` `count` `offset` `mf`）、自己填表（`mode: fill`）、多段 MTU（`mtu: 1500, 576`）都做了，还有错法诊断（没取 8 的倍数、片偏移写成字节数）。填表那块我特意换了 MTU 1000（980 不是 8 的倍数），错法诊断有机会用上。
- 「为什么是 8 的倍数」用 `quiz` 问 + `answer` 算 MTU 576 每片最多装多少（556 → 552）。
- `practice` 自定义题型随机出「最后一片的片偏移」，`where mod(m - 20, 8) != 0` 保证每题都有取 8 倍数的坑。

**想做但做不到的**
- **拖着切**：没有能拖的「切分条」，只能看页面切好的。
- **IP 首部字段图**：组成原理那边的 `bits` 能按字段画位，但只给组成原理用；计网没有「首部格式」组件，13 位片偏移只能用文字讲。
- **practice 一题只能答一个数**：我想要的练习是「写出每片的总长度、片偏移、MF」整张小表，practice 给不了带标签的多格答案，只好只问最后一片的片偏移。
- **没有 `ceil`**：片数是 ⌈数据长度 ÷ 每片数据⌉，只能写成 `div(d + s - 1, s)`。能用，但容易写错，也不好读。

**拿不准、只能猜的**
- `ask: offset` 问的是哪一片的片偏移？每一片都问，还是只问一片？说明没写。
- `mtu: 1500, 576` 配 `ask: offset` 时，问的是第一段分出的片，还是第二段再分出的小片？
- `mode: fill` 配两段 MTU 时，表里是不是每个最终的小片一行？
- `after: \text{字节}` 这种单位写法对不对（说明里 `after:` 是 TeX，没有带中文单位的例子）。
- `quiz` 的选项里能不能写 `\calc{…}`（说明说「任何公式里都能写」，我按能写处理）。
- 实时黑板里一段的 `let` 块，后面的段能不能用？说明讲的是「整节课」，可实时黑板是一段段分开写进数据库的，不知道先后、跨段怎么算。所以我每处都把表达式写全了（`floor((1500-20)/8)`），没敢用 `let`。

## cn-tcpseq　TCP 的序号和确认号

**理想的教法**
- 一条「字节尺」：每格一个字节，学生自己拖出第一段的右边界（拖到 99 和拖到 100 页面给的反馈不一样），点一个字节就显示它属于哪一段。差 1 这个错（30 / 31）在尺子上一眼就能看出来。
- 第 (4) 问：B 的接收缓存画成一排格子，到的段填进去，中间的洞空着，确认号的箭头指在第一个洞上。学生自己拖确认号箭头放到哪，页面判对错。

**现有组件做到了的**
- `tcp` 的 `send: 70 100` + `last: 180` 正好就是这道题：时序图、先猜确认号和长度（`ask: ack, len`）；`lost: 1` 演示累积确认。
- 字节尺用 `sketch` 画了个静态的；「为什么还是 70」用 `conjecture`（实时黑板默认 `grade: off`，由我来看）；换数用 `tcp` 的 `mode: quiz` 和 practice。

**想做但做不到的**
- **能拖的字节尺 / 接收缓存**：`sketch` 是静的，学生不能在上面拖边界、点字节；`scene` 能拖，但它是线代专用的坐标图，不是格子。
- **差 1 的错法诊断**：`tcp` 列出的错法里没有「长度 = 后序号 − 前序号 + 1」，学生最常见的错就是 31，页面认不出。
- 第 (4) 问的「为什么」只能自由作答，我得自己看；想要的是学生在缓存图上点出「第一个洞」，页面能判。

**拿不准、只能猜的**
- `ask: len` 问的是第几段的长度？有 `last:` 时问第二段（这题的第 3 问），我是这么猜的。
- `lost: 1` 和 `last: 180` 一起写时，图上是不是先画出 B 发 70 的重复确认，再重传、确认到 180？说明只写了「B 暂存失序的，重传后一起确认」。
- `seq: 1000` + `lens: 200 300 400` + `lost: 2` + `mode: quiz`：「依次写确认号」时，重复确认（1200 出现两次）要不要写？要写几个？说明没说，学生可能照着我的题面写不对。
- 课堂里想用 `board mark` 标 `sketch` 里写着 100 的文字：`label=` 找 sketch 文字只写在「完整写法」里，课堂 Claude 拿到的精简说明里没有。所以我在正文公式里用 `\hl{n100}{100}` 起了名字，再 `mark term=`，这是精简说明里写明了的路子。

## cn-csma　CSMA/CD 的最短帧长

**理想的教法**
- 时空图上让学生**自己拖 B 开始发的时刻**（0 到 τ 之间），看两个信号在哪相遇、A 什么时候检测到冲突，拖到最右边时 A 检测到的时刻逼近 2τ，结论「最坏 2τ」是学生拖出来的。
- 两个滑块：距离、数据率。拖着看最短帧长怎么变（成正比），再先猜后拖。

**现有组件做到了的**
- `csma` 的 `bsend: last` 画了最坏情况的时空图，`ask: tau, detect` 先猜；`mode: fill` 让学生自己填 τ、争用期、最短帧长；错法诊断（争用期当 τ、以为 A 总在 2τ 检测到）很对口。
- 「数据率、距离变了」用两道 `quiz`，`explain` 里用 `\calc` 算出新的帧长；练习用 practice。

**想做但做不到的**
- **拖 B 的开始时刻**：`bsend:` 只能写死一个值（`0`、`8μs`、`last`），不能拖。想看「B 越晚发、A 越晚知道」，只能放好几个 `csma`，一屏放不下。
- **滑块 what-if**：计网的演示组件都没有 `slider`；`graph` 能画最短帧长随距离变的直线，但它是线代专用的（标了科目），计网里能不能用、带不带单位，都不知道。
- `dframe:`（帧长变了距离怎么变）是反着问的，和「数据率提高 / 距离变长时最短帧长怎么变」方向不一样，没用上。

**拿不准、只能猜的**
- `mode: fill` 每一行的单位（τ 写 μs 还是 s？最短帧长写 bit）：说明说「单位写在行名里」，我猜学生只填数，单位照行名。
- 不写 `v:` 时默认 200 m/μs，等于题目里的 2×10⁸ m/s，我就没写。
- 没有 `bsend:` 的 fill 只有三行（τ、争用期、最短帧长），还是也带「两边检测到冲突的时刻」？

## cn-encode　差分曼彻斯特编码

**理想的教法**
- **学生用 Apple Pencil 在网格上画波形**（或者一个半码元点一下切换高 / 低），页面一位一位判，标出第一处错，错的那位旁边写「开头该跳 / 不该跳」。这是这道题「自己画出波形」最直接的做法。
- 同一条波形，点一下「当曼彻斯特读 / 当差分曼彻斯特读」切换，看的位置（中间 / 开头）在图上亮出来。

**现有组件做到了的**
- `encode` 的 `code: diffman, manchester` 画在一起对比，`ask: level` 每位先猜前半个码元；`mode: fill` 逐位填「高低」；`levels:` 反过来读波形（`ask: bit`）；`rate:` + `ask: baud` 算码元速率。错法诊断（把有跳变当 1、按曼彻斯特读差分曼彻斯特）正好是这课要抓的。
- 练习：practice 没有电平串的题型，我用 `check: bin`、`width: 16` 绕过去：把 16 个半码元当成一串二进制位，用 8 行 `let` 加 `xor`、`bit` 一位一位递推出电平。题面的例子我对过，算得对。

**想做但做不到的**
- **画波形 / 点格子切换电平**：fill 填的是「高低」文字，不是画。学生在 Notability 里画的波形只能截图交，页面判不了。
- **practice 出编码题**：上面那个 `bin` 的绕法太绕，换一种编码（NRZI、曼彻斯特）就得重写一遍递推。想要 practice 里直接能用 `encode` 当题型（随机比特串，判电平串）。`bin(w, 16)` 按四位一组显示，和两位一位的半码元对不齐，解析读起来别扭。

**拿不准、只能猜的**
- `mode: fill` 每格填「高低」「低高」，还是 `10` / `01`、`HL` 都认？说明写「每一位填『高低』」。
- `levels:` 配 `code: diffman` 时开始前的电平照 `start:` 的默认（低），我是这么猜的。
- `ask: baud` 需不需要同时有 `bits:`？我写了。

## cn-sw　停止-等待协议的信道利用率

**理想的教法**
- 一个周期的时间线，帧长做成滑块：学生拖帧长，看实线（在发）和虚线（空等）的比例跟着变，U 的读数实时更新；先猜「多长能到 50%」，再拖到正好一半。
- 画出 U 随帧长变化的曲线，标出 50% 那一点。
- 停等和滑动窗口并排的时间线，窗口也做成滑块，看空等怎么被填满。

**现有组件做到了的**
- `util` 很合适：`proto: sw` 画一个周期，`ask: tframe, cycle, u` 先猜；不写 `frame:`、写 `target: 50%` 正好就是原题的反求（`ask: lmin`）；`proto: gbn` + `target: 100%` + `ask: wmin` 讲滑动窗口怎么改善。
- 「自己写出式子」用了 `answer` 的 `formula: T, d`（answer 写 `T/(T+2*d)`），页面代值比较。

**想做但做不到的**
- **帧长、窗口滑块**：`util` 没有 slider，不能拖着看 U 怎么变，只能换几个写死的数。
- **U–L 曲线**：同 csma，`graph` 是线代专用的。

**拿不准、只能猜的**
- **`formula:` 在计网里能不能用**：它写在「answer 的线代写法」那一节（标了线代），说明又说「别的变量也行：`formula: n, k`」。实时黑板里我照完整说明用了 `formula: T, d`；课堂 Claude 拿到的计网说明里根本没有 `formula`。要是计网不支持，这一格会报错。另外两个变量时代哪些值、会不会代到 0，也不知道。
- `frame: 40bit` 带 `bit` 单位能不能读（例子里是 `1000B`，`csma` 有 `-800bit`，我照着写的）。
- 停止-等待写了 `target:` 又不写 `frame:` 时，`ask: lmin` 是问帧长至少多少 bit，我是这么理解的；`ask: reach` 只在写了 `frame:` 时才有。

## 课堂（cn-tcpseq，三轮）

- 第一轮：常驻栏放题目的两个序号；第一块板是字节条 `sketch` + 问第 (1) 问。
- 第二轮：学生填 31（差 1）。用 `mark term=n100` 圈出 100，`add` 一道小 `quiz`：「100 号字节在哪一段」。
- 第三轮「没懂」：缺的是计数的直觉，不是 TCP 知识。换成一格一个字节的小数（序号 1 和 4），让学生数蓝格子，再回到 70 / 100。
- 拿不准的：课堂说明里 sketch 只写着「只能 highlight」，`mark` 能不能标 sketch 里的文字没说，所以改成在公式里用 `\hl`。sketch 的 `text-anchor` 属性我是照例子写的；白名单里允许哪些属性没有列全。

## 只能再加三样的话

1. **能在时间轴 / 波形上直接动手的输入**：一个半码元点一下切换高 / 低（或者用 Pencil 在网格上画），页面逐位判；时空图上能拖时刻（CSMA 里 B 开始发的时刻）、拖边界（字节尺、分片的切口，只能停在合法的位置上）。计网的过程题都是「在时间轴、字节轴上标东西」，现在学生只能看页面画好的、再用文字填表，最核心的「自己画出波形」「自己切」做不到。
2. **计网演示组件的参数滑块和曲线**：在 `csma`、`util`、`frag` 里写 `slider`（距离、数据率、帧长、窗口、MTU），拖着看最短帧长、U、片数怎么变；或者把 `graph`（函数图）开放给计网，带单位，能画 U–帧长、最短帧长–距离。「数据率提高 / 距离变长时怎么变」「滑动窗口怎么改善」这类教学目标都是 what-if，现在只能靠选择题。
3. **practice 的多格答案和更多判法**：一题能有几个带标签的格子（每片的总长度 / 片偏移 / MF，几个确认号），能判电平串（或者直接拿演示组件当随机题型：`type: frag`、`type: encode`），再补一个 `ceil`。现在练习只能问一个数，编码题得用 `bin` 和 8 行 `xor` 硬绕，换一种编码就得重写。
