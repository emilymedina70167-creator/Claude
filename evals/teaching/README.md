# 教学尺子（模拟学生）

`evals/` 量的是「老师写的东西对不对」（一次写对率）；这里量的是**老师教得好不好**：给一个带着设定好的误解的模拟学生上课，看老师多久把误解问出来、是不是针对它讲、守没守红线。见 `docs/learning-plan.md` 第 4 节。

## 怎么搭的

- `scenarios/*.json`：一个场景一个文件：科目、资料包（`pack`，和真课一样）、学生的设定（`persona`，只给扮学生的子代理看）、误解（`misconception`）和评分细则（`rubric`，只给评卷人看）。
- `tools/teach-sim.mjs`：一节模拟课的「页面」。老师和学生不直接对话，都经过它：
  - 老师的输出用真的 `protocol.js` 读、按真的规矩上黑板；
  - 学生看到的板面去掉了答案（`answer:`、`[x]`、`show:` 这些都不给）；
  - 学生的作答由它判分（steps 的选项、quiz、answer 的数和矩阵），用真的 `actionText` 写成课堂里一样的 `[作答]` / `[动作]` 行，连同真的「黑板现状」（和教学计划）发回给老师。
- 老师：子代理（和课堂一样的模型），开头读一次整份课堂说明 `system.md`（真的 `buildSystem` 拼的），之后每一轮读页面发来的 `to-teacher.md`。和真课的差别：真课每一轮整份说明重发，这里只发一次、之后发变化的部分（黑板现状、计划、学生）。
- 学生：子代理（便宜一点的模型），照 `persona` 演，误解前后一致、不主动说出来。
- 模拟课里学生能答 `steps`、`quiz`、`answer`、英语的组件，和演示组件的 `mode: quiz`、`ask:`（用真的引擎判、真的 `checkAsk`，错法诊断也照页面写「页面看出来：像是……」；在图上点的，学生写出点的名字）。`mode: fill` 填表、图（拖不了）判不了，老师子代理的说明里写着。

## 跑一轮

现在由脚本调用已经装好的 `claude` 命令行，自动跑完一节课、课后测验和评卷，不再手工轮流派子代理：

```bash
# 一节
node tools/teach-run.mjs <目录> evals/teaching/scenarios/<场景>.json [--system 文件] [--memory 文件] \
  [--teacher claude-opus-5-5] [--student claude-sonnet-5-5] [--grader claude-opus-5-5]
node tools/teach-run.mjs <目录> --continue      # 停下的（用量上限）、失败的那一节从停下的那一步接着跑
# 一整套（scenarios/ 下每个场景一节，几节一起跑；一节失败不影响别的；再跑一遍同一条命令就接着跑）
node tools/teach-suite.mjs <输出目录> --arm <名字> [--system-dir 目录] [--memory 文件] [--only a,b] [--parallel 2]
```

- `--system`：老师读这一份整份说明（旧版规则那一版：动手改之前用 `main` 生成的存在 `baseline/`）；不给就照现在的代码拼。`--system-dir` 里有 `<场景 id>.system.md` 就用它。`--memory`：记忆样例，照课堂的写法带进说明。
- 四个会话：老师（只用 `claude-opus-5-5`、effort high，不设退路模型）、学生、课后测验的学生（新开的，只拿人设、原来会什么、上课记的笔记）、评卷人。每个都在仓库外的空临时目录里跑，关掉全部工具（`--tools "" --strict-mcp-config --setting-sources "" --disable-slash-commands`），环境变量只留登录和代理要的（`cleanEnv`）：模型读不到任何文件，学生看不到 `scenario.json` 里的答案，要的东西全在提示词里。`--system-prompt-file` 是整份替换（一行字的说明约 550 token）；命令行还会自己加一小段环境说明（目录、平台、日期、模型、账户邮箱），去不掉。续会话一律 `--resume <上一次成功的会话> --fork-session`：失败的那一次留在它自己的分叉里，重试和下一轮都从成功的点接，作废的回复不进老师的上下文。
- 流程：`teach-sim init` → 老师读 `to-teacher.md` 写 `t-N.txt` → `teach-sim teacher` → 学生读 `view.md` 回一个 JSON 存 `s-N.json` → `teach-sim student`（打印「页面按预案接了」时不跑老师、学生接着答）→ …… 到任何一边打印「到时间了」或「下课了」→ `transcript` → `posttest` → 课后测验 → `score` → 评卷。
- 什么时候下课（`metrics.json` 的 `endedBy`，表里「怎么下课的」）：学生回 `"end": true`（老师说这节课到这里了、板上没有留给学生的东西，`student`）；连着 3 个来回老师没动板、学生也没作答（`idle`，钟退回到空转之前，空转的几轮不算进指标）；到时间（`time`）；老师写满 40 轮（`rounds`）。
- 花费：命令行返回的 `total_cost_usd` 是这条会话（连同分叉出来的前身）到现在的累计数，`calls[].cost` 记和这个角色上一次成功调用的差值、`calls[].total` 记原始的累计数，`costUsd` 是差值之和。
- 出错：撞了用量上限（429、`rate_limit`、「hit your … limit」）不重试、不算失败：`run.json` 写 `paused: true`、停在哪一步（`phase`、`next`、`stoppedAt`）、每个角色的会话（`sessions`）、已经花的钱，退出码 2。别的错（返回空、超时 10 分钟、退出码非 0、用的模型不对）重试一次，再不成 `failed: true`、同样记下，退出码 1。两种都能 `--continue`，都不评卷。一整套里有一节停在用量上限就不再开新的课，`summary.md` 写清哪几节没跑完。跑完的一节会删掉自己的临时目录和命令行在 `~/.claude/projects/` 下存的会话；停下的不删。学生的回复不是合法 JSON 带着报错重问一次，还不成记成「学生没有作答」接着走（`studentFallbacks`）。
- `--fake 目录`：不调用命令行，回复读 `t-N.txt` / `s-N.json` / `post.md` / `grade.txt`（一轮老师都没有不算跑完）；`--cli 命令`：换一个和 `claude` 同样参数、同样输出的程序。测试（`tests/teach-run-lib.test.js`）用这两样，不调用模型。

一节课的目录里：

| 文件 | 是什么 |
|---|---|
| `system.md` | 老师读的整份说明 |
| `t-N.txt` / `s-N.json` | 老师第 N 轮的输出 / 学生第 N 轮的作答 |
| `transcript.md` | 整节课的记录（评卷人看） |
| `notebook.md` | 学生上课记的笔记（课后测验只看它） |
| `posttest.md` / `posttest-key.md` / `posttest-answers.md` | 课后题面 / 标准答案（只给评卷人）/ 学生的作答 |
| `metrics.json` | 页面算的数：分钟、白停、第一次动笔、最长连讲、产出几分钟…… |
| `grade.json` | 评卷人打的分（见下） |
| `run.json` | 成没成、停下没有、停在哪一步、各角色的会话、每次调用花了多少（`calls`、`costUsd`）、每一轮结束时第几分钟（`timeline`） |
| `*-system.md` | 学生、课后测验、评卷人的说明（事后看发了什么） |

一整套的 `<输出目录>/summary.md` 一行一节：课后测验同类 / 迁移各对几道、用了几分钟、白停、第一次动笔第几分钟、最长连讲几分钟、产出几分钟、总体分；`summary.json` 是同一份数。行为的数和课后测验并排看，不单独报行为的数。结果写进 `results.md`。

只在改了课堂的提示词、教法、协议时跑。花多少的量级（2026-11-15 实测，os-lru 按 15 分钟、老师 10 轮、说明约 61 KiB；按累计数的差值重算过，早先每次的累计数相加记多了五六倍）：老师约 $0.52、学生约 $0.07、课后测验约 $0.03、评卷约 $0.16，一节约 $0.8、跑 4 分钟。一节讲到下课的课大约一两美元，一整套 10 个场景十几到二十几美元（花的是开发会话的额度，不是上课的），先用 `--only` 跑几个。

## 评卷（`grade.json`）

评卷人不知道是哪一版规则，读整节课的记录、场景（设定、断点、细则、要拿下的事）、页面算的数、课后题的标准答案和学生的作答，只回一个 JSON：

- `post`：每道课后题 0 / 0.5 / 1（同类 `near`、迁移 `far` 在表里分开数）。
- `found`：老师在第几分钟用一个具体的问题把设定的断点问出来（没问出来 `null`）。
- `targeted`：问出来以后是不是针对那一处讲（3 只讲错的那一步、用一个具体例子说服；1 整段重讲定义）；`onlyGap`：是不是只补了那一处。
- `contentErrors`：老师讲错（或漏讲要紧的）几处。
- `verdictAgree`：老师自己判的开放作答和评卷人判的一致几成（没判过 `null`）。
- `skipped`：细则要看老师有没有跳过学生已经会的内容时填（半会的那种学生），否则 `null`。
- `overall`：1～5；`why`：理由，举出轮次。

## 以前手工评卷的细则（`results.md` 前几轮照它打的）

- **看出误解**：第几轮老师第一次用一个具体的问题把误解暴露出来（问形状、设计出能区分两种做法的那一步……）；暴露以后第几轮老师明确说出（或在计划里写出）学生是怎么想的。没看出来记「没有」。
- **针对着讲**：看出来以后是针对那一条讲（1–3 分：3 = 只讲错的那一步、用一个具体例子说服；1 = 整段重讲定义）。
- **确认**：讲完有没有换一道新题让学生自己再做一遍（有 / 没有）。
- **红线**：红线 1（一次只推进一件事）、2（学生没作答不往下推）、5（「没把握」按没过处理）、6（不宣布掌握）、8（话要短），各犯了几次，举出轮次。
- **总体**：1–5 分，一句话理由。
