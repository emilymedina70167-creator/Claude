## p1
TCP 首部固定部分是 20 字节，画成 5 行，每行 4 字节（32 位）：

| 行 | 字段（位数） |
|---|---|
| 第1行 | 源端口(16) ｜ 目的端口(16) |
| 第2行 | 序号(32) |
| 第3行 | 确认号(32) |
| 第4行 | 数据偏移(4) ｜ 保留(6) ｜ 控制位 URG ACK PSH RST SYN FIN(各1位，共6) ｜ 窗口(16) |
| 第5行 | 校验和(16) ｜ 紧急指针(16) |

后面还有选项（长度可变）和填充。

## p2
- 说明首部长度的字段是数据偏移。
- 它占 4 位，单位是 4 字节（写 5 就是 20 字节）。
- 最大值是 1111=15，所以首部最长 15×4=60 字节，选项最多 60-20=40 字节。

## p3
按 4 字节一行切：
- 第1行：04D2 00 50
- 第2行：000003E8
- 第3行：00000000
- 第4行：5002 FFFF
- 第5行：8C3E 0000

答案：
- 源端口：04D2 = 1234
- 目的端口：0050 = 80
- 序号：000003E8 = 1000
- 首部长度：第4行前两字节 5002 展开成二进制是 0101 0000 0000 0010。按 4|6|6 切，数据偏移 0101=5，首部=5×4=20 字节。保留 000000，控制位 000010。
- 控制位对应 URG ACK PSH RST SYN FIN = 0 0 0 0 1 0，只有 SYN=1。
- 窗口：FFFF，16 位全是 1，是 65535。
- 确认号是 0，而且 ACK=0，确认号无效。

这个报文段多半是在请求建立连接，因为 SYN=1 表示建立连接、同步序号。至于它具体是三次握手的第几步，我只听过名字，不会细说。

## p4
六个控制位从左到右：
- URG：=1 时紧急指针才有效。
- ACK：=1 时确认号才有效（相当于开关）。
- PSH：尽快交付。
- RST：连接出错，要释放后重建。
- SYN：建立连接，同步序号。
- FIN：数据发完了，要求释放连接。

确认号只有在 ACK=1 时才有效。
