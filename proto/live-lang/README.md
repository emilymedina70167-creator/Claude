# 活板（测试版）

组件库机制升级的第一个试验：老师不再从组件菜单里挑，而是写几行「例子是什么」，页面把它变成能拨、能拖、能折的东西。学生一动，图、句子里的数、空的答案一起跟着变。

- `engine.js`：不碰 DOM 的引擎。读描述（`let` / `draw` / `when` / `goal` / 正文里的 `{…}`），算值，判分，`find` 替老师搜一个满足条件的例子（按条件的差模拟退火，不是瞎试：Belady 异常在随机序列里大约百万分之一，这样几十毫秒就能找到）。
- `index.html`：页面。三块示范板（408 页面置换、线代特征向量、英语定语从句），每块旁边是「老师的追问」（只写一两行 `set` 或新的行）、「页面告诉老师的」（学生的动作和板上跟着变的东西）、源码（能改）。最后一块让 Opus 5.5 当场写板、计时（出第一个字、写完），学生在板上动完再「发给老师」，它只写要改的几行。

发布成 artifact 时，`engine.js` 作为附带文件一起传，`capabilities` 是 `{ sample: {} }`。不连学习台、不写记忆。

## 写法（老师拿到的说明就是 index.html 里的 `DOC`，约 3 KB）

```
# 标题
let f = 3 拨 1..6                      学生能拨的整数
let x = [1, 0] 拖 吸附 0.5             学生能拖的向量
let r = paging(refs, f, fifo)          一个量，用到它的地方跟着变
let s = find v in 序列(15, 1..6) where faults(v, 4, fifo) > faults(v, 3, fifo)
draw A, x, A*x "Ax"                    画图：向量和矩阵进同一个平面；置换过程画成表；句子画成能折的
FIFO 分 {f} 块，缺页 {r.faults?} 次     正文：{值}、{能拨的量}、{空?}、{? 甲 | *乙}
when 条件：文字                        条件成立才出现
goal 条件 => "做到时说的话"
```

追问时：`set 名字 = 表达式` 改一个量，别的行接在板的最后。
